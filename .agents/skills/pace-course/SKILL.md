# Pace a live course

Read `../OPERATION-CONTRACT.md`, then `.planning/AGENT-WORKFLOW.md` and
`.planning/SOURCE-TO-COURSE.md`. Preserve the course's resource and AI policy.
A collected prompt, partial solution, or answer never enters an unauthorized
agent surface.

## Produce the rolling plan

1. Inventory the syllabus or LMS meeting map, posted slides, filled notes,
   assigned source sections, question sets, existing lessons, banks, and learner
   evidence across the user-approved roots. Record what is posted, withheld,
   duplicate, stale, or uncertain.
2. Reconcile the files into one accepted unit artifact. Use filled notes or the
   assigned source for content. Use slides to detect emphasis, sequence,
   diagrams, and questions. Do not create parallel summaries of the same facts.
3. Divide readings at conceptual boundaries and place first exposure one
   published class ahead, usually two to four calendar days before class.
   Reserve the morning of class for 5 to 10 minutes of retrieval, not new
   reading. Keep unpublished units out of the required lane.
4. Classify questions as instructor examples, in-class prompts, uncollected
   source questions, collected work, or formal assessment. Record the objective
   tested by collected work without reproducing its prompt when the policy bars
   agent use.
5. Require one small pre-class production attempt, then stop after the first
   slow or wrong move. Within 24 hours after class, add only the instructor's
   correction, emphasis, or changed explanation and record the miss.
6. Revise the rolling plan when the LMS map changes. Preserve the prior plan
   through the host project's supersession rules and report any deadline or
   source conflict.

The accepted pacing artifact states the class date, source locator or page
range, concept boundary, pre-class production, post-class delta, policy
boundary, and next unpublished dependency.

## Hand off to Itembank only when earned

A reading layer is the source and a bank is a later assessment artifact. Do not
build a bank merely because notes exist.

Use `author-bank` only when practice is authorized, the objectives and source
bindings are stable, and the bank can be completed and validated for coverage,
answer accuracy, explanations, structure, and scope. Never derive an item from
collected coursework. Run the shipped lint, stats, and coverage gates, keep
real banks outside this repository, and let the runtime own scoring and keyed
disclosure.

Close with the files read, accepted artifact or diff, dated plan, unresolved
posting dependencies, validation, and exact next action.
