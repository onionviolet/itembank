<objective>
Close the second submit path and give the runner's bounds a settings home.

Plan 05-01 gated the browser route. `/api/submit` is a separate, agent-facing route that
reaches `score_response()` directly today; left ungated, an agent driving `itembank submit`
against a `check` item skips execution entirely and is scored against whatever string it
sent. This plan gates it, moves the deadline and the output cap out of the runner's
defaults and into `itembank.json`, and makes the one place where the phase's honest limit
has a matching default — refusing execution when the daemon is reachable from the network
— real on both routes.

Purpose: a bound that only one of two doors respects is not a bound.
Output: the `check` settings group, both submit paths gated, and a default-closed network
refusal with its own locked copy.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN device → daemon | the boundary this plan closes by default; a phone on the same wifi reaches every route |
| agent/CLI → `do_submit` | a second, independent path to the scorer that this plan gates |
| daemon/CLI → spawned interpreter | attacker-influenced code is executed here, by design |
| spawned interpreter → host OS | **no boundary is enforced here.** Filesystem and network reach are unrestricted |
