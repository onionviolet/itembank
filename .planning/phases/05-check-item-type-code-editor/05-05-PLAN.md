<objective>
Give the `check` item a real code field: monospace, a gutter whose row N is the
editor's line N, and a Tab key that inserts a tab instead of moving focus — rendered
by a vendored CodeMirror 6 bundle, per ruling 5/11's CM6 adoption.

CODE-03 is the requirement that a rubric point citing "line 7" cites the line the learner
sees. That is not a styling nicety — it is why wrapping is off and why the gutter and the
code area share one font declaration. CM6's `Diagnostic{from,to,severity,message}` maps
1:1 onto our existing lint records (the reason the roadmap names CM6 as the editor), but
this phase uses the editor for learner input only; the lint mapping is exercised by the
future authoring surface (Phase 11). This plan builds the field and the copy beside it,
and threads the per-case run result through to the page so plan 05-06 has something to
render.

Purpose: a code field that makes every line citation a guess is not a code editor; CM6
is the editor, and the vendoring pipeline (pinned version, SHA-256, named license
review) is part of this plan's deliverable.
Output: `asCheck()` in the existing dispatch table, a mount element the CM6 boot script
renders into, the editor theme CSS built from existing theme properties, and the
honest-limits line that reads the same constant `SPEC` does.
</objective>
