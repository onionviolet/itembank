<objective>
Harden the two bounds the runner promises and prove the kill reaches two levels deep.

Plan 05-01 laid the seams: one `kill_tree()`, one threaded drain, one deadline. This plan
fills them in — the output cap gets its truncation verdict and its early kill, the Windows
branch gets a Job Object in front of the fallback, and the grandchild case Success
Criterion 3 names by hand gets its own fixture and its own test.

Purpose: a wall clock alone does not stop the two most common accidents. A program that
prints without bound is only bounded by the deadline, and a program that spawns a child
outlives the process the deadline kills.
Output: a runner whose bounds hold on both platforms, and a kill test that does not leak
processes when it fails.
</objective>

Make the cap a real bound rather than a post-hoc measurement.

`drain_pipe()` already accumulates to `cap_bytes` and then keeps reading to EOF without
accumulating. Add the second half: when the cap is crossed, set the truncated flag and
set the shared stop event, and have `run_one_case()`'s main loop watch that event
alongside the deadline. Whichever fires first calls the same `kill_tree()` — one kill
mechanism with two triggers, never two mechanisms. Do not break out of the drain loop
when the cap is crossed: a reader that stops reading while data remains in the pipe leaves
the child blocked on its next write, which converts an output overrun into a hang, which
is the exact failure the cap exists to prevent.

Set `passed` False whenever `truncated` is True, regardless of what the accumulated
prefix compares to. D-08 is explicit that a bounded run fails its case; a program whose
first 64 KB happens to match the expected text has not demonstrated correct output, and
scoring it right would teach the wrong lesson.

Keep `timed_out` and `truncated` as separate flags on the result dict. The browser copy
plan 05-06 renders distinguishes "stopped by a bound" from "produced wrong output" and
distinguishes the two bounds from each other, so collapsing them here would force the
surface to guess.

The two kills are not the same verdict. When the deadline branch fires, surface the
run-level `killed_at_timeout: True` flag on the run result (plan 05-01 already requires
the shape; pick the same one it states), so a caller can tell "killed" from "ran and
failed" without re-reading the source. The killed run produces **no dichotomous verdict**:
the normalizer plan 05-01 registered returns `None` when any case timed out, and
`score_response()` on that `None` is `None` — never `False` (criterion 12), matching the
None-not-False discipline the scorer already applies to `short`. The output-cap kill stays
a real fail (D-08): `truncated` True forces `passed` False and the run completes, so the
scorer sees a vector and returns `False`. Only the deadline kill removes the verdict.

Join both drain threads with a bounded join before returning, and reap the direct child,
so a case cannot leave a thread or a zombie behind for the next case in the same
submission.

Cap accounting is over bytes read from the pipes, not over decoded characters — decode
once at the end with a replacement error handler so a program emitting a partial multibyte
sequence at the cap boundary cannot raise inside the runner.

Create `tests/check_kill_roundtrip.py` as a new stdlib-only, framework-free script in the
house shape (`fail()` + `main()` + `sys.exit(main())`, matching `tests/check_roundtrip.py`).
Cover the behaviours above by building question dicts inline in the test rather than by
authoring more fixture bank items — these are runner-level properties and do not need a
parse round trip. Assert the early-kill property by wall clock: run a flooding,
non-terminating program with a deliberately long deadline and assert the call returns in
much less than that deadline. Assert the timeout-is-not-a-verdict property against the
scorer: for the never-terminating case, assert `run_cases()` surfaces the run-level
`killed_at_timeout` flag and that `score_response()` on that run's result (the `None` the
05-01 normalizer returns for a killed run) is `None` — not `False` (criterion 12) — while
the over-cap case still scores `False` because D-08 keeps the cap kill a real fail. Keep
every deadline in this file at one second or below so the file stays inside the phase's
80-second feedback budget.

`new_job_object()` creates the job, sets the extended limit information with the

05-04 measures it and the number goes in the spike record.

On the timeout or cap branch, close the job handle. With the kill-on-close limit set, that
one call terminates the whole tree and no separate per-process termination call is needed

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon/CLI → spawned interpreter | attacker-influenced code is executed here, by design |
| spawned interpreter → its own children | the boundary this plan hardens; a grandchild inherits the group or job the runner created |
| spawned tree → host OS | **no boundary is enforced here.** Filesystem and network reach are unrestricted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-5-01 | Denial of Service | code that never terminates | high | mitigate | Per-case wall-clock deadline with `kill_tree()` on expiry. Bounds an accidental loop; a program that detaches itself from the group or job is out of reach. |
| T-5-02 | Denial of Service | unbounded stdout/stderr, and the pipe-buffer deadlock a naive reader causes | high | mitigate | Threaded drains with a byte cap; past the cap the drain keeps reading and discarding to EOF so the child never blocks on a full pipe, and the stop event triggers the same `kill_tree()` the deadline does. A capped case fails rather than hanging the reader. |
| T-5-03 | Elevation of Privilege | a grandchild outliving the process the deadline kills | high | mitigate | POSIX: new session at spawn, group-wide SIGKILL. Windows: job object with kill-on-close, taskkill fallback. Proven by `fixtures/grandchild_spawner.py`. Reaches a child that inherited; does **not** reach one that double-forks or starts its own session. |
| T-5-04 | Elevation of Privilege | the unclosable window between spawn and job assignment on Windows | medium | accept | `subprocess.Popen` cannot resume a suspended child (bpo-1677688), so assignment is the statement immediately after spawn and a process created inside that window escapes the job. Accepted per D-16, written into the source as a comment, and **measured** over 50 iterations in plan 05-04 rather than claimed to be zero. |
| T-5-05 | Information Disclosure / Tampering | filesystem reach of the executed code | high | accept | **Not restricted.** Neither bound in this plan touches the filesystem. Disclosed, not defended. |
| T-5-06 | Information Disclosure | network reach of the executed code | high | accept | **Not restricted.** No egress control is applied at any point in this plan. |
