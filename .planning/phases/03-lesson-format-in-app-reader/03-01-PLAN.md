<objective>
Prove the whole lesson architecture end to end on the thinnest real path: a bank carries one
`## LESSON` section with one referenced heading, the reader renders it at `/lesson/<stem>`, the
heading links into the item that tests it, and that item links back to the heading.

**User story (MVP framing, from ROADMAP Phase 3 Goal):** **As a** learner, **I want to** open the
lesson an item is drawn from inside the app, **so that** I can read the teaching text and jump
straight back to the question that tests it.

proves — the lint namespace widens its validation, the renderer widens its markdown scope, the CLI
widens its selection. If the shape is wrong (a second slugifier, a corrupted stem, a lesson parser
that forks `parse_bank`'s boundary rule), it is wrong after one commit instead of after five.

`fixtures/lesson_bank.md`, and `tests/lesson_roundtrip.py` — the Wave 0 harness every later plan in
this phase extends rather than duplicates.

  <context>
`content_fingerprint()` is the digest recorded in every item's `[HASH:]` line, and `item.content_drift`
fires when a bank's recorded hash no longer matches. Today the function reads only tested-content keys
(`type`, `stem`, `opts`, `correct`, `select`, `cats`, `rows`, `steps`, `model`, `rubric`) — verified by
direct read of `model.py:142-177` — so excluding the new lesson keys needs zero code. The decision is
which side of the door to lock.

The undo cost is asymmetric and that is why this is a gate rather than a note. Excluding it now and
including it later is a one-line change that invalidates nothing. Including it now and removing it
later invalidates **every stored `[HASH:]` in every bank**, private banks included, and requires a
re-run of `itembank id-assign` over all of them plus a reconciliation of the drift warnings that
re-run produces. `03-CONTEXT.md` records this as one-way in practice.

`03-CONTEXT.md` also records that every D-number in this phase is Claude's judgment under a delegated
"plan the most optimal solution" instruction, not a user-stated preference — so this door has not been
walked through by a human yet. That is why the gate exists here rather than being skipped as
already-decided.

**3. `model.py` — `lesson_slug(text)`.** Place it immediately after `collapse()`, since it builds on
it. One function, structurally, for the same reason there is one scorer: the value stored on the
question dict and the value emitted as an HTML anchor id must come from the same call, or a lookup
that agrees with an anchor by coincidence eventually disagrees (D-03). Behaviour: `collapse()` the
input, lowercase it, drop every character outside the set of ASCII letters, digits, spaces and
hyphens, then replace each run of whitespace with a single hyphen and strip leading and trailing
hyphens. Empty input returns the empty string, and the function is idempotent over its own output.
Give it a docstring recording the deliberate consequence that a heading written entirely in
non-ASCII characters reduces to the empty string, which collides with any other such heading and is
caught loudly by plan 03-03's duplicate-heading check rather than fabricated into a unique id.

**4. `model.py` — `parse_lesson(bank_path)`.** A second, independent read over the bank file for a
different purpose. It must not change `load()`'s or `parse_bank()`'s return shape, and it must not be
called from inside either of them.

Extract the preamble by mirroring `parse_bank()`'s own boundary rule exactly: iterate every chunk of
the unbounded `re.split(r"(?m)^(?=Q\d+\.)", text)`, and stop accumulating the moment a chunk both
matches `Q\d+\.` at its start **and** parses as a real question. A first-match-only split is wrong
here and the failure is silent: a lesson containing an illustrative prose line shaped like a question
marker would be cut at that line while `parse_bank` itself sails past it, and the two would disagree
about how long the document is with nothing to tell you (03-RESEARCH.md Pitfall 2).

Inside the preamble, find the section opened by a line matching `^##\s+LESSON\s*$` and running to the
end of the preamble. Return `None` when there is no such section. Otherwise return a dict with exactly
these keys, so every downstream consumer sees one shape: `source` (the absolute path actually read),
`body` (everything after the `## LESSON` line), `intro` (the text between that line and the first
`###`, possibly empty), `headings` (a list of dicts with `text`, `slug` and `body`, in document
order, where `body` runs from just after the heading line to just before the next `###` or the end),
and `error` plus `detail`, both the empty string in this plan. Plan 03-02 is the only plan that ever
sets `error`; declaring the keys now is what keeps that addition one branch in the loader and nothing
in the parser (D-02).
