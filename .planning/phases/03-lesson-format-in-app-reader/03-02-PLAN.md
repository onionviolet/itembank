<objective>
Make one lesson shareable across banks without a format break, and make an unreadable or out-of-tree
source a reported condition rather than a crash or a silent read.

**User story (MVP framing, from ROADMAP Phase 3 Goal):** **As a** learner studying the same concept in
two subjects, **I want to** point both banks at one lesson file, **so that** I read one explanation
instead of two copies that drift apart.

Purpose: D-02 is the decision that keeps the grammar open. Written now it costs one branch in the
loader; retrofitted later it costs a migration over every bank that already carries an inline lesson.
It is also this phase's one real path-handling surface, and 03-RESEARCH.md's security domain names
path traversal through this directive as the phase's Information Disclosure threat.

D-02 gave the planner explicit leave to defer this if lint and the reader could not share one code
path cheaply. They can: plan 03-01 declared `parse_lesson()`'s full key set including the error keys,
so this plan fills a branch rather than forking a loader. Implementing it.

Output: `[LESSON-SRC:]` in the grammar, a containment refusal that never reads what it refuses, a
degraded reader state, and two fixtures that prove the shared case.
</objective>

When it is present:

- Resolve the bank file's own directory to an absolute path; that directory is the containment root.
  Join the captured value onto it and resolve the result to an absolute path. An absolute captured
  value resolves to itself, which is what makes the check catch it too rather than needing a separate
  branch.
- Refuse unless the resolved path is inside the root: it must either equal the root or begin with the
  root followed by the OS path separator. Reuse `surfaces/migrate.py`'s proven shape rather than
  writing a second containment idiom — the trailing separator is load-bearing and a check written
  fresh is where it goes missing.
- On refusal, return the dict with `error` set to the string `lesson.src_unreadable` and `detail` set
  to the locked reason text for an out-of-tree path (03-UI-SPEC.md's Copywriting Contract fixes the
  three reason forms: file not found, the escapes-its-directory phrasing, and the raw OS error text).
  Return before any file is opened. The refusal is decided from the resolved path alone; a check that
  reads first and validates after is not a containment check.
- On acceptance, read the file inside a guard for OS-level failures and, on failure, return the same
  error shape carrying the raw OS error text as the detail. On success, replace the preamble text with
  the file's contents and set `source` to the resolved path, so everything after this branch — the
  section match, the heading walk, the returned key set — runs unchanged over one string. That
  single-substitution shape is what makes D-02's "one branch in the loader and nothing in the parser"
  literally true rather than aspirational.
- Record in the docstring that an external source wins over an inline section when a bank carries
  both, so the precedence is documented rather than discovered.

Do **not** add `lesson.src_unreadable` to `LINT_CODES` and do not touch the lint-error schema in this
plan. Until a lint finding actually carries the code, it is a string this function returns, and the

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bank file → filesystem read | `[LESSON-SRC:]` is author-controlled text used to derive a path the process then opens |
| external lesson file → rendered HTML | Prose from a file outside the bank is interpolated into a served page on the same terms as inline prose |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-02 | Information Disclosure | `parse_lesson()`'s `[LESSON-SRC:]` path resolution | high | mitigate | The captured value is joined onto the bank file's own directory and resolved to an absolute path; the read happens only if that path equals the containment root or begins with the root plus the OS separator, reusing `surfaces/migrate.py:241-248`'s proven shape. A relative climb, an absolute path outside the root, and a sibling directory sharing a name prefix are all refused **before** any open, asserted by a test that places a real readable file outside the root and proves none of its content reaches the returned value. |
| T-3-01 | Tampering | rendering of prose read from an external file | high | mitigate | External lesson text goes through the identical `html.escape`-per-text-run path plan 03-01 built for inline text; there is no second render path, so there is no second escaping discipline to keep in sync. |
| T-3-04 | Denial of Service | `parse_lesson()` on an unreadable source | medium | mitigate | The OS-level read failure is caught and turned into a structured result carrying the raw error text; the function returns a dict on every path and raises on none, so neither `cmd_lesson` nor `handle_lesson_get` reaches an unhandled exception (ROADMAP SC3's "never a render-time crash"). |
| T-3-07 | Information Disclosure | the degraded page's interpolated path | low | accept | The page echoes the path the bank author wrote, not a resolved absolute path, so it discloses nothing the bank file does not already contain. It is HTML-escaped like every other interpolated value. |
| T-3-SC | Tampering | dependency supply chain | low | accept | No package-manager install exists in this phase or this project; there is no manifest to audit. |
</threat_model>
