## Phase Framing — Read This First

This phase's UI surface is small but real: one new route (`/lesson/<bank>`) rendered by a new
`surfaces/lesson.py`, plus **two small, additive touches to `surfaces/quiz_page.py`** that this
document identifies as necessary to satisfy D-09's literal bidirectional-linking requirement — touches
`03-CONTEXT.md`'s own "Integration Points" list did not enumerate. Both are flagged below with
reasoning; the planner may scope them into this phase's plan or defer them, but ROADMAP Success
Criterion 1 ("a working link from the lesson to each item that references it") is not satisfiable
without at least the first one.

| Gap this document closes | Why `03-CONTEXT.md` didn't already resolve it | Resolution |
|---|---|---|
| The quiz surface renders one item at a time from a client-shuffled array (`quiz_page.py` `Q.sort(()=>Math.random()-0.5)`); there is no existing mechanism to "deep-link into the quiz at that item." | D-09 states the requirement ("deep-linked into the quiz at that item") but `03-CONTEXT.md`'s Integration Points list scopes changes to `model.py`, `surfaces/lesson.py`, `surfaces/daemon.py`, `surfaces/cli.py` only — it does not mention `quiz_page.py`. | **New: a `#<item-id>` URL fragment on `/quiz/<bank>`.** See "Lesson → Item Deep Link" below. Minimal, additive JS in `quiz_page.py`'s existing bootstrap, no daemon route change. |
| D-09 also requires the reverse: "each item's rendered view carries a 'Read the lesson' link back to `#<slug>`." | Same list omission. Also easy to conflate with Phase 6's tier-0 hint pointer — D-09 itself pre-empts that reading: *"exactly what Phase 6's tier 0 will return — build the pointer here, **gate nothing here**."* Un-gated means visible now, not deferred. | **New: an always-visible link in the item's meta/chip row** (pre-answer, not buried in the post-answer explanation panel — see reasoning below). |

Everything else in this phase (the `LESSON`/`LESSON-REF` grammar, lint codes, `spec` text) is
`model.py`-only and has no visual surface; this document does not restate `03-CONTEXT.md`'s D-01–D-06
grammar/lint decisions, only the copy strings D-05/D-06 require to be locked (see Copywriting Contract).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps (chip padding, list marker offsets) |
| sm | 8px | Compact spacing (backlink list item gap) |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions — deliberate, not drift:** `surfaces/lesson.py`'s actual page chrome (`.wrap` max-width
and padding, `header`/`h1`/`.sub` sizing, `.card` padding/radius/margin) reuses `quiz_page.py`'s and
`study.py`'s existing off-grid literals verbatim (`22px 18px 96px`, `18px 18px 16px`, `12px` radius,
etc.) rather than the clean 8pt table above, so the reader visually reads as the *same product* as the
quiz and study pages it links to and from. Phase 4 (SURF-07, "one shared palette... `day` no longer
carries its own literal-hex stylesheet") is the phase that reconciles every surface onto one real
system; this phase does not get ahead of it by inventing a third spacing convention. New elements this
phase authors with no existing precedent (the backlinks list, fenced-code block padding) use the
declared 8pt scale above since there is nothing to match.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.55 |
| Label (uppercase meta caption — mirrors `.exp h4`) | 11px | 400 | 1.4 |
| Heading (H1 — page title) | 21px | 700 (bold) | 1.2 |
| Display (H2 — lesson section heading, rendered from `###` inside `LESSON`) | 19px | 700 (bold) | 1.3 |

Exactly two weights, matching the researcher constraint and this phase's actual needs: 400 for body
text and the uppercase label caption (labels lean on `text-transform:uppercase` + `letter-spacing`, not
extra weight, exactly as `.exp h4`/`.chip` already do — no new 500/600 weight is introduced), and 700
for both heading levels and rendered markdown `**bold**`/`<strong>`. `quiz_page.py`'s existing 600
weight (`button.go`, `.verdict`) is not reused here because this is a read-only surface with no buttons
or verdicts of its own (D-10).

Any heading level the lesson markdown produces beyond `##`/`###` (D-08's renderer is generic over
"headings," and an author could nest a `####` inside body prose) renders at the same Display size as
`###` — this phase does not add a third heading size for a nesting depth the grammar itself doesn't
define (D-01 only names `##` for the section marker and `###` for subheadings).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` | Page background |
| Secondary (30%) | `var(--card)` | The lesson body panel; matches `quiz_page.py`'s `.card` |
| Accent (10%) | `var(--accent)` | Reserved for exactly: the "Read the lesson" link (text + hover/focus), each lesson→item backlink (text + hover/focus), and the deep-linked heading's anchor-target highlight border. Nothing else — not chip backgrounds, not code blocks, not table headers. |
| Destructive | `var(--bad)` | Not used this phase — the reader is read-only and performs no destructive action (D-10) |

One additional existing token this phase reuses (not a new role, already in `THEME_CSS`):
`var(--warn)` marks the one degraded-but-not-broken state this phase renders — the
`[LESSON-SRC:]`-unreadable notice — the same token `quiz_page.py`'s `.pend` (pending/not-yet-marked)
already uses, so "something needs attention but nothing crashed" reads consistently across surfaces.

Inline/fenced code blocks use `var(--chip)` background with `var(--mut)` text for the language label,
matching `.chip`'s existing neutral treatment — code is content, not navigation, so it never takes
accent.

## Copywriting Contract

Every string below is locked and meant to be copied close to verbatim. Conventions matched:
`"Qn: message"` for a per-item lint line and `"BANK: message"` for a bank-level lint line
(`model.py:lint()`'s own two tag shapes — `"BANK"` is the literal tag `bank.answer_position_skew`
already uses, at `model.py:553`), and `"%d x -> %s"` / `sys.exit("...")` for CLI output
(`surfaces/anki.py:cmd_export()`, `surfaces/study.py:cmd_study()`).

| Element | Copy |
|---------|------|
| Primary CTA — item → lesson link (quiz item's meta/chip row, pre-answer, un-gated per D-09) | `Read the lesson` — locked verbatim from D-09's own text. Href `/lesson/<bank>#<slug>`, opens in a **new tab** (`target="_blank"`) so following it never discards the client-side quiz session's in-memory shuffle/cursor state |
| Primary CTA — lesson → item backlink (under each `###` heading) | Link text: `Q<n>: <stem, truncated to 100 chars, "…" if cut>` — matches `quiz_page.py`'s existing `finish()` miss-list truncation convention (`m.q.stem.slice(0,110)`; 100 chosen here since backlink rows sit inside a narrower card). Href `/quiz/<bank>#<id>`, navigates in the **same tab** — the reader holds no session to lose, and "jumps straight to that item" (ROADMAP's own phrasing) implies leaving the reader |
| Lesson page title | `<bank title> lesson` — matches `surfaces/study.py`'s existing `"__TITLE__ study set"` pattern (`STUDY_TEMPLATE`'s `<title>` and `<h1>`) |
| Lesson page byline (`.sub`, under the H1) | `Reading material for this bank. Following a link below opens the item in a new tab; nothing here is scored.` |
| Backlinks section label (heading has ≥1 referencing item) | `Items testing this` |
| Backlinks section — orphan heading (D-06 `lesson.orphan_heading`, warning not error) | `No items reference this section yet.` — plain `var(--mut)`, never `var(--warn)`/`var(--bad)`: matches D-06's own reasoning that "a lesson legitimately teaches more than it tests," so this is informational, not a problem to flag visually |
| Empty state — bank parses with no `## LESSON` section at all | Heading: `No lesson yet` · Body: `This bank has no ## LESSON section. Add one above the first Qn. line — see itembank spec for the LESSON/LESSON-REF grammar.` |
| Degraded state — `[LESSON-SRC:]` names a file that cannot be read | Appended below the empty-state body, in `var(--warn)`: `The external lesson file for this bank could not be read. Run itembank lint <bank> for details.` — the reader degrades to the same empty-state layout rather than a 500 or a crash, matching SC3's "never a render-time crash" spirit even though that clause is written for `LESSON-REF`, not `LESSON-SRC` |
| Error state — unknown bank stem | Reuses the daemon's existing `handler.send_not_found(stem)` 404 text verbatim (same convention `/quiz/<stem>` and `/study/<stem>` already use) — no new 404 copy invented |
| Stale deep link — `#<id>` fragment names an item that no longer exists (renumbered/deleted since the lesson was written) | **No error shown.** The quiz page loads exactly as an ordinary visit — full random shuffle, no item pinned first. Silent degrade is the correct behavior here (not a bug to surface): the same fragility already exists for every other use of `q.id` in this codebase, and a broken deep link should cost the learner nothing more than "not pinned first" |
| CLI — `itembank lesson <bank>`, success | `%d lesson section(s) -> %s` — mirrors `anki.py:cmd_export()`'s `"%d items -> %s"` shape; `%d` is the count of `###` headings rendered, zero included (an empty-state page still writes successfully — see next row) |
| CLI — `itembank lesson <bank>`, no `## LESSON` section | **Not a hard stop.** Writes the same empty-state HTML the daemon route renders (`%d lesson section(s) -> %s` prints `0 lesson section(s) -> <out>`) — one degraded-state policy for both surfaces, not two, matching this project's "one scorer, one parser" ethos extended to "one empty-state policy" |
| CLI — `itembank lesson <bank> --ref <text>`, heading not found (only when `--ref` is explicitly given) | `sys.exit("no lesson heading matching %r in %s" % (a.ref, a.bank))` — matches `surfaces/session.py`/`surfaces/anki.py`'s `sys.exit("message")` hard-stop convention; this is the one case that *does* stop, because the learner explicitly asked for a heading that isn't there |
| lint — `item.lesson_ref_unknown` (ERROR, D-05) | `Q<n>: LESSON-REF '<heading text>' does not match any lesson heading` |
| lint — `lesson.duplicate_heading` (ERROR, D-06) | `BANK: lesson heading '<heading text>' collides with '<earlier heading text>' after slugifying to '<slug>' -- rename one` |
| lint — `lesson.src_unreadable` (ERROR, D-06) | `BANK: [LESSON-SRC: <path>] could not be read (<reason>) -- fix the path or remove the directive` — `<reason>` is one of `file not found`, `<path> escapes the bank's directory` (D-02's out-of-tree-path case folds into this same code, not a fourth `lesson.*` code, keeping D-06's declared 3-code namespace exact), or the raw OS error text |
| lint — `lesson.orphan_heading` (WARNING, D-06) | `BANK: lesson heading '<heading text>' is not referenced by any item's [LESSON-REF:] -- fine if it's background reading, but check it wasn't meant to be tested` |
| Destructive confirmation | None in this phase's scope. `surfaces/lesson.py` performs no writes at all — its only I/O is `model.load()`'s existing read path plus `[LESSON-SRC:]`'s read-only external file open (D-10, D-02) |

## Lesson → Item Deep Link (mechanism, locked)

Because this is new interaction surface `03-CONTEXT.md` didn't fully specify, the mechanism is locked
here precisely so the planner does not have to redesign it mid-plan:

1. Each backlink href is `/quiz/<bank>#<id>`, where `<id>` is the **same `id` field already in the
   client's `Q` array** (`q.id`, i.e. `"q" + number`, sent by `runtime.public_item()` and used
   throughout `quiz_page.py`'s existing `canon()`/`verify()`/`settle()`). This is a deliberate reuse of
   the identifier that already governs answer submission end-to-end, not the newer opaque `[ID:]`
   `item_id` from Phase 1 — introducing `item_id` into the client payload would touch `runtime.py`
   (outside every integration point either `03-CONTEXT.md` or this document names) for a benefit this
   phase doesn't need, since the whole quiz surface already keys off `q.id`, not `item_id`, in the
   browser today.
2. **Known limitation, accepted, not hidden:** `q.id` is positional (`Qn`), so a deep link written into
   prose today can point at the wrong item after a bank is renumbered. This is not a new fragility this
   phase introduces — every existing reference to `q.id` in `quiz_page.py` already has it — but it is
   worth naming so a future phase (plausibly Phase 9, when the loop matures) doesn't rediscover it as a
   surprise.
3. `quiz_page.py`'s bootstrap script gains one small, additive check before its existing
   `Q.sort(()=>Math.random()-0.5); render();` tail: if `location.hash` (minus its leading `#`) matches
   an `id` present in `Q`, splice that entry to index 0 *before* the shuffle runs over the rest, so it
   is the first item shown. No match (empty hash, or a stale one) is a no-op — the page behaves exactly
   as it does today.
4. The daemon route (`GET /quiz/<stem>`) itself is unchanged — the fragment is never sent to the
   server (fragments aren't part of an HTTP request), so `handle_quiz_get` needs no new logic. This
   keeps the change entirely client-side and additive.

| Category | Element | Status | Resolution / Reason |
