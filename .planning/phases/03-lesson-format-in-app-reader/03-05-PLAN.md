<objective>
Finish the CLI twin so the surface without an anchor can still ask for one section, and lock the
output contract that tells a caller what it got.

**User story (MVP framing, from ROADMAP Phase 3 Goal):** **As a** learner at a terminal, **I want to**
ask for one lesson section by name, **so that** I get the passage an item is drawn from instead of the
whole chapter I have to scroll.

Purpose: D-07 requires every route to have a CLI twin that reaches the same render through the same
call, and 03-RESEARCH.md left `--ref`'s success-path scope as an open question. D-11 closed it:
filtering, not scrolling. This plan implements that and locks the rest of the CLI's observable
contract, which 03-UI-SPEC.md fixed string by string.

The matching rule is the point worth protecting. A heading is typed by a human at a terminal and
written by an author in a bank; they will differ in casing, spacing and punctuation. One slugifier
already reconciles the item tag with the HTML anchor, and it reconciles this too. A second rule here —
a raw string comparison — would agree with the others today and drift tomorrow, which is exactly the
failure D-03 names.

Output: `--ref` filtering, the locked success and failure lines, and the assertion that the browser's
selection mechanism stayed a fragment.
</objective>
