<objective>
Widen the reader from headings-and-paragraphs to the whole of D-08's deliberately small scope, and cut
the seam Phase 9 attaches to.

**User story (MVP framing, from ROADMAP Phase 3 Goal):** **As a** learner reading a lesson that
contains a comparison table, a numbered procedure and a worked example, **I want to** see them
rendered as a table, a list and a code block, **so that** the teaching text reads the way it was
written instead of as a wall of markers.

Purpose: this is the plan the subject loop depends on. LOOP-04 wants tables for EMT comparison
material, LOOP-02 wants a place to put LaTeX, and LOOP-03 wants a place to put runnable code. D-08's
answer to all three is one markup shape — a preformatted code element carrying a language class with
verbatim, escaped content — cut now and left inert. Phase 9 then attaches behaviour by selector
without re-parsing the lesson or forking the renderer.

D-08 gave the planner leave to drop tables if a stdlib table renderer proved out of proportion to what
EMT prose needs. It is not: a pipe table is a line scanner over a split, the same class of work as a
list, and LOOP-04 names tables explicitly. Keeping them, and holding the line at D-08's list rather
than drifting toward completeness.

Output: a renderer that covers exactly the declared scope, a fixture that exercises every block kind,
and a test that proves code content survives the inline pass untouched.
</objective>

**2. The extraction pass.** Before any other work on a section's text, walk it once and lift every

than two.

**3. Fenced-code rendering.** Emit a preformatted element wrapping a code element. When the fence
carried an info string, put a class on the code element formed from a fixed prefix and the info string
itself, sanitised to the same safe character set the slug uses so a hostile info string cannot escape
the attribute. The content is the block's source, HTML-escaped and otherwise untouched — no re-indent,
no trailing-whitespace strip beyond the fence's own lines, no syntax highlighting. Style it with the
neutral chip background, the muted foreground for any language label, and the existing monospace stack,
never the accent colour. Implement no behaviour: no KaTeX, no run button, no copy button. This plan
cuts the seam and leaves it inert; Phase 9 attaches to it by selector.

Handle an unterminated fence by treating the rest of the section as the block's content. That is the
forgiving reading and it keeps the document readable, which matters more here than strictness.

**4. Lists.** A run of consecutive lines each opening with a dash-and-space becomes an unordered list;
a run each opening with digits, a period and a space becomes an ordered list. One item per line. A
blank line, or a line that fits neither shape, ends the run. Support exactly one level — D-08 rules out
arbitrary-depth nesting, and a lesson that needs a nested list can use a second heading.

**5. Tables.** A run of consecutive lines each containing a pipe, whose second line is a separator row
of dashes and pipes, becomes a table: first line as the header row, the rest as body rows, cells split
on the pipe with the optional leading and trailing pipes discarded, each cell trimmed and escaped.
Anything that does not fit that shape — a lone pipe line, a missing separator row, a row with a
different cell count — falls back to a paragraph rather than raising or emitting a broken table. Do not
implement alignment markers; they are the kind of edge case D-08 explicitly declines.

**6. Overflow.** Wrap both the code element and the table element in their own container with
horizontal overflow set to auto, so a wide table or a long code line scrolls inside its own box and the
page body never scrolls sideways at any viewport width. Set no nowrap and no ellipsis truncation on
lesson prose.

**7. Heading levels.** Any heading deeper than the grammar's own subheading renders at the same size as
a lesson section heading. The grammar defines two levels and this phase does not invent a third size for
a depth it does not define.

Throughout: escape text runs after structure is resolved, never the raw source before parsing, or the
markup the renderer itself emits would be escaped along with the author's text. And add no third-party
markdown package — the project is standard library only with two named exceptions, and neither is this.
