## 2026-08-24 the sitting path was smoke tested on the Mac, and the recorded instruction is wrong

Weibao asked whether itembank works on macOS at all before spending a sitting
on it. Tested end to end against `fixtures/lesson_bank.md` in a temp directory,
never against the EMT bank, so nothing below touched the real course root.

**What works.** `serve` binds, the page returns HTTP 200 at 126,475 bytes,
renders with all four vendored faces and the 17A token layer live in the served
bytes, leaks no key before answering, scores a multiple-choice answer
correctly, advances the cursor, writes `_evidence/evidence.jsonl` and the
session JSON as the answer is given, and `evidence --objective <id>` returns
the right counts with both denominators. The loop is real.

**Finding 1, and it invalidates an instruction in this file.** The session id
printed in the startup banner is NOT the id the evidence is written under.
Measured in one run: banner `7604f17b7578499795374de1c4ab92be`, evidence and
session JSON `556862266e14463b98b75564bbf82f74`, file name
`_attempts/session_5b0b5f08dfbb.json`. Three different values.

The cause is in the code, not in the run. `quiz.cmd_serve` mints and prints one
id, then hands it to the daemon in `extra["sessions"]`. The daemon's
`_ensure_quiz_session` ignores it, calls `session.do_start`, which mints its
own, and stores that as `api_session_id`. Every evidence row carries the
second id.

The 2026-08-22 entry above, and 13.9-03's `key_links` row, both instruct
capturing the banner id before answering. **That instruction is wrong and must
not be followed.** A calibration corpus naming the banner id would name a
session that appears nowhere in the evidence store, and the error would only
surface when a later plan tried to query it.

**What to capture instead:** the path of the file that appears under
`_attempts/` once the first answer is given, `session_<12 hex>.json`. The
authoritative id is the `session_id` field inside it.

**Finding 2.** `itembank report` takes a session file PATH, not a session id.
13.9-03 Task 1's verify step says "`itembank report` on the session". Passing
the banner id fails with `cannot read session <id>: No such file or directory`.
Passing `_attempts/session_<hex>.json` returns the expected document.

**Finding 3, cosmetic, routed to 13.5.** The sitting header reads `Item 1 of 0`
and the position does not advance between items. `quiz_page.render()` sets both
counters, but under scoped `serve` the daemon injects a server-rendered
baseline into `#host` and the client `render()` path never runs, so the
template defaults of 1 and 0 stand. No console error. Reproduced identically at
`eb96118`, so it predates the 2026-08-24 17A work; none of `daemon.py`,
`surfaces/session.py`, `surfaces/quiz.py` or `quiz_page.py` was touched that
day. Recorded here as an observation, not repaired: 13.9-03 is explicit that
the skeleton observes and does not fix.

Findings 1 and 2 are corrections to this document's own instructions rather
than repairs to a surface, so they are made here before the sitting rather than
recorded as defects after it.

## 2026-08-24 the sitting ran, found a blocking defect, and must be redone

Weibao sat the rebuilt EMT bank through `itembank serve` on 2026-08-24. It
produced **one response out of ten** and must be repeated. The walking skeleton
worked exactly as A9 intended: one real sitting on real material found a
blocking defect in the core loop that seventy green suites did not.

**What happened.** The daemon shuffles with a hardcoded `seed: 0`, which placed
the bank's single `short` item (`q8`, obj-03) first. He answered it. The runtime
recorded it correctly as pending, and the sitting could go no further.

**The defect, and it was not what it looked like.** A pending prose answer parks
the cursor on purpose: `hint_roundtrip` pins `a pending short response must not
advance the cursor` and `exam must not move the cursor before an accepted mark`.
Nothing implemented the second half. `itembank mark` appends an evidence event
and never touches a session, so no bank containing a `short` item could be
completed on any surface, browser or CLI. `tests/lti_roundtrip.py` reached that
state only by hand-writing cursor and status into a session file, under a
comment calling it the runtime's own completion arithmetic.

Fixed the same day under `.planning/quick/260824-m4k-marker-closed-transition/`:
`runtime.marker_close` advances a sitting whose parked item has a settled mark,
`session.do_next` triggers it, both render paths now explain the parked state
instead of showing an empty panel, and `agent_roundtrip.check_marker_close` pins
both halves. Full suite 70 of 70 green afterwards.
