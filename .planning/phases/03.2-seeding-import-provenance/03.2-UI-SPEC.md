# Phase 3.2: Seeding, Import & Provenance - UI Design Contract

**Specified:** 2026-08-10
**Scope:** The one learner-facing/author-facing surface this phase owns is the **human-accept seeding loop** - the approve-one-item-at-a-time gate that is the phase's whole reason for existing (D-06). Import, provenance, and lint are CLI/report surfaces; the UI-SPEC covers the accept loop's browser surface and its copy contract, per ROADMAP criterion 8 ("the UI must say so" - authoring is a batch operation).

## 1. Design System

INHERITED unchanged from `.planning/UI-SPEC.md` section 7 and Phase 4: `surfaces/theme.py` is the one palette, `surfaces/presentation.py` SHARED_CSS the one token layer, the 8-point spacing scale, the five type sizes (14/16/20/28 plus the locked `text-lesson`), the 400/600 weight pair, the 44px interactive target, the 2px focus ring, the 150ms motion cap, and the nine accessibility gates (UI-SPEC section 8). This phase adds **no** new size, token, palette entry, or component library.

## 2. The accept loop surface - one item at a time, batch framing

### 2.1 The screen

The accept loop renders one candidate item at a time (D-06) through the existing presentation shell:

- **Progress line (Ledger):** `Draft {n} of {m} · stage {stage}` - staged progress, never a percentage bar (the anti-streak/anti-target rule carries: a fill bar is a target; a count is a fact).
- **The candidate item** at `text-body` (the same projection the quiz surface uses - the item is the item).
- **The provenance line (Ledger):** `[SRC:]` and `[OBJ:]` resolved from the `## SOURCES` registry, when present; `No source recorded` when absent - and `style.unsourced_specific` lint findings surface here when the item carries numerals/units/doses without a source (D-14).
- **The lint result block:** errors and warnings from `model.lint()` rendered as the existing lint output shape; an item with errors shows them and the Accept control is disabled with the reason stated (never a silent dead button - C9).
- **The accept control (Chrome):** one primary button, `Accept item`. One secondary control, `Skip item` (moves to the next draft; the skipped item stays in the draft set and is reported at the end - skipping is a deferral, not a discard). A `Cancel run` control stops the batch; a cancelled run writes nothing (D-09).

### 2.2 Batch framing (D-09)

- The surface states in plain words that authoring is a batch operation: a Ledger line at the top, `This is a batch authoring run. Each item is drafted, checked, and accepted one at a time.` No chat affordance exists - no input box, no "ask the model" control, no streaming text.
- Staged progress is shown (deterministic source selection, outline, drafting, checks, verification, accept) as a Ledger text line naming the current stage; no animation, no auto-advance.
- A cancelled run writes nothing and the summary line states `Nothing was written.` (verbatim).

### 2.3 Degraded behavior (D-10)

- With no model backend reachable, the accept loop refuses by name with the exact line `The authoring backend is unreachable. Import, lint, and provenance still work.` and no draft is started. Every other surface in the phase (import report, lint, coverage map) renders normally.
- With the daemon unreachable (browser surface), the CLI path remains fully operable - the accept loop is both surfaces (D-07), never only the browser.

## 3. The import report surface

The .apkg import report (D-03) renders as a Ledger-voice table: `Converted`, `Skipped`, `Refused` rows with per-note ids and reasons, and the total line `{n} notes accounted for, 0 dropped silently.` The report is a document (printable, plain table), not an interactive surface.

## 4. Copywriting Contract

Every string below is new to this phase and must be reproduced verbatim by the CLI, the renderer, and any test that greps for it (the Phase 3 precedent):

| Element | Copy | Voice |
|---|---|---|
| Batch framing line | `This is a batch authoring run. Each item is drafted, checked, and accepted one at a time.` | Ledger |
| Stage/progress line | `Draft {n} of {m} · stage {stage}` | Ledger |
| Accept control | `Accept item` | Chrome |
| Skip control | `Skip item` | Chrome |
| Cancel control | `Cancel run` | Chrome |
| Cancelled summary | `Nothing was written.` | Ledger |
| Backend unreachable | `The authoring backend is unreachable. Import, lint, and provenance still work.` | Ledger |
| Import total | `{n} notes accounted for, 0 dropped silently.` | Ledger |
| Missing source (no [SRC:]) | `No source recorded` | Ledger |

Copy rules that bind: no percentage or fill bar anywhere in the accept loop; no chat/streaming affordance; every unavailable string names the condition or the command that fixes it; no string implies a streak, target, or celebration (C17).

## 5. UI Considerations

| Category | Element | Status | Resolution |
|---|---|---|---|
| empty | no drafts to accept | covered | The loop renders `No drafts to accept.` (Ledger) and exits; no dead controls |
| error | lint errors on the candidate | covered | Errors render in the lint block; Accept is disabled with the reason, never silent |
| partial | skipped items | covered | Skipped items stay in the draft set, are reported at the end, and are never discarded silently |
| loading | model call in flight | covered | The current control is disabled only while the request is in flight; no spinner-forever |
| zero-one-many | import with 0 notes | covered | The report renders `0 notes accounted for, 0 dropped silently.` - an explicit state, never a blank |
| long-text | a 5000-word draft item | backstop | The item renders at the reading measure with the existing overflow discipline; no horizontal prose scroll |

## 6. Required verification gates for this phase

1. **Accept-gate fixture:** an item with lint errors cannot be accepted (control disabled + reason); an item with zero errors accepts and writes exactly once.
2. **Cancel fixture:** cancelling mid-run writes nothing; the summary line is verbatim.
3. **Batch-framing fixture:** the surface contains no chat affordance, no percentage/fill bar, and renders the exact batch-framing line.
4. **Degraded fixture:** with the backend unreachable, the exact refusal line renders and no draft starts; import/lint/provenance surfaces still work.
5. **Copy fixture:** every string in section 4 renders in the voice section 1 assigns, asserted by computed font-family token, never a literal family.

## 7. LOCKED / DEFAULT / OPEN

**LOCKED:** one-item-at-a-time accept, batch framing with staged progress and cancel, no chat affordance, skip-as-deferral, refuse-by-name on backend unreachable, the verbatim copy rows.
**DEFAULT:** none in this spec beyond the locked rows.
**OPEN:** the exact draft-item projection details are Phase 3.1/3's renderer's; this phase consumes them unchanged.

## Registry Safety

This phase adds no vendored asset and no package to the runtime; the zstandard dependency for the importer is a pinned, checksummed, license-reviewed dependency per Directive 4a (see 03.2-RESEARCH.md section 1), not a vendored asset.
