## Deviations from Plan

1. **Scope additions (required by the plan's own verification):** registering a new lint-code namespace `prov.*` requires touching the three coupling locks the foundation locked: `schemas/lint_error.schema.json` code enum (+3 prov codes) and `tests/protocol_roundtrip.py` LINT_PREFIXES (+"prov"). These files are outside the plan's declared `files_modified` list but are enforced by `tests/lesson_roundtrip.py` (test_lint_codes_schema_enum_contains_all_codes, test_lint_codes_namespace_prefixes_match_protocol), which the plan's verification block runs. Recorded as the registration cost of a closed catalogue, not an opening.
2. **schema_validate.py support gap fixed:** schema-valued `additionalProperties` (e.g. `{"type": "string"}`) was silently ignored -- the validator only handled boolean `False`, contradicting its own "a green result means the whole document was checked" contract. Plan 02's registry test needs schema-valued additionalProperties (locators are strings), so schema_validate.py was extended ~10 lines to validate additional properties against a subschema. Additive; the boolean-`False` path is unchanged and pre-existing schemas are unaffected. (This is the one product-code change outside the declared scope; it is the registry-shape check the plan's acceptance criteria call for.)
3. **Editorial repair:** during this plan the schema file was accidentally reverted to HEAD (a `git checkout` used to undo an over-formatting), which dropped the 12 Phase 3.1 style content codes the 03.1 WIP had registered. Restored exactly those 12 + the 3 prov codes, verified by the bidirectional containment tests. Net schema state = 03.1 working-tree state + prov.* additions.
4. **`python schema_validate.py --all` does not exist** (the plan's verification block references it); CI validates per-schema. The equivalent coverage is provided by tests/protocol_roundtrip.py (runs every schema/instance pair, "schema --all self-contained and stable") which passes, plus the unit fixtures above.

The deterministic edge probe is skipped visibly per the plan's `must_haves`: the gate requires pre-assigned requirement IDs and they were assigned at plan time.
