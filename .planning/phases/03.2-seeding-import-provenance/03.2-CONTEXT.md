# Phase 3.2: Seeding, Import & Provenance - Context

**Gathered:** 2026-08-10
**Status:** Ready for planning
**Mode:** autonomous (Directive §2)

<domain>
## Phase Boundary

This phase puts **real content** in the bank and makes every piece of it name where it came from. It delivers: an Anki `.apkg` importer, a human-accept-per-item seeding loop, the `## SOURCES` registry with `[SRC:]` and `[OBJ:]` resolution, a paraphrase lint, `[CASE:]` grouping, `[PREREQ:]` edges, and the calibration corpus every Phase 3.1 style warning is measured against.

It does **not** deliver: autonomous authoring without a human accept (Phase 11), the curriculum auditor (Phase 11), selection over `[PREREQ:]` edges (Phase 7), or exam-sim presets over `[CASE:]` (Phases 6/7). It authors items; it does not author lesson prose style (Phase 3.1 owns that contract).
</domain>

<decisions>
## Implementation Decisions

### Open ruling

- **D-01 (ruling 4 — ADOPTED):** The widening and re-sequencing of this phase stands. Seeding lands **before Phase 5**, because the research named content and adherence — not features — as the real bottleneck, and no success criterion anywhere else measures actual use. If this were declined, 03.2 would shrink to provenance only and Phase 11 would keep the seeding loop; it is not declined. — **Reversibility:** reversible — declining later moves work between phases, it does not undo a format or a store.

### Import

- **D-02:** The `.apkg` importer reads through **stdlib ZIP + `sqlite3`** only. No `anki` package, no AnkiConnect. A dependency here would buy compatibility with Anki's internal schema churn at the price of tracking it.
- **D-03:** The per-note report is **exhaustive and per-note** — converted, skipped, and the named reason — and no note is silently dropped. A skipped note appears in the report with the note id, so a human can go find it. — **Reversibility:** reversible.
- **D-04:** Unknown or unsupported Anki note types produce a **loud named refusal per note**, the same posture GIFT already takes for unsupported item types (`surfaces/gift.py`). No lossy approximation, ever.
- **D-05:** Import writes nothing without passing the same `model.lint()` the human path uses. There is one parser and one validation surface; the importer is a client of it.

### Seeding loop

- **D-06:** Draft → lint → retry → **explicit human accept, one item at a time**. Nothing in this phase writes to a bank without an accept. Autonomy beyond that is Phase 11's problem and may not be prototyped here.
- **D-07 (both surfaces, per `CLAUDE.md`):** The accept loop ships as **both** a CLI command and a daemon route, because every capability has both and neither is the real one. The browser surface is a client of the same accept endpoint the CLI calls — not a second implementation of the decision.
- **D-08 (criterion 8 staging, LOCKED ORDER):** Six stages: deterministic source selection → outline-only → per-section drafting → **deterministic checks before any model critique** → independent CoVe-style verification → human accept. The ordering is the finding: critiquing a draft a lint pass would have rejected is waste, and a model critiquing before the deterministic gate anchors on its own text. No plan may reorder these.
- **D-09:** Roughly nine model calls per lesson means **authoring is a batch operation and the UI must say so**. It shows staged progress and a cancel; it never presents itself as interactive chat. A cancelled run writes nothing.
- **D-10 (degrade, never block):** With no model backend reachable, seeding refuses by name and every other command in this phase — import, lint, `[SRC:]` resolution, coverage map — still works. `CLAUDE.md:57`.

### Provenance

- **D-11:** `[SRC: <source-id> <locators>]` and `[OBJ: framework/objective-id]` resolve through an **additive `## SOURCES` registry**. An unresolvable id is a lint error naming the id and the file.
- **D-12:** The objective coverage map is **computed on demand and never stored**. A stored map goes stale against the bank silently; a computed one cannot. — **Reversibility:** reversible, and caching later is an optimization behind the same call.
- **D-13 (source text is never stored):** Paraphrase lint uses **stdlib winnowing over fingerprints only**. Error at ≥8 consecutive copied words; warn above Jaccard 0.25. Both thresholds are settings with those defaults, because they will need tuning against the real corpus and a code change per tune is the wrong cost. Not storing source text is also the defensible posture for AAOS-derivative EMT content. — **Reversibility:** one-way in spirit — a design that stored source text would be a copyright and residency problem to unwind. Do not store it.
- **D-14:** New check `style.unsourced_specific` — numerals, units and doses require a `[SRC:]`. This is a **structural check, not a model judgement**, and it lands here because seeding is where fabricated specifics enter the corpus. It registers into the closed `LINT_CODES` catalogue Phase 3.1 defines; it does not open it.

### Grouping and edges

- **D-15:** `[CASE:]` is authored grouping in the format contract, additive. Phases 6 and 7 serve it as an exam-sim preset; this phase only authors and lints it.
- **D-16:** `[PREREQ:]` edges are authorable and linted here — cycle detection and unresolvable-target detection — ahead of Phase 7 consuming them. Phase 7 owns the selection semantics; this phase owns the grammar and its validity.

### Corpus

- **D-17 (residency):** The real EMT / Math 1400 / CSCI 1100 corpus lives **beside the private bank, outside this repository**, and `itembank guard` keeps it out of CI. Fixtures in-repo stay synthetic. This is Directive §4.3 and it is not negotiable for convenience.
- **D-18:** This phase's corpus is the **calibration set for every Phase 3.1 style warning**. A warning ships enabled only with a recorded false-positive rate; above roughly 20% it ships disabled by default. Phase 3.1 owns the checks; this phase owns the evidence that any of them are usable. The calibration run and its recorded rates are a deliverable of this phase, not a side effect.
- **D-19 (contention, from R5):** Seeding writes **items**; a style pass writes **prose**. With Phase 3.1's two-file layout as the default, the two must not contend for one file — that separation is what makes Phase 11's one-action reversibility possible without hunk surgery.
- **D-20 (compatibility floor):** A bank using none of `## SOURCES`, `[SRC:]`, `[OBJ:]`, `[CASE:]` or `[PREREQ:]` parses and renders **byte-identically**, proven by fixture. Directive §4.4.

### Claude's discretion

Winnowing window and k-gram size, report layout, importer module factoring, and the on-disk shape of the source registry cache are open. Not open: stdlib-only import, never storing source text, human-accept-per-item, the six-stage order, and the corpus staying out of the repo.
</decisions>

## Existing Code Insights

### Reusable assets
- `model.lint()` and the stable lint-code registry — the importer and the paraphrase check are clients, not new validators.
- The GIFT unsupported-type refusal path — the template for D-04's per-note refusal.
- `itembank guard` — already enforces D-17 in CI; extend its globs rather than adding a second guard.
- `schema_validate.py` — the `## SOURCES` registry validates through it.

### Established patterns
- One parser, one scorer, one evidence store (Directive §4.2). This phase adds grammar to the one parser; that is §4.4's subject and is permitted, proven by fixture.
- Every capability has a CLI command and a daemon route.

### Integration points
- `[OBJ:]` and the on-demand coverage map are what Phase 11's auditor reads; do not let the auditor re-derive them.
- `[PREREQ:]` is what Phase 7's fringe-based selection consumes.
- The corpus is what Phase 3.1's warning calibration measures against.
</code_context>

<specifics>
## Specific Ideas

- The named unknown carried forward: **no benchmark for single-objective adherence in long generation exists** as of mid-2026. Criterion 8's staging is a structural argument, not a measured improvement. No plan may carry a percentage figure for it.
- The default authoring backend is a hosted coding-agent-class model (Claude Code or equivalent), per Directive §1. Prompt-size and latency budgets are written against it; the local backend declares its own.
</specifics>
