> **Phase goal (quoted verbatim from `.planning/ROADMAP.md`):** A wrong answer holds
> the session open for a real second attempt, hints unlock one authored tier at a time,
> and feedback behavior changes correctly by session mode.

<objective>
Expose the proven teaching transition through CLI, identifier-addressed JSON API, and
the served browser without creating a second authority.

Purpose: learners and agentic teaching clients can act, observe, request one bounded
next hint, and resume/report through one policy. Brilliant and other competitors remain
benchmarks for diagnose -> bounded guidance -> learner action -> feedback, not a parity
checklist. This plan introduces no Phase 06.1 visual item implementation and no Phase 4
styling work.

Output: `itembank hint`, `POST /api/hint`, Phase 6 action envelopes with a minimal
non-persisted opaque renderer metadata seam, a runtime-driven
served ladder/stumped control, and cross-surface roundtrip proofs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/agent JSON -> daemon API | Untrusted Phase 6 action, answer, session ID, and optional opaque renderer_meta string enter the local server |
| daemon -> session adapter/runtime | Identifier-addressed requests become persistent transitions and evidence |
| runtime payload -> browser DOM | Authored/private content crosses into a renderer only after policy authorization |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-11 | Information Disclosure | API/browser feedback payloads | high | mitigate | Diagnostic and exam pre-release tests build forbidden strings from the bank and fail if any answer, rationale, explanation, key, or later tier appears; served clients receive public_item plus policy-selected payload only. |
| T-06-12 | Tampering | action/renderer metadata envelope | high | mitigate | Validate the Phase 6 action kind/shape; accept only an opaque renderer_meta string up to 256 UTF-8 bytes; reject observation/canvas objects and authority-shaped fields; discard metadata before policy or persistence. |
| T-06-13 | Elevation of Privilege | session addressing | high | mitigate | Every route resolves opaque session_id through session_index; raw path fields stay forbidden and are never joined to filesystem paths. |
| T-06-14 | Denial of Service | renderer metadata and authored payload rendering | medium | mitigate | Enforce the 256-byte string limit before transition work; render authored text through escaping/text nodes rather than evaluating markup. |
| T-06-15 | Repudiation | CLI/API/browser surface divergence | medium | mitigate | All three clients call session.do_action/do_hint/do_report, and cross-surface tests compare explicit actions, evidence IDs, tiers, and outcomes. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists; integration uses the existing stdlib daemon and inline browser JavaScript. |
