# Phase 9.1: Audio Drill Export - Context

**Gathered:** 2026-08-10
**Status:** Ready for planning
**Mode:** autonomous (Directive §2)

<domain>
## Phase Boundary

This phase makes an objective leave itembank as an **audio drill pack** — stem, timed pause, key, why — plus a plain-text transcript, via `itembank export audio --objective <id>`. The TTS engine sits behind one interface with named registered implementations, exactly like the model backend.

It does **not** build: a player, a mobile app, a sync service, playback tracking, or any evidence write. Listening records nothing. An audio pack is a one-way export.
</domain>

<decisions>
## Implementation Decisions

No open rulings block this phase. The decisions below are the gray areas the roadmap left to discuss.

### The engine interface

- **D-01 (Extensibility Rule 1):** One `TTSEngine` interface with named registered implementations. Adding an engine is a new module plus a settings entry — no branch in a dispatcher, and if the dispatcher already has three branches the plan converts it to a registry in the same commit (Rule 2).
- **D-02 (which engines, and in what order):** Register **`edge-tts`** (network, best quality today, zero local hardware), **Piper** (local, CPU, no network), and **`transcript-only`** (the always-available null engine). **Kokoro** is a documented registration target for the 7900 XTX and is **not built here** — the card does not exist, and Directive §1 says the local path is a second backend, not the design target.
- **D-03:** `transcript-only` is a **real registered engine**, not an error path. That is what makes criterion 3 (refuse cleanly, still emit the transcript) fall out of the interface instead of being special-cased.
- **D-04 (selection):** Engine choice is a settings entry, defaulting to `edge-tts`. When the configured engine is unreachable or missing, the command **does not silently fall back** — it emits the transcript, names the engine and the reason, and exits non-zero. A silent fallback would hand the learner a different voice and quality without saying so. — **Reversibility:** reversible.
- **D-05 (degrade, never block):** No engine reachable means the transcript still writes and the refusal is named and actionable. It **never half-writes an audio file**: audio is written to a temp path and atomically renamed on success, matching the session-file pattern already used by `runtime.write_session()`.

### Pack shape

- **D-06 (sequence, LOCKED):** stem → timed pause → key → why. The pause is the pedagogy; a pack without it is a lecture.
- **D-07:** Pause duration is a **setting with a per-item-type default**, not a constant, because a `build` ordering item needs longer than an `mc` recall item. Defaults are recorded in the plan and tuned against real use, not invented precisely.
- **D-08 (both surfaces):** `itembank export audio` is a CLI command **and** a daemon route, per `CLAUDE.md` — neither surface is the real one.
- **D-09 (format):** Default output is **MP3**, because criterion 4 says playback is any podcast app and MP3 is what every podcast app accepts. The container is a setting; WAV is available for engines that emit it natively.
- **D-10 (chunking, Directive §3 — build both):** `--split per-item` and `--split per-pack` both ship, defaulting to **per-pack** (one file per objective, since a pack is a commute). Per-item exists because some podcast apps handle skip-by-track better than skip-by-30s. This is a flag, not two code paths through the writer.
- **D-11 (transcript):** One plain-text transcript per pack, emitted **always**, containing the same text in the same order the audio speaks — so it is a readable artifact and a diffable check on what the engine was given.
- **D-12 (naming):** Files are named from the objective id and a content digest, so re-exporting an unchanged objective is idempotent and re-exporting a changed one does not silently overwrite a pack already on a phone.

### What this phase refuses

- **D-13 (no evidence write):** Listening records **nothing**. The evidence log stays the record of what was actually answered. A "listened" event would be an unfalsifiable claim about a file that left the machine — and Directive §4.3 keeps evidence about things the runtime actually saw.
- **D-14:** No player, no sync, no mobile build, no playback position. Criterion 4 is a scope boundary, not a suggestion.
- **D-15 (supply chain, Directive §4a):** `edge-tts` and Piper are third-party artifacts. Each is pinned to a version with a recorded checksum and a named license review, following the KaTeX precedent (`09-03-PLAN.md`). "It needs a dependency" is not an argument against them; an unpinned unreviewed dependency is.
- **D-16 (network honesty):** `edge-tts` sends **item text to a Microsoft endpoint**. This is the same accepted risk already recorded for hosted models in `CLAUDE.md`, and the plan must state it in the command's own help text — not only in a planning document. Piper is the local alternative for any subject the learner wants kept off the network.

### Claude's discretion

Audio encoding parameters, transcript layout, the digest algorithm for D-12, and module factoring are open. Not open: the interface-plus-registry shape, transcript-always, no evidence write, atomic write, and the named refusal.
</decisions>

<code_context>
## Existing Code Insights

### Reusable assets
- The model-backend adapter pattern (Phase 8) is the exact shape D-01 copies. Do not invent a second registry idiom.
- `runtime.write_session()`'s write-temp-then-`os.replace` — D-05's atomicity.
- The existing export command surface (`itembank export`) — audio is a subcommand of it, not a new top-level verb.
- Objective resolution already exists via the `Educational Objective` line (Phase 3.1) and `[OBJ:]` (Phase 3.2) — this phase reads them and re-derives nothing.

### Established patterns
- Named refusal over silent degradation, everywhere (the `day` surface omits Anki counts when Anki is closed; GIFT refuses unsupported types by name).
- One interface per swappable decision.

### Integration points
- Objective ids come from Phase 3.2's `[OBJ:]` registry; item selection for a pack reuses Phase 7's selection where available, and falls back to "every item on the objective, in bank order" when it is not.
</code_context>

<specifics>
## Specific Ideas

- Weibao's framing: a commute or a run is study time, with no app to build and no dependency the tool cannot do without. D-03's `transcript-only` engine is what makes "cannot do without" literally true.
</specifics>
