# Phase 09.1 — Plan 09.1-03: Pack assembly — timed silence, per-pack/per-item split, container policy, digest-stable atomic writes, and the daemon route

**One objective becomes one commute-length pack: the plan 09.1-01 sequence becomes finished audio with real timed pauses between stem/key and key/why, MP3 by default with WAV available, split per-pack or per-item through a single writer, named so re-exporting an unchanged objective never overwrites what is already on a phone, and reachable from both the CLI and a daemon route that call the same runtime function.**

## Performance

- **Duration:** ~50 min
- **Completed:** 2026-08-11
- **Tasks:** 3/3
- **Files modified:** 4 modified (surfaces/audio.py, surfaces/audio_edge_tts.py, surfaces/audio_piper.py, surfaces/daemon.py), 2 test files updated (audio_export_roundtrip.py, daemon_roundtrip.py)

## Accomplishments
- `TTSEngine.silence(seconds)` added to the interface; the assembler calls it for every pause segment (D-06/D-07). transcript-only returns None; piper synthesizes real PCM-zero WAV (or lameenc MP3 when the container says mp3); edge-tts refuses by name (no local MP3 encoder) rather than silently dropping the pause.
- `assemble_pack(...)` is the ONE writer: per-pack (one file per objective) and per-item (one file per item) are modes of it, selected by a `split` parameter (D-10). All segments are spoken in memory first, then each file is written temp-then-`os.replace`, so a mid-pack engine error leaves no partial files at all (D-05).
- `build_sequence` now emits stem → pause → key → pause → why (two timed pauses per item), matching the plan 03 requirement of silence between stem/key and key/why.
- Container policy: the assembler records the container from the engine contract and never branches on codec — the same writer produces `.mp3` or `.wav` (D-09).
- Digest-stable naming: per-pack files and the transcript use `digest_name(objective_id, transcript)`; per-item files use the item index + that item's spoken text, so identical items never collide, unchanged re-exports are idempotent, and a changed item never overwrites (D-12).
- `POST /api/export_audio` added to the daemon: bank resolved through the scanned-stem allowlist, `out_dir` validated as relative under the served root, engine/split/container enum-validated, then the SAME `export_audio` the CLI reaches (D-08). ROUTE_CLI maps it to the export CLI command.
- `check_api_route_scope` updated to six /api routes; the route/CLI inventory test still passes.
