<interfaces>
Create and keep these contracts stable for plan 04-06:

- `day_document.snapshot(path, year, iso) -> {status, revision, date, columns, cells, document}`
- `day_document.save(path, iso, edits, revision, force=False) -> {status, revision, cells, ...}`

`status` is one of `ready`, `saved`, `invalid`, `conflict`, or `unsupported`. Error/conflict results include the submitted `draft`; conflict additionally includes the fresh `current` snapshot and performs no write. The `document` field is the current UTF-8 text for copy/download conflict recovery and must never include a filesystem path.
</interfaces>
</context>

<binding_decisions>
- **Additive document ownership:** per D-08, the adapter locates and patches exact UTF-8 cell spans; it never parses and serializes the whole file.
- **Supported grammar:** one unambiguous pipe table with a header row, Markdown delimiter/rule row, and exactly one row whose date matches the requested ISO date. Optional outer pipes, LF or CRLF, leading/trailing cell padding, unknown columns, surrounding prose, and unrelated tables are supported and preserved byte-for-byte. Escaped pipes (`\|`) and pipes inside a closed inline-code span are data inside the target cell; a literal pipe entered by the learner is encoded safely.
- **Refused grammar:** duplicate matching dates, a missing header/rule, multiple candidate matching tables, a missing requested column/dated row, multiline cell/table extensions, HTML tables, colspan/rowspan constructs, an unclosed code span or escape that makes a span ambiguous, and newline/control characters in submitted values return `invalid` or `unsupported` and perform no write.
- **Concurrency:** revisions are SHA-256 of the complete raw file bytes; every save re-reads and compares immediately before same-directory fsync plus `os.replace` per D-09 through D-11.
</binding_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI edit values -> Markdown plan | Structured user strings become bytes inside a human-authored document. |
| Snapshot revision -> save-time disk bytes | Another editor may change the authoritative file between read and write. |
| Temporary file -> target plan | A replacement crosses from newly generated bytes into durable user-authored data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Tampering | `day_document.save` stale revision | high | mitigate | Re-read exact bytes immediately before replace; require SHA-256 equality; return conflict with no write on mismatch. |
| T-04-06 | Tampering | table-cell input | medium | mitigate | Allow only located editable columns and single-line UTF-8 cell values; safely encode pipes; reject ambiguous syntax without mutation. |
| T-04-07 | Denial of Service | malformed/ambiguous Markdown | medium | mitigate | Bound work to a single file/row scan and return an `unsupported` contract rather than looping, guessing, or serializing the document. |
| T-04-08 | Repudiation | forced stale overwrite | medium | mitigate | Require two explicit CLI signals and the newest conflict revision; return the new revision so the action is attributable in command output. |
| T-04-SC | Tampering | package supply chain | low | accept | No dependency is installed; hashing, parsing, fsync, and replacement use Python stdlib. |
</threat_model>
