<binding_decisions>
- **Persisted schema:** keep top-level `theme` unchanged with enum `system|light|dark` and default `system`; add a required top-level `accent` object whose required opaque normalized six-digit `source` defaults to `#0e6e62`. Existing files missing `accent` are valid after `load_settings` merges schema defaults. Persist source only; rendered pairs, correction notices, ratios, and advanced overrides never enter `itembank.json`.
- **Polished default:** light `bg=#f3f5f4`, `ink=#171d1c`, `card=#ffffff`, `chip=#eef2f1`, `line=#dfe5e3`; dark `bg=#0e1413`, `ink=#e4ebe9`, `card=#161e1d`, `chip=#1d2726`, `line=#26312f`. Fixed semantic light `ok=#1b7a3d`, `ok-bg=#e8f4ec`, `bad=#b4272b`, `bad-bg=#fbebeb`, `warn=#8a5900`; fixed semantic dark `ok=#4fbf74`, `ok-bg=#11291b`, `bad=#f0666a`, `bad-bg=#2b1416`, `warn=#e0a23a`.
- **Native picker:** the `itembank theme pick` CLI lazily invokes `tkinter.colorchooser` on its process main thread; no Tk import occurs at module startup. It supports JSON output plus an initial source so plan 04-04 can launch the same source/`.pyz` entry point as a child process from the local browser route, keeping Tk off a threaded HTTP handler. Selection is preview-only until explicit save. Cancel, missing Tk, headless/display errors, unavailable packaged runtime, chooser exceptions, or child-process failure return `available: false`, preserve file/draft, and direct the learner to the browser color field.
- **Accessibility derivation:** preserve the source and hue/saturation where possible, choose the nearest deterministic lightness meeting 4.5:1 text/control and 3:1 focus/border requirements, derive soft pairs per mode, and disclose every correction. Semantic verdict tokens never derive from the accent.
</binding_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI/color chooser -> settings file | Untrusted color text or OS-dialog output becomes persistent local configuration. |
| Source accent -> rendered semantic UI | A learner-selected color is transformed into tokens used for controls and focus. |
| Optional Tk runtime -> CLI | A platform GUI dependency may be missing or fail outside a display session. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-09 | Tampering | `accent.source` | medium | mitigate | Accept normalized opaque `#RRGGBB` only, validate through the settings schema, and persist via atomic `write_settings`. |
| T-04-10 | Denial of Service | color derivation | medium | mitigate | Use bounded deterministic math/binary search and reject malformed inputs before conversion. |
| T-04-11 | Information Integrity | semantic feedback tokens | high | mitigate | Keep ok/bad/warn palettes independent of custom accent, test contrast, and require non-color textual/icon/border cues. |
| T-04-12 | Denial of Service | native Tk picker and child bridge | low | mitigate | Lazy import, catch display/chooser failures, always destroy root, use fixed no-shell source/`.pyz` argv, bound/validate output, and return browser-fallback status with no write. |
| T-04-SC | Tampering | package supply chain | low | accept | No package install; `colorsys`, `tkinter`, JSON, and filesystem operations are stdlib. |
</threat_model>
