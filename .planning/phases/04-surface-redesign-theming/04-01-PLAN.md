<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> `/api/*` | Untrusted JSON crosses from a page that must not hold scoring authority into session/runtime code. |
| API session id -> session/evidence files | An opaque identifier is resolved to server-owned paths and durable local evidence. |
| Bank content -> served DOM | Human-authored text is rendered into HTML/JavaScript without becoming executable markup. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `/api/submit` | high | mitigate | Accept only session id, answer, and validated confidence; resolve current item and verdict server-side through `session.do_submit`/`runtime.score_response`; reject authority/path fields and test forged claims. |
| T-04-02 | Information Disclosure | served quiz HTML/API payload | high | mitigate | Emit bootstrap metadata plus `runtime.public_item` only before submit; keep key/canonical/explanation material out of served source and assert against every full-bank secret. |
| T-04-03 | Spoofing | bank stem and session id resolution | medium | mitigate | Resolve bank stems through `handler.banks` and session ids through `session_index`/`api_session_path`; never join a client path. |
| T-04-04 | Tampering | bank text embedded in page data | medium | mitigate | Serialize inline JSON with script-terminator-safe escaping and render learner content through `textContent`/HTML escaping. |
| T-04-SC | Tampering | package supply chain | low | accept | No package-manager install occurs; implementation remains Python stdlib plus embedded HTML/CSS/JS. |
</threat_model>
