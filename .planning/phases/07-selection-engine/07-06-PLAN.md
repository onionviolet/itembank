> **Phase goal (quoted verbatim from `.planning/ROADMAP.md` § Phase 7 — this line is
> NOT in user-story form; run `/gsd mvp-phase 7` to convert it before the next replan):**
> A session is assembled by rule, not by hand — targeted at an objective, a difficulty,
> or a discrimination pair — and the tool can say why it picked each item.

<objective>
Give the selector its surfaces. Publish the selection spec as the sixth contract, add
`itembank select <bank> --explain` so the trace can be read rather than merely returned,
extend `/api/start` with a `preview` field so the daemon reaches the same capability
without a fifth route (D-14), and expand named profiles from settings so Phase 10's
weights and per-subject defaults have somewhere to hang (D-02).

Purpose: SEL-05 — "it can explain why it chose each item" — is the requirement that most
easily degrades into a checkbox. A trace returned in a JSON blob nobody prints satisfies
it on paper. This plan is where it becomes something a learner actually reads.

Output: `schemas/selection.schema.json`, `itembank select`, `render_trace()`, the
`preview` request field, and one profile-expansion function every surface shares.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `/api/start` JSON body → `do_select()` | A loopback HTTP body becomes a preview request |
| `itembank.json` profile → `expand_spec()` → `select()` | On-disk named profiles expand into the same spec every surface builds |
| `render_trace()` output → learner | Rendered prose crosses the public/private boundary `runtime.public_item()` enforces |
| `/api/start` preview response → HTTP client | Item payloads leave the process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-03 | Information Disclosure | `render_trace()` output and the preview response | high | mitigate | The preview returns `runtime.public_item()` payloads, the same ones a learner sees before answering, never raw parsed dicts; `check_explain_renders_plain_text` and `check_preview_writes_no_session` both assert no keyed answer, option text or rationale string reaches either surface, with the forbidden-string list built from the parsed bank rather than from literals |
| T-07-01 | Denial of Service | an unbounded `count` or a pathological profile on the preview path | medium | mitigate | The preview branch reuses `handle_api_start`'s existing per-field type coercion and `select()`'s positive-integer count guard; `expand_spec` validates every expanded profile against `schemas/selection.schema.json` (`count` has `minimum: 1`) before the selector ever sees it |
| T-07-05 | Tampering | a profile name or `exclude_item_ids` value from a client | medium | mitigate | A profile name is only ever a dict key into the settings profile map, never joined to a path; `API_FORBIDDEN_FIELDS` still refuses `session`/`bank_path`/`out` with a 400 on the preview branch too; the bank is still resolved through the stem allowlist and never treated as a path |
| T-07-02 | Denial of Service | preview requests bypassing the session write but not the history read | low | accept | A preview costs one bank parse and one bank-scoped history read, the same cost as starting a session, on a single-user loopback daemon with no concurrency requirement. No rate limit is added; `.claude/CLAUDE.md` records one user, no accounts and no multi-tenancy |
| T-07-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists in this phase — stdlib only, no lockfile, no install step |
</threat_model>
