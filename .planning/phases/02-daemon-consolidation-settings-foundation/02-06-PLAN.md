<objective>
Close SURF-03: make starting the daemon twice a non-event, make `--lan` reach a phone, and make the
`daemon` settings group the first key group in `itembank.json` that something actually reads.

**User story (MVP framing):** **As a** learner who has already got itembank open, **I want to** run the
command again and land in the tab I already have, **so that** I never end up with two daemons on two
ports wondering which one is recording my answers.

Purpose: D-02 reads "no second daemon ever binds" — satisfied by detecting and attaching, not by two
daemons peacefully coexisting on different ports. RESEARCH.md refines it in one important way: not every
bind failure means another instance. `server.py`'s own docstring records that Windows reserves scattered
port ranges for Hyper-V and WSL, producing an `OSError` that "reads as a bug in this tool" — and treating
that case as "maybe another itembank, go probe" burns a network timeout on every start on exactly the
platform this project runs on.
Output: a startup path that distinguishes the three bind-failure cases, a `--lan` that works, and a
`daemon` settings group that is no longer inert.
</objective>

  <action>
Add the probe and the three-case startup, then wire `--lan` and the settings defaults.

**`probe(port, host="127.0.0.1", timeout=0.5)`** — `urllib.request.urlopen` against
`http://<host>:<port><MARKER_PATH>` with that timeout, parse the body as JSON, and return `True` only when
the parsed object's `itembank` field is exactly `True`. Wrap the whole thing in a blanket
`except Exception: return False`, matching `day.anki_read()`'s shape: a timeout, a refused connection, a
non-JSON body, a JSON body of the wrong shape and a redirect all mean *not us*. The asymmetry is
deliberate and worth a comment — a false negative costs one unnecessary free-port fallback, while a false
positive would send a learner to somebody else's web server believing it was their study tool.

**`start_server(handler_cls, port, host)`** returning `(srv, bound_port, fell_back)`. Try
`socketserver.TCPServer`-based construction of the `Daemon` class from plan 02-01 on `(host, port)` first.
On `OSError`, branch on the *kind* of failure before deciding whether to probe:

- **Reserved or permission-denied** — `getattr(exc, "winerror", None) == 10013` or
  `exc.errno == errno.EACCES`. Nothing is listening; probing would only burn the timeout on exactly the
  platform this project runs on. Go straight to `server.bind(handler_cls, port, host)` and return with
  `fell_back` true.
- **Occupied by another itembank** — `probe(port)` returns `True`. Print
  `itembank is already running at http://127.0.0.1:<port>/` verbatim, open a browser at that URL unless
  `--no-open`, and `sys.exit(0)`. Exiting here is correct and is not the Pitfall #3 hazard: this runs in
  the CLI entry point's own process before any server exists, not inside a request handler.
- **Occupied by something else** — `probe(port)` returns `False`. Fall through to
  `server.bind(handler_cls, port, host)` and return with `fell_back` true. This is the third case
  RESEARCH.md's Open Question 3 raises and CONTEXT.md does not resolve; the planner's flagged assumption
  above records the choice and why.

Reuse `server.bind()` for both fallback branches rather than duplicating its free-port logic — D-02
explicitly scopes this plan's change to the daemon's own startup path and leaves `bind()` intact and
general for its other callers. When `fell_back` is true, print the port actually bound, so a learner who
typed one port and got another is told.

**`cmd_daemon` wiring.** Resolve the port and the LAN flag from settings with the command line winning:
call `settings.load_settings(a.dir)` and read `daemon.port` and `daemon.lan` as the defaults, then let an
explicitly-given `--port` or `--lan` override. Detect "explicitly given" properly — set the argparse
defaults to `None` and `False` respectively so an omitted flag is distinguishable from a flag set to the
same value as the file, rather than comparing against a hardcoded 8730. Compute the bind host as
`"0.0.0.0"` when LAN is on and `"127.0.0.1"` otherwise, the same expression `cmd_day` already uses. Call
`start_server`, then `serve_scoped` with the returned server.

Extend the banner: keep the existing lines, add the bound port when it differs from the requested one, and
when LAN is on add a phone line using `day.lan_address()` in the same shape `cmd_day` prints —
`phone   http://<addr>:<port>/   (same wifi only)`. Import `lan_address` from `surfaces.day` rather than
reimplementing the UDP-connect trick; it is one best-effort helper and there should be one of it.

Also print, whenever LAN is on, a one-line notice that the daemon is reachable by every device on this
network and that itembank has no accounts and no authentication by design. This is not decoration: the
project has exactly one user and no auth, so the only thing standing between a device on the wifi and the
routes is that the learner knowingly asked for it. `--lan` widens who can reach the daemon; it must not be
something a learner discovers after the fact.

**`surfaces/cli.py`** — add `--lan` to the `daemon` subparser with `action="store_true"` and help text
matching the `day` subparser's: `bind all interfaces so a phone on the same wifi can open it`. Change
`--port`'s default to `None` so settings can supply it. Change nothing else on the subparser.

| Boundary | Description |
|----------|-------------|
| local network → daemon | Under `--lan` the daemon accepts requests from every device on the wifi, with no accounts and no authentication by project design; this is the widest boundary in the phase |
