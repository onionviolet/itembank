## Phase Framing — Read This First

This is **not** a greenfield UI phase. Per CONTEXT.md's Phase Boundary and RESEARCH.md's own
framing, Phase 2 consolidates existing per-surface HTTP servers onto one daemon and adds a
settings CLI. Of the six routes the daemon stands up or re-serves, **four already have a
render function this phase must call into unmodified**, and only **two are genuinely new HTML**
this phase authors from scratch. No new visual language, no new palette, no new component
system is in scope — Phase 4 (Surface Redesign & Theming, SURF-02/05-09) owns all of that.

This document is deliberately short where the project already has an answer, and specific
where it does not.

## Spacing Scale

Declared values (must be multiples of 4) — **[AUTO]** this is the standard 8-point scale applied
to the **new** HTML this phase authors (`/` index, `/report`). It is not retroactively applied
to `quiz_page.py`/`STUDY_TEMPLATE`/`day.py`'s existing CSS, which already ships with its own
(slightly off-grid: `18px`, `13px`, `9px`, `7px`) spacing values — rewriting those is Phase 4's
job (SURF-05/07), not this phase's, and touching them here would be undocumented scope creep.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Chip/badge internal gaps on new pages |
| sm | 8px | Row-internal spacing (link groups, meta lines) |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, gap between list rows |
| xl | 32px | Layout gaps (header to list) |
| 2xl | 48px | Major section breaks (index vs. footer note) |
| 3xl | 64px | Page-level top/bottom padding |

Exceptions: `/quiz/<bank>`, `/study/<bank>`, and the day view keep their existing (pre-Phase-2)
spacing values unmodified — reuse, not migration. Only `/` and `/report` (the two new pages)
follow the 8-point scale above.

## Typography

**[AUTO]** — reused from `quiz_page.py:TEMPLATE`'s existing scale (the project's only precedent
for a "shell page" typographic system) and applied to the two new pages so the daemon's pages
read as one family rather than a third, unrelated style. Not a new typographic system.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.55 |
| Label (chip/meta/status) | 12.5px | 500 (medium, via existing `.chip`/`.sub` classes) | 1.4 |
| Heading (h1/page title) | 21px | 700 (bold, browser default `<h1>`) | 1.2 |
| Display (headline stat, `/report` score) | 34px | 700 (bold) | 1.1 |

Font sizes used: 12.5, 16, 21, 34 (4 sizes — matches the "3-4 sizes" rule). Weights used: 400 and
700 (2 weights — matches the "2 weights max" rule; `quiz_page.py` itself uses a 600 for buttons,
which is out of scope here since buttons on `/` and `/report` are plain links/anchors, not
`button.go` elements).

## Color

**[AUTO]** — reused verbatim from `surfaces/theme.py:THEME_CSS`, the project's own single shared
palette (light + `prefers-color-scheme: dark` pair), substituted via `__THEME__` exactly the way
`quiz.py:page_for()` and `study.py:cmd_study()` already do. No new color is introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` (`#f3f5f4` light / `#0e1413` dark) | Page background on `/` and `/report` |
| Secondary (30%) | `--card` (`#fff` light / `#161e1d` dark) | List rows, report table/card panels |
| Accent (10%) | `--accent` (`#0e6e62` light / `#34b3a0` dark) | Link hover/focus rings only, and the `/report` headline score number |
| Destructive | n/a this phase | No destructive action exists on `/` or `/report` (see Copywriting Contract) |

Accent reserved for: the score number on `/report` (mirrors `quiz_page.py`'s `.score` /
`--accent`-adjacent `--ok` styling precedent), and link `:focus-visible`/`:hover` states on `/`
and `/report`. Never used as a background fill for large surface areas — that stays `--bg`/`--card`
per the existing 60/30/10 split every other page already follows.

**Explicit exception, carried over unmodified:** `surfaces/day.py`'s existing inline stylesheet
(`#fbfbfa` background, `#4f8f3f` accent green — a *different* palette from `THEME_CSS`) is
**not** touched by this phase. SURF-07 ("`day` stops being a third stylesheet") is Phase 4's
requirement, explicitly out of scope here per CONTEXT.md's Phase Boundary. The daemon's `GET`
route for the day view calls `day.day_page()` unmodified and returns its bytes as-is.

## Copywriting Contract

**[AUTO]** — all copy below is for the genuinely new surface area (`/` index page, `/report`
page, and the two HTTP-level failure states — 404/unreachable — a browser can hit against this
daemon). Existing pages (`quiz`, `study`, `day`) keep their existing copy unmodified; e.g.
`quiz_page.py`'s "Could not reach the process that scores and records this sitting..." stays as
the connectivity-failure copy for quiz/study — it is not rewritten here.

| Element | Copy |
|---------|------|
| Primary CTA (`/` index, per bank row) | `Sit this bank` (links to `/quiz/<stem>`) — "sit"/"sitting" matches the project's own vocabulary (`quiz.py` docstring: "a graded sitting") |
| Secondary CTA (`/` index, per bank row) | `Study this bank` (links to `/study/<stem>`) |
| Secondary CTA (`/` index, per day-plan row) | `Open day view` (links to the day route) |
| Report link (`/` index, per bank row, only if `_attempts/session_*.json` exists for it) | `View report` (links to `/report?session=<id>`) |
| Empty state heading (`/`, no banks or plans found) | `Nothing to serve here yet` |
| Empty state body (`/`, no banks or plans found) | `This daemon serves whatever bank and day-plan files it found in <working directory> when it started. Add a bank (any .md file with items) or a day plan, then restart the daemon.` |
| Empty state heading (`/report`, session has zero recorded responses) | `Nothing answered yet` |
| Empty state body (`/report`, session has zero recorded responses) | `This session hasn't recorded a response. Sit the bank, then refresh this report.` |
| Error state (unknown bank/session stem, any route) | `Not found` / `No bank or session matching "<name>" is being served from this daemon. It may have been renamed, or the daemon was started in a different folder.` — plain 404, no stack trace, no path echoed back verbatim beyond the already-validated stem (per RESEARCH.md Pitfall #5's security note: an unknown identifier must return a clean 404, never a filesystem detail) |
| Error state (daemon already running, CLI-level, not browser-rendered) | `itembank is already running at http://127.0.0.1:<port>` — **[AUTO] verbatim from RESEARCH.md Pattern 2**, printed by the CLI process, not an HTML page |
| Destructive confirmation | None in this phase's scope. Neither `/` nor `/report` nor `itembank config set` performs a delete/irreversible action — `config set` overwrites one settings value, which is itself correctable by another `config set`, not a destructive action requiring a confirmation dialog. |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). Elements classified below cover
> only the genuinely new HTML this phase authors (`/` index, `/report`). `/quiz/<bank>`,
> `/study/<bank>`, and the day view are unmodified reuses of existing render functions whose
> state coverage (empty/loading/error/etc.) was already resolved when those pages were built —
> re-litigating it here would be scope creep this phase's own boundary forbids.

Applicable state considerations resolved: 10 covered, 3 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | `/` index (list-collection: scanned banks + day plans) | ✅ covered | Zero banks/plans found renders the documented "Nothing to serve here yet" heading + body (see Copywriting Contract) instead of a blank page or a raw empty `<ul>` |
| zero-one-many | `/` index (list-collection) | ✅ covered | One bank/plan renders the same row markup as many (no singular/plural copy branch needed — row labels are per-item, not a count sentence); zero renders the empty state above |
| overflow | `/` index (list-collection) | 🧪 backstop | Plain vertical list with no max-height/scroll container — the browser's normal document scroll handles any number of banks. Held out as backstop because "many banks" (20+) was not manually exercised this session; verified at UAT with a working directory carrying several fixture banks |
| long-text | `/` index (static-content: filenames as link text) | ✅ covered | Filenames wrap naturally (no `white-space:nowrap`, no forced truncation/ellipsis) — a long bank filename reflows onto a second line rather than being cut off or breaking the row layout |
| loading | `/` index, `/report` (server-rendered, not client-fetched) | ✅ covered — dismissed | Both pages are rendered synchronously server-side on `GET` (same model as `quiz.page_for()`/`day.day_page()`); there is no client-side fetch-then-render step, so no loading/skeleton state applies. Dismissal reason: "server-side render, page arrives fully populated on first paint, no async data fetch on this route" |
| error | `/` index (list-collection; directory scan at daemon startup) | ✅ covered — dismissed | The D-03 stem allowlist is built once at startup via `model.parse_bank()`, which returns an empty list (never raises) for a file that isn't a valid bank — so a malformed `.md` file in the served directory is silently excluded from the index rather than crashing the scan or rendering a broken row. Dismissal reason: "parse_bank()'s graceful-empty-list behavior already prevents a render-time error state here" |
| error | `/report` (unknown `session` id in query string) | ✅ covered | Renders the documented "Not found" copy at HTTP 404, never a stack trace or the raw filesystem path attempted (RESEARCH.md Pitfall #5) |
| empty | `/report` (session exists, zero responses recorded — e.g. `start` just ran) | ✅ covered | Renders the documented "Nothing answered yet" empty state rather than a report table with all-zero/blank cells |
| partial | `/report` (session in progress — some items answered, some remain) | ✅ covered | Report shows `cursor`/`len(items)` progress (`session_summary()`'s existing fields) alongside whatever accuracy stats exist so far — a mid-session report reads as "in progress," not as a broken or final report |
| zero-one-many | `/report` (per-objective / per-item breakdown rows) | ✅ covered | Report renders the same per-objective row shape at one response or many; percentage/accuracy math guards divide-by-zero the same way `quiz_page.py`'s `finish()` already does (`pct = autoTotal ? Math.round(...) : 0`) — reused pattern, not a new one |
| long-text | `/report` (objective names, item stems in a pending-review list) | ✅ covered | Table/list cells wrap rather than truncate, matching the `/` index's long-text resolution above — one consistent rule across both new pages |
| overflow | `/report` (many items pending manual marking) | 🧪 backstop | Same plain-scroll resolution as `/` index's overflow row — held out as backstop pending a UAT pass with a fixture session carrying 10+ pending `short` items |
| populated | `/report` (normal case: session with a mix of correct/incorrect/pending responses) | 🧪 backstop | The exact table/`<pre>` layout for the populated case is sized as new work per RESEARCH.md's Open Question 2 ("no existing render function to strangle"); the *shape* of the data (`session_summary()`'s fields) is settled, but the concrete visual layout is a planner/executor decision, not fully pre-specified here — held out as backstop, confirmed against the actual `session_summary()` field list at UAT |

### Decision: `/settings` HTML page — **[AUTO] deferred to optional/stretch, not required**

RESEARCH.md's Open Question 1 flags that D-01's route-table sketch lists `/settings` but the
phase's own numbered success criteria (ROADMAP.md, Phase 2, criterion 4) only require the CLI
`itembank config` command, not an HTML page. Per CONTEXT.md's own instruction ("if a planner
finds any of D-01 through D-07 impractical against the real code, that is a legitimate
reversal — flag it rather than silently overriding"), this is flagged here as a design-contract
decision, not silently dropped:

**Resolution:** `/settings` HTML is **not required** by this UI-SPEC. `itembank config` (CLI,
mirroring `itembank schema`'s existing precedent) fully satisfies DEL-05 and SURF-04. If the
planner elects to add `/settings` anyway for completeness with D-01's route-table sketch, it
must be scoped to **read-only display** of the current schema + values (a `list-collection` of
key/type/default/current-value rows, same visual system as `/` and `/report` above) — never an
editing UI. Editing stays `itembank config set KEY VALUE`, matching D-04's existing "not yet
SURF-02" scoping precedent for quiz/study. If built, it inherits this document's empty/error
state resolutions (an unset/default-only settings file is not an "empty" state — every key
always has a default per D-05, so there is no empty-state row to define for this route).
