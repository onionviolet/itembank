<objective>
Stand up `surfaces/daemon.py` as one process, one port, one ordered route table — and prove the whole
architecture end-to-end on the thinnest real path: a learner opens the daemon on a directory, sees the
banks it found, opens one bank's quiz, answers an item, and that answer is scored by the one scorer and
recorded by the one evidence writer.

**User story (MVP framing, from ROADMAP Phase 2 Goal):** **As a** learner, **I want to** open one
process on one port for everything, **so that** I stop starting a separate server per subcommand.

Purpose: this is the tracer slice. Every later plan in this phase expands the route table this task
builds; if the architecture is wrong, it is wrong after one commit rather than after five. D-01's
"thin dispatchers into the existing render functions" is proven here or it is not proven at all.
Output: a working daemon serving the index and the quiz slice, plus the Wave 0 test harness every
later plan in this phase extends.

Create `surfaces/daemon.py` holding the whole HTTP surface for this phase. Follow the import order
`surfaces/quiz.py` already uses: stdlib first (`html`, `json`, `os`, `re`, `socketserver`, `sys`,
`threading`, `webbrowser`), then `evidence`, `server`, then `from model import load, parse_bank`,
then the surface modules it dispatches into (`from surfaces import quiz`). Give the module a docstring
in the established voice stating the invariant it exists to hold: one process, one port, one route
table, and route handlers that dispatch into the existing render and runtime functions rather than
reimplementing any of them.

Build these pieces, in this order:

1. `MARKER_PATH = "/__itembank__"` — a fixed literal that cannot collide with a filename-derived stem,
   and `handle_marker` returning the JSON object `{"itembank": true}`. This is the identifying response
   plan 02-06's detect-and-attach probe will look for (D-02); ship it now so the probe has something to
   find.

2. `scan_dir(root)` — walk `root` once, skipping the same directories `cmd_guard` skips (`.git`,
   `.github`) plus `_attempts` and `_evidence`. For each `.md` file, classify it: `parse_bank(text)`
   returning a non-empty list means bank; otherwise `surfaces.day.parse_plan(path, year)` returning a
   non-empty dict means day plan; otherwise skip it silently. Key both dicts by `os.path.splitext(
   os.path.basename(path))[0]`. Iterate candidate paths in case-insensitive stem order so the winner of
   a stem collision is deterministic across restarts, and return a third value: a list of
   `(stem, winner_path, loser_path)` collision records. `cmd_daemon` prints one line per collision at
   startup naming both paths and which one lost. Return `(banks, plans, collisions)`.

3. The route table. `ROUTES` is an ordered tuple of `(method, pattern, handler_name)` where `pattern`
   is either a literal string or a compiled regex with one named group `stem`. Order matters and is
   load-bearing: every fixed literal route (`/`, `MARKER_PATH`) comes before every stem-parameterised
   route, so a bank whose stem is `report`, `day`, or `api` can never shadow a fixed route. Dispatch is
   first-match-wins: `do_GET`/`do_POST` walk `ROUTES` in order, take the first entry whose method
   matches and whose pattern matches `urllib.parse.urlsplit(self.path).path`, and call the named
   handler. No route handler generates HTML or reaches a verdict inline — each one resolves its
   identifier through the allowlist and calls an existing function.

4. `ROUTE_CLI` — a dict mapping every entry in `ROUTES` to the name of the CLI command that reaches the
   same runtime call, so SURF-04's "every route has a CLI equivalent" is a machine-checkable inventory
   rather than a claim in prose. For this plan's routes: `/` and `/__itembank__` map to `daemon`,
   `GET /quiz/<stem>` maps to `serve`, `POST /quiz/<stem>/answer` maps to `serve`. Later plans add their
   rows. Keep `ROUTE_CLI`'s key set exactly equal to `ROUTES`' entries — the test asserts that equality,
   so a route added without a CLI equivalent fails the build instead of shipping silently.

5. `DaemonHandler(server.Handler)` — the one and only `Handler` subclass in this phase. It reads its
   state (the `banks`/`plans` dicts, the root directory, the per-bank session ids and attempt paths)
   from class attributes set by `cmd_daemon` before the server starts, the same closure-over-startup-
   state shape `cmd_serve` uses today. Add a `send_not_found(name)` helper emitting the UI-SPEC's
   documented not-found copy — the message names the stem the client asked for and nothing else; it
   never echoes a filesystem path, a stack trace, or the directory being served.

6. `Daemon(socketserver.ThreadingMixIn, socketserver.TCPServer)` with `daemon_threads = True` and
   `allow_reuse_address = True`. This is required, not optional: one process now serves quiz, study,
   day and api concurrently, and `day`'s AnkiConnect calls carry a two-second timeout per lane, so a
   plain single-threaded server would let one slow render stall every other route (RESEARCH.md Pitfall
   #4). Bind it with `server.bind()`'s existing free-port fallback for now; plan 02-06 layers
   detect-and-attach on top.

7. `handle_index` — the `GET /` page. This is genuinely new HTML with no existing render function to
   call into, so author it here as `INDEX_TEMPLATE`, a Python string template following the same
   `str.replace()` substitution convention `page_for()` uses, wrapping `THEME_CSS` through a `__THEME__`
   placeholder. Follow 02-UI-SPEC.md exactly: the 8-point spacing scale (4/8/16/24/32/48/64), the four
   font sizes (12.5 / 16 / 21 / 34) at weights 400 and 700, `--bg` for the page, `--card` for rows,
   `--accent` reserved for link hover and focus-visible rings only. One row per bank carrying the
   primary link `Sit this bank` to `/quiz/<stem>` and the secondary link `Study this bank` to
   `/study/<stem>`; one row per day plan carrying `Open day view`. Row link text must wrap naturally —
   set no nowrap and no ellipsis truncation anywhere in the index stylesheet. Rows are a plain vertical
   list in ordinary document flow with no max-height and no scroll container, so any number of rows
   scrolls with the page. When both dicts are empty, render the documented empty state instead: heading
   `Nothing to serve here yet`, body `This daemon serves whatever bank and day-plan files it found in
   <working directory> when it started. Add a bank (any .md file with items) or a day plan, then
   restart the daemon.` with the actual served directory substituted and HTML-escaped. Emit the same
   row markup for one row as for many — no count sentence, no singular/plural branch.

   The `Study this bank` and `Open day view` targets are wired in plan 02-02; in this plan they are
   real links to the real final paths, and those paths 404 until 02-02 lands. Do not stub them out and
   do not hide them.

8. `handle_quiz_get` — resolve `stem` through the `banks` allowlist (never through `self.path`
   directly); on a miss call `send_not_found(stem)`. On a hit call `load(bank_path)` and
   `quiz.page_for(bank_path, qs, serve=True, reveal=False, post_path="/quiz/%s/answer" % stem)` and send
   the result as HTML. No HTML is generated in this function.

9. `handle_quiz_answer` — resolve `stem` through the same allowlist, look the posted `id` up in that
   bank's `by_id` map, type-guard `elapsed_ms` exactly the way `cmd_serve`'s POST handler does today
   (a non-integer or a bool becomes `None`, never a fabricated number), then call
   `quiz.record_answer(...)` and return `{"item_id", "score", "explain"}` built from
   `runtime.explain_payload`. Wrap the body in `except Exception as exc: self.send_error(500, str(exc))`,
   matching the existing handler. Do not call `score_response` or `evidence.append_event` directly from
   `daemon.py` — going through `quiz.record_answer` is what keeps the "one scorer, one writer" invariant
   structural instead of remembered.

10. `cmd_daemon(a)` — takes `a.dir` (positional, default `.`), `--port` (default 8730, a number
    distinct from `serve`'s 8731 and `day`'s 8732 so an old command and the daemon can run side by side
    during rollout), `--no-open`, and `--force`. It runs `scan_dir`, prints a banner in the established
    voice (`itembank daemon`, then indented lines for the directory, the bank count, the plan count, any
    stem collisions, and the URL), sets the class attributes on `DaemonHandler`, binds, opens a browser
    after a `threading.Timer(0.4, ...)` unless `--no-open`, and calls `serve_forever()` inside a
    `try/except KeyboardInterrupt` that prints a closing line. `--lan` is added in plan 02-06 — do not
    add a host argument here.
