<objective>
Give the daemon its last route: a report page a learner can actually read, rendered from the same summary
the `report` command prints.

**User story (MVP framing):** **As a** learner who has just finished a sitting, **I want to** see how it
went in the same tab I sat it in, **so that** I do not have to drop to a shell and read JSON to find out.

Purpose: `/report` is the one route in D-01's list with no existing render function to call into —
`session.cmd_report` has only ever emitted JSON, so RESEARCH.md sizes this as new work rather than as a
migration. It is deliberately the *last* route: by now the route table, the allowlist, the session lookup
and the containment are all proven, so this plan is one page and its states rather than a page plus an
architecture.
Output: `GET /report?session=<id>` on the one port, with its empty, in-progress, populated and not-found
states all defined.
</objective>

Add `handle_report_get()`. It reads the `session` value from the query string via
`urllib.parse.parse_qs(urllib.parse.urlsplit(self.path).query)`, resolves it through the same
`session_index(root)` lookup `/api/*` uses, and calls `session.do_report(path)` inside the same
`except SystemExit` / `except Exception` pair every reused command body gets — a session file with a bad
or future `schema_version` is exactly the routine condition that would otherwise take the daemon down.
An absent parameter, an unknown id, or a value that is not a key in the lookup all take the same branch:
`send_not_found(...)` with the documented copy. The value is never joined to a path and never normalised,
because it is never treated as a path.

Render three states from the returned dict, chosen on the data rather than on a flag:

- **Empty** — `summary["auto_attempts"]` and `summary["pending_manual"]` both zero: render the heading
  `Nothing answered yet` and the body `This session hasn't recorded a response. Sit the bank, then refresh
  this report.` No table, no zeroed cells.
- **In progress** — the session's `status` is `active`: render the same report as the populated case plus a
  position-of-total progress reading built from the session's cursor and item count, and a label making it
  read as in progress rather than final. Take both numbers from the session data the summary came with;
  do not recompute them from the responses list.
- **Populated** — the headline number is the auto-marked accuracy, computed as
  `round(auto_correct / auto_attempts * 100)` guarded so a zero denominator yields 0, mirroring the guard
  the quiz page's own finish step already uses. Below it, the auto-marked count, the correct count and the
  pending-manual count as three labelled figures, then one table row per entry in `summary["objectives"]`
  carrying the objective name and its attempts, correct and pending counts. Emit the same row markup for
  one objective as for many — no count sentence, no singular/plural branch. HTML-escape every objective
  name; they come from bank content.

The three states are branches of one template, not three templates.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /report` | The `session` query parameter is untrusted input; under `--lan` (plan 02-06) the source is any device on the same wifi |
| report page → bank content | Objective names and item text rendered into the page originate in bank markdown, which is learner-authored but not necessarily trusted markup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2-01 | Tampering / Information Disclosure | the `session` query parameter | high | mitigate | Resolved through `session_index(root)` — the same server-built lookup `/api/*` uses. The value is never joined to a path; a miss is the fixed 404. Asserted by a parent-directory-path case. |
| T-2-03 | Denial of Service | `do_report` on a malformed or future-versioned session file | high | mitigate | The call site carries both `except SystemExit` and `except Exception`; `runtime.upgrade_session` exits on a missing or newer `schema_version` and that must not reach the request loop. The not-found test asserts the daemon still answers afterwards. |
| T-2-05 | Information Disclosure | the 404 body and the 500 body | medium | mitigate | The 404 carries only fixed copy plus the identifier the client already sent. Asserted by checking the body for the absence of both `Traceback` and the served directory path. |
| T-2-18 | Tampering | objective names and item text rendered into the page | medium | mitigate | Every value interpolated into `REPORT_TEMPLATE` is passed through `html.escape` before substitution, matching `page_for`'s existing treatment of the bank title; bank content cannot inject markup into the report. |
| T-2-19 | Denial of Service | a session with a very large objective set | low | accept | The page renders one row per objective with no pagination; a single-user local tool with a bank large enough to matter would already be slow to lint. Recorded rather than mitigated. |
| T-2-SC | Tampering | dependency supply chain | low | accept | No package-manager install in this phase; Python standard library only. Nothing to audit. |
</threat_model>
