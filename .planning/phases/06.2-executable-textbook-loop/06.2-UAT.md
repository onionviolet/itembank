# Phase 6.2: Executable Textbook Loop — User Acceptance Test

**As a learner**, I read a gated lesson like a textbook that holds the next
idea until the check is cleared — and I can always read ahead by an
explicit, recorded choice that is never punished, never confirmed, and
never final.
**As the runtime**, the gate is a presentation policy over existing item
types: one parser, one scorer, one evidence store, and the lesson-embedded
check is the same object as a quiz attempt to every consumer.

## Acceptance Scenarios

### A1. A required gate holds the next idea

Given a lesson declaring `[GATE: required]` with a `[!CHECK: q1]` and
sections below,
when I open it with a session,
then I see the first section, the gate band (check item + `Check answer`
and `Read ahead without answering`), and `2 more sections below this
check.` — and **no** content from the sections below (A1 passes: verified
by `test_gate_required_truncation_no_leak` and
`check_gate_route_check_and_reveal`).

### A2. Clearing the check reveals the next idea

When I answer the check correctly and submit,
then the runtime scores it through the one scorer, records response
evidence with `context="lesson_gate"`, redirects (a reload never
re-submits), and the next section renders with focus on its heading and
`The next section is below.` announced (A2 passes: verified by
`check_gate_route_check_and_reveal` and `check_gate_route_reload_no_resubmit`).

### A3. Reading ahead is a normal, recorded choice

When I press `Read ahead without answering`,
then exactly one `gate_skip` event is recorded (never a response, never a
hint tier), the next section renders, the band stays live and answerable,
and `Read ahead recorded. This check stays open.` is announced once
(A3 passes: verified by `check_gate_route_skip_single_event`).

### A4. The compatibility floor

Given a bank whose lessons declare no gates,
when I render it,
then it is byte-identical to the Phase 3.1 output (A4 passes: verified by
`test_gate_compatibility_floor` + `test_lesson_content_region_byte_identical_phase3`).

### A5. The gate degrades honestly

Given a diagnostic or exam sitting with a declared required gate,
when I open the lesson,
then the whole lesson renders (no wall that can never open), the exact
degrade line states why, and no skip control or `gate_skip` appears
(A5 passes: verified by `test_gate_mode_degrade`).
Given the runtime is unreachable,
when I open a gated lesson,
then the band states `This check cannot be submitted while the runtime is
unreachable. Run itembank daemon and reload.` and no section is revealed
(A5 passes: verified by `check_gate_route_unreachable_no_reveal`).

### A6. The loop is visible to the scheduler, not a second store

Given a lesson-gate response on an objective,
when any consumer reads `objective_history(log, objective)`,
then it appears in the same list as a quiz response on that objective,
differing only by `context` — Phase 10 needs no branch (A6 passes:
verified by `test_objective_history_collapses_lesson_and_quiz`).
The gate outcome split (cleared vs skipped, stated denominator, no target,
no streak) is derivable from the evidence log alone (A6 passes: verified
by `test_gate_outcome_split_pair_level` and
`test_gate_outcome_split_report_copy`).
