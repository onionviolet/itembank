## Pattern Assignments

### `model.py` - `[GATE:]` directive (the one new grammar)

**Analog:** `model.py:213` `[LESSON-SRC:]` grab (VERIFIED in 06.2-RESEARCH.md section 1):

```python
src = grab(r"(?m)^\[LESSON-SRC:\s*(.*?)\s*\]", head)
# 6.2 adds, following the identical shape:
gate = grab(r"(?m)^\[GATE:\s*(.*?)\s*\]", head) or "recommended"
```

The value must validate against `("required", "recommended", "off")`; an invalid value is a lint error, never a render-time crash. Scope: lesson-preamble level, one value per lesson (A2 in 06.2-RESEARCH.md).

### `evidence.py` - `gate_skip` event + `context` field

**Analog 1 - the one-line tuple addition (VERIFIED, evidence.py:43):**

```python
KNOWN_EVENT_TYPES = ("response", "retraction", "mark", "day_tick", "gate_skip")
```

`events()` already skips-and-warns on unknown types (evidence.py:418-436), so this one line is the entire mechanism - every existing reader (`live_events`, `attempt_number`, `objective_history`, `session_events`, `retracted_ids`) uses explicit type-equality checks and needs no change (VERIFIED in RESEARCH section 3).

**Analog 2 - `gate_skip_event()` mirrors `day_tick_event()`/`mark_event()`** (VERIFIED: evidence.py:1350-1370, 1035-1080): own envelope, narrow `dedupe_key`, `ValueError` on malformed args, and - structurally - **no `score` key at all** (not even `None`), which is the concrete form of criterion 8.

**Analog 3 - `context` on `response_event()`** (VERIFIED: evidence.py:355-395): additive keyword parameter with default `"quiz"` so every existing call site compiles unchanged; `additionalProperties: false` in the schema means `required`/`properties` are updated in the same commit.

### Gate state - read-side derivation

**Analog:** the read-side filter discipline Phase 1 established (`live_events()` is the only reader views may use; retractions collected before anything is emitted - evidence.py:996-1011). `gate_state()` computes from live events per session, never a second store (D-06).
