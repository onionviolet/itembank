<objective>
Publish the contract. After this plan an agent can read five JSON Schema documents and know what an
item, a session, a response event, a report and a lint entry are, without opening a single Python
file — and every runtime payload stamps the version of the contract it was written against.

Purpose: PROTO-01 requires items, sessions, responses and reports each to carry an explicit schema
version. `.planning/codebase/CONCERNS.md` flags the existing `SESSION_VERSION = 1` as a stamp with
no migration logic — `runtime.read_session()` simply exits on any mismatch. CONTEXT.md's canonical
references say plainly that PROTO-01 has to fix that, not repeat it, so this plan ships version
*evolution*: a registry of upgrade functions, an explicit forward path, and a named error for a
version from the future.

This is also where EVID-07's capture policy stops being a plan decision and becomes a published
one: `schemas/response.schema.json` carries, in each field's `description`, why
`response_time_ms` and `confidence` hold real values while `error_category` and `hint_tier` are
reserved null until Phases 6 and 8 give them a source.

Output: version stamps on every payload, the session upgrade seam, five schema documents under
`schemas/`, and two new tests in `tests/protocol_roundtrip.py`.
</objective>

  <action>
    Create a `schemas/` directory at the repository root holding five documents. Every one of them
    declares, at the top level: `"$schema": "https://json-schema.org/draft/2020-12/schema"`, an
    `"$id"` of the form `"https://itembank.local/schemas/<name>.schema.json"` (a stable identifier,
    deliberately not a resolvable URL — this tool makes no network calls), a `"title"`, a
    `"description"` written for a reader who has never seen the repository, and
    `"x-itembank-version": 1` recording which version of *this contract* the document describes.

    **Stay inside a fixed keyword subset.** Every schema may use only: `$schema`, `$id`, `title`,
    `description`, `x-itembank-version`, `type` (a string or a list of strings, so a nullable field
    is `["integer", "null"]`), `properties`, `required`, `additionalProperties`, `enum`, `const`,
    `items`, `minItems`, `minLength`, `$defs`, `$ref` (local `#/$defs/<name>` form only), and
    `oneOf`. Nothing else. Plan 01-06 implements a validator for exactly this set and fails loud on
    anything outside it, so a schema that reaches for `patternProperties` or `allOf` would break the
    gate rather than be silently ignored. This is the concrete answer to the open cost D-15 named.

    **`item.schema.json`** — what `public_item()` returns. Required: `schema_version` (`const: 1`),
    `id`, `number`, `type` (`enum` of the six item types), `stem`, `objective`, `difficulty`. Use
    `oneOf` over `$defs` variants for the per-type extras: an mc/multi item carries `options` (array
    of `{key, text}`) and a `response_schema` of `{type, select, allowed}`; a table/dnd item carries
    `rows` (array of `{text, id}`), `categories`, and a `response_schema` of `{type, keys, values}`;
    a build item carries `steps` and a `response_schema` of `{type, items, ordered}`; a short item
    carries a `response_schema` of `{type, min_length}`. In the top-level `description`, state
    explicitly that this shape never carries an answer key, a rationale, or a model answer — that is
    the boundary `runtime.public_item` exists to draw, and an agent reading the contract cold needs
    to know not to look for one.

    **`session.schema.json`** — the session file. Required: `schema_version` (`const: 1`),
    `session_id`, `bank`, `items` (array of integers), `cursor`, `responses`, `status`
    (`enum: ["active", "complete"]`), `mode` (`enum` of the mode values registered in
    `surfaces/cli.py`, including `drill`), `objective`, `seed`. `served_ts` is optional (a session
    written before plan 01-02 has none). Describe `items` as indices into the parsed bank, not
    copies.

    **`response.schema.json`** — one evidence event, and the most important document here.
    `additionalProperties: false` and `required` listing all 22 keys, so a missing key is a
    validation failure rather than a shrug: a consumer must be able to tell "not captured" from
    "this field did not exist in that era", and that only works if every key is always present.
    Give each of the six EVID-07 fields a `description` stating its Phase 1 disposition and the
    reason:
    - `response_time_ms` — captured live; milliseconds between the item being served and the
      response being submitted; null only when the session carries no `served_ts`.
    - `confidence` — captured live where the surface offers it (`submit --confidence`); null when
      the learner did not say, which is different from low confidence.
    - `mode` — captured live on every surface; this is what makes a drill-mode correct
      distinguishable from an exam-mode correct.
    - `review_state` — `n/a` for an auto-scored item, `pending` for a constructed response awaiting
      a marker, `marked` once a mark event lands.
    - `error_category` — **reserved, always null in schema version 1.** No error taxonomy exists;
      it depends on the tutoring work in Phases 6 and 8. A guessed category would be recorded as
      fact and read as fact by later trend work, so it is recorded as unknown instead.
    - `hint_tier` — **reserved, always null in schema version 1.** The hint ladder is Phase 6. Null
      means no ladder existed, which is a different fact from "the ladder existed and the learner
      reached tier 0"; conflating them is unrecoverable once written.
    Also document `event_type` as an `enum` covering `response`, `mark`, `retraction` and
    `day_tick`, with `$defs` variants for the three non-response types (plans 01-07 and 01-09 write
    them), and state that `source_ref` is null except on records imported by `itembank migrate`.

    **`report.schema.json`** — two shapes under `$defs`, selected by `oneOf`: the session summary
    (`schema_version`, `auto_attempts`, `auto_correct`, `pending_manual`, `objectives`) and the
    objective history (`schema_version`, `objective`, `count`, `events`). State in the description
    that every count is post-retraction — a raw line count of the log overstates history, because
    D-10 undoes by appending a compensating event rather than removing anything.

    **`lint_error.schema.json`** — `code`, `field`, `item`, `message`, all required,
    `additionalProperties: false`, with `code` carrying an `enum` of every value in
    `model.LINT_CODES`. State in the description that the codes are an API and that adding one is
    additive while renaming one is breaking.

    Write every document with two-space indentation and a trailing newline, so a future diff is
    readable.
  </action>

| session file → runtime | A session file on disk may have been written by an older or newer build, or hand-edited |
| schema document → consumer | An agent with no repository access acts on these documents alone; a wrong contract silently produces wrong behaviour with no error anywhere |
