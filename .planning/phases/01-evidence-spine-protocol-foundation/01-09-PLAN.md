<objective>
Turn the attempt file and the session JSON from stores into views. After this plan there is one
place a response is written and several places it can be read out, which is what EVID-03 asks for
and what stops the two-writers problem the phase exists to end.

Purpose: D-11 makes `_attempts/*.md` and the session JSON renders generated on demand from the log —
outputs, never inputs. That has a direct consequence D-12 names: the attempt file was where a human
marked a `short` answer by editing a `MARK:` line, and a generated file cannot be an input, so
marking moves to a command that appends a first-class timestamped event. D-12 also fixes the shape:
the command **must accept a batch**, because marking twenty short answers as twenty invocations is a
workflow regression, not a migration.

`.planning/codebase/CONCERNS.md` records that today's attempt file is rewritten in full on every
answer (`surfaces/quiz.py:172`). Rewriting a whole file per response is exactly the anti-pattern the
append-only log replaced; regenerating that same file on demand from the log, once, is the correct
shape for a render.

Output: `render_attempt_md`, `render_session_json`, `itembank render`, `mark_event`, the batch
`itembank mark`, a rewritten `GRADING.md`, and `test_renders_match_log`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| log → render | A render reads events that may be torn, retracted, or written by a newer schema version |
| render → disk | `render --out` writes a file the learner may have open in an editor or a vault |
| mark batch file → writer | An NDJSON batch is arbitrary input naming permanent evidence records |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-22 | Tampering | `cmd_render --out` whole-file write | high | mitigate | Renders write through the tmp-file-then-`os.replace()` pattern from `runtime.py:143-150`, so a half-written render never replaces a good one. `.planning/codebase/CONCERNS.md` lists five non-atomic writers today; no render may join that list. |
| T-1-23 | Repudiation | A mark that mutates the response it marks | medium | mitigate | Marks are separate append-only events; `review_state` is computed at read time from `marks_by_event`. `test_mark_flow` asserts the response event's `score` is unchanged after marking, so a future edit that mutates the response goes red. |
| T-1-24 | Spoofing | A model verdict recorded as accepted evidence | high | mitigate | `mark_event` rejects any `marker` other than `human` in this phase. TEACH-09 makes a model verdict land as pending review, and that belongs to Phase 8; accepting one here would record it as settled. |
| T-1-01 | Denial of Service | Renders over a log with a torn line | medium | mitigate | Renders build on `live_events`, which inherits `iter_raw`'s per-line skip-and-report (D-09). |
| T-1-SC | Tampering | npm/pip/cargo installs | low | accept | This phase installs nothing; `01-RESEARCH.md` § Package Legitimacy Audit records "Not applicable". |
</threat_model>
