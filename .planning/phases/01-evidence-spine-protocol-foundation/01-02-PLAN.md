<objective>
## Phase Goal

**As a** learner sitting a session, **I want to** have every response I give land in one auditable
evidence store, **so that** I can ask how I am doing on an objective months later and get an answer
that survived every edit I made to the bank in between.

This plan is the **tracer**: the thinnest real path through every layer the phase touches. One
response goes in at `itembank submit`, becomes one line in `_evidence/evidence.jsonl` through the
one writer, and comes back out through `itembank evidence --objective`. Nothing on that path is a
prototype — the event carries its full production field set and the reader is the defensive one
from plan 01-01.

Purpose: prove the spine end to end on the phase's first commits, so an architectural dead end
surfaces after one plan rather than after eight. Every later plan in this phase is an expansion
outward from this slice: machine-readable lint codes (01-03), item identity assignment (01-04),
the published schemas (01-05), the validator and the `schema` command (01-06), idempotency and
retraction (01-07), the indexed query (01-08), the renders and batch marking (01-09), the browser
and day surfaces (01-10), and the migration (01-11).

Output: `evidence.py` grows the writer, the builders, the reader and the first query;
`model.py` parses two new additive identity fields; `surfaces/session.py` becomes a caller of the
writer; `surfaces/evidence_cli.py` and the `evidence` command are born; `tests/evidence_roundtrip.py`
runs the whole path.
</objective>

<task type="checkpoint:decision" gate="blocking">
  <name>Task 1: Decide the on-disk response-event contract and the EVID-07 capture policy</name>
  <decision>
    What exactly goes into one response event on disk, and — for the six fields EVID-07 names —
    which are captured with real values in Phase 1 versus recorded as explicitly reserved null.
  </decision>
  <context>
    This is a one-way door. D-07 makes `_evidence/evidence.jsonl` the system of record; migration
    (01-11) writes into this shape and every later phase reads it. Changing a field name or its
    null semantics after evidence exists means rewriting every recorded line.

    Two things are already fixed and are not part of this decision: the envelope
    (`schema_version`, `event_id`, `event_type`, `ts`) and the store location
    (`_evidence/evidence.jsonl` beside the bank). What is genuinely open is the EVID-07 capture
    policy, because RESEARCH.md Common Pitfall 4 found that **none** of response time, confidence
    or error category has any capture point in the codebase today — `surfaces/session.py:46-67`
    takes only `a.answer`, there is no timer, no confidence prompt and no error taxonomy anywhere.
    Adding the fields to the schema without adding the plumbing satisfies the letter of "recorded"
    and defeats the stated reason for the requirement ("because an uncaptured field cannot be
    backfilled").

    The proposed event shape, for reference while choosing:

    envelope — `schema_version` (int), `event_id` (uuid4 hex), `event_type` (`response`), `ts`
    (ISO-8601 UTC, `Z`); identity — `session_id`, `item_id` (the opaque `[ID:]`, `""` when
    unassigned), `item_ref` (the positional `q["id"]`, e.g. `q3`, always present), `item_type`,
    `bank` (basename only, never an absolute path, so the log does not record where the private
    vault lives), `objective`, `subject` (the text before the first colon in `objective`, `""` when
    unnamespaced); the response — `mode`, `attempt_number`, `answer`, `canonical`, `score`;
    EVID-07 — `response_time_ms`, `confidence`, `error_category`, `hint_tier`, `review_state`;
    bookkeeping — `dedupe_key`, `source_ref` (null except for migrated records).
  </context>
  <options>
    <option id="option-a">
      <name>Capture what has a real source; reserve what does not, and say why in the schema</name>
      <pros>
        `response_time_ms` is captured live on both surfaces — the session path from a `served_ts`
        written when `next`/`start` hands the item over to the submit timestamp, the browser path
        from an `elapsed_ms` the page reports on its POST. `confidence` gains a real optional
        `submit --confidence high|medium|low`, null when omitted so nothing is forced on the
        learner. `mode` is captured everywhere (`serve` gains `--mode` so EVID-08 is true on both
        surfaces). `review_state` is computed: `pending` for `short`, `n/a` otherwise, flipped to
        `marked` by a mark event. `error_category` and `hint_tier` are recorded as null with the
        reason written into `response.schema.json`'s field description — no taxonomy and no hint
        ladder exist before Phase 6/8, and a guessed category is worse evidence than an honest null.
        Nothing is silently null; every null has a stated reason.
      </pros>
      <cons>
        Adds real plumbing this phase: `cmd_next` starts writing the session (it is read-only
        today), `submit` gains a flag, the quiz page gains a timer field. Four of six EVID-07
        fields carry values, two do not.
      </cons>
    </option>
    <option id="option-b">
      <name>Reserve all six now; wire every capture point in Phase 6</name>
      <pros>Smallest change to the existing surfaces; no behaviour change to `next`, `submit` or the quiz page in this phase.</pros>
      <cons>
        Exactly the failure RESEARCH.md Pitfall 4 warns about: six fields that exist and are always
        null. EVID-07's stated purpose is that an uncaptured field cannot be backfilled — every
        session sat between now and Phase 6 loses its response times permanently.
      </cons>
    </option>
    <option id="option-c">
      <name>Capture all six now, inventing an error taxonomy and a hint-tier placeholder</name>
      <pros>Every EVID-07 field carries a value from the first event.</pros>
      <cons>
        Invents two contracts this phase has no basis for. The error taxonomy depends on the
        tutoring work in Phases 6 and 8; a category guessed now would be recorded as fact and read
        as fact by Phase 10's trends. `hint_tier: 0` would be indistinguishable from "the ladder
        existed and the learner used none of it", which is a different thing from "no ladder
        existed", and the difference is unrecoverable once written.
      </cons>
    </option>
  </options>
  <resume-signal>Select: option-a, option-b, or option-c (option-a is the plan's recommendation).</resume-signal>
</task>
