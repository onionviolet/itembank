<objective>
Bring the history in. This is phase success criterion 2: running the one-time migration against
existing `_attempts/*.md`, session JSON and `daily_log.md` produces a single evidence store with no
recorded response lost, verified by comparing pre- and post-migration counts.

Purpose: `.planning/research/PITFALLS.md` names the exact way an evidence spine fails — "one
evidence store often ships as the only store *new* writes go to, while history sits unmigrated."
Plans 01-02 through 01-10 built the store new writes go to. Without this plan the tool would have
that failure, precisely and completely.

Two rules shape the design. D-13: the migration is re-runnable and idempotent, with a dry run first
reporting what it would import and the counts it expects — that is what makes the criterion
*verifiable* rather than asserted. D-14: a record keyed by a positional reference that cannot
resolve to an item id is imported as unresolved, never dropped, because a wrong match attaches your
history to the wrong question and nothing ever tells you. RESEARCH.md Common Pitfall 3 extends that
prohibition from stem-similarity matching, where CONTEXT.md wrote it, to positional matching, which
is deterministic and equally wrong when a bank has been reordered since the record was written.

Output: `surfaces/migrate.py`, three synthetic legacy fixtures, the `itembank migrate` command, and
the reconciliation test.
</objective>

  <action>
    Create `surfaces/migrate.py` with a module docstring stating that this is a one-time, re-runnable
    import, that it reads the three legacy stores and never writes to them, and that it reaches the
    log through `evidence.append_event` like every other surface.

    **Deterministic identity.** `source_key(kind, path, ref)` returns a sha256 hex digest of
    `"%s|%s|%s" % (kind, os.path.basename(path), ref)` where `kind` is one of `attempt_md`,
    `session_json` or `daily_log` and `ref` identifies the record within its file — the item heading
    number for an attempt file, the index within `responses` plus the positional `item_id` for a
    session, and `date|lane` for the day log. Use the **basename** rather than the full path so
    moving the legacy files does not change their records' identity. This digest becomes the
    imported event's `dedupe_key`, which is what makes D-13's "a second run imports nothing new"
    fall out of the writer's existing idempotency rather than needing separate bookkeeping. Say that
    in the docstring, and say that a migrated event's dedupe key therefore means "this source
    record" rather than "this response", which is a different question from the live path's.

    **Readers**, each returning a list of plain dicts and each tolerating malformed input by
    recording it rather than raising:
    - `read_attempt_md(path)` — split on `## Item ` headings; extract the item number and type from
      the heading, `[auto: correct]` / `[auto: WRONG]` into a `score` of `True` / `False` / `None`,
      the `**Selected:**` line or the verbatim fenced block into `answer`, the `*Objective: ...*`
      line into `objective`, and a `MARK:` line into a `mark` of `pass`, `fail` or `None`. A section
      it cannot parse is recorded as `{"ref": ..., "unparsed": True}` and counted, never skipped.
    - `read_legacy_session(path)` — `json.load`, then one dict per entry of `responses` carrying its
      index, its positional `item_id`, `objective`, `type`, `answer` and `score`, plus the file's
      `session_id`, `mode` and `bank`.
    - The day log is read by calling `surfaces.day.load_day_log(path)` directly. Do not write a
      second table parser.

    **Scope the inputs.** `scan_legacy(base, legacy_dir=None)` resolves, by default, `_attempts/`
    beside `base` and `daily_log.md` beside `base`. When `--legacy-dir` is given, resolve it with
    `os.path.abspath` and reject it with a named error unless it is inside `os.path.abspath(base)`
    — a migration tool handed an arbitrary path reads files it was never meant to see, and
    `.planning/codebase/CONCERNS.md` already flags the same shape in `resolve_notes()`.

    **Resolution, and the refusal to guess.** For each legacy record, resolve `item_id` only when it
    can be done without inference:
    - Default: no resolution. The event carries `item_id` of `""`, `item_ref` set to the original
      positional reference, and `source_ref` of `{"kind": ..., "path": <basename>, "ref": ...,
      "resolution": "unresolved"}`. Counted as unresolved, imported, never dropped.
    - `--resolve-by-position BANK.md`: an explicit, separately-passed opt-in. Load the bank, map
      each positional reference to that item's `[ID:]`, and record
      `"resolution": "position"` in `source_ref` on every event it resolves — so how each event was
      attributed is in the record itself rather than in the operator's memory. A reference with no
      matching item stays unresolved even under this flag. Its help text states plainly that
      position-based attribution is only correct if the bank has not been reordered since the record
      was written, and that a wrong match attaches history to the wrong question with nothing to
      tell you.
    - There is no stem-similarity path and none is to be added.

    **Subject namespacing.** `--subject <name>` prefixes `"<name>:"` onto any imported objective that
    carries no colon, satisfying D-06 for legacy records. Without the flag, objectives import as
    written and the `item.objective_unnamespaced` lint warning is what surfaces them later.

    **Events.** A session or attempt response becomes a `response_event` with `mode` taken from the
    session where known and `"legacy"` where not, `attempt_number` of 1, `response_time_ms`,
    `confidence`, `error_category` and `hint_tier` all `None` — a legacy record has no such data and
    inventing one would be worse evidence than a null — and `review_state` computed as it is on the
    live path. A `MARK: (pass)` or `(fail)` becomes an additional `mark_event` referencing the
    response event just written, with `marker` of `"human"`, since a human did the marking. A day-log
    tick becomes a `day_tick_event`.

    **Reconciliation.** Accumulate `found` as a dict of `attempt_md`, `session_json` and `daily_log`
    counts, and `written` as a dict of `resolved`, `unresolved`, `marks`, `ticks` and
    `already_present`. Print both in the house `"%d ..., %d ..., %d ..."` style, on the pattern
    `01-RESEARCH.md` § Code Examples gives. Then assert that the total found equals the total
    accounted for; on a mismatch, print every unaccounted record's reference and exit non-zero.
    Reporting a clean migration while a record went missing is the one outcome this command must
    never produce.

    **`cmd_migrate(a)`.** A **dry run by default**: it scans, resolves, computes every event and its
    dedupe key, checks each against the existing log, and prints the full reconciliation without
    appending anything. `--write` is what makes it import. Emit one
    `json.dumps({"schema_version": 1, "dry_run": bool, "found": {...}, "written": {...},
    "unresolved_refs": [...]}, ensure_ascii=False, indent=2)` alongside the human status lines, so
    the pre/post comparison the phase's success criterion asks for is a diff of two JSON objects
    rather than a reading of prose.

    **In `surfaces/cli.py`,** import `cmd_migrate` and add a `migrate` subparser: `--base` defaulting
    to `"."`, `--legacy-dir`, `--bank`, `--subject`, `--resolve-by-position`, `--write`
    (`action="store_true"`), and `set_defaults(fn=cmd_migrate)`. Help text says the command is a dry
    run unless `--write` is given.

    Export `source_key`, `read_attempt_md`, `read_legacy_session` and `scan_legacy` from
    `itembank.py`.
