<objective>
Make an item's identity outlive its text. This is phase success criterion 1: a learner edits a
stem after the item has been linted once, and a query for that item's evidence history still
resolves to the same trail.

Purpose: `.planning/research/PITFALLS.md` Pitfall 1 documents content-hash-as-the-ID as the
accepted, author-acknowledged trade-off of the closest prior-art system — it loses learning history
on every edit. This project's own material makes that failure near-certain: 25 of 45 EMT wrong
options are due for editing this milestone. D-01 and D-02 answer it with an opaque ID that lives in
the bank markdown and a content hash stored *beside* it, used only for change detection and never
as the key.

D-03 keeps `lint` read-only: it reports what is missing or drifted, and a separate explicit
`id-assign` action writes. That way every identity change lands in `git diff` before it is
committed, rather than happening as a side effect of validating.

Output: `model.content_fingerprint()`, `model.new_item_id()`, `model.assign_ids()`, four new lint
checks with dotted codes, the `itembank id-assign` command with `--dry-run`, and the
`test_identity_survives_edit` test that proves the whole point of the phase.
</objective>

      position; insert missing lines together, immediately **before** the first line in the chunk

      `MODEL:`, `RUBRIC:` or `WHY BEST:`. If no terminator line exists, append them at the end of
      the chunk. Inserting before the first terminator is what keeps a multi-line stem intact.
