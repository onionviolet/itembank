<objective>
Turn `lint` from a producer of human sentences into a producer of a machine contract, without
changing a single character of what a human sees.

Purpose: PROTO-02 requires a stable error code and the field at fault alongside the human text, so
an authoring agent can act on `item.missing_key` without a lookup table (D-16). This lands before
item identity (plan 01-04) deliberately: identity adds four new lint checks, and authoring them
against the string shape only to convert them one plan later is waste.

The hazard this plan exists to defuse is named in RESEARCH.md Common Pitfall 2: `lint()`'s entries
are concatenated with `+` at three call sites, and changing the return type without moving all
three in the same commit raises `TypeError: can only concatenate str` the moment any bank fails to
lint — breaking `lint`, `build` and `serve` simultaneously, and turning CI's "Broken fixture is
caught" step into a traceback.

Output: a `LintError` namedtuple whose `__str__` reproduces today's text exactly, a dotted code on
every entry, `itembank lint --json`, three updated call sites, and `tests/protocol_roundtrip.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bank markdown → linter | Every field `lint()` inspects comes from a file an authoring agent or the learner wrote; it may be malformed, empty, or contain any Unicode |
| linter → agent | `lint --json` is the machine contract an authoring agent branches on; a wrong or unstable code silently changes what the agent does |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-07 | Denial of Service | `model.lint` on hostile or malformed field content | medium | mitigate | ASVS V5. `lint()` already reads only what `parse_question` produced, and `parse_question` returns `None` for an unparseable block rather than raising. This plan adds no new parsing; the `--json` path serializes with `json.dumps(..., ensure_ascii=False)`, which cannot fail on any `str`. Covered by `test_lint_json_encoding`. |
| T-1-08 | Spoofing | Unstable or undeclared lint codes | medium | mitigate | Every emitted code must be a member of the published `LINT_CODES` tuple; `test_lint_codes_declared` fails on a code that is not declared, so a typo cannot become a de-facto API. |
| T-1-05 | Tampering | `hashlib` usage in this phase | low | accept | Not exercised by this plan; carried in the register for continuity. sha256 here is change detection, not a security boundary. |
| T-1-SC | Tampering | npm/pip/cargo installs | low | accept | This phase installs nothing; `01-RESEARCH.md` § Package Legitimacy Audit records "Not applicable". |
