# Phase 999.4: Canvas LMS Integration via LTI — UI Design Contract

**Specified:** 2026-08-11
**Scope:** Two surfaces, both reached through a verified LTI 1.3 launch inside a
Canvas iframe: (1) the **instructor deep-link selection** — pick an objective
from the local bank registry, one item at a time; (2) the **embedded learner
player** — the existing served quiz page behind a resource-link launch, which is
the phase's whole reason to exist (D-03). The UI must state what leaves the
machine (D-09) and must never offer or imply a score before the runtime grants
one (Directive §4.1).

## 1. Design System

INHERITED unchanged from `.planning/UI-SPEC.md` section 7 and Phase 4:
`surfaces/theme.py` is the one palette, `surfaces/presentation.py` SHARED_CSS
the one token layer, the 8-point spacing scale, the five type sizes
(14/16/20/28 plus the locked `text-lesson`), the 400/600 weight pair, the 44px
interactive target, the 2px focus ring, the 150ms motion cap, and the nine
accessibility gates (UI-SPEC section 8). This phase adds **no** new size, token,
palette entry, or component library.

One addition, inherited from LTI rather than invented: the page must render
inside the LMS's iframe. The tool's responses carry
`Content-Security-Policy: frame-ancestors <lms-origin>` derived from the
registration's issuer, so Canvas may frame the tool and no other origin may.

## 2. The embedded learner player

The learner sees the **existing served quiz page** (`surfaces/quiz.py` serve
path) rendered inside the Canvas assignment iframe, launched with the objective
the instructor selected at deep-link time (D-07).

- **The item is the item.** Stem, options, response schema, and the post-answer
  feedback granted by the runtime — the same projection `itembank serve` gives.
  No new controls, no LTI chrome, no score badge. The player is the quiz, not a
  quiz inside a wrapper.
- **Session framing (Ledger):** one line above the first item:
  `This is a Canvas assignment. Answers are scored by the local runtime and the
  final score is sent to this course's gradebook when the assignment is
  complete.` — the D-09 privacy statement, verbatim, plus the D-04 completion
  boundary.
- **Nothing before a recorded response.** No key, why-best, distractor analysis,
  or higher-tier content is reachable, inspectable, or returned before the
  learner has answered that item (D-03; the payload equals `runtime.public_item()`
  — a browser that inspects the page finds the same public payload as the quiz
  surface).
- **Completion state (Ledger):** when the runtime reports the session ended,
  the player renders `Assignment complete. Your score has been sent to the
  gradebook.` only if AGS passback actually succeeded; on passback refusal or
  with pending prose it renders the exact refusal line from section 4. The
  learner is never shown a raw number the runtime did not compute.

### 2.1 Degraded behavior

- **Unverified launch:** the LTI handler refuses with the exact line
  `This launch could not be verified. Close this window and relaunch the
  assignment from Canvas.` — no page, no redirect, no hint at why beyond the
  named failure class (D-06 named refusals).
- **Unregistered platform / unknown client:** `This Canvas site is not
  registered with this itembank installation.` (D-06).
- **Missing objective in a resource-link launch:** `No objective was selected
  for this assignment. Ask your instructor to re-link it.` (D-07).
- **Crypto dependency absent:** `The LTI surface needs its cryptography
  dependency. Run "itembank lti doctor" for the install command.` — the
  degrade-never-block line for the rest of the tool (D-08).
- **Passback unreachable:** the learner's session and score still complete
  locally; the completion line becomes `Assignment complete. Your score could
  not be sent to the gradebook this time.` and the named reason is logged
  locally (never blocks, never lies).

## 3. The instructor deep-link selection

Reached when a verified launch arrives with `message_type=LtiDeepLinkingRequest`
(the tool opened from the assignment editor / course link placement).

- **Purpose line (Ledger):** `Choose the itembank objective this assignment
  will run.` No chat affordance, no search box, no score preview — selection is
  one deliberate choice (the 03.2 anti-chat rule carries).
- **The objective list (Ledger):** one row per objective in the local bank
  registry (Phase 3.2 `[OBJ:]` ids with their titles; banks with no objectives
  are refused by name with `This bank has no objectives.`). Each row is a 44px
  target.
- **Selection:** one objective per assignment (single-select, D-07); after
  selection the surface shows `Objective "{title}" selected.` and the single
  confirm control, `Link this assignment`.
- **Cancel:** `Cancel` returns an empty `LtiDeepLinkingResponse` (no content
  items) to Canvas, which shows its own "no tool content" state — the tool
  never leaves the instructor on a dead end.
- **Nothing sensitive renders here.** The picker lists objective ids and
  titles only — no item stems, no keys, no counts of correct answers (a picker
  that revealed item text would leak the bank to every course member with
  editing rights).

### 3.1 Degraded behavior

- **Empty registry:** `No itembank banks are registered. Add a bank to this
  installation first.` and only `Cancel` is available.
- **Deep-link return unreachable:** the selection cannot be returned; the
  surface shows `Could not return the selection to Canvas.` and offers `Retry`
  and `Cancel`.

## 4. Copywriting Contract

Every string below is new to this phase and must be reproduced verbatim by the
renderer, the LTI handler's refusal paths, and any test that greps for it:

| Completion, passback OK | `Assignment complete. Your score has been sent to the gradebook.` | Ledger |
| Completion, passback refused | `Assignment complete. Your score could not be sent to the gradebook this time.` | Ledger |
| Unverified launch | `This launch could not be verified. Close this window and relaunch the assignment from Canvas.` | Ledger |
| Unregistered platform | `This Canvas site is not registered with this itembank installation.` | Ledger |
| Missing objective | `No objective was selected for this assignment. Ask your instructor to re-link it.` | Ledger |
| Crypto dependency absent | `The LTI surface needs its cryptography dependency. Run "itembank lti doctor" for the install command.` | Ledger |
| Picker purpose | `Choose the itembank objective this assignment will run.` | Ledger |
| Bank with no objectives | `This bank has no objectives.` | Ledger |
| Selection confirmed | `Objective "{title}" selected.` | Ledger |
| Link control | `Link this assignment` | Chrome |
| Cancel control | `Cancel` | Chrome |

Copy rules that bind: no score, percentage, bar, streak, or target anywhere in
either surface (C17); no chat affordance; every refusal names the condition or
the command that fixes it; the privacy statement (D-09) appears on the learner
surface, in `itembank lti` help text, and in the reverse-proxy hosting doc —
never only in planning documents.

## 5. UI Considerations

| Category | Element | Status | Resolution |
|---|---|---|---|
| empty | no banks registered | covered | Picker renders the empty-registry line; only `Cancel` is live |
| error | unverified launch | covered | Exact refusal line; no page, no redirect, no partial render |
| error | missing objective | covered | Exact refusal line (D-07) |
| partial | passback refused | covered | Local completion still renders; exact refusal line; reason logged locally |
| loading | launch verification in flight | covered | The player renders only after verification; no spinner-forever |
| zero-one-many | one objective per assignment | covered | Single-select; confirmed row before `Link this assignment` |
| long-text | a 5000-word stem in the iframe | backstop | The existing quiz overflow discipline; no horizontal prose scroll |
| frame | the page inside the LMS iframe | covered | `frame-ancestors` from the registration issuer; no other origin may frame |

## 6. Required verification gates for this phase

1. **public_item fixture:** the embedded player's payload is byte-equal to
   `runtime.public_item()` and contains no key/why/distractor/tier field before
   a recorded response (D-03).
2. **Refusal fixtures:** unverified launch, unregistered issuer, unknown
   client_id, missing objective, and absent crypto dependency each render their
   verbatim section-4 line; none renders a page or a score.
3. **Privacy-copy fixture:** the learner surface renders the section-4 privacy
   line verbatim, and `itembank lti --help` contains the same statement (D-09).
4. **Deep-link fixture:** selection of one objective returns exactly one
   `ltiResourceLink` content item carrying the objective custom param; `Cancel`
   returns an empty content_items list; nothing sensitive (no stems, no keys)
   is present in the picker's DOM.
5. **Frame fixture:** the player's response header is
   `Content-Security-Policy: frame-ancestors <lms-origin>` for the registered
   issuer and refuses other origins.
6. **Copy fixture:** every string in section 4 renders in the voice section 1
   assigns, asserted by computed font-family token, never a literal family.

## 7. LOCKED / DEFAULT / OPEN

**LOCKED:** the learner player is the existing quiz page (no new item
projection), public_item-only before a recorded response, the D-09 privacy line
on the learner surface and in help, one-objective-per-assignment deep-link
selection with no sensitive content in the picker, verbatim refusal lines,
`frame-ancestors` from the registration, and passback-refusal-never-blocks.
**DEFAULT:** none in this spec beyond the locked rows.
**OPEN:** the exact objective-row layout in the picker is this phase's
renderer's; item-projection details are the quiz surface's and are consumed
unchanged.

## Registry Safety

This phase vendors no asset and adds no package to the runtime; `cryptography`
and `PyJWT` are optional, pinned, checksummed, license-reviewed dependencies per
Directive 4a (see 999.4-RESEARCH.md section 5), not vendored assets.
