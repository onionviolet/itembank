<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| platform (Canvas) -> tool launch | The id_token is the only claim of authenticity; JWKS verification is the gate |
| tool -> platform redirect | The authorize redirect must carry the minted nonce/state so the launch cannot be replayed or forged |
| LTI handler -> daemon handlers | The in-process wrap must never introduce a second scoring or parsing path |
| settings -> registration | An unregistered issuer/client_id must never reach a handler |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-994-01 | Spoofing | forged launch JWT | high | mitigate | JWKS RS256 verify + iss/aud/nonce/exp/deployment checks; named refusal on first failure (Task 2) |
| T-994-02 | Spoofing | replayed launch (nonce reuse) | high | mitigate | one-time, short-TTL nonce store (D-02) |
| T-994-03 | Spoofing | unregistered platform | high | mitigate | registry lookup by issuer/client_id/deployment; named refusal (D-06) |
| T-994-04 | Tampering | objective/deployment values | high | mitigate | values resolved through the existing stem allowlist, never as paths (D-07, carried from daemon T-2-02 discipline) |
| T-994-05 | Information disclosure | key/why reached via the launch handler | high | mitigate | launch handler calls only the daemon handlers; the learner page is plan 02's public_item-only projection (D-03) |
| T-994-06 | Denial of service | unbounded JWKS fetch / nonce store | medium | mitigate | bounded JWKS cache with TTL; nonce store capped and expired (Task 2) |
| T-994-SC | Tampering | cryptography / PyJWT supply chain | high | mitigate | optional, pinned, checksummed, license-reviewed per Directive 4a; the pin record lands in this plan's commit (D-08) |
