explicitly hosted, authenticated LTI 1.3 surface — an adapter to the same

## Phase findings (carried forward)

1. **Complete + pending is unreachable through the learner flow in this
   build.** A `short` item's submit transitions to `defer_feedback` without
   advancing the cursor (score None is pending, never wrong), and the
   marker's mark event does not yet advance the cursor either. So a session
   whose report shows `pending_manual > 0` cannot reach status `complete`
   through the learner path. The passback's PendingManual branch is
   spec-correct (AGS's own "a human must confirm" vocabulary) and is tested
   against the marker-closed state (the runtime's own `_advance_cursor`
   arithmetic applied via `runtime.write_session`). A future close-session
   feature makes the branch reachable end-to-end; until then the branch is
   defensive and honest. Recorded in 999.4-03-SUMMARY.md.
2. **CVE disposition on the pinned optional deps.** The verified versions
   (cryptography 43.0.0, PyJWT 2.10.1) carry published advisories, all in
   code paths this implementation never calls (PyJWT decode — JOSE is
   hand-rolled over cryptography's RSA primitives; cryptography x509
   verification — only the test's TLS cert builder uses x509). The pin
   record documents the upgrade path (PyJWT>=2.13.0, cryptography>=49.0.0).
3. **Transient daemon-roundtrip flake.** `tests/daemon_roundtrip.py` showed
   two transient failures under socket churn from the LTI harness servers
   (fixed-port probing colliding with TIME_WAIT); 3/3, 2/2 re-runs green —
   pre-existing test-isolation sensitivity, not a regression.
