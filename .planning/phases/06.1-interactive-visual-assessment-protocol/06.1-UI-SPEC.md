# Phase 06.1 — UI Design Contract: Interactive Visual Assessment Protocol

> This is a protocol-first contract. It locks the visible and accessible behavior required of any future renderer; it does **not** authorize a learner renderer before the Phase 4 presentation host and the protocol tests exist.

## Authority and Decision Legend

| Label | Meaning and source |
|---|---|
| **LOCKED** | Binding requirement, ROADMAP success criterion, shared `.planning/UI-SPEC.md`, or Phase 6 policy. A plan may not weaken it. |
| **UPSTREAM-CONTRACT** | Implementable only as a published schema/runtime/evidence seam; consumers must not guess fields. |
| **UI-BLOCKED** | Learner-facing rendering/interaction must not ship until named UI/a11y evidence exists. |
| **UI-INDEPENDENT** | Parser, schema, deterministic scorer, evidence, CLI parity, or GIFT refusal work may proceed without a browser surface. |
| **ASSUMED** | A safe rendering detail from 06.1 research; prove or replace it in a fixture before promotion. |
| **OPEN** | A real choice not answered by authority. Implement only a seam/prototype, never a learner-visible behavior. |

**Authority order:** REQUIREMENTS/ROADMAP and Phase 6 decisions → shared UI-SPEC → this phase spec → research recommendations. Phase 6.1 has no `CONTEXT.md`; this document does not fabricate user choices.

## Goal and Plan-Gating Matrix

**Goal:** A plot/number-line assessment exposes only a public declarative scene and the same semantic learner action through pointer, keyboard, touch, and assistive technology. The runtime alone normalizes/scorers, selects feedback entitlement, and appends evidence.

| Plan / work | Classification | Required gate and completion evidence |
|---|---|---|

| 06.1-02 author lint/schema, semantic actions, `/api/interact`, CLI parity | **UPSTREAM-CONTRACT / UI-INDEPENDENT** | Closed action vocabulary, server-side identity/tier resolution, dedupe and no-telemetry tests. |
| 06.1-03 SVG/HTML renderer and feedback display | **UI-BLOCKED** | Phase 4 presentation primitives exist; 320px/200%/keyboard/touch/SR/no-leak/reduced-motion tests pass. |
| Static-file/offline visual rendering | **UI-BLOCKED** | Must be an honest served-runtime-required refusal, never a client scorer or key-bearing fallback. |
| Future canvas/dense simulation | **OPEN / UI-BLOCKED** | Separate design review proves an equal semantic HTML control/state path; canvas is not part of this slice. |
| GIFT export | **UI-INDEPENDENT** | Both default and strict exports refuse every visual item with `gift.type_unsupported`; no lossy approximation. |

## Information Architecture

1. **ContextLine**: bank/lesson, objective, item progress, feedback mode only.
2. **ActivityCanvas**: prompt, mandatory prediction/action instruction, visual scene, equivalent semantic controls, action status, then final response control.
3. **Feedback/status**: one reserved `role=status` region directly after controls; it contains only runtime-issued observation/allowed feedback.
4. **Help and evidence**: in-flow after the activity; shown hint tiers, source/feedback label, and an evidence disclosure. It is never an answer-bearing side channel.

The public payload contains only `type`, protocol version, interaction, scene, initial state, semantic actions, response grammar, and accessibility text. It never contains accepted state, tolerance, key, misconception mapping, reveal content, solution path, hidden region, verdict, or future hint tier.

## Annotated Wireframes

### Desktop (≥1024px)

```text
┌ Context: lesson · objective · 3/8 · practice · [Details] ────────────────┐
├──────────────── ActivityCanvas (2/3) ─────────────────┬ Help (1/3) ──────┤
│ H1 Prompt / [Predict first: place the point]           │ shown hints only │
│ [SVG plot or number line: named geometry + focus]      │ evidence details │
│ [x stepper] [y stepper] / [interval controls] [Commit] │ no chat/default  │
│ State: (2, 3). Committed.                               │                 │
│ [Check response]                                        │                 │
│ status / runtime observation (reserved height)          │                 │
└────────────────────────────────────────────────────────┴─────────────────┘
```

SVG is enhancement, not the only path. The native control group is present and operable even when SVG succeeds. DOM order is activity → controls → status → support.

### Tablet (768–1023px)

```text
┌ ContextLine ─────────────────────────────────────────────────────────────┐
│ prompt → SVG scene → semantic controls → Commit → Check response → status │
│ <details><summary>Help and evidence</summary>shown tiers / evidence</...> │
└───────────────────────────────────────────────────────────────────────────┘
```

Support is in-flow after response controls; it may not overlay, reorder, or steal focus from the task.

### Narrow (320–767px and 200% zoom)

```text
Prompt and prediction instruction
[scene frame: local pan/scale only if needed; no page horizontal scroll]
Coordinate / tick / interval controls (full-width, 44px targets)
[Commit action]  [Check response]
State and feedback status
[Help and evidence disclosure]
```

Scene-local horizontal pan is allowed only inside a labeled container; instructions, controls, primary action, and status remain visible in normal document order.

## Interaction Contract and State Machines

### Semantic visual action lifecycle

```text
READY → TENTATIVE (pointer/key/stepper change; no evidence)
TENTATIVE → COMMIT_REQUESTED (explicit Commit, Enter/Space, or changed pointer-up)
COMMIT_REQUESTED → INTERACTING → COMMITTED | REJECTED | ALREADY_RECORDED
TENTATIVE → CANCELLED (Escape / pointercancel / pointerleave) → READY
COMMITTED → FINAL_SUBMITTING → runtime verdict → feedback-policy state
```

Only protocol v1 `place_point`, `move_point`, `select_numberline_point`, and `set_interval` may be committed. Pointer-down/move, hover, focus, viewport pan/zoom, unchanged values, tentative/cancelled changes, raw CSS/SVG coordinates, screenshot, and drag frequency produce no event. Final submission remains the ordinary response event.

### Assessment/feedback lifecycle

```text
PRE-ANSWER → ACTION_COMMITTED* → SUBMITTING
SUBMITTING → correct: COMPLETE | wrong/practice: HELD | diagnostic: DEFERRED
HELD → legal authored/generated feedback → RETRY → SUBMITTING
UNAVAILABLE/DROP → authored tier if available | honest unavailable notice
```

`*` a visual action is useful evidence, never a verdict. Prediction/action occurs before explanation. Phase 6 alone decides genuine attempts, tier, held/advance/reveal/defer behavior; model output cannot request or advance it.

| Major interaction | User goal / visible state | Action → response | Evidence, model, deterministic enforcement | Failure/recovery and accessibility | Acceptance |
|---|---|---|---|---|---|
| Make a prediction | State a coordinate/point/interval before explanation; scene and controls are ready | Adjust via SVG, stepper, tick list, keyboard; explicit commit | Canonical scalar/domain state only; runtime validates grammar and derives observation. No model verdict. | Escape/cancel restores last committed state; arrows step declared units; Enter/Space commits; named SVG plus controls. | Matching pointer, touch, keyboard, and controls serialize byte-identical semantic state. |
| Submit response | Receive a deterministic result | **Check response** posts ordinary response after committed state | `runtime.score_response()` alone normalizes and scores; browser has no key/tolerance. | In-flight disables only submit and announces once; daemon failure preserves state and offers retry. | Zoom/DPR/renderer rounding cannot change border verdict. |
| Request legal help | Continue without premature answer | Open only shown tier / use Phase 6 stumped action | Runtime selects feedback anchor/tier. A later model may phrase bounded content only after gate pass. | Drop/unavailable shows authored tier or exact unavailable copy; hidden tiers absent from DOM/ARIA. | No unshown tier/key/reveal in HTML, JSON, CSS-off content, SVG labels, or live region. |
| Inspect evidence | Understand a committed move without a hidden solution | Open details after action | Append-only action includes version, action ID/type, before/after semantic state, invariant/error category, opaque anchor, tier and dedupe key; no pointer telemetry/private envelope. | Duplicate returns `already_recorded`; conflict/reject explains action can be adjusted then recommitted. | Browser/API/CLI obtain the same safe observation and exactly one live event. |

## Components, Responsive, and Accessibility

| Component | Required behavior |
|---|---|
| `VisualInteraction` | Public declarative renderer; uses one semantic reducer/serializer/commit function for every modality. |
| `SvgScene` | Inline SVG only for plot/numberline; accessible name and description, visible 2px/2px-offset focus; never carries key-bearing `title`, `desc`, data attribute, or hidden text. |
| `SemanticControls` | Native labeled inputs/steppers/tick or interval lists reproduce every supported state; are not hidden when SVG works. |
| `ActionStatus` | One persistent polite live region announces committed state, validation, and runtime observation once; use `role=alert` only for action-blocking failure. |
| `FeedbackPanel` | Reserved space; runtime payload only; no model/provider/native renderer data is interpolated directly. |
| `OfflineRefusal` | Replaces non-answerable static visual interaction; has no scorer/private scene fields and provides next step. |

- Tab order follows prompt → SVG/semantic controls → Commit → Check response → status → help. Focus remains on the committing control until status is announced; final submit keeps focus on submit/status.
- Arrow keys adjust focused declared units; Escape cancels a tentative move; no drag is required. Pointer capture/cancel must restore the committed state.
- All labels, errors, selection, correct/incorrect, unavailable, and pending states use text plus structure, never color alone.
- Test desktop 1280px, tablet 768px, narrow 375/320px, and 200% zoom. No page-level horizontal scroll or clipped primary action.
- `prefers-reduced-motion` disables animated markers, panning transitions, and feedback animation. It does not remove state indication.

## Assessment Integrity and Authority Boundaries

| Actor | May | Must not |
|---|---|---|
| Browser/SVG/HTML | Render public scene, form semantic state, request commit/submit, display safe result | Score, compare answer, own tier, send identity/key/tolerance/verdict/observation, or retain answer-bearing fallback. |
| Runtime | Resolve session/item/tier, validate canonical action, score, build bounded observation and feedback intent | Accept browser authority fields or let a renderer change result semantics. |
| Evidence store | Append/retract/retrieve concise committed actions and final responses | Store raw pointer stream, pixels, private scoring/reveal path, or infer correctness anew. |
| Model (future Phase 8) | Phrase a runtime-entitled opaque-anchor plan after gate pass | Score, advance tier, expose key/higher tier, write accepted evidence, or receive raw pointer telemetry. |

Static/offline is an **unavailable**, not an approximation: `This visual item needs a served itembank session because scoring and answer protection happen there. Open it with itembank serve or the daemon.` GIFT copy is exporter-owned and must name the refused item/code without embedding scene/private sentinels.

## Copywriting Contract

| Element | Exact copy |
|---|---|
| Prediction instruction | `Make a prediction, then commit your move before checking it.` |
| Commit | `Commit move` |
| Final CTA | `Check response` |
| Committed status | `Move committed. You can adjust it or check your response.` |
| Empty/invalid authored scene | `This visual activity is not available because its scene could not be loaded. Choose another item or ask the bank author to fix it.` |
| Interaction error | `That move could not be recorded. Your last committed state is still here. Adjust it and try again.` |
| Offline/static refusal | `This visual item needs a served itembank session because scoring and answer protection happen there. Open it with itembank serve or the daemon.` |
| Model/policy unavailable | Reuse shared copy: `Generated help is unavailable. You can keep learning with the lesson and authored hints.` |
| Destructive action | None. Commit/submit append evidence but do not overwrite a learner record. |

## UI Considerations

| Category | Element | Status | Resolution / verification |
|---|---|---|---|
| empty/error | Scene and semantic controls | ✅ covered | Invalid/no scene renders documented unavailable copy, not blank geometry or client fallback. |
| loading | Commit/final submit | ✅ covered | Only active control disables; persistent status names operation and retains committed state. |
| populated/partial | Plot/numberline state | ✅ covered | SVG and native controls show one canonical committed state; tentative state is visually distinct and not evidence. |
| overflow/long-text | Prompt, labels, accessibility text | 🧪 backstop | Long text wraps; scene can locally pan; automated 320px/200% screenshot/DOM test. |
| zero-one-many | Tick/point/interval choices | ✅ covered | Zero valid choices is unavailable; one/many retain labels and identical commit semantics. |
