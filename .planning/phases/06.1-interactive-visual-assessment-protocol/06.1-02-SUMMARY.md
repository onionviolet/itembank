## What this plan set out to do

Publish the visual authoring contract and make semantic learner
actions/observations durable and agent-queryable through one CLI/API/runtime
path: a complete lint/schema/golden authoring contract (Task 1), a versioned
append-only `visual_action` evidence event plus a tutor-facing reader
(Task 2), and one `do_interact` body reachable identically from the CLI and
`POST /api/interact` (Task 3).

## Locked contract fixtures (06.1-VALIDATION.md) — all green

- Request keys exactly `session_id`, `interaction_version`, `action_id`,
  `action_type`, `state`; `action_id` matches the locked lowercase UUID-v4
  regex (pinned in the schema and enforced in `do_interact`).
- Action enum exactly `place_point`, `move_point`,
  `select_numberline_point`, `set_interval`.
- Event keys: the common audit fields plus `interaction_version`, `action_id`,
  `action_type`, `before_state`, `after_state`, `error_category`,
  `invariants`, `feedback_anchor`, `hint_tier`, `dedupe_key` — asserted as an
  exact key set in the test.
- Append boundary: only explicit successful state-changing commits; final
  submit remains the ordinary response event (the test drives submit after an
  interact and verifies the response event reconciles to the final committed
  state).
- Retry behavior: identical action id/action/state returns
  `already_recorded`; same id with changed action/state is a `conflict`;
  distinct commits append in order with the prior committed state as
  `before_state`.
- No raw pointer events, CSS/SVG coordinates, screenshots, private accepted
  states/tolerance, client verdict, client hint tier, or authored reveal text
  anywhere in the event or observation (test scans the serialized event for
  banned material).

## Architecture decisions honored

- **One grammar:** model lint reuses `runtime.canonical_scalar` /
  `canonical_axis` / `_visual_interaction_contract` / `_reject_visual_exec`
  through a function-local import — the same pattern runtime.py uses for
  `import model` — so lint and the scorer can never drift apart.
- **One runtime observation:** the evidence layer stores exactly the
  already-authoritative Plan-01 observation fields; it never recomputes
  correctness, tolerance, invariant categories, or tier entitlement (D-06).
- **Server-side authority (T-06.1-06):** `do_interact` resolves the session,
  current item, before-state, and Phase-6 hint entitlement; a client cannot
  choose an item, a path, a score, a key, a tolerance, a tier, an observation,
  or an evidence field — unknown fields are refused by name at both the CLI
  and the HTTP boundary.
- **Dedupe identity** `(session_id, item identity, interaction_version,
  action_id)` flows through the existing append-only writer
  (`append_event`/`append_line_checked`), so replay/conflict semantics ride
  the one evidence path rather than a second store.
- **Append-only + retraction-aware:** `visual_actions` reads through
  `live_events`, so a retracted action disappears exactly as it disappears
  from a report.
