# 06.1-03 — SUMMARY

**Phase:** 06.1-interactive-visual-assessment-protocol · **Plan:** 03
**Date:** 2026-08-11 · **Status:** complete · **Wave:** 3

## What this plan set out to do

Finish the initial visual protocol with accessible modality equivalence and
truthful interoperability behavior: every input modality (mouse, tap,
keyboard, adjacent native controls) commits the same semantic move through one
reducer and one serializer (Task 1), and GIFT refuses plot/number-line items
loudly by item number with `gift.type_unsupported` in default and strict modes
(Task 2).

## Requirements and UI-SPEC gates (D-07/D-08)

- **Modality equivalence (VIS-03):** pointer, keyboard, and native selects all
  mutate one `tentative` state and serialize through one function; equivalent
  states produce byte-identical canonical SCALAR action requests.
- **Commit boundary (D-04/D-05):** only native commit/Enter/Space, tap, or
  pointer-up after a changed drag posts one of the four protocol actions
  (`place_point` first point, `move_point` thereafter, `select_numberline_point`,
  `set_interval`); pointer-down/move, focus, hover, tentative/cancelled, and
  unchanged commits append nothing ("No change to commit."). Final submit stays
  the ordinary response event via "Check response".
- **No canvas (VIS-05):** the plot/number-line slice is inline SVG + semantic
  HTML controls; the automated test greps both clients for `<canvas`.
- **Accessibility (VIS-07):** SVG has `role="img"` + `aria-label`, a
  `tabindex="0"` focus surface, a polite `role="status"` live region, 44px+
  controls via the existing shared 44px target, arrows step declared units,
  Escape cancels, and the offline state uses the UI-SPEC's exact copy
  ("This visual item needs a served itembank session…").
- **Static refusal (D-03/A-05, T-06.1-11):** `page_item(offline=True)` returns
  `served_required` with no key; the static build page renders `asVisualOffline`
  and carries no private scene/scoring material.
- **GIFT loud refusal (VIS-09, D-09):** both modes refuse every visual item by
  original item number with the stable `gift.type_unsupported` code, before any
  renderer, with the expressible half of a mixed bank exported intact.
