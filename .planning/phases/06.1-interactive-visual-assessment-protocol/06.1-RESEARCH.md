## Summary

The first visual-item implementation should be a protocol vertical slice, not a gallery of canvases: author one declarative `plot`/`numberline` item, serve only its public scene and response grammar, submit a semantic response, score it exclusively in `runtime.score_response()`, append an evidence event, and return a bounded feedback intent. The same intent is what a later agent adapter may phrase, but it must never let the browser or model determine correctness or reach past the permitted hint tier. [VERIFIED: runtime.py:1-10; VERIFIED: runtime.py:120-130; VERIFIED: evidence.py:355-360]

Use HTML for controls, instructions, status, and the non-pointer equivalent; use inline SVG for the first coordinate/number-line scene because it preserves scalable, inspectable geometry; reserve `<canvas>` for genuinely dense or animated simulations and require an equal semantic HTML control/state view. Canvas fallback content is shown when canvas support or scripting is unavailable, and W3C’s graphics guidance requires interactive graphics to be tested for device-independent access and accessibility-API exposure. [CITED: https://html.spec.whatwg.org/multipage/canvas.html] [CITED: https://www.w3.org/TR/graphics-aria-1.0/]

**Primary recommendation:** Define one versioned `visual` item protocol now, prove it with a shared plot/number-line slice, and make every future renderer an adapter from declarative public configuration to the same semantic response/feedback/evidence contracts.

### Pattern 1: Declarative visual item with a private scoring envelope

**What:** Add a single visual family with an interaction discriminator and JSON values that are parsed/validated by the model layer. The public projection contains only the scene, initial state, response grammar, labels, and permitted semantic actions. The runtime alone retains accepted states, tolerance, misconception classifiers, and feedback anchors. [ASSUMED]

**When to use:** Every plot, numberline, hotspot, diagram, timeline, trace, or simulation. Never let a bank file carry executable JavaScript or allow a renderer to infer the key. [ASSUMED]

**Recommended authoring grammar (proposal):**

```markdown
[TYPE: visual]
[INTERACTION: plot]
[VISUAL: {"version":1,"axes":{"x":{"min":-5,"max":5,"step":1},"y":{"min":-5,"max":5,"step":1}},"initial":{"points":[]},"actions":["place_point","move_point","submit"]}]
[SCORING: {"kind":"point","accepted":[{"x":2,"y":3}],"tolerance":{"x":0,"y":0},"partial_credit":false}]
```

All values in this proposed grammar are `[ASSUMED]`; they are design recommendations, not existing repository values. The public form must omit `accepted`, tolerance parameters, misconception classifications, answer text, and reveal feedback. The parser must reject unknown interaction kinds, malformed JSON, unsupported scoring rules, invalid grid/range geometry, and an empty accessible fallback. [ASSUMED]

### Pattern 2: Semantic response, not pixels or screenshots

**What:** A visual renderer submits a normalized domain value: e.g., a snapped grid coordinate, selected interval/region identifier, ordered timeline identifiers, graph relation classification, or named construction state. It does not submit CSS pixels, SVG path strings, a screenshot, pointer trajectory, or a renderer-specific object graph. [ASSUMED]

**When to use:** Always. Domain values stay meaningful in evidence, work across mouse/touch/keyboard, and give the tutoring loop something interpretable. [ASSUMED]

**Scoring policy:** Use exact comparison after runtime normalization whenever the author declared discrete ticks/regions. For a genuinely continuous value, declare a finite tolerance in the private scoring envelope, normalize with fixed decimal/rational grid units before comparison, and record the normalized submitted value plus the tolerance policy version. Do not compare browser floats, and do not silently widen tolerances by renderer. Auto-scored visual items remain dichotomous; diagnostic feedback may describe a partial/invariant-preserving move but must not convert it into fractional mastery. [ASSUMED]

### Pattern 3: Agent-ready feedback intent

**What:** The scorer returns a small structured result alongside the verdict: submitted semantic state, a deterministic error/invariant category when authored, the highest allowed hint tier, and opaque authored anchor IDs. The agent can receive a tier-limited tutoring context and propose language, but the runtime chooses the anchor/tier and blocks any content not allowed by the Phase-6 policy. [ASSUMED]

**When to use:** After a committed action or submission, not for raw pointer movement. For prediction-first instruction, present the scene and request a prediction/action before explaining the causal relation; after the learner acts, reveal only the next entitled feedback layer. This reuses the pedagogical loop described publicly by Brilliant and the existing Phase-6 hold/hint policy rather than copying any proprietary interaction. [CITED: https://brilliant.org/help/using-brilliant/] [VERIFIED: .planning/phases/06-hint-ladder-cursor-hold-feedback-modes/06-CONTEXT.md]

### Pattern 4: One interaction contract, renderer registry

**What:** Register a renderer by `INTERACTION`, each implementing the same conceptual operations: `render(public_item)`, `read_semantic_state()`, `apply_keyboard_or_touch_action()`, `serialize_response()`, and `render_runtime_feedback()`. The API never accepts renderer code; it accepts only the response document prescribed by `response_schema`. [ASSUMED]

**When to use:** The first plot/numberline renderer and every later geometry/hotspot/diagram/timeline/simulation renderer. [ASSUMED]

### Canvas/SVG/HTML Role Policy

| Medium | Owns | Must not own |
|---|---|---|
| HTML | Prompt, instructions, form controls, status/live feedback, keyboard/touch fallback, submit/stumped controls, text/table representation | Scene-specific coordinate painting or score calculation. [ASSUMED] |
| SVG | Static/retained coordinates, axes, ticks, labeled points/regions, geometry relations, visible focus affordance | Hidden key, client-side verdict, raw pointer-only behavior. [ASSUMED] |
| Canvas | Optional paint layer for a dense simulation/animation | Sole accessible representation, durable answer state, or scoring. Canvas fallback must remain meaningful. [CITED: https://html.spec.whatwg.org/multipage/canvas.html] |

### Anti-Patterns to Avoid

- **Pixel scoring:** pixels change with zoom, DPR, responsive layout, and renderer implementation; score the semantic coordinate/identifier instead. [ASSUMED]
- **Author JavaScript in bank markdown:** it bypasses lint/schema review and makes behavior non-deterministic and unsafe. [ASSUMED]
- **A canvas-only drag interaction:** WCAG 2.2 requires a non-drag single-pointer alternative unless dragging is essential; keyboard equivalence is also required by the project’s existing UI contract. [CITED: https://www.w3.org/TR/WCAG22/] [VERIFIED: .planning/phases/04-surface-redesign-theming/04-UI-SPEC.md:211-218]
- **Answer-shaped public scene data:** do not send accepted points, hidden regions, tolerance, solution path, or final simulation value before the runtime releases it. [VERIFIED: runtime.py:27-48; VERIFIED: runtime.py:258-283]
- **Telemetry firehose:** do not append every pointer move; record action commits and final state so evidence stays interpretable and bounded. [ASSUMED]
- **Canvas/LTI as a Phase-6.1 deliverable:** LTI needs a hosted, authenticated external tool and is correctly a future adapter boundary. [CITED: https://developerdocs.instructure.com/services/canvas/external-tools/lti]

For `visual`, publish a parallel public schema with `interaction`, `scene`, `initial_state`, `semantic_actions`, `response_schema`, `accessibility`, and a non-answer-bearing feedback capability. Keep `scoring`, accepted state(s), tolerance, reveal content, solution trajectory, and answer-specific misconception mapping private. The static `build` surface is an explicit exception: it carries a key because no serving runtime exists. ## Accessibility, Mobile, and Touch Contract

- Give the plot/numberline an SVG visual plus an adjacent semantic control such as coordinate steppers, a tick/region list, or a labeled choice grid; both must serialize the same response. [ASSUMED]
- Keyboard: Tab reaches controls in visual order; arrows adjust a focused point/tick, Enter/Space commits, Escape cancels an in-progress move, and focus moves to the runtime status after submit. Reuse native controls where possible. [CITED: https://www.w3.org/WAI/perspective-videos/keyboard/] [VERIFIED: .planning/phases/04-surface-redesign-theming/04-UI-SPEC.md:211-218]
- Touch/pointer: do not score on pointer-down; permit cancel/undo, use at least 24×24 CSS-pixel targets or an equivalent control, and supply a tap/stepper alternative to drag. WCAG 2.2 makes the non-drag alternative a Level-AA requirement unless dragging is essential. [CITED: https://www.w3.org/TR/WCAG22/]
- Responsive: preserve the information order at 320 CSS px and 200% zoom; the scene may horizontally pan/zoom, but instructions, status, and fallback controls remain visible and usable. [VERIFIED: .planning/phases/04-surface-redesign-theming/04-UI-SPEC.md:218]
- Nonvisual: provide an accessible name/description for the graphic, announce committed state and feedback through a status region, and expose data/relationships in text. SVG with an explicit role needs an accessible name; WAI graphics roles can express structured graphics but must be tested with assistive technology. [CITED: https://www.w3.org/WAI/standards-guidelines/act/rules/7d6734] [CITED: https://www.w3.org/TR/graphics-aria-1.0/]

## GIFT, QTI, and Canvas LMS/LTI Boundary

GIFT is a plain-text importer for a limited set of conventional item forms, while QTI 3 supports portable custom interactions and adaptive testing but is explicitly out of scope in the project. Therefore Phase 6.1 should report visual items as unsupported in GIFT, by item number and named code, rather than export an answer that changes the assessment. [CITED: https://docs.moodle.org/501/en/GIFT_format] [CITED: https://www.1edtech.org/standards/qti/index] [VERIFIED: PROJECT.md; VERIFIED: surfaces/gift.py:173-218]

Canvas is a future integration tier, not an implementation dependency. Canvas supports LTI 1.3 tools embedded in assignment/module contexts; deep linking selects a tool resource for later launch, and Assignment and Grade Services is the grade-passback interface. An Itembank LTI adapter must translate a verified launch to a scoped runtime session and translate an accepted runtime result to the LMS only under an explicit future privacy/identity/hosting decision. It must not make Canvas the scorer, assume local `127.0.0.1` is reachable from Canvas, or upload the append-only evidence store by default. [CITED: https://developerdocs.instructure.com/services/canvas/external-tools/lti/file.content_item] [CITED: https://developerdocs.instructure.com/services/canvas/external-tools/lti/file.assignment_tools] [ASSUMED]

## Common Pitfalls

### Pitfall 1: Rendering becomes the product

**What goes wrong:** The phase delivers drag handles and animation but no semantic response, evidence, or tutor-readable feedback state.  
**Why it happens:** Visual polish is easy to demonstrate while protocol ownership is cross-cutting.  
**How to avoid:** Make plot+numberline acceptance require the authoring→public payload→semantic submit→runtime score→evidence→feedback-intent trace.  
**Warning signs:** Tests assert SVG markup or pointer coordinates but cannot name the domain action or inspect the evidence row. [ASSUMED]

### Pitfall 2: Float/pixel nondeterminism

**What goes wrong:** Zoom, device-pixel ratio, resize, or rounding changes a verdict.  
**How to avoid:** Normalize to declared discrete grid/rational units inside the runtime; test borders of every tolerance.  
**Warning signs:** Browser code uses `getBoundingClientRect()` values as the submitted answer or a scorer compares unrestricted floats. [ASSUMED]

### Pitfall 3: Helpful feedback reveals the target

**What goes wrong:** A feedback message names the correct coordinate/region or shows the completed construction before the allowed reveal tier.  
**How to avoid:** Runtime returns only a feedback anchor/category permitted by Phase 6; the renderer/agent cannot read private scoring data from the public payload.  
**Warning signs:** DevTools network responses contain answer fields, tolerance, `accepted`, solution SVG paths, or agent prose is rendered without a policy check. [VERIFIED: runtime.py:27-48; VERIFIED: .planning/phases/06-hint-ladder-cursor-hold-feedback-modes/06-CONTEXT.md]

### Pitfall 4: Pointer-first accessibility retrofit

**What goes wrong:** Dragging works on a laptop but has no keyboard, screen-reader, or touch alternative.  
**How to avoid:** Design the semantic HTML response first and make SVG/canvas another adapter; test the non-drag control before visual polish.  
**Warning signs:** The only action handler is `pointermove`/`drag`; focus or a submitted state is not announced. [CITED: https://www.w3.org/TR/WCAG22/] [CITED: https://www.w3.org/WAI/perspective-videos/keyboard/]

### Pitfall 5: Partial credit silently changes evidence meaning

**What goes wrong:** A renderer paints a partly correct state as a half score although reports, selection, and existing item policy interpret scores as boolean.  
**How to avoid:** Keep auto-scored visual verdicts boolean. Preserve intermediate semantic state and error category for teaching/analytics without inventing fractional mastery.  
**Warning signs:** `score` becomes numeric in one renderer, or a report averages mixed boolean and numeric values. [VERIFIED: runtime.py:120-130; VERIFIED: schemas/response.schema.json:69-72]

## Open Questions

1. **Which coordinate vocabulary is most useful for the first authored math items?**
   - What we know: a discrete semantic response and private tolerance are required for determinism. [ASSUMED]
   - What is unclear: whether Math 1400 needs integer ticks only, rational ticks, or exact symbolic values in its first real bank.
   - Recommendation: lock this in the first synthetic fixture plus one representative private-bank spike; do not speculate a symbolic algebra engine into the protocol. [ASSUMED]

2. **What event granularity is enough for agent feedback?**
   - What we know: the evidence store is append-only and current response records have a reserved error category/hint tier. [VERIFIED: schemas/response.schema.json:78-97]
   - What is unclear: whether one submitted-state snapshot plus an error category suffices, or whether selected committed intermediate actions materially improve tutoring.
   - Recommendation: begin with submit plus explicit “commit action” events; evaluate with fixtures before recording movement streams. [ASSUMED]

3. **When does an interactive visual item merit QTI/LTI work?**
   - What we know: QTI 3 has portable custom-interaction concepts and Canvas supports LTI deep links/AGS. [CITED: https://www.1edtech.org/standards/qti/index] [CITED: https://developerdocs.instructure.com/services/canvas/external-tools/lti/file.content_item]
   - What is unclear: the actual consuming Canvas instance, hosting posture, user identity mapping, and evidence/grade retention policy.
   - Recommendation: retain the adapter boundary; do not include Canvas/LTI code in this phase. [ASSUMED]
