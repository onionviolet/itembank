## What this plan set out to do

Establish the one versioned visual interaction protocol and prove it end to end
with a real served plot response, then expand the same contract to number-line
points and intervals with deterministic, runtime-bounded scoring and feedback
intent (plan 06.1-01, tasks 1–3).

## Locked protocol fixtures (from 06.1-VALIDATION.md) — all green

- Plot: `{"kind":"point","x":"2","y":"3"}` scores True; wrong point and
  out-of-domain/exponent/NaN/forged-field responses score False.
- Number-line point: `{"kind":"numberline_point","value":"1/2"}` scores True;
  decimal alias `"0.5"` canonicalizes to `"1/2"` and also scores True.
- Interval: `{"kind":"interval","start":"-1","end":"3/2","start_closed":true,
  "end_closed":false}` scores True; the reversed form with swapped closures
  normalizes to the same canonical state and scores True.
- SCALAR grammar: rational reduction (`"2/4"` → `"1/2"`), decimal
  trailing-zero removal (`"2.50"` → `"5/2"`), negative zero → `"0"`, exact
  step alignment, 201-tick cap, numerator/denominator bounds
  (1e9 / 1e6), and refusal of exponents, non-finite, mixed numbers, symbols,
  `1/0`, and excessive precision.
- Tolerance: `1/2` and `3/2` pass exactly on both boundaries of tolerance
  `1/2` around `1`; adjacent representable values `0` and `2` fail.
- Public payloads carry no `accepted`/`tolerance`/`partial_credit`/`scoring`
  sentinels; the served `/api/start` item and `interaction_result`/observation
  were scanned by the test's sentinel set.

## Architecture decisions honored

- **One scorer:** the visual verdict lives in `_visual_verdict`, reached only
  via `runtime.score_response`; `tests/scoring_roundtrip.py`'s structural
  one-scorer scan stays green (the helper is deliberately not named `*_score`).
- **Public/private separation:** the `interaction_contract` carries only
  version/type/interaction/`renderer_config` (axes, initial, actions,
  accessibility) and `response_schema`; the SCORING envelope stays on the
  server item and is read only by the scoring/observation helpers.
- **Closed grammar (T-06.1-03):** unknown VISUAL/SCORING members and any
  script-bearing key/value are rejected before a renderer sees them.
- **Forged authority fields (T-06.1-02):** extra keys in a response make it
  invalid per the exact wire grammar; a forged `hint_tier`/`score` cannot
  raise the entitlement or change a verdict.
- **Phase-6 feedback boundary (D-06):** `visual_observation` takes the hint
  entitlement as an input from the caller and never reads it from the client;
  observations carry an opaque authored feedback anchor, the deterministic
  error/invariant category, and the tolerance-policy version — never the
  accepted state or tolerance amounts.

## Divergences from plan text (all additive, documented)

- The plans were authored against a base where Phase 5's `interaction_contract`
  envelope already existed on `main`. Phase 5 is a concurrently-executing
  branch (`gsd/phase-05-check`) not yet merged, so plan 01 implemented the
  visual contract in the same envelope *shape* (`version`/`type`/
  `renderer_config`/`response_schema` + `interaction_result`) additively, with
  its own `VISUAL_PROTOCOL_VERSION`. When Phase 5 merges, the two compose
  without a second parser or scorer.
- Plan 01's `files_modified` lists `fixtures/visual_bank.md`; the fixture also
  carries a fourth tolerance-bounded item so task 3's boundary fixtures run
  against a real authored bank rather than only in-memory questions.
- Served evidence in this plan uses the existing response-event path (the
  `answer` field carries the canonical semantic state). The versioned
  `visual_action` event, `/api/interact` route, schemas, and lint codes are
  plan 06.1-02's contract, as its `files_modified` list specifies.
