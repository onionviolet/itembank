<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| runtime/gate -> append-only evidence | Private provider and gate state is reduced to a safe durable record. |
| model proposal -> accepted mark | Untrusted suggestion must not gain grading or evidence authority. |
| evidence reader -> session/report consumer | Retrieval must remain session-scoped and must not reconstruct dropped content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-08-03-01 | Repudiation | model interaction history | high | mitigate | Durable interaction IDs, request fingerprints, response/tier links, timing, outcome, and retry parent lineage. |
| T-08-03-02 | Information Disclosure | dropped interaction event | critical | mitigate | Descriptor-only event schema plus raw-log and reader sentinel-absence tests. |
| T-08-03-03 | Elevation of Privilege | rubric proposal acceptance | critical | mitigate | Separate pending proposal event; require proposal link, reviewer actor ID, and trusted-local confirmation metadata in addition to `marker=human`; retain accepted-mark indexes. |
| T-08-03-04 | Tampering | interaction replay/retry | high | mitigate | Evidence-backed idempotency, same-session/item/operation parent validation, immutable append-only lineage. |
| T-08-03-05 | Spoofing | cross-session response/proposal links | high | mitigate | Validate session, item, response type, active/retracted state, and operation before append or acceptance. |
</threat_model>
