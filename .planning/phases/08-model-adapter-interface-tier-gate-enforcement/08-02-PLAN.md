<objective>
**As the** runtime, **I want** one bounded adapter boundary that any number of model backends register behind, **so that** switching providers is a config change and every provider failure is a typed unavailable result instead of a broken sitting.

Purpose: MODEL-01 through MODEL-03 and MODEL-05 require provider portability and degradation without letting provider syntax, credentials, or failure modes infect the teaching loop (D-01..D-04, D-17, D-18, D-27).
Output: One adapter module, one published schema, a named-profile settings registry, and deterministic subprocess/loopback parity tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| settings -> adapter resolver | Configuration (including profile names and env references) becomes transport behavior; invalid entries must fail typed |
| adapter -> provider process/endpoint | Item and learner text transits to a hosted provider (accepted risk, recorded in PROJECT.md); secrets must not ride along |
| provider output -> typed result | Provider-native bytes are untrusted; only the normalized envelope crosses |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-08-10 | Elevation of Privilege | hosted_cli command vector | high | mitigate | Configured argv only, shell=False, learner/item text never interpolated into the command; typed unavailable on any transport error (RESEARCH Known Threat Patterns) |
| T-08-11 | Information Disclosure | secret handling | high | mitigate | secret_env references resolved from os.environ only; no secret value in settings, requests, results, logs, or evidence (D-03/D-15); tests assert absence |
| T-08-12 | Denial of Service | timeout/oversize | high | mitigate | Per-profile timeout_seconds and max_output_bytes enforced on both transports; over-cap and timeout are typed unavailable (D-04) |
| T-08-13 | Tampering | profile registry | medium | mitigate | Schema validation plus runtime unique-name/active resolution; invalid entries are named errors, never silent fallbacks |
| T-08-14 | Spoofing | provider refusal as success | medium | mitigate | status enum ok|refused|unavailable with named error codes; refusal is never a candidate |
| T-08-SC | Tampering | package operations | high | mitigate | This plan performs no package operation; transports are stdlib subprocess and urllib only (AI-SPEC §2) |
</threat_model>
