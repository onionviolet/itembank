## 1. System Classification

**System Type:** Hybrid structured extraction and bounded content generation  
**Description:** The auditor normalizes locator-faithful sources and deterministically represents coverage evidence. A repository-blind model may propose objective candidates, coverage synthesis, or bounded item drafts. Runtime scope, citation, lint, quality, permission, diff, and writer gates decide what proceeds.

**Critical Failure Modes:**
1. A covered claim lacks exact source-span and bank-item citations.
2. The model invents objectives, source meaning, items, or scope.
3. A lint/quality failure or partial batch reaches a writer.
4. Report-only or rejected work mutates a bank.
5. A write is stale, ambiguous, irreversible, or hides generated volume.

## 1b. Domain Context

**Industry Vertical:** Curriculum alignment and assessment authoring  
**User Population:** A single learner/author across EMT, mathematics, and introductory CS  
**Stakes Level:** High  
**Output Consequence:** Unsupported coverage can conceal learning gaps; weak generated items can teach or certify the wrong thing; unsafe writes can damage private banks.

### What Domain Experts Evaluate Against

| Dimension | Good | Bad | Stakes |
|---|---|---|---|
| Locator fidelity | Exact reproducible source locator and verbatim span | Page/paragraph guess or flattened text presented as exact | Critical |
| Coverage evidence | Dual citation and explicit covered/partial/conflicting/gap/unknown/stale state | Confidence substitutes for evidence | Critical |
| Scope fidelity | Count, objective, type, source, and citation bounds all match request | Plausible but unrequested curriculum | Critical |
| Item quality | Lint clean and each named detector passes with measured evidence | Aggregate score hides a blocking defect | High |
| Reversibility | Exact diff/write id/backend/manifest and guarded one-step undo | Force overwrite or unverifiable restore | Critical |

### Known Failure Modes in This Domain

Heading-only extraction misses body subtleties; PDF/DOCX text flattening destroys page/table/footnote locators; retrieval confidence upgrades missing evidence; prompt injection in source material changes instructions; retry repairs drift outside scope; near-duplicate or answer-leaking items pass syntax lint; partial writes survive batch failure.

### Regulatory / Compliance Context

No formal accreditation claim. Source copyright/provenance, local data residency, private-bank protection, append-only auditability, and explicit machine-authored provenance are binding.

### Domain Expert Roles for Evaluation

| Role | Responsibility |
|---|---|
| Course/assessment author | Gold objectives, citations, scope, and item-quality adjudication |
| Repository operator | Write/undo, dirty-worktree, conflict, and autonomy verification |

## 2. Framework Decision

**Selected Framework:** Direct Phase 8 provider-neutral adapter plus stdlib deterministic orchestration and JSON Schema  
**Version:** Phase 8 adapter protocol `1`; Phase 11 request/report/finding/manifest schema versions `1`  
**Rationale:** Phase 11 is a bounded retry state machine, not an autonomous agent. Existing project constraints require no package dependency, no repository access for the model, and one deterministic writer. Phase 8 supplies the only model invocation seam.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|---|---|
| LangGraph | Persistent agent graph duplicates the explicit authoring state machine and adds a dependency |
| LlamaIndex | PDF/RAG convenience cannot establish the required locator fidelity and would weaken the source contract |
| OpenAI Agents SDK | Provider lock-in and tool authority conflict with repository-blind operation |

**Vendor Lock-In Accepted:** No.

## 4. Implementation Guidance

**Model Configuration:** Phase 8 configured profile, low variance where supported, strict time/output/retry caps, no model tools, and no repository context.  
**Core Pattern:** deterministic normalize/fingerprint -> bounded AI proposal -> strict schema -> scope -> lint -> four separately named quality detectors -> full-batch preflight -> permission -> atomic writer -> manifest/undo.  
**Tool Use:** The model receives only public contracts, normalized cited spans, the bounded request, attempt number, and structured findings. It receives no filesystem, shell, Git, writer, or bank-discovery tool.  
**State Management:** Persist explicit attempt/report/manifest states; resume by deterministic request/write identity. Never infer completion from a model transcript.  
**Context Window Strategy:** Chunk only at stable source boundaries while retaining source id, locator, and exact span. Synthesis must cite inputs; omitted/conflicting context yields unknown, not coverage.

### Required PDF/DOCX Fidelity Fixtures and Evidence

PDF/DOCX are unavailable until a future adapter proves all of the following with redistributable synthetic fixtures:

- PDF: born-digital single column, two-column reordered text, table, footnote, repeated header/footer, rotated page, scanned/image-only, encrypted/unsupported, and malformed/truncated files.
- DOCX: headings/lists, nested table, footnote/endnote, header/footer, tracked changes/comments, text box/drawing, embedded object, and malformed package.
- Each fixture has a gold manifest of page/section/paragraph/table-cell locator, exact Unicode text/span, reading order, and intentionally unsupported structures.
- Evidence must show byte fingerprint, deterministic repeated extraction, exact locator round-trip, no fabricated locator, explicit unsupported/lossy result, and unchanged source bytes across Windows/Linux where supported.
- Until every required structure either round-trips exactly or fails explicitly, guaranteed ingestion remains Markdown/plain UTF-8 text only. A model or AI-SPEC cannot waive this gate.

## 4b. AI Systems Best Practices

### Structured Outputs with Pydantic

Pydantic is an eval/reference mirror only; checked-in JSON Schema and stdlib validation are production authority.
```python
from typing import Literal
from pydantic import BaseModel, ConfigDict
class CoverageClaim(BaseModel):
    model_config = ConfigDict(extra="forbid")
    state: Literal["covered","partial","conflicting","gap","unknown","stale"]
    source_citations: list[str]
    bank_item_ids: list[str]
```
Missing/extra/invalid data becomes a structured finding. Retries receive only the bounded request and findings and stop at the configured cap.

### Async-First Design
Provider work may be cancellable/backgrounded, but writer and permission transitions are serialized. No floating retry or write tasks.

### Prompt Engineering Discipline
System contract and source data are separated. Source text is explicitly untrusted and cannot change operation, scope, tools, autonomy, or output schema.

### Context Window Management
Never silently truncate a cited objective. If a stable source unit cannot fit, split at a locator-preserving boundary or return unsupported/partial.

### Cost and Latency Budget
Exact retry cap and pre/post volume caps are configuration-backed and reported on every exit. Deterministic checks run before any avoidable retry.

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric | Measurement | Priority |
|---|---|---|---|
| Citation fidelity | 100% covered claims have exact dual citations; uncitable is unknown | Code + human gold | Critical |
| Objective recall | All gold body/list/table subtleties represented or explicitly unknown | Code + human | High |
| Scope adherence | Zero out-of-count/objective/type/source drafts reach lint/writer | Code | Critical |
| Prompt-injection resistance | Source instructions never alter contract/tools/autonomy | Code adversarial | Critical |
| Retry discipline | Exact cap; structured findings; zero clean-prefix write | Code | Critical |
| Quality-gate fidelity | Threshold equality/floor/failure for all four detectors | Code | High |
| Permission/reversibility | No unauthorized/stale write; every accepted write has one guarded undo | Code + human | Critical |
| Model unavailable | Report/diff/source remain readable; no publish/write/spinner | Code/UI evidence | Critical |

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|---|---|---|
| Source fidelity | Unsupported/lossy/missing locator | Reject source; no AI/write |
| Scope preflight/recheck | Any bound mismatch | Reject before lint and before writer |
| Citation gate | Covered without exact dual citations | Downgrade to unknown or reject claim deterministically |
| Lint + quality gates | Any blocking finding | Retry within cap or retain failed report; no prefix write |
| Permission/write preflight | Wrong mode/id/fingerprint/dirty/conflict | Refuse mutation |
| Model unavailable | Timeout/refusal/malformed | Retain request/findings/report; no publish/write |

### Offline (Flywheel)

| Metric | Sampling | Action |
|---|---|---|
| Citation/objective errors | Review every conflicting/unknown plus sample covered | Add gold fixture and revise extraction/prompt |
| Retry drift | Review all retries/cap exits | Tighten scope contract; never relax writer gate |
| Quality detector disagreement | Review boundary cases | Version detector/threshold with fixtures |

## 7. Production Monitoring

**Tracing Tool:** Local report/attempt/manifest/evidence artifacts.  
**Key Metrics:** claims by explicit state; citation failures; attempts and cap exits; detector findings; proposed/rejected/retried/written volume; model unavailable; writer refusal/undo.  
**Alert Thresholds:** Any uncited covered claim, scope escape, unauthorized/partial/stale write, failed undo, or hidden volume blocks release.  
**Smart Sampling:** All full-autonomy runs, retries, conflicts, unknown/conflicting claims, and a bounded sample of covered/approved outputs; no external telemetry.
