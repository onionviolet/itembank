<objective>
Land the token layer this whole phase stands on, and prove it reaches a real
rendered page end-to-end.

This is the phase's tracer slice: one thin path through the palette
(`theme.py`) → the shared token layer (`presentation.py`) → a surface template
(`quiz_page.py`) → the daemon-served document → an executable fixture. Nothing
downstream in Phase 14 can be implemented or judged until it lands, because
today `--space-1` … `--space-7` are referenced 64 times in `surfaces/lesson.py`
and defined nowhere in the repository (DEFECT D-A), `--font-chrome` and
`--font-code` are named by the design contract and defined nowhere,
`RUNNABLE_CSS` twice references a `--panel` token that does not exist, and
`quiz_page.py` includes neither the shared token layer nor any `@font-face`
rule at all (DEFECT D-B).

Purpose: every spacing, rhythm, voice and contrast decision in plans 14-02
through 14-08 is unverifiable until a referenced token is guaranteed to be a
defined token. The fixture that guarantees it is written first, deliberately
red, because it is the test that would have caught D-A, D-B and the `--panel`
stray before any of them shipped (14-UI-SPEC §15 gate 8).

Output: a complete token layer, the quiz page joined to it, and two new
stylesheet invariants that make an undefined or uncontrasted token a build
failure rather than a browser surprise.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
