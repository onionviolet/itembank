<objective>
Set the reader's type, vertical rhythm and measure against Source Serif 4 and
iA Writer Quattro as they actually render — which, until 2026-08-12, they never
did on any daemon page.

ROADMAP criterion 2. The 14-UI-SPEC parsed the shipped WOFF2 bytes directly, so
every number here is measured rather than assumed: Source Serif 4's x-height is
0.475 em against Georgia's 0.484, which is why **the 18px lesson size does not
change**; its glyph box is 1.371 em, which is why the 24px paragraph gap is
0.81 of a line rather than the 0.54 it is today; and `1ch` is the advance of
`0` at 0.500 em while the frequency-weighted average character is 0.447 em,
which is why `66ch` has always been 74 characters.

Purpose: this is the half of "feels designed rather than assembled" that lives
in the reader. It is mechanical, every value is already decided, and a plan
that proposes a sixth type size has misread the contract.

Output: a reader on one type scale with a real paragraph rhythm and a correct
reading measure, plus the fixture that makes a stray font size a build failure.
</objective>

  `max-width:calc(var(--measure-prose) + 2 * var(--space-3))`

keeping its existing `padding:var(--space-4) var(--space-3) var(--space-7)`.
At 18px that is a 563px box holding a 531px, 66-character column. Tables, code,
`[!EXAMPLE]` grids and math displays keep their existing escape to
`--measure-wide`.

(3) **Paragraph rhythm.** The lesson line box is 29.7px, so today's 16px gap is
0.54 of a line — the standard "reads as one grey slab" figure. Add rules SCOPED

enhancement hook for math and for runnable code. Do NOT change the existing
bare `p,li` rule: it also styles callouts, the gate band, the nav and the
glossary, and those keep their shipped values.

  `#lesson-content p{margin:0 0 var(--space-4)}`        (24px = 0.81 line)
  `#lesson-content li{margin:0 0 var(--space-2)}`       (items are one unit)
  `#lesson-content :is(ul,ol){margin:0 0 var(--space-4)}` (the list is a block)

The heading ramp is inherited unchanged and is now verified against the real
line box: `h2` is 48/16 = 1.6 lines above and 0.54 below, `h3` is 32/8, `h1` is
0 / 16. Do not touch them.

(4) **Inline voice mix.** Quattro's x-height ratio is 0.516 against Source
Serif's 0.475, so a Ledger or Code span at the inherited 18px renders glyphs
8.6% larger than the prose around it. Add:

  `#lesson-content :is(code,samp,kbd,.ledger-inline){font-size-adjust:0.475}`

This normalises the used glyph size without changing the computed `font-size`,
so it introduces no sixth size; where unsupported it is ignored and the page
renders exactly as it does today. `.ledger-inline` currently matches nothing and
is included because the design contract names it — leave it in the selector.
This applies ONLY to inline runs inside prose: `pre code`, `.gate-note`, and

receive it.

At 16px the same column carries 47.9. This uses an existing token and adds no
size. At 320px the column yields 40 characters; that is recorded as not meeting
the floor and is deliberately not faked by going below 16px — the page stays
readable and horizontally scroll-free, which is what the accessibility gate
requires.

Scope is an explicit module-level tuple, not "everything", because the design

  `TYPE_SCALE_SCOPE = ("surfaces.presentation", "surfaces.lesson",
                       "served /lesson/")`
  `TYPE_SCALE_DEBT  = ("surfaces.theme SETTINGS_CSS", "surfaces.day",

`TYPE_SCALE_DEBT` carries a comment naming it as 14-UI-SPEC §17 item 6 — the
Phase 4 cleanup this phase deliberately does not widen its diff to reach — and
the closing `print` lists it, so the debt is visible on every green run instead
of being forgotten. Plan 14-04 appends `surfaces.quiz_page` and `served /quiz/`
to `TYPE_SCALE_SCOPE`; do not add them here, because the quiz has not been
migrated yet and a premature entry turns this fixture red for the wrong reason.

For every collected stylesheet whose name starts with an in-scope prefix, walk
its blocks and, for each declaration, apply three assertions:

  1. **Size.** A declaration whose property is `font-size`, or whose property is
     `font` and whose value carries a length, must express that length in `px`
     and the value must be one of 12, 16, 18, 20, 32. A `font:inherit`
     declaration carries no length and is skipped. Report the selector, the
     property and the offending value.
  2. **Weight.** A `font-weight` declaration must be 400 or 600.
  3. **Family.** A `font-family` declaration, and the family portion of a `font`
     shorthand, must consist only of `var(--…)` references. Any bare family name
     is a failure naming the selector.

Three exclusions, each of which is real and must be implemented or the fixture
is wrong:

  - **`@font-face` descriptor blocks are excluded from all three assertions.**
    A `font-weight` inside `@font-face` declares what a FILE IS, not what a rule
    USES — the vendored Quattro Bold is a 700-weight file and must stay declared
    as one — and a `font-family` inside `@font-face` is the family being defined,
    which cannot be a token. Detect the block by its prelude and skip it.
  - **SVG presentation attributes are not CSS.** Match only declarations (a
    property followed by `:`), never `font-size=` in markup. This matters for
    plan 14-04, where the visual-item renderers legitimately set unitless
    `font-size` attributes on SVG `<text>` elements that this rule does not and
    must not govern.
  - The `:root` custom-property block is not a font declaration; a
    `--font-chrome:` definition is a definition, not a use.

Run it. `surfaces.presentation` and `surfaces.lesson` must be clean after Tasks
1 and 2; if either is not, the remaining site is a gap in this plan.
  </action>
