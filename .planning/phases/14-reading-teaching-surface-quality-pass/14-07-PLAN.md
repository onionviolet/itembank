<objective>
Make the wrong-answer state the strongest screen in the product instead of the
weakest.

ROADMAP criterion 5. Today a wrong answer produces one red sentence and a
collapsed `<details>`, and the sentence points the learner at the model panel as
if that were the help. The reason is DEFECT D-D: the six-tier ladder that
`06-UI-SPEC.md` fully specifies and LOCKS has never had a route to the browser.
Plan 14-03 built that route. This plan renders it.

Almost nothing here is a new design. Every card design, every locked-tier string
and every mode rule is INHERITED verbatim from `06-UI-SPEC.md` §5-§7 and is not
re-litigated; the four genuinely new calls are the shell resolution, the held-card
layout, the offline-is-not-degraded rules and the no-pre-announcement rules, all
of which 14-UI-SPEC §9 already made.

Purpose: this is the single most important teaching moment in the product, and
it is the moment the whole thing exists for.

Output: an in-flow support region carrying the ladder, a state machine whose
names a fixture uses, a degraded path that is a complete path, three retirements,
and the executable proof that nothing pre-announces a reveal.
</objective>

**The shell.** `06-UI-SPEC.md` §6.1 places the ladder in the support column and
rejected the inline-under-the-item option because the project shell reserves the
activity canvas. The sat quiz has no support column — it is one 800px column —
so rather than invent a third answer, apply the project shell's own tablet rule,
which already covers exactly this shape: activity full width, support as an
in-flow "Help and evidence" disclosure after the active response controls.
**The sat quiz is the tablet shell at every viewport width, and `hint_display`
resolves to `slot` there.** This is not the rejected inline option: that put hint
content inside the activity canvas; this puts it in the support region the shell
defines for a single-column layout.

**The support region** sits immediately after the response controls and the
reserved feedback slot and before the next action, separated from the activity by
a full-measure 1px `--line` rule. Its order is **hints → document navigation →
evidence**, inherited and testable: the `Hints` block, then the collapsed section
nav, then the collapsed `Help and evidence` disclosure that already exists.

**The state machine.** These names are binding; the fixture in Task 3 uses these
strings:

  PRE_ANSWER → SUBMITTING;
  SUBMITTING + empty → PRE_ANSWER + EMPTY_NOTICE (no attempt recorded);
  SUBMITTING + same canonical → HELD + DUPLICATE_NOTICE (no tier movement);
  SUBMITTING + correct → CORRECT → next activity;
  SUBMITTING + wrong in drill → REVEAL_AND_ADVANCE;
  SUBMITTING + wrong in diagnostic or exam → DEFERRED;
  SUBMITTING + wrong in practice → HELD_FIRST (one tier unlocks, none shown);
  HELD_FIRST + open next hint → HELD_TIER_SHOWN;
  HELD_TIER_SHOWN + changed retry, wrong → HELD_REPEAT (one more tier unlocks);
  HELD_* + stumped → HELD_TIER_SHOWN (unlocks and shows exactly one);
  HELD_* + tier 5 shown → REVEALED; REVEALED + any submit → advance.

**Rendering per state.** The status copy goes in the single reserved `.feedback`
region; the support region holds the ladder and announces nothing. Every string
below is INHERITED verbatim — reuse the existing locked constants where the file
already holds them and add the rest as named constants beside `ASSIST_COPY`,
never as inline literals:

  `HELD_FIRST` — `Not correct. Try a different answer, or open the next hint.`
    Support: the `Hints` heading, **no shown cards**, and the next locked card.
    Controls: `Check answer` re-enabled, and `Open the next hint`.
  `HELD_TIER_SHOWN` — status unchanged. Support: shown cards in index order, then
    the next locked card. Controls: `Check answer`, plus `Open the next hint`
    when the payload reports entitled, **or** `I'm stumped — show the next hint`
    when it does not.
  `HELD_REPEAT` — status unchanged; one more shown card is available; the ladder
    grows and nothing is replaced.
  `DUPLICATE_NOTICE` — `That is the same answer as before. Change it, or use "I'm stumped" to open the next hint.`
    Support unchanged; no tier movement.
  `EMPTY_NOTICE` — `Enter an answer before checking. An empty answer does not open a hint.`
  `REVEALED` — `The answer is shown above. Move on when you're ready.` Full
    ladder with tier 5 shown; no locked cards remain; control is `Next item`.
  `DEFERRED` and drill — the ladder block is **absent with the payload's own
    stated reason**, which plan 14-03's route already supplies as
    `unavailable_reason`. The client renders that string and decides nothing.

`Open the next hint` is the one new string in this phase; everything else is
inherited. **The currently shipped held sentence is RETIRED** — it describes a
mechanism instead of an action and points at the model panel as if that were the
help. Find every occurrence in both clients and replace it with the inherited
copy appropriate to that client's flow from the table above.

**Layout of the held card** (concrete values, all from the existing scale): the
ladder is an `<ol>` with `list-style:none`; card padding `--space-3`; gap between
cards `--space-2`; the `Hints` heading has `--space-4` above and `--space-2`
below and is Ledger at the label size with `.08em` tracking in `--mut`. A shown
card is `--card` with a 1px `--line` border and `--r-2`; its body is **Paper at
16px/1.5**. A locked card is `--chip` with a **1px dashed `--line`** border; its
header and body are **Ledger at 12px/1.5**. **Locked and shown cards carry
identical padding** so the ladder does not jitter as tiers arrive. An unavailable
shown tier uses `--unknown` on `--unknown-bg` with its accompanying text label —
never colour alone — which is what plan 14-01's measured tokens unblocked.

`hint_display: slot` means: the most recent shown tier renders as one card,
earlier shown tiers collapse behind a `<details>` labelled `Hints shown (n)`, and
the next locked card and the next legal action follow.

**Where `further_locked` renders, stated so the table above is not read as
capping the ladder at one locked card.** The state table says "the next locked
card" because that card is the one carrying the two-line unlock copy. Under the
default `hint_locked_preview: full`, the `further_locked` entries render **below**
the next locked card, in index order, each as its own locked card with **identical
padding** to the next-locked and shown cards, each carrying only its header and
its single `Tier {n} unlocks after tier {n-1}.` line. Under `next` the route sends
`further_locked` empty and no further cards render. Rendering only the next locked
card under `full` would make plan 14-03's default a UI no-op and would break the
inherited depiction the no-pre-announcement rule depends on: six locked cards each
showing its own unlock condition is the honest picture, and it is precisely what
makes a progress bar unnecessary.

**A new tier card arrives with no entrance animation, no highlight pulse and no
scroll-into-view.** One status update, no focus jump; focus stays on the control
the learner pressed. This is inherited and is an accessibility gate, not a taste.

The renderer consumes only what the route sends: `shown`, `next_locked`,
`further_locked`, `entitled`, `exhausted`, `unavailable_reason`. It never counts
attempts, never derives entitlement, never re-derives display text from an id,
and cannot construct a request for a specific tier.

**Sitting, scoring, the ladder, the reader, the gloss, evidence and the report
must all work with the network unplugged.** That is the project's
degrade-never-block rule and it is this phase's gate 5.

(1) **Shown tiers are server-rendered.** When the page is rendered for a held
card, the server emits the ladder markup from `session.do_teach`'s read path
(plan 14-03's `kind=None`), so the whole ladder is present and correct before any
script runs. The client enhances that markup in place rather than replacing it —
a page whose script never loads is a complete teaching surface, not a stub.

(2) **The unlock control is a form post.** Extend `handle_quiz_answer`'s existing
form contract with one additional submit-button name whose value is `hint` or
`stumped`, and route it through the same `session.do_teach` the JSON route calls
— one adapter, one transition, one evidence writer. Refuse any other value by
name. The page then re-renders server-side with the new tier shown. Do not add a
second transition path and do not let the form name a tier.

(3) **Absence is communicated by the absence of an offer, and by nothing else.**
No banner, no status chip, no colour, no badge, and the word for being offline
must not appear on screen anywhere. The locked model-unavailable sentence renders
as **static text inside the `Help and evidence` disclosure**, seen only by a
learner who opened that disclosure and pressed the request control. Routing it
through the shared canvas region would announce the model's absence to every
learner on every wrong answer, which is precisely the page-that-announces-what-it-
does-not-have this rule exists to prevent.

(4) **The authored ladder is the product; generated help is an accessory.** The
ladder is unconditionally visible, at full measure, above the section nav and
above the collapsed `Help and evidence` disclosure. With the model unreachable
the page loses a collapsed disclosure's contents; the teaching surface is
untouched.
  </action>
