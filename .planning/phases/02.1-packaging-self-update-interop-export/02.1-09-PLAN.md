<objective>
Close CR-02 and CR-03, which are one problem wearing two hats. `background_check` only refreshes the
manifest when a manifest already exists, so on a machine that has never installed an update the
throttle never engages and every launch asks GitHub -- and this repository's own `itembank.json` ships
`check_on_launch`, so the README's primary checkout Install path was exactly that machine.

Give the throttle a record of its own, separate from the manifest, so the clock starts on the first
check rather than the first install. Then make the first background check on any machine disclose what
it is about to do, once, before it does it.

Purpose: DEL-07 promises the update behaviour "toggles between opt-in-only and check-on-launch". A
check-on-launch that is really check-every-launch is not the toggle that was promised, and an
unconsented check on a fresh clone is not the opt-in half either. Both halves come back with these
three tasks.

Output: a `updates/check_state.json` record and the two functions around it, a consent gate in front
of the first request, one new locked line in the UI-SPEC, and the documented reason the schema default
and this repository's own file still say different things.
</objective>
