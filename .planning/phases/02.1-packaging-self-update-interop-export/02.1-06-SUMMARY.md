# Phase 02.1 Plan 06: GIFT Export Refusal Paths -- build, Unescapable Fields, Strict Promotion Summary

**The loud-failure half of GIFT export: `build` items are refused by item number in every mode, an unescapable field is named and skipped rather than corrupting the file, `--strict` promotes `multi`'s scoring-divergence warning to a per-item failure, and a new dotted `gift.*` code namespace makes every refusal machine-branchable.**

## Accomplishments
- `surfaces/gift.py` gained `GIFT_CODES` (`gift.type_unsupported`, `gift.field_unescapable`, `gift.strict_divergence` -- sorted-set-built like `model.LINT_CODES`/`settings.SETTINGS_CODES`) and `unexpressible_field(q)`, which names the first field (stem, an option by letter, a matching row by position, category, model answer, general feedback) that still carries a line break after escaping
- `gift_item()` now runs two refusals before any renderer: `build` (ordering) is refused unconditionally in every mode with the locked wording (`Q<n>: type 'build' (ordering) has no GIFT equivalent -- not exported`), and an unescapable field is refused by name -- both return `None` and append to `errors` rather than writing a corrupted block
- `--strict` promotes the `multi` divergence warning to a per-item failure via a shared `MULTI_DIVERGENCE` sentence constant: the default-mode warning and the strict-mode failure state the identical divergence and differ only in the not-exported marker and which list (`warnings` vs `errors`) the message lands in
- `export_gift()`'s summary/exit-code contract (built in plan 02.1-04) needed **no changes** -- it already prints every warning/error before a single summary line, chooses between the all-clear and exported-and-skipped lines correctly, and writes the output file even when every item was skipped
- `fixtures/gift_build_only_bank.md`: 11 synthetic `build` items (brewing tea, planting a seedling, mailing a letter, changing a tire, baking bread, assembling a bookshelf, doing laundry, brushing teeth, filing an expense report, watering a garden, pitching a tent), each with a distinct stem and a distinct, valid step sequence; lints clean at 0 errors
- `tests/gift_export_roundtrip.py` gained five tests: build refused by item number in both modes, `--strict` promotion sharing the divergence sentence, unescapable-field naming per field kind, the partial-vs-all-clear-vs-all-skipped exit-code/summary distinction (via a new inline `NO_BUILD_BANK` fixture proving the true all-clear path), and the all-build bank's zero-exported, identically-shaped-row case

- **Issue:** The first draft of the fixture omitted every item's `[TYPE: build]` tag. `model.parse_question()` defaults an untyped block to `qtype = "mc"`, and the `mc` branch requires `opts` and `correct` to be non-empty or it returns `None` -- so all 11 blocks silently vanished from `model.load()`'s output instead of parsing as `build`.
- **Fix:** Added `[TYPE: build]` immediately after each item's stem line, matching `fixtures/sample_bank.md` Q4's and `fixtures/gift_escapes_bank.md` Q4's own placement.
- **Files modified:** `fixtures/gift_build_only_bank.md`
- **Verification:** `python -c "from model import load; print(len(load('fixtures/gift_build_only_bank.md')))"` now reports 11, all type `build`; `itembank lint` exits 0.
- **Committed in:** `2c8994b` (Task 2 commit) -- caught before the commit, not a follow-up fix
