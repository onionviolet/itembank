### Gaps Summary

Three findings block a clean pass, and all three were independently confirmed against the actual code in this
session (not merely carried over from the code review's prose):

1. **Credential leak on redirect (CR-01).** `download_asset()` sends the update token to GitHub and the same
   header survives onto GitHub's cross-origin CDN redirect target, because stdlib `urllib`'s default redirect
   handling does not strip `Authorization` across hosts and this module builds no custom handler that does.
   This directly contradicts the phase goal's own word "safely" and the module's own threat-model claim
   (T-02.1-22) that the token is "placed only in an outbound authorization header... never written... to any
   printed line" — the threat model did not account for a redirect leaking it to a *different* host entirely.

2. **Rate-limit guard does not engage on a fresh install (CR-02).** `background_check()`'s manifest-refresh
   step is conditional on a manifest already existing, so `should_check()`'s clock never starts until after
   the first real `itembank update` install — meaning every `itembank daemon` launch before that point makes
   an unthrottled GitHub request, contradicting the function's own documented purpose.

3. **Shipped default contradicts the schema's own opt-in default (CR-03).** `itembank.json`'s `update_policy`
   is `check_on_launch` while `schemas/settings.schema.json` declares `opt_in` as the default. A directory with
   no `itembank.json` is safe (verified this session), but the README's primary checkout-based Install
   instructions run directly against the checked-in file, so the project's actual primary user — this
   project has exactly one, per CLAUDE.md — gets unconsented background checks by default, compounding gap 2
   into a live, not merely theoretical, problem.

All three are narrow, well-scoped fixes inside `surfaces/update.py` and `itembank.json` (the code review's own
suggested fixes are concrete and small), and none require re-architecting anything this phase built. The
packaging (DEL-01/DEL-02), the daemon window (DEL-03), and the GIFT export (DEL-08) halves of this phase are
solid — well-tested, clean of debt markers, and structurally sound. The updater's download-and-install
mechanics (Success Criterion 3) are also sound. What fails is specifically the "safe" and "does not exhaust a
rate-limit budget" halves of the self-update story that the phase goal and DEL-07 explicitly promise.
