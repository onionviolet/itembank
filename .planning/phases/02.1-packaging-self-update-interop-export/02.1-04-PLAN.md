types GIFT can express, escapes every user-authored field through one function, and is deterministic

head, and lets the golden-file test land with the transform it pins.

`GIFT_ESCAPE` is a compiled regex matching any one character of GIFT's escape set — tilde, equals,
hash, opening brace, closing brace, colon, and backslash — and `gift_escape(text)` substitutes each
match with itself preceded by a backslash, treating a `None` or empty input as the empty string. Every
user-authored field in every renderer goes through this one function. Do not add a second escaping
path for any type; a bank author writing "between 50% and 60%" or "A ~ B" in a stem corrupts the file
if a single field is missed, and one function is the only way to be sure none is.

`gift_name(q)` returns the GIFT question name for an item as the item number wrapped in the double-
colon name delimiters, with the number rendered by the same `Q%d` shape `model.lint()` already uses for
its own per-item messages, so a `Q<n>` in a console error line and a `::Q<n>::` in the exported file
name the same item.

Four renderers, each returning a rendered block as a string and none of them writing anything:

`gift_mc(q)` — the name, then the escaped stem, then an opening brace on the same line. One line per
option letter in sorted order: the equals marker for a letter in `q["correct"]`, the tilde marker
otherwise, then the escaped option text, then — when `q["da"]` carries a non-empty entry for that
letter — a space, the hash feedback marker, a space, and the escaped feedback. Then, when `q.get("why")`
is non-empty, a GIFT general-feedback line: four hash characters followed by the escaped `why` text.
Then a closing brace on its own line.

`gift_multi(q)` — the same frame, but every answer carries a percentage weight, because GIFT expresses
pick-N through weighted answers. Each correct option carries a positive weight of one hundred divided
by the number of correct options; each incorrect option carries a weight of negative one hundred.
Render the positive weight with five decimal places and then strip trailing zeros and any trailing
decimal point, so two correct options render a clean whole number and three render a repeating value
truncated identically on every run — an unspecified float repr here is what makes two exports of the
same bank differ. Keep the same feedback and general-feedback lines as `gift_mc`.

`gift_matching(q)` — the name and escaped stem, then one line per entry of `q["rows"]` in row order:
the equals marker, the escaped row text, the GIFT matching arrow, and the escaped category. Repeated
right-hand category values across rows are correct and expected — that is precisely what makes GIFT
`matching` a structural fit for itembank's categorise-rows-into-buckets shape — so do not deduplicate,
do not sort, and do not merge rows that share a category. Row order is the bank's own order.

`gift_short(q)` — the name, the escaped stem, and a single-line answer block holding the equals marker
followed by the escaped `q["model"]` text.

`gift_item(q, errors, warnings, strict=False)` dispatches on `q["type"]` and returns the rendered block
or `None`. For now, dispatch mc, multi, table, dnd and short to their renderers and return `None` for
anything else after appending a message to `errors`; plan 02.1-06 fills in the `build` case, the
strict-mode promotion, and the unescapable-field case, so leave the `errors`, `warnings` and `strict`
parameters in the signature from the start rather than adding them later. Follow `model.lint()`'s house
convention of accumulating into lists rather than raising.

`render_gift(qs, strict=False)` walks the items in the order `model.load()` returned them, calls
`gift_item` for each, joins the returned blocks with a blank line between them, and returns the
document text together with the accumulated errors and warnings. It writes nothing: the whole document
is assembled in memory and handed back, which is what makes an item that fails mid-transform abort
before any output file exists.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
