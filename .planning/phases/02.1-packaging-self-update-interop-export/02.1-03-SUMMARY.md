# Phase 02.1 Plan 03: The daemon's app-window branch, and the whole phase's settings contract Summary

**`daemon.window` (app/tab) plus a corrected phase-number annotation on `update_policy` land in one settings-schema edit, and `surfaces/launcher.py` gives `itembank daemon` a frameless Chromium `--app=` window with a tab fallback -- both former `webbrowser.open()` call sites in `surfaces/daemon.py` now route through one decision point.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 3
- **Files modified:** 7 (2 created, 5 modified)

## Accomplishments

- `schemas/settings.schema.json`: `daemon.window` (enum `app`/`tab`, default `app`), a new non-required `update` group (`repo` default `onionviolet/itembank`, `check_interval_hours` 1-720 default 24), and `update_policy`'s `x-itembank-phase` corrected from `12` to `2.1` with a description that states what the two enum values actually do instead of calling the key inert
- `surfaces/settings.py`: `THIS_PHASE` bumped from `2` to `2.1` (a float, confirmed by grep as the constant's only two call sites, both tolerant of a non-integer compare)
- `itembank.json`: dogfoods `check_on_launch`, `daemon.window: "app"`, and the `update` group -- deliberately different from the schema's own `opt_in` default (D-13)
- `surfaces/launcher.py` (new): `find_browser()` (registry-first on Windows via `winreg`'s `App Paths` key, live-verified this session to return the real installed Chrome path where a PATH-only lookup would have found nothing; fixed `/Applications` paths plus an `mdfind` fallback on macOS; `shutil.which()` across a name list on Linux) and `open_window(url, window, no_open)`, the one function that decides app-mode-window vs. tab vs. no-browser-fallback vs. opt-out
- `surfaces/daemon.py`: both former `webbrowser.open()` call sites (`start_server()`'s already-running branch and `serve_scoped()`'s 0.4-second timer) now call `launcher.open_window()`; `cmd_daemon` reads `daemon.window` from settings and computes its effective no-open as `--no-open` combined with `cfg["daemon"]["open_browser"]` -- the first reader `open_browser` has ever had
- `tests/config_roundtrip.py`: the seventh settings group (`update`) added to the expected key set, plus a new regression test asserting `update_policy`/`daemon.window`/`update.repo`/`update.check_interval_hours` never print `inert` in `itembank config`'s table (RESEARCH Pitfall 8)
- `tests/launcher_roundtrip.py` (new): detection tolerance (path-or-`None`, never raises), Windows registry-preference, and every `open_window` branch (app spawn, tab setting, no-browser fallback, spawn-failure fallback, opt-out) -- all against a mocked `subprocess`/`webbrowser`, no real browser launched

## Decisions Made

- The plan's `read_first` for Task 2 pointed at `_bind()`'s "already-running branch" for the first `webbrowser.open()` call site, using line numbers CONTEXT.md itself flags as unreliable ("re-locate rather than trusting the numbers"). The actual code has no browser-opening logic in `_bind()` at all -- the already-running branch lives in `start_server()`. Wired `start_server()` and `serve_scoped()` (the two functions that actually call `webbrowser.open()`) with the `window` parameter instead of adding a dead, unused parameter to `_bind()`. Both plan acceptance criteria ("`surfaces/daemon.py` calls `launcher.open_window` at both former browser-open sites") and CONTEXT.md's own caveat are satisfied by this reading.
- `cmd_daemon`'s effective no-open is `a.no_open or not cfg["daemon"]["open_browser"]` -- `--no-open` and `open_browser: false` both suppress opening, and `open_browser` now has its first reader in the codebase (confirmed zero readers by grep before this task, per CONTEXT.md/the plan's own note).

## Known Gaps

- **DEL-03's real-window visual check is unperformed, not merely deferred.** The plan's Task 2 `<human-check>` asks that `itembank daemon .` be run on this machine with Chrome installed, observed to open a genuinely chromeless window with working minimize/maximize/close, then repeated with `daemon.window` set to `tab` and with `daemon.open_browser` set to `false`. This session verified `find_browser()` returns the real installed Chrome path via the registry and that `open_window`'s spawn argv is exactly `[chrome_path, "--app=" + url]` under a mocked `subprocess.Popen`, but did not visually confirm the actual GUI window. This matches the phase's own `must_haves.truths` backstop item ("Whether a slow browser cold-start needs any 'opening...' text... unverified") and the flagged planner assumption A-DEL-03 (spawn-failure behavior asserted only via a simulated `OSError`, never a real locked profile). Recommend a manual pass: `python itembank.py daemon .`, then `itembank config set daemon.window tab` and rerun, then `itembank config set daemon.open_browser false` and rerun.
