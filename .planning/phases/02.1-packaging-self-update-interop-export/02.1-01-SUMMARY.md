# Phase 02.1 Plan 01: Packaging Tracer -- resources.py, build.py, itembank.__version__, launchers/itembank.bat Summary

**A single `python build.py` produces a double-clickable `.pyz` that runs every existing itembank command from outside the checkout, closing the `__file__`-relative schema-read bug that broke `config` and `schema item` inside a zipapp archive.**

## Performance

- **Duration:** ~20 min
- **Started:** 2026-08-07T22:29:12-05:00 (first task commit)
- **Completed:** 2026-08-07T22:34:48-05:00 (last task commit)
- **Tasks:** 3
- **Files modified:** 9

## Accomplishments
- `resources.py`: the one bundled-resource reader (`ROOT`, `archive_path()`, `read_bytes()`, `read_text()`), verified to close the `FileNotFoundError` that `itembank config` and `itembank schema item` raised inside a `.pyz` before this plan
- `surfaces/settings.py` and `surfaces/protocol_cli.py` rewired off their own `__file__`-relative `SCHEMA_DIR`/`SCHEMA_PATH` computations onto `resources.read_text()`
- `itembank.__version__ = "0.3.0"`, added to `__all__` in sorted position; `surfaces/cli.py` gained a top-level `--version` flag that reads it (lazily imported to avoid a circular import through the built `.pyz`'s `__main__.py`)
- `build.py`: `STAGE_FILES`/`STAGE_DIRS` allowlists, `MAIN_TEMPLATE`, `stage()`, `build()`, `sha256sums()`, `copy_launchers()`, `main()` -- one command producing `dist/itembank-<version>.pyz` plus `dist/SHA256SUMS.txt` covering both the artifact and `launchers/itembank.bat`
- `launchers/itembank.bat`: probes `py -3` once for Python 3.11+, prints the UI-SPEC-locked failure sentence and `pause`s on failure, otherwise runs `py -3 "%~dp0itembank.pyz" %*`
- `tests/packaging_roundtrip.py`: builds a real artifact into a temp directory and drives it as a subprocess, proving DEL-01/DEL-02 rather than asserting them by inspection

## Decisions Made
- `itembank.__version__` starts at `0.3.0` (first release ever cut from this repo, deliberately pre-1.0)
- `--version`'s `itembank` import is lazy and scoped inside `main()`, not module-level, because the built `.pyz`'s `__main__.py` imports `surfaces.cli` directly (not `itembank.py`), and a module-scope `from itembank import __version__` there would trigger a circular import back into a partially-initialized `surfaces.cli`
- `build.py` excludes itself from `STAGE_FILES` -- it is dev-time tooling only, never shipped inside the artifact it builds
