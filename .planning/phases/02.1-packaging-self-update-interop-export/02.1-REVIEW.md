## Warnings

### WR-01: `check_latest()` raises on a 200 response that is not JSON, breaking the module's "nothing here raises" contract

**File:** `surfaces/update.py:325`

**Issue:** `return json.loads(resp.read().decode("utf-8"))` is inside the `try`
whose `except` clauses only catch `urllib.error.HTTPError`, `URLError`,
`TimeoutError`, and `OSError`. A clean 200 carrying a non-JSON body (an HTML
error page from a proxy/captive portal, a truncated or corrupted response, a
GitHub-side outage returning an HTML page) raises `JSONDecodeError`
(`UnicodeDecodeError` for undecodable bytes) out of `check_latest`. Verified
by direct execution: a 200 with `b"<html>not json"` raises
`JSONDecodeError`. The module docstring promises "Returns the parsed JSON
document, or `None` on anything short of a clean 200" and "Nothing here
raises." `background_check` happens to swallow it via its outer `except
Exception`, but `cmd_update` calls `check_latest` directly with no wrapper,
so `itembank update` crashes with a traceback instead of printing the
documented offline line. This is exactly the "an update check must never
reach a caller as an exception" invariant stated at the top of the module.

**Fix:** Catch decode failures inside `check_latest` and return `None`:
```python
try:
    with _open_request(req, timeout=timeout) as resp:
        status["reached"] = True
        if resp.headers.get("X-RateLimit-Remaining") == "0":
            status["rate_limited"] = True
            return None
        try:
            return json.loads(resp.read().decode("utf-8"))
        except (ValueError, UnicodeDecodeError):
            return None
except urllib.error.HTTPError as exc:
    ...
```

### WR-02: `should_check()` raises TypeError on a non-string `checked_at` in the check-state record, contradicting its degrade-not-raise docstring

**File:** `surfaces/update.py:361-366`

**Issue:** `datetime.strptime(state["checked_at"], ...)` raises `TypeError`
when `checked_at` is a JSON number or array (the check-state record is
deliberately not schema-validated). The `except (KeyError, ValueError)` does
not catch `TypeError`, so `should_check` propagates. Verified by direct
execution: a check_state.json of `{"checked_at": 123}` raises `TypeError`.
The docstring claims "should_check treats an unparseable timestamp as no
timestamp at all"; instead, every `background_check` launch raises inside
`should_check`, is swallowed by the outer catch, and silently never checks
again (no clock is stamped either, so the failure repeats every launch).

**Fix:** Guard on type before parsing:
```python
checked_at = state.get("checked_at")
if isinstance(checked_at, str):
    try:
        parsed = datetime.strptime(checked_at, "%Y-%m-%dT%H:%M:%SZ")
        candidates.append(parsed.replace(tzinfo=timezone.utc))
    except ValueError:
        pass
```

### WR-03: `sessions_by_bank()` crashes the daemon's index page on a session file with an unhashable `bank` value

**File:** `surfaces/daemon.py:429`

**Issue:** `stem = by_abspath.get(data.get("bank"))` assumes `bank` is a
string (a dict key must be hashable). A `session_*.json` whose `bank` field
is a JSON array or object raises `TypeError: unhashable type: 'list'`, which
propagates out of `handle_index` (no handler-level try/except) and kills the
request thread serving `GET /`. Verified by direct execution. The function's
own docstring promises that a session file "whose `bank` no longer matches
anything scanned ... is skipped rather than raised." The file only needs to
exist in `<root>/_attempts/`; this is reachable from any local process that
can write there and, on a `--lan` daemon, breaks the landing page for every
visitor.

**Fix:** Type-check before the lookup:
```python
bank = data.get("bank")
stem = by_abspath.get(bank) if isinstance(bank, str) else None
if stem is None:
    continue
```

### WR-04: `update_manifest.schema.json` accepts any `path` string, so the manifest provides none of the traversal defense `handoff()` relies on

**File:** `schemas/update_manifest.schema.json:26-29` (used by `surfaces/update.py:654`)

**Issue:** `read_check_state()`'s own docstring justifies validating the
manifest because "`handoff()` spawns the artifact it names, so a malformed
pointer there is a code-execution question." But the schema's `path`
property is an unconstrained string -- no pattern, no format. Verified:
`path: "../../../../tmp/evil.py"` passes `schema_validate.validate` with zero
errors, `read_manifest` accepts the document, and `handoff` resolves the
target to a path outside `update_root()` (demonstrated: resolved to
`...\AppData\Local\escape_target.py` with `base` elsewhere). The only
remaining guards are the digest match and `is_newer`, both of which an
attacker who can write `updates/current.json` can satisfy (they can also
write the payload). Exploitation requires local write access -- same trust
domain as the artifact itself -- so this is not an escalation, but the
schema validation is currently pure ceremony for the one field that gates
process spawn. Note `schema_validate.SUPPORTED` does not include `pattern`,
so adding a pattern also requires extending the validator.

**Fix:** Constrain the path to this project's own layout, and fail closed in
`handoff` as defense in depth:
```python
# schemas/update_manifest.schema.json
"path": {
    "type": "string",
    "pattern": "^versions/[A-Za-z0-9._-]+$",
    ...
}
```
```python
# surfaces/update.py handoff(), after resolving target
base_abs = os.path.abspath(base)
if os.path.commonpath([target, base_abs]) != base_abs:
    return None
```
(Add `pattern` to `schema_validate.SUPPORTED`, which currently rejects it.)

### WR-05: `cmd_update` reports "up to date" when a newer release exists but carries no matching asset

**File:** `surfaces/update.py:753-756`

**Issue:** Carried from the previous review (WR-01) and still open: `asset is
None` is folded into the same branch as `offered == running_parsed`, printing
"itembank is up to date". A release tagged `vX.Y.Z` whose asset is misnamed,
missing, or renamed is a publishing-side packaging mistake, and the learner
is told they are current instead of being pointed at the release page -- a
silent masking of a real update.

**Fix:** Distinguish the cases:
```python
if offered == running_parsed or offered is None or running_parsed is None:
    print("itembank is up to date (%s)." % running_display)
    return 0
if asset is None:
    print("A newer itembank version (%s) exists but has no downloadable "
          "artifact for this platform -- check the release page directly."
          % latest_display)
    return 0
```

### WR-06: `read_manifest()`'s "never raising" contract does not cover a missing bundled schema or a `SchemaError`

**File:** `surfaces/update.py:205-207`

**Issue:** Carried from the previous review (WR-02) and still open: the
docstring promises `read_manifest` "never raising", but
`resources.read_text(MANIFEST_SCHEMA_RESOURCE)` raises `FileNotFoundError`
if `schemas/update_manifest.schema.json` is missing from a corrupted install
or a `.pyz` built with a stale `STAGE_DIRS` list, and
`schema_validate.validate` can raise `SchemaError` if the schema ever uses
an unsupported keyword. Today's schema is well-formed and staged, so this is
defense-in-depth, but every other corrupt-input path in the module degrades
to `None`, and a future schema edit could turn a startup path into an
exception.

**Fix:**
```python
try:
    schema = json.loads(resources.read_text(MANIFEST_SCHEMA_RESOURCE))
    if schema_validate.validate(raw, schema):
        return None
except (OSError, ValueError, schema_validate.SchemaError):
    return None
return raw
```

### IN-01: `_ASSET_RE` anchors with `$` instead of `\Z`

**File:** `surfaces/update.py:491`

**Issue:** Carried from the previous review (IN-02) and still open.
`re.compile(r"^itembank-\d+\.\d+\.\d+\.pyz$")` also matches a name ending in
a single trailing `\n`, which would later become a literal newline inside a
real filesystem path under `versions/`. No known exploitation path, but the

**Fix:** `_ASSET_RE = re.compile(r"^itembank-\d+\.\d+\.\d+\.pyz\Z")`

### IN-03: `itembank.desktop` does not percent-decode a `file://` `%k` value

**File:** `launchers/itembank.desktop:12`

**Issue:** `Exec=bash -c 'p="$0"; p="${p#file://}"; cd "$(dirname "$p")" ...' %k`
strips a `file://` prefix but never unquotes percent-escapes. The freedesktop
spec allows `%k` to be a URI; a downloaded desktop entry at
`file:///home/me/Downloads/My%20Folder/itembank.desktop` would resolve
`dirname` to a literal `%20` path, `cd` fails, and the launcher silently does
nothing (no error message). Environment-dependent (many desktop environments
pass a plain path for local files), but it is a real failure for the shipped
launcher on common setups.

**Fix:** Decode the URI before resolving the directory, e.g.:
```sh
p="$0"; p="${p#file://}"; p="$(python3 -c 'import sys,urllib.parse;print(urllib.parse.unquote(sys.argv[1]))' "$p")"; cd "$(dirname "$p")" && ...
```
(python3 is guaranteed present by the probe that follows.)

### IN-04: Several file reads/writes do not use context managers

**File:** `surfaces/update.py:202,254`; `surfaces/settings.py:113`;
`surfaces/gift.py:253`; `surfaces/anki.py:44`; `resources.py:40`;
`build.py:94-95`

**Issue:** `json.load(open(path, ...))` and `open(...).write(...)` leave the
handle to reference counting / GC instead of deterministic close. On CPython
the handle closes promptly, so this is not currently a leak, but it emits
`ResourceWarning`s under `-W error::ResourceWarning` and is inconsistent with
the tmp-then-`os.replace` writers elsewhere in the same modules, which all use
`with`.

**Fix:** Wrap every open in `with open(...) as fh:`, including
`json.load` calls:
```python
with open(path, encoding="utf-8") as fh:
    raw = json.load(fh)
```
