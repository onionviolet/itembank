# Phase 02.1 Plan 02: macOS/Linux Launcher Shims, Executable-Bit Packaging, README Coverage Summary

**`launchers/itembank.command` and `launchers/itembank.desktop` complete the three-OS launcher set DEL-01 requires, with `build.py` preserving the `.command` shim's executable bit through the copy and a new `.gitattributes` rule protecting its shebang from Windows line-ending corruption.**

## Accomplishments
- `launchers/itembank.command`: bash shim that resolves its own directory from `$0`, probes `python3` for 3.11+, prints the UI-SPEC-locked failure sentence and holds the Terminal open with `read -p` on failure, and `exec`s into `python3 itembank.pyz` on success
- `launchers/itembank.desktop`: freedesktop entry (`[Desktop Entry]`, `Type=Application`, `Terminal=true`, `Categories=Education;`) whose `Exec=` resolves its own directory from the `%k` field code, runs the identical probe, and prints the same locked sentence word-for-word
- `build.py`: `LAUNCHERS_DIR` renamed to `LAUNCHER_DIR` per the plan's acceptance criteria; `copy_launchers()` now re-applies the source file's mode to the destination on POSIX so a shipped `.command` keeps its executable bit
- `.gitattributes` (new, not in the plan's file list — added as a Rule 2 fix): forces `text eol=lf` on both new shims, because this dev machine's `core.autocrlf=true` would otherwise silently rewrite the working-tree copy to CRLF on the next checkout, breaking the `#!/bin/bash` shebang and the `Exec=` line the moment anyone else clones the repo
- `README.md`: new "Install and run (release)" section — release contents, the Python 3.11+ requirement stated without hedging, the Windows/macOS/Linux double-click paths, the Gatekeeper quarantine workaround with `V2-DEL-01` named as the deferral reason, and the `sha256sum -c SHA256SUMS.txt` verify command
- `tests/packaging_roundtrip.py`: `test_every_launcher_ships` (every file in `build.LAUNCHER_DIR` lands in the built release directory and in `SHA256SUMS.txt` with a matching digest, read via `os.listdir()` so a fourth shim needs no test edit) and `test_launchers_carry_the_locked_failure_sentence` (all three shims carry the identical sentence, each names its interpreter explicitly — `py -3` on Windows, `python3` on the other two)

- Added `.gitattributes` (Rule 2 — missing critical functionality): without it, `git`'s own line-ending normalization on this Windows dev machine would corrupt the macOS/Linux shims' shebang/Exec line on the very next checkout, which is exactly the kind of silent breakage `02.1-CONTEXT.md`'s "double-click must fail with a clear message, never a silent no-op" framing warns against — except here the corruption would happen before the shim even reaches a user

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Added `.gitattributes` to pin LF line endings on the two new shims**
- **Found during:** Task 1, immediately after `git add launchers/itembank.command`
- **Issue:** `git status` warned "LF will be replaced by CRLF the next time Git touches it" — this machine's `core.autocrlf=true` combined with no existing `.gitattributes` means a future checkout (by this same machine or any Windows contributor) would silently rewrite the bash shebang and the desktop `Exec=` line to CRLF, breaking both shims outright since `build.py`'s `copy_launchers()` copies the working-tree file verbatim into the release directory
- **Fix:** Added `.gitattributes` with `text eol=lf` for both `launchers/itembank.command` and `launchers/itembank.desktop`, then re-staged so the committed blobs and any future checkout stay LF-only
- **Files modified:** `.gitattributes` (new)
- **Verification:** Read the blob back via `git show :launchers/itembank.command` and confirmed no `\r` bytes present; `git ls-files -s` shows `100755` for the `.command` shim
- **Committed in:** `7afe7c0` (Task 1 commit)
