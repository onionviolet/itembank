## GIFT `multi` Scoring Divergence

Alternatives on the table, from RESEARCH Choice Point 9:

| Option | Description | Selected |
|--------|-------------|----------|
| Warn and export | Weighted GIFT encoding plus a non-fatal per-item warning. Research leaned here. | partial |
| Fail loudly | Treat `multi` as inexpressible alongside `build`. Conservative but forecloses exporting any bank containing `multi`. | partial |
| Both, behind a flag | Warn-and-export by default, `--strict` promotes warnings to failures. | ✓ |

**Rationale:** the two originals trade usability against a correctness guarantee, and
the steering instruction asks for the option that keeps doors open. One branch buys
both behaviors. `build` still always fails loudly in either mode — no flag makes it
exportable, since Success Criterion 5 depends on that.

## Release & Version Identity

| Option | Description | Selected |
|--------|-------------|----------|
| `__version__` constant in `itembank.py` | Importable, works inside a `.pyz`, single source for updater/banner/build script. | ✓ |
| `VERSION` text file inside the zip | Equivalent at runtime, one more file to keep in sync. | |
| Derive from git tag at build time | Couples runtime to a build step the project deliberately avoids. | |

Repository visibility of `onionviolet/itembank` was **not verified** this session.
Resolved by not depending on it: owner/name come from settings with a default, and an
optional `ITEMBANK_GITHUB_TOKEN` environment variable covers a private repo and also
lifts GitHub's 60-request/hour unauthenticated limit. Token never lands in the
checked-in `itembank.json`.

Tag format locked to plain `vX.Y.Z` with no suffixes, because Choice Point 7's
integer-tuple comparison cannot parse `v1.3.0-rc1`. Flagged one-way: a suffixed tag
published once is visible to every installed updater forever, so the parser must skip
unparseable tags rather than crash.

## Launch & Update Behavior

| Option | Description | Selected |
|--------|-------------|----------|
| App-mode hardcoded on for all launches | Simplest, no way to turn off without editing code. | |
| App-mode only from the OS launcher | Two divergent launch paths to maintain. | |
| `daemon.window` enum setting, default `"app"` | One code path; switchable without a code change. | ✓ |

Install root resolved as: beside the running `.pyz` when writable, falling back to
`%APPDATA%` / `$XDG_DATA_HOME` — reusing `surfaces/day.py:339-343` rather than adding a
second platform-directory implementation. Keeps a portable copy self-contained while
still allowing updates from a read-only install location.

`update_policy` schema default stays `opt_in` so a fresh install never phones home
unasked; this repo's own `itembank.json` flips to `check_on_launch` so the updater gets
exercised through Phases 3–11, which is why the phase was pulled forward.
