# Phase 02.1 Plan 04: GIFT Export -- Escape Function, Five Renderers, CLI Wiring, Golden-File Tests Summary

**A second `itembank export --format gift` produces a deterministic, byte-diffable GIFT document for the five item types GIFT can express, with a single `gift_escape()` function guarding every user-authored field and a non-fatal warning naming every `multi` item's scoring-semantics divergence.**

## Accomplishments
- `surfaces/gift.py`: `GIFT_ESCAPE`/`gift_escape()` (the one canonical escaping function), `gift_name()`, `gift_mc()`, `gift_multi()`, `gift_matching()`, `gift_short()`, `gift_item()`/`render_gift()` (dispatch and in-memory document assembly), and `export_gift()` (the CLI command body)
- `mc` renders `=`/`~` markers with per-option feedback and a `####` general-feedback line; `multi` uses GIFT's weighted-answer encoding (100/N for each correct option, -100 for each incorrect, five-decimal-then-trimmed for determinism); `table`/`dnd` render as GIFT `matching` with repeated categories preserved across rows; `short` renders a single-line answer block
- `itembank export` gained `--format gift` and a `--strict` flag (wired through, not yet acting -- see Decisions) on the existing subparser; `surfaces/anki.py:cmd_export()` delegates to `gift.export_gift()` when the format is `gift`, leaving the Anki TSV paths untouched
- `export_gift()` prints one of two locked status lines depending on whether anything was skipped, and returns exit code 1 when anything was, 0 otherwise -- a partial export can never read as a complete one to a script
- `multi` items emit a non-fatal, item-numbered scoring-divergence warning and are still written to the file; `build` items (and any future unrecognized type) are skipped with a per-item error, never silently dropped
- `fixtures/gift_escapes_bank.md`: a synthetic six-item-type bank carrying every character in the GIFT escape set (`~ = # { } : \`) across a stem, option text, matching row text, a category name, and a short item's model answer; lints clean
- `tests/gift_export_roundtrip.py`: exact golden-string renders for all five expressible types over `sample_bank.md`, a field-driven escape-set scan over the new fixture, repeated-category matching preservation, byte-deterministic export via the real CLI, the multi divergence warning named by item number, and a mechanical no-second-scorer/no-second-parser check

## Decisions Made
- `gift_item()`'s handling of `build` (and any future unrecognized type) is one generic fallback branch appending `"Q<n>: type %r has no GIFT equivalent -- not exported"`, not a build-specific case with the fully polished refusal contract -- the important_note attached to this plan explicitly reserves the tailored `build` refusal wording, `--strict` promotion, and unescapable-field detection for plan 02.1-06
- `--strict` exists as a CLI flag and is threaded through `render_gift()`/`gift_item()`'s signature (per Task 1's own instruction to add the parameter now rather than later), but has no effect yet -- promoting the `multi` divergence warning to a per-item failure under `--strict` is explicitly plan 02.1-06's job
- `export_gift()` returns exit code 1 when anything was skipped, 0 otherwise (the plan's own resolution of an unspecified gap: the UI-SPEC names no exit code, `cmd_lint` already sets the precedent of returning 1 on errors, and a partial export that exits 0 would be indistinguishable from a complete one to anything not reading stdout)
- GIFT's `####` general-feedback line is emitted only by `gift_mc()`/`gift_multi()`; `gift_matching()` (table/dnd) and `gift_short()` render no such line, because GIFT's own grammar has no general-feedback slot for `matching`/short-answer, so `why`/`model` text is not force-fit into a syntax position that doesn't exist for those types

## Issues Encountered

Task 3's first draft of `test_every_escape_set_character_is_escaped` scanned the whole rendered document character-by-character and flagged GIFT's own structural syntax (`::Qn::` name delimiters, `{`/`}` block braces, `=`/`~`/`#`/`####` markers) as "unescaped," which is correct GIFT syntax rather than a bug -- these characters are deliberately unescaped by design since they are not user-authored text. Redesigned the test to check, per user-authored field (stem, option text, row text, category, model answer), that the field's `gift_escape()`-transformed form appears verbatim in the rendered document, which correctly distinguishes structure from content and is still a generic scan over `ESCAPE_CHARS` rather than seven hand-written literals.
