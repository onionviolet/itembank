## Flagged planner assumption (unresolved edge, surfaced not dropped)

The deterministic edge probe returned `unclassified` for DEL-03, so no acceptance criterion was
auto-derived for it.

- **A-DEL-03 — the boundary of "frameless".** Assumed to mean a Chromium `--app=` window: the OS
  title bar is retained, the browser's own tabs, address bar and bookmarks bar are hidden. This is the
  conventional meaning in this space and matches Success Criterion 1's intent, but it is not a literal
  borderless or kiosk window; `--kiosk` was rejected because it removes ordinary close and resize,
  which is worse for a tool the learner opens and closes repeatedly (RESEARCH Choice Point 3 caveat).
  **Unverified:** behaviour when a Chromium browser is found but fails to launch — a locked profile,
  a broken install, a sandbox refusal. This plan treats any `OSError` from the process spawn as the
  tab fallback; that path is asserted with a simulated failure in the test, not against a real locked
  profile.

Create `surfaces/launcher.py`: a small utility module whose only job is deciding what container the
daemon's page opens in. Give it a docstring stating the invariant — this module chooses a container,
never a page; the daemon is unaware which one it got — and the reason there is no dependency here:
a `--app=` shell-out to a browser the machine already has costs nothing, and the only real
webview library would be a third named exception to the stdlib-only constraint.

Declare three constants. `CHROME_NAMES` is the POSIX binary-name preference order:
`google-chrome-stable`, `google-chrome`, `chromium`, `chromium-browser`, `microsoft-edge`.
`WINDOWS_APP_PATHS` is the registry subkey preference order under
`SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths` — the Chrome executable name first, then the
Edge executable name. `MAC_BROWSERS` is the fixed executable path preference order inside
`/Applications` for Chrome then Edge then Chromium.

`find_browser()` returns a path string or `None`, branching on `sys.platform` the same three ways
`surfaces/day.py` already does. On `win32`, import `winreg` inside the function (it does not exist on
other platforms) and query each subkey in `WINDOWS_APP_PATHS` against `HKEY_CURRENT_USER` then
`HKEY_LOCAL_MACHINE`, returning the default value of the first key that opens; catch `OSError` per
attempt and continue. This ordering is not optional: a live registry query this session found both
Chrome and Edge where a PATH lookup for the same two browsers found neither, on a machine where both
are installed at their standard locations. Fall through to a PATH lookup for the same two names.
On `darwin`, return the first entry of `MAC_BROWSERS` that exists on disk, then fall through to an
`mdfind` query for the Chrome bundle identifier for a non-default install location, guarding the
subprocess call so a missing or slow `mdfind` returns `None` rather than raising. Otherwise, return
the first `shutil.which()` hit across `CHROME_NAMES`. Return `None` when nothing is found — that is a
normal outcome, not an error.

`open_window(url, window="app", no_open=False)` is the one decision point and returns what it did, so
a test can assert the branch taken without a real window appearing. Return `None` immediately when
`no_open` is true — this is the opt-out and nothing may run past it. When `window` is `tab`, call
`webbrowser.open(url)` and return `"tab"`. Otherwise call `find_browser()`; when it returns a path,
spawn `subprocess.Popen([browser, "--app=" + url])` and return `"app"`, catching `OSError` and falling
through on failure. The final fallthrough calls `webbrowser.open(url)` and returns `"tab"`. Reference
`subprocess.Popen` and `webbrowser.open` through their module attributes rather than importing the
names directly, so a test can substitute either one.

Wire both existing call sites in `surfaces/daemon.py`. Add a `window` keyword parameter defaulting to
`"app"` to `_bind` and to `serve_scoped`, threading it through the call `serve_scoped` makes into

window, no_open)`, and replace `serve_scoped`'s timer body so the deferred call is
`launcher.open_window(url, window, no_open)` — keep the same 0.4-second `threading.Timer` delay that
every launch has used, because the delay exists so the socket is accepting before anything points at
it. Leave the `webbrowser` import in place only if something else still uses it; otherwise remove it,
since the module's browser-opening responsibility now lives in one place.
