## Flagged planner assumptions (unresolved edges, surfaced not dropped)

The deterministic edge probe returned `unclassified` for DEL-01 and DEL-02, so no acceptance
criterion was auto-derived for them. These are the planner's own assumptions, recorded rather than
silently resolved:

- **A-DEL-01 — the boundary of "double-clickable".** Assumed to mean: a machine that already has
  Python 3.11+ installed and reachable as `py -3` (Windows) or `python3` (POSIX). No interpreter is
  bundled; `zipapp` cannot bundle one and DEL-02 forbids the tools that can. **Unverified:** RESEARCH
  assumption A3 — whether a Python installed from the Microsoft Store, a portable zip, or with file
  associations declined still runs the raw `.pyz` on double-click. The `.bat` shim is therefore
  treated as the primary Windows launch path, not a backup.
- **A-DEL-02 — the boundary of "plain Python inside".** Assumed to mean: every `.py` member of the
  archive decodes as UTF-8 source, `zipapp` is invoked with no compression, and no `.pyc` or
  `__pycache__` member is staged. **Unverified:** whether a person or agent who edits a file inside
  the archive and re-zips it produces a still-runnable `.pyz` — this plan asserts readability and
  editability of the members, not a full edit-and-rezip round trip.

Three pieces, in this order, because each one is a precondition of proving the next.

**Piece 1 — `resources.py` at the repository root.** A new top-level module holding the one way this
codebase resolves a bundled non-Python resource. It exists because a path computed from `__file__`
names a real file in a checkout and names a member inside an archive when the same code runs from a
`.pyz`, and `open()` cannot read the second. Verified this session: `itembank config` and
`itembank schema item` both raise `FileNotFoundError` from inside a `zipapp` archive today.

Give it a module docstring in the established voice stating that invariant. Define `ROOT` as
`os.path.dirname(os.path.abspath(__file__))` — in a checkout that is the repository root; inside a
`.pyz` that is the archive path itself, because `resources.py` sits at the archive's top level.
Define `archive_path()` returning `ROOT` when `zipfile.is_zipfile(ROOT)` is true and `None`
otherwise; the updater in a later plan uses this to answer "am I running from a `.pyz`, and where is
it". Define `read_bytes(relpath)`: join `relpath` onto `ROOT` and return the file's bytes when that
path exists; otherwise, when `archive_path()` is not `None`, open the archive with `zipfile.ZipFile`
and return the member named by `relpath` with forward slashes; otherwise raise `FileNotFoundError`
naming the joined path. Define `read_text(relpath)` as `read_bytes(relpath).decode("utf-8")`. Keep
the module dependency-free apart from `os`, `sys` and `zipfile` — nothing in the four-layer model may
import it in the other direction.

**Piece 2 — rewire the two `__file__`-relative schema reads.** In `surfaces/settings.py`, replace the
`SCHEMA_DIR`/`SCHEMA_PATH` pair with a `SCHEMA_RESOURCE` constant naming the archive-relative path
`schemas/settings.schema.json`, and make `load_schema()` parse `resources.read_text(SCHEMA_RESOURCE)`.
`cmd_config`'s `schema` action reads the same file a second time to print it verbatim — route that
through `resources.read_text(SCHEMA_RESOURCE)` too, keeping the `print(..., end="")` shape so the
printed bytes are unchanged. In `surfaces/protocol_cli.py`, make `_schema_path`/`_load_schema_text`
resolve `schemas/<name>.schema.json` through `resources.read_text()` on the same terms; the command's
contract is "the bytes on disk, printed verbatim", and reading them out of the archive keeps that
true. Do not add a second reader helper in either module and do not leave a fallback `open()` path
behind — one reader, both call sites, matching this codebase's own one-function-per-rule precedent.

**Piece 3 — `itembank.__version__` and `build.py`.** In `itembank.py`, add
`__version__ = "0.3.0"` as a module-level constant above the imports with a comment stating D-07's
release-process constraint in one line: releases are tagged plain `vX.Y.Z` with no pre-release or
build suffix, because the updater compares version components as integers. Add `"__version__"` to
`__all__` in its existing sorted position among the uppercase names. `0.3.0` is the first release
ever cut from this repository — there is no prior tag, no `VERSION` file and no existing constant to
migrate — and it is deliberately below `1.0.0` because the v1.0 milestone's twelve phases are not
complete.

Create `build.py` at the repository root: dev-time tooling, imported by nothing at runtime, and
therefore not staged into the artifact it builds. Its docstring records two things a code comment
alone would lose: that the release tag format is plain `vX.Y.Z` with no suffixes (D-07), and that the
artifact filename, the checksum file and `itembank.__version__` are emitted together from this one
script specifically so they cannot drift apart (D-08). Define `STAGE_FILES` as the explicit tuple of
root-level modules that belong in the archive — `itembank.py`, `model.py`, `runtime.py`, `server.py`,
`evidence.py`, `schema_validate.py`, `resources.py` — and `STAGE_DIRS` as `("surfaces", "schemas")`.

private bank out of the artifact. Copy directories with `shutil.copytree` passing

`MAIN_TEMPLATE` is the source of the `__main__.py` written into the staging directory: insert the
archive's own directory onto `sys.path`, then import and call `surfaces.cli.main`. Keep it four lines

is a template that will be edited badly.

`stage(tmpdir)` copies the allowlists in. `build(out_dir)` stages into a `tempfile.mkdtemp()`, writes
`__main__.py` from `MAIN_TEMPLATE`, calls `zipapp.create_archive(stage_dir, target, interpreter="/usr/bin/env python3")` with no `compressed` argument so the members stay stored uncompressed and
readable, and returns the artifact path — `dist/itembank-<__version__>.pyz` by default.
