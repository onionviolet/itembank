### `surfaces/gift.py` (or `surfaces/anki.py` new branch) — service, transform

**Analog:** `surfaces/anki.py` (full file, 44 lines — read in one pass)

**Imports pattern** (lines 1-9):
```python
"""Anki TSV export: Basic and Cloze, generic to any bank.
...
"""
import os, re, sys

from model import lint, load
from runtime import answer_text
```
GIFT export should mirror this: `from model import lint, load`, and pull whatever
`runtime` accessors it needs (`answer_text`, `canonical_key`) — never re-parse or
re-score.

**Core CRUD/transform pattern** (lines 16-43, `cmd_export`):
```python
def cmd_export(a):
    qs = load(a.bank)
    errors, _ = lint(qs)
    if errors and not a.force:
        sys.exit("refusing to export a bank with errors; fix them or pass --force")
    rows = []
    for q in qs:
        ...
    os.makedirs(os.path.dirname(a.out) or ".", exist_ok=True)
    open(a.out, "w", encoding="utf-8").write("\n".join(header + rows) + "\n")
    print("%d items -> %s" % (len(qs), a.out))
    return 0
```
GIFT export copies this exact shape: `load()` → `lint()` gate with `--force` escape
hatch → per-item dispatch loop → `os.makedirs` → single write → the **locked**
`"%d items -> %s"` status line (`02.1-UI-SPEC.md` requires this reused verbatim). The
`--format gift` branch is a sibling of the existing `basic`/`cloze` branches in the
same `cmd_export`, per RESEARCH's recommended structure — CONTEXT.md's canonical_refs
frames this as "a second `--format` branch in this same shape, not a new command
family."

**Error handling pattern** (loud, by item number — new for this file, no existing
analog in `anki.py` since Anki export has no per-item failure mode):
```python
def gift_export_item(q, errors):
    if q["type"] == "build":
        errors.append("Q%d: type 'build' (ordering) has no GIFT equivalent -- "
                      "cannot export" % q["number"])
        return None
    ...
```
(from RESEARCH.md's own skeleton, `02.1-RESEARCH.md` lines ~747-761) — follow the
existing `lint()` convention of accumulating `(errors, warnings)`-shaped lists rather
than raising, since `model.lint()` is the house pattern for "collect, don't throw."

**GIFT escaping — single canonical function** (RESEARCH Pattern 3, mirrors the
project's own "one scorer, one canonical function" philosophy that `canonical_response()`
embodies):
```python
import re
_GIFT_ESCAPE = re.compile(r"([~=#{}:\\])")
def gift_escape(text):
    return _GIFT_ESCAPE.sub(r"\\\1", text or "")
```
Every user-authored text field (stem, option text, `why`, category names) must route
through this one function — never re-implemented per item type.

**Item field shapes to read (never re-derive):** `runtime.py` — `canonical_key(q)`
(line 103), `score_response(q, answer)` (line 120), `answer_text(q)` (line 219). GIFT
export reads `q["type"]`, `q["opts"]`, `q["correct"]`, `q["da"]`, `q["rows"]` (table/dnd),
`q["number"]`, `q["stem"]` directly off the dict `model.load()` returns — the same dicts
every other surface consumes, never a second parse.

### `surfaces/update.py` (new) — service, file-I/O + request-response

**Analog A (atomic write):** `surfaces/settings.py:write_settings()` (lines 125-139)
```python
def write_settings(base, data):
    target = settings_path(base)
    target_dir = os.path.dirname(os.path.abspath(target))
    os.makedirs(target_dir, exist_ok=True)
    tmp = target + ".tmp"
```

**Analog B (platform data directory):** `surfaces/day.py:336-354` (`_anki_addon_port`,

```python
def _anki_addon_port():
```

already implements exactly this platform-directory selection — reuse that shape, do
not invent a second one."

**Settings read pattern** — `surfaces/settings.py:load_settings()` / `surfaces/daemon.py`'s
own settings-driven default resolution (`cmd_daemon`, lines ~1125-1128 of `daemon.py`):
```python
cfg = settings.load_settings(root)
port = a.port if a.port is not None else cfg["daemon"]["port"]
lan = True if a.lan else cfg["daemon"]["lan"]
```
The updater's `owner/repo` (D-09) and `check_on_launch` policy read follow this same
"settings value, with an explicit override winning" shape: `cfg["update"]["repo"]`,
never a hardcoded string, and `os.environ.get("ITEMBANK_GITHUB_TOKEN")` for the token
— never read from `itembank.json` itself (D-09 explicit constraint).

**Error handling / offline degrade** — mirrors the project's existing "degrade, never
block" pattern already used for Anki (`surfaces/day.py`'s own doc comment: "Anki only
answers while it is open ... a closed Anki degrades to an omitted badge rather than an
error"). The updater's `check_latest()` (RESEARCH skeleton) should follow the identical
shape:
```python
try:
    with urllib.request.urlopen(req, timeout=timeout) as resp:
        return json.loads(resp.read())
except (urllib.error.URLError, TimeoutError, OSError):
    return None    # offline / unreachable -- degrade silently (DEL-07)
```

**Version-string handling** — no existing analog (repo has no `__version__` today).
`itembank.py`'s own `__all__` list-construction convention (sorted, explicit, one
place) is the closest structural precedent for *where* `__version__` should live: a
single module-level constant in `itembank.py`, added to `__all__`, per D-06.

### `surfaces/launcher.py` (new) — utility, event-driven

**Analog:** `surfaces/daemon.py`'s two existing `webbrowser.open()` call sites.

**Call site 1** (`daemon.py:1044-1053`, inside `_bind`, the "already running" path):
```python
        reserved = getattr(exc, "winerror", None) == 10013 or exc.errno == errno.EACCES
        if not reserved and probe(port):
            url = "http://127.0.0.1:%d/" % port
            print("itembank is already running at %s" % url)
            if not no_open:
                webbrowser.open(url)
            sys.exit(0)
```

**Call site 2** (`daemon.py:1108-1109`, inside `serve_scoped`, the normal-launch path):
```python
        if not no_open:
            threading.Timer(0.4, lambda: webbrowser.open(url)).start()
```

Both are the exact spots D-11's `daemon.window` branch attaches: `open_app_window(url,
no_open)` (RESEARCH Pattern 1 skeleton below) replaces the bare `webbrowser.open(url)`
call, itself falling through to `webbrowser.open()` when no Chromium browser is found
or when `daemon.window == "tab"`. CONTEXT.md: "the launcher gets no special-cased
branch — and the behavior is switchable without a code change."

**Browser detection skeleton** (RESEARCH.md Pattern 1, adapted from `eel/chrome.py`,
stdlib-only):
```python
import shutil, subprocess, sys

CHROME_NAMES = ("google-chrome-stable", "google-chrome", "chromium", "chromium-browser")

def find_chrome_windows():
    import winreg
    for hive in (winreg.HKEY_CURRENT_USER, winreg.HKEY_LOCAL_MACHINE):
        try:
            key = winreg.OpenKey(
                hive, r"SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\chrome.exe")
            return winreg.QueryValue(key, None)
        except OSError:
            continue
    return None

def open_app_window(url, no_open=False):
    if no_open:
        return
    browser = find_browser()
    if browser:
        subprocess.Popen([browser, "--app=%s" % url])
    else:
        import webbrowser
        webbrowser.open(url)
```
Windows detection is registry-first (`winreg`), never PATH-only — RESEARCH
live-verified `shutil.which("chrome")` fails on a real Windows 11 machine where Chrome
is installed at its standard path.

## Shared Patterns

### Atomic file writes (manifest, and any updater-owned JSON)
**Source:** `surfaces/settings.py:write_settings()` (lines 125-139)
**Apply to:** `surfaces/update.py` (manifest write), any new schema-validated JSON
this phase introduces. Do not write a second helper — this is the codebase's one
canonical atomic-write shape, also used identically by `runtime.write_session()`.

### Platform data directory selection
**Source:** `surfaces/day.py:336-354` (`_anki_addon_port`'s `win32`/`darwin`/else
branch)
**Apply to:** `surfaces/update.py`'s D-12 fallback root when the directory beside the
running `.pyz` is not writable.

### Degrade, never block (offline / unreachable dependency)
**Source:** `surfaces/day.py`'s Anki-closed handling (module comment above
`_anki_addon_port`, and its `None`-return-on-failure contract) — the house philosophy
CLAUDE.md itself states: "the core loop must degrade, never block ... The model layer
goes quiet when unreachable, the same way `day` omits Anki counts when Anki is closed."
**Apply to:** `surfaces/update.py`'s `check_latest()` (network failure → silent `None`,
never an exception reaching `cmd_daemon`'s startup path).

### One canonical transform function per rule
**Source:** `runtime.py`'s `canonical_response()` / `canonical_key()` / `score_response()`
— "one scorer, structurally, across every module."
**Apply to:** `gift_escape()` in the new GIFT export module — one function, every call
site, never reimplemented per item type (RESEARCH Pattern 3 explicitly names this
precedent).

### Load → lint-gate → transform → single status line
**Source:** `surfaces/anki.py:cmd_export()` (full pattern, lines 16-43)
**Apply to:** GIFT export's `cmd_export` `--format gift` branch — same `load()` /
`lint()` / `--force` gate / write / `"%d items -> %s"` status line, the last one locked
verbatim by `02.1-UI-SPEC.md`.

### Settings-value-with-explicit-override-wins
**Source:** `surfaces/daemon.py:cmd_daemon` (lines ~1125-1128):
```python
cfg = settings.load_settings(root)
port = a.port if a.port is not None else cfg["daemon"]["port"]
lan = True if a.lan else cfg["daemon"]["lan"]
```
**Apply to:** `surfaces/update.py` reading `cfg["update"]["repo"]` (D-09) and
`daemon.window` (D-11) — CLI flag, if any, wins; otherwise the settings file's value.

### Dotted, sorted, set-built error-code namespaces
**Source:** `surfaces/settings.py:SETTINGS_CODES` (lines 34-37):
```python
SETTINGS_CODES = tuple(sorted({
    "settings.invalid_type", "settings.invalid_value", "settings.out_of_range",
    "settings.unknown_key", "settings.missing_key", "settings.malformed_file",
}))
```
**Apply to:** any new error-code namespace this phase publishes (e.g., `update.*` or
`gift.*` codes, if the planner decides GIFT/update failures should be dotted-coded per
CONTEXT.md's "Named dotted error codes" established pattern).
