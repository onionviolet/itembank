<objective>
Close CR-01. The updater's token currently follows GitHub's own 302 from the release-asset endpoint onto
`objects.githubusercontent.com`, because stdlib `urllib` copies request headers across a redirect and
does no cross-host check. Route every request this module makes through one opener whose redirect
handler removes the Authorization header the moment the target host changes, and attach the token in
the first place only when the target is GitHub.

Purpose: the phase goal's own word is "safely", and DEL-06's delivery mechanism is the one place in
this project where a credential leaves the machine. 02.1-VERIFICATION.md confirmed the leak against
this project's own interpreter, not as a hypothesis. Threat entry T-02.1-22 claimed the token is
"placed only in an outbound authorization header... never written to any printed line" -- true, and
beside the point, because it reasoned about *output* and never about *redirects*. This plan supersedes
it.

Output: `AuthStrippingRedirectHandler`, the `_redirect_safe_opener` / `_open_request` seam, a
host-gated `_github_token_for`, and two tests that drive the real opener through a substituted
transport and assert what each hop carried.
</objective>

  <action>
Add `AuthStrippingRedirectHandler`, a subclass of `urllib.request.HTTPRedirectHandler` that overrides
`redirect_request` only. Call the superclass implementation first and return immediately if it returns
`None`; the superclass is what decides whether a redirect is legal at all, and this subclass does not
second-guess that. When it returns a new Request, compare the redirect target against the request the
header was set on: split both urls with `urllib.parse.urlsplit`, lowercase the scheme and the hostname,
and resolve a missing port to the scheme's default (443 for https, 80 for http) so a url that spells
its default port out does not read as a different origin. When the resulting scheme/host/port triples
are not equal, delete every key of the new Request's `headers` whose lowercase form is
`authorization`, and delete the same from its `unredirected_hdrs`. Delete case-insensitively by
iterating a copy of the key list rather than trusting a single capitalisation -- `Request` capitalises
keys it is given, but the header may also arrive from a caller-built dict.

Why an override and not a filter after the fact: stdlib's own `redirect_request` copies `req.headers`
onto the new Request and removes only content-length and content-type. It performs no host comparison
at all, which is exactly the defect 02.1-VERIFICATION.md confirmed against this project's interpreter.
Overriding the one method that builds the follow-up request is the only place the header can be
removed before it is ever sent.

The stripped state is sticky by construction and must stay that way: each hop's new Request is built
from the previous hop's headers, so once the header is gone it cannot reappear on a later hop that
returns to the original host. Do not add any code that re-attaches it.

Add `_redirect_safe_opener()` returning `urllib.request.build_opener(AuthStrippingRedirectHandler())`.
Build a fresh opener on each call rather than caching one in a module global -- CLAUDE.md's own
architectural constraint is that this project holds no module-level mutable state, and the cost is
irrelevant at the at-most-two requests an update check makes. `build_opener` substitutes a passed
instance for the default handler of the same family, so the default `HTTPRedirectHandler` is not in
the resulting chain; verified against this project's interpreter at plan time.

Add `_open_request(req, timeout)` returning `_redirect_safe_opener().open(req, timeout=timeout)`. This
is the module's single outbound-request seam. Point `download_asset` at it in place of its current
direct `urlopen` call, leaving its `with`-statement, its `_MAX_ASSET_BYTES` read cap and its
`except (urllib.error.URLError, TimeoutError, OSError)` clause exactly as they are -- `HTTPError`
subclasses `URLError`, so an error status raised through the opener is caught by the clause already
there and still returns `None`. Leave `check_latest` on its current call for now; Task 2 moves it,
which keeps the existing suite green after this task rather than after both.

`_checksum_fallback` needs no change: it fetches through `download_asset`, so it inherits the opener.
Say so in its docstring, because the gap named it as a second exposure and a future reader deserves to
know it is covered by one fix rather than overlooked.

In `tests/update_roundtrip.py`, add the end-to-end test. Substitute the transport, not the seam:
define a `urllib.request.BaseHandler` subclass with an `https_open(self, req)` method and a
`handler_order` below the real https handler's 500 (100 is fine) so it answers first, and have it
record `(req.full_url, dict(req.header_items()))` for every request it sees. Its first response is a
302 and its second is a 200. The response object must satisfy what the stdlib chain asks of it:
`.code`, `.status`, `.msg`, a `.headers` that is an `email.message.Message` (so `Location` is found
case-insensitively), an `.info()` returning that same object, `.read()`, `.close()`, and
context-manager support -- subclassing `io.BytesIO` supplies the last three for free. Inject the
transport by wrapping `_redirect_safe_opener` in a context manager that calls the real function and
then `add_handler`s the fake onto the returned opener, so the handler under test is the real one the
module builds and only the network is substituted. Set `ITEMBANK_GITHUB_TOKEN` to a sentinel for the
duration, restoring the previous value in a `finally` exactly as
`test_token_never_comes_from_the_settings_file` already does.

Assert all five behaviours listed above, and assert the sentinel token string appears in no header
value of the cross-host request rather than only checking for the header name -- a leak that arrived
under a differently-spelled header would otherwise pass. Register the new test in `main()` and extend
`main()`'s closing summary line to name the redirect coverage.
