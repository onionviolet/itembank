## Decisions Made

- **The redirect handler only strips; stdlib still decides legality.** `redirect_request` calls `super()` first and returns immediately when the superclass says the redirect is invalid. The origin comparison resolves a missing port to the scheme's default, so `https://api.github.com` vs `https://api.github.com:443` are the same origin and `http` vs `https` is not.
- **Sticky stripping by construction.** Each hop's Request is built from the previous hop's headers, so once Authorization is removed it cannot reappear on a later hop that returns to the original host. No re-attach code exists (T-02.1-39).
- **The token is destination-gated before the header is built.** `_github_token_for` returns the token only for GitHub-owned hosts and returns `None` for anything else -- including an explicitly-passed token. The redirect handler cannot help with a foreign first request (there is no redirect); the check happens before the header exists (T-02.1-38).
- **One seam, structurally asserted.** Both network functions route through `_open_request`, proven by `inspect.getsource` rather than only behaviourally, so a future call site appears as a failing assertion rather than a silent unguarded path (T-02.1-40).
