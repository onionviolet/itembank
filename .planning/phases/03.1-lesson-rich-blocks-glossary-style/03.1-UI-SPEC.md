# Phase 3.1 — UI Design Contract: the Reading Surface

> **This is the project's reading surface.** Phase 6.2 adds a gate band, a recorded-skip control
> and a truncation boundary to *this* layout and redesigns nothing else (§18). Phase 9's
> `## SCENARIO` stages render in this column with this ramp. If a later phase ships a second
> reading layout the project has two readers, which is the same class of error as two parsers.
>
> Every option below was **selected from** the costed option set in
> `.planning/research/2026-08-10-ui-inspiration-missing-surfaces.md` §1. No option was invented
> here and no prior art was re-surveyed. Each selection names its option label and its reason.

| Property | Value |

| Motion | 150ms functional maximum; no autoplay, no looping; `prefers-reduced-motion: reduce` removes transition and animation. A popover opens with **no** transition at any setting — a definition that fades in is a definition that arrives late. |

## 3. Spacing Scale

The 8-point scale from UI-SPEC §7 is unchanged and is the only scale. This phase adds no value to it.

| Token | Value | Usage in this phase |
|---|---:|---|
| `space-1` | 4px | icon-to-label gap; gloss panel inner tight gap; small-caps label letterspacing block |
| `space-2` | 8px | popover offset from its trigger; `[!KEY]` footer separation; sub-heading bottom margin |
| `space-3` | 16px | paragraph rhythm; callout inner padding; `<dd>` indent block |
| `space-4` | 24px | callout block margin; glossary entry separation; sub-heading top margin |
| `space-5` | 32px | section top margin at `###`; appendix top rule |
| `space-6` | 48px | `##`/section heading top margin (the asymmetric ramp, §4) |
| `space-7` | 64px | lesson foot padding; page-break breathing before the glossary appendix |

**Exceptions, each with its reason:**

1. **44px minimum interactive target** (UI-SPEC §7) applies to every control in this phase *except*
   the inline `[[term]]` trigger, which takes the WCAG 2.2 §2.5.8 **inline exception** for a target
   in a sentence. Inflating an inline trigger to 44px would seize control of `--leading-lesson`,
   which is exactly the failure the Kindle Word Wise row rejects (research §1.1). **The compensating
   path is not optional:** every glossed term also has a full-size (≥44px) entry in the glossary
   appendix (§9.1), which is one of the three reasons the appendix is built rather than stubbed
   (D-21).
2. **`--measure-prose: 66ch` / `--measure-wide: 90ch`** are character measures, not pixel spacing,
   and are deliberately off the scale (C13).
3. **Hairlines:** the `[!KEY]` card's single non-blurred `box-shadow: 0 1px 0 var(--line)` and every
   1px `--line` border are borders, not spacing.
4. **Print page margin `18mm`** (§10) is a physical unit; the pixel scale does not apply to paper.

## 4. Typography

Five sizes exist project-wide and **this phase adds none** — D-02: *"do not re-litigate and do not
introduce a sixth type size."* `text-lesson` is C14, already added at project level on 2026-08-10.

| Role | Token | Size / line-height | Weight | Voice | Use in this phase |
|---|---|---|---|---|---|
| Lesson prose | `text-lesson` | 18px / `--leading-lesson` 1.65 | 400 | Paper | lesson paragraphs, list items, `[!KEY]`/`[!EXAMPLE]` bodies, `<dd>` definitions, gloss panel definition text |
| Body | `text-body` | 16px / 1.5 | 400 / 700 | Chrome | every non-lesson surface; sub-heading `h3` at 700 |
| Label | `text-xs` | 12px / 1.4 | 700 | Ledger | callout small-caps labels, `[!KEY]` export footer, `[!CHECK:]` anchor label, style footer, backlink label, print position lines |
| Heading | `text-heading` | 20px / 1.2 | 700 | Paper | lesson section heading (`###` → `<h2>`) |
| Display | `text-display` | 32px / 1.1 | 700 | Paper | lesson title (`<h1>`) |

**Heading ramp — LOCKED (ROADMAP criterion 4, "the Q1 reading measure/heading ramp").** Three levels,
spacing-asymmetric so a heading belongs to what follows it rather than floating between:

| Level | Element | Size | `margin-top` | `margin-bottom` |
|---|---|---|---:|---:|
| Lesson title | `h1` | `text-display` | 0 | `space-3` (16) |
| Section (`###` in the bank) | `h2` | `text-heading` | `space-6` (48) | `space-3` (16) |
| Sub-heading (`####+`) | `h3` | `text-body` @700 | `space-5` (32) | `space-2` (8) |

**Weights — RECOMMENDED, with the cost stated honestly.** UI-SPEC §7 locks *"400 regular, 700 bold |
exactly two weights."* Shipped `surfaces/presentation.py` and `surfaces/lesson.py` use `600` in
several rules. Every **new** rule this phase writes uses 400 or 700 only. Renumbering the existing
`600` declarations is a Phase 4 reconciliation item (UI-SPEC §7 already names it as RECOMMENDED) and
is **out of scope here** — the honest reason is churn, not a constraint, and dragging it into this
phase would put unrelated diff into the byte-identity fixture of §12.

**Small caps.** Ledger labels render as `font-size: text-xs; letter-spacing: .08em;
text-transform: uppercase` — the shape already shipped in `lesson.py`'s `.blabel`. This is a
treatment of `text-xs`, not a sixth size.

## 5. Color

**No hex literal appears in this document.** `surfaces/theme.py` is the single palette source
(UI-SPEC §7, LOCKED) and it derives contrast-correct light/dark values from one persisted accent.
Naming values here would create the second palette that rule exists to prevent.

| Role | Token | Usage in this phase |
|---|---|---|
| Dominant (60%) | `--bg`, `--ink` | the reading field and lesson prose |
| Secondary (30%) | `--card`, `--chip`, `--line`, `--mut` | callout bodies, gloss panel, table headers, rules, small-caps labels |
| Accent (10%) | `--accent`, `--accent-soft` | **exactly:** the 2px focus ring; the gloss panel's `Full entry` link; the glossary appendix backlinks and existing `Items testing this` links; the `Add to review` primary action's soft-fill pairing |
| Semantic | `--warn`, `--unknown`, `--pending` | `--warn`: unreadable style file / unreadable `[LESSON-SRC:]` (existing Phase 3 degraded state). `--unknown`: nothing in this phase. `--pending`: nothing in this phase — no mark is produced here |

**Accent reserved for:** focus rings, the `Full entry` link, backlinks, and the single `Add to
review` primary action. **Never** for: callout kind differentiation, the `[[term]]` trigger, a
`[!KEY]` card border, correctness, or "all buttons" (UI-SPEC §7: *"never correctness, mastery,
warning, or all buttons"*).

**Two colour rules this phase must not break:**

1. **The gloss trigger's channel is underline style, not colour.** Research §1.1 (LingQ row): *"Our
   channel is **underline style**, colour secondary."* A `[[term]]` renders
   `text-decoration: underline dotted; text-underline-offset: .15em` in `currentColor`. Colour-only
   state is a UI-SPEC §7 never-colour-alone violation and is REJECTED on that basis.
2. **Callout kinds are distinguished by icon + Ledger small-caps label + structure**, with colour a
   secondary channel only (UI-SPEC §7.3). `[!KEY]`, `[!EXAMPLE]`, `[!NOTE]`, `[!CHECK:]` must remain
   tellable apart in a monochrome print and with CSS disabled.

## 7. The reading column

### 7.1 Selection: **R1 + R2 behind `reader_nav: none | column`** — LOCKED interface

Selected from research §1.3. Reason, quoting the option set: R1 is *"one layout, three uses, which is
the whole point"* — identical in the reader, in 6.2's gated mode, and in print — and its named
weakness is that *"a long lesson has no persistent orientation cue."* R2 closes exactly that gap and
*"is the MDN answer with the JS removed."* Research: *"ship R1 and R2 behind one setting,
`reader_nav: none | column`. They are the same DOM with one optional `<nav>`; per Directive §3 this
is a registration, not a fork."*

- **R1 (base, always):** one `--measure-prose` 66ch column centred in the activity canvas. Tables,
  figures, code blocks and `[!EXAMPLE]` parallel step grids may escape to `--measure-wide` 90ch.
  Headings, `[!KEY]`, `[!CHECK:]` anchors and the glossary appendix stay at full 66ch measure.
- **R2 (`reader_nav: column`):** R1 plus a static heading `<nav>` built from the lesson's `###`
  headings — real anchors, server-rendered, no scroll-spy. `aria-current` highlighting is an
  enhancement that must be **announced, not merely painted**, and is never a requirement.
- **Default: `none`** — **DEFAULT**, on research §1.3's own label ("recommended default") plus a cost
  fact: there is no real bank yet (CONTEXT named unknowns), so the length at which orientation starts
  paying is unmeasured. Revisit against the Phase 3.2 corpus.

**R3 (margin rail) — REJECTED for this phase.** Research §1.3: *"it directly contradicts round one's
structural rejection of margin notes — the support column already owns that third — and it introduces
a third responsive behaviour to test at three widths. **Do not ship R3 in 3.1.**"* Recorded as the
reason a **later shell revision** might revisit UI-SPEC §3, not as a 3.1 option. It is not rejected
for being distinctive; research calls it *"the most distinctive of the three."*

`keyboard/SR:` headings are real headings in reading order; nothing is pointer-only; the `<nav>` is a
labelled list of real anchors.
`print:` the measure becomes the page measure; the `<nav>` is `display:none` — *"a printed page does
not need a TOC of itself"* (research §1.3), and if it does, that is §10's page-reference machinery.
`degraded:` unaffected. Static server-rendered HTML; only R2's optional current-section highlight is
lost.

### 7.2 Responsive behaviour

| Width | Reading column | `reader_nav: column` |
|---|---|---|
| Desktop ≥1024px | 66ch centred in the 2/3 activity column (C16) | sticky `<nav>` in the 1/3 support column |
| Tablet 768–1023px | full width, capped at 66ch | collapsed `<details class="details-section">` labelled `Sections in this lesson` |
| Narrow <768px | one column, 66ch cap, `space-3` side padding | same collapsed `<details>` |
| 320px / 200% zoom | no horizontal scroll on prose; tables and code use the labelled scroll wrapper already shipped (`.scroll`) | unchanged |

Long headings wrap; no `nowrap`, no ellipsis anywhere (the shipped `presentation.py` discipline).

### 7.3 **The TOC-versus-hint-ladder ruling — LOCKED, and this is the question 6.2 must not rediscover**

Research §1.3 flags it: *"in a **sitting** the TOC must yield, and 6.2 has to specify which. That
'which wins' question is exactly the kind of thing that should be settled in 3.1's UI-SPEC and not
discovered in 6.2."* Settled here.

**The rule, in one sentence: the table of contents sits with the thing it navigates.**

| Context | Where the TOC goes | Where the hint ladder goes |
|---|---|---|
| **Standalone reader** (`/lesson/<stem>`, no active item) — the lesson *is* the activity | Desktop: support column. Tablet/narrow: collapsed `<details>` placed **after the `<h1>` and before the first section**. | not present |
| **Sitting or gated reading** (Phase 6, 6.2 — an item is active) — the lesson is support | Support column, **below the hint ladder**, collapsed by default, summary `Sections in this lesson`. Narrow: inside the existing "Help and evidence" disclosure, still after the ladder. | **Support column, first. The hint ladder wins.** |

**Why the ladder wins:** the ladder is tied to the active attempt; the TOC is document-scope. The
support column is ordered by proximity to the active attempt — hints, then document navigation, then
evidence. That ordering is a rule a plan can test, not a preference.

**Why the standalone reader's TOC may precede content in DOM order** despite C16 (*"support … begins
below activity in DOM order"*): a table of contents is *navigation to* the activity, not support
*about* it, and C10's keyboard path begins *"global navigation → ContextLine details → activity
heading."* A document nav belongs with global navigation. This is a scoped, reasoned reading of C16,
not a relaxation of it: in every context where the lesson is **not** the activity, the TOC obeys C16
exactly.

## 8. The gloss — written from the declarative footing

### 8.1 The mechanism is the **Popover API plus CSS Anchor Positioning**, and it is the baseline — LOCKED

Research §0, "the single most important correction to round one": *"The Popover API is fully
declarative. `<button popovertarget="gloss-x">` paired with `<div id="gloss-x" popover>` gives
show/hide toggling, Escape dismissal, light-dismiss, focus return, and top-layer stacking **with
zero JavaScript**, and it is supported across Chrome, Edge, Firefox and Safari."* And: *"the gloss
popover is **not** an enhancement over a link fallback — the popover *is* the baseline, and it
arrives with Escape, focus return and top-layer stacking already correct, which is most of B1
satisfied by the platform rather than by us."*

**Round one's "JS enhancer over a link fallback" framing is superseded and must not be reproduced in
any plan.** ROADMAP criterion 1's phrase *"degrade to a glossary appendix with no JavaScript"* is
therefore satisfied **at the baseline** rather than by a fallback. The appendix is still built and is
still not a stub (D-21), for three independent reasons: it is the print surface (§10), it is the
`Full entry` target, and it is the ≥44px full-size target path the inline exception in §3 owes.

**DOM shape — LOCKED.** For a term where `glossable()` returns true, in the lesson reader:

```html
<button type="button" class="term"
        popovertarget="gloss-oropharyngeal-airway"
        aria-details="gloss-oropharyngeal-airway">oropharyngeal airway</button>

<div id="gloss-oropharyngeal-airway" class="gloss" popover>
  <p class="gloss-term">Oropharyngeal airway</p>
  <p class="gloss-def">A rigid curved adjunct that holds the tongue off the posterior pharynx.</p>
  <p class="gloss-more"><a href="#term-oropharyngeal-airway">Full entry</a></p>
</div>
```

- **Anchoring — LOCKED shape.** `anchor-name` / `position-anchor` pairs are emitted **once per
  glossed term into a single per-lesson `<style>` block keyed by slug**, never as an inline `style`
  attribute on bank-derived markup. Reason: an inline style attribute on author-derived output is
  the one place a future CSP `style-src` policy would have to be relaxed, and this costs nothing to
  avoid now. `position-try-fallbacks: flip-block, flip-inline` keeps the panel on screen at 320px.
- **No positioning polyfill.** Where anchor positioning is unsupported, the popover still opens as a
  centred top-layer panel — legible, operable, and correct. That is a graceful platform fallback,
  not a defect to script around.
- **Hover is decoration and may never be the only path.** Research §1.1 and §8: `interestfor` /
  interest invokers are *"not Baseline — Chromium-only with recorded WebKit objections"*, and
  UI-SPEC §8 forbids hover-only controls at narrow widths regardless. If hover-to-open is added it
  is additive over the click/focus path, which stays complete on its own.
- **Panel sizing:** `max-width: min(38ch, calc(100vw - var(--space-4)))`; body text at `text-lesson`
  (it is authored prose, Paper voice); the term line at `text-lesson` weight 700.

`keyboard/SR:` a real `<button>` in reading order; Enter/Space toggles; Escape dismisses; focus
returns to the trigger — all platform behaviour. `aria-details` associates the panel. **The trigger
must not carry the definition in `aria-label` or `title`** — that is both a verbosity failure and a
C7 leak channel. AT receives the DEF text and never more.
`print:` §10, governed by `print_gloss`.
`degraded:` in the reader the definition ships with the page, so the gloss works with the network
unplugged and before any script loads.

### 8.2 Marks density — `gloss_marks: all | first-use | none` — DEFAULT `all`

Selected from research §1.1's Kindle Word Wise row: *"Take: the **density control** as a concept: a
learner setting for how many terms are marked."* Our marking is authored (`[[term]]`), so density is
a rendering choice, not a corpus inference. `first-use` marks only the first occurrence of each term
per section; `none` renders every term as plain prose and leaves the glossary appendix as the only
path. The first-use machinery is owed by print C3 regardless (§10), so this setting is free.
Revisit against the Phase 3.2 corpus.

### 8.3 Inside a live sitting: **fetch-on-open primary, navigation as the degraded path** — LOCKED

Selected from research §1.2(b), including its reconsideration: *"the fetch is in fact the right
primary design, because it is the mechanism that keeps the gloss body out of the sitting's HTML
entirely — which is a B4 answer-leak property, not a JS property."*

```html
<!-- in a sitting; permitted term -->
<a class="term" data-gloss="oropharyngeal-airway"
   href="/gloss?item=Q12&amp;term=oropharyngeal-airway&amp;return=%2Fquiz%2Femt%23Q12"
   >oropharyngeal airway</a>
```

- **Enhanced path:** the vendored enhancement script intercepts activation, fetches
  `/gloss?item=&term=`, injects the response into a client-created `[popover]` element and calls
  `showPopover()` — same panel, same styling, same Escape/focus-return behaviour, because it is the
  same platform API.
- **Degraded path:** with no script, activation is an **ordinary navigation** to a served gloss page
  carrying a `Back to the question` link. *"Same server contract, same event, one extra template."*
- **In both paths the runtime records `term_lookup` server-side because it served the content.**
- The enhancement script is **runtime-shipped, vendored and reviewed**. It is not bank-authored and
  C15 does not reach it (§13).

### 8.4 `glossable()` false: **silence, not a notice** — LOCKED

D-20: *"A gloss passes through a runtime `glossable()` gate, so a term whose definition would leak a
keyed answer renders as plain text with the lookup suppressed. This is Directive §4.1 in miniature."*

**Rendering — exact:** the term renders as **bare text**. No element, no class, no `data-*` attribute,
no underline, no title, no ARIA. Nothing in the DOM, the accessibility tree, or the CSS-off text
distinguishes a suppressed term from ordinary prose (C7).

**The apparent conflict with C8, and its resolution.** C8 requires a surface to *"say exactly what is
unavailable."* Naming a suppressed term **per term** would itself disclose which term carries the
discriminating definition, which C7 forbids. Resolution, LOCKED:

- **Per term: silence.** Never a per-term notice, a struck-through affordance, or a disabled control.
- **Once per sitting, generically, in Ledger voice:** `Some definitions are held until you answer.`
  That satisfies C8 at the level where it can be satisfied without leaking — the learner knows the
  gate exists and cannot infer where it bit.
- **The in-sitting glossary appendix filters identically:** a suppressed term is **absent**, not
  shown as an empty `<dt>`.

**What `glossable()` is and is not, stated so 6.2 does not overclaim it.** It is the runtime refusing
to serve a keyed answer through its own surface — the same class of decision as `public_item()`
withholding a key, which is why CONTEXT places it *"in `runtime.py` beside the existing
public/private projection."* It is **not** a secrecy mechanism against the file on disk. A learner
can open the lesson markdown. Research §3.3 already rules on this shape of claim: *"a hard gate is
theater on a plaintext file the learner owns."* Do not write copy that claims otherwise.

### 8.5 `term_lookup` recording — LOCKED behaviour, OPEN field

ROADMAP criterion 1 requires *"each lookup lands as a `term_lookup` event."* In the reader the
definition ships with the page, so there is no server round trip to record. Settled:

| Path | Recorder | Completeness |
|---|---|---|
| In-sitting fetch (§8.3 enhanced) | **server-side**, because it served the body | complete |
| In-sitting navigation (§8.3 degraded) | **server-side**, same event | complete |
| Reader popover | **client**, on the popover `toggle` event, POSTed to the daemon and written through the one `evidence.append_event()` | **best-effort** |
| Static offline build | **nothing is recorded** | the surface says so; it never implies a complete series |

**LOCKED:** no surface may present reader-path lookup counts as a complete series, and a report that
mixes the two must say which it is showing. This is the same provenance discipline research §2.2
applies to `served_at` versus `first_input_ms` for Phase 6: *"any surface displaying a duration must
say which of the two it is showing, and must never present a nullable client field as the record."*

**OPEN — owed at `/gsd-plan-phase 3.1`, before the first write.** Whether that provenance is carried
as a `source` field on the event (`served` | `reader`) is an **append-only evidence field**, which
Directive §2 lists as a stop condition: *"An action that is **hard to reverse** — an append-only
evidence field, a published schema, a format decision other phases will build against."* D-19 says
the same: *"Fix the field set before the first write."* **Default if unruled: carry it**, because a
series that cannot state its own provenance is worse than one field of overhead, and the log is
append-only so it cannot be added later.

## 12. The compatibility floor — what "byte-identical" means here — LOCKED

D-23 and ROADMAP criterion 4 both require that a bank and lesson using none of the new constructs
render **byte-identically** to Phase 3 output. Criterion 4 *also* requires a render pass that lands
the measure and the heading ramp. Read naively those two clauses contradict each other, and an
executor would be stuck. Settled here.

**C3 quoted in full:** *"Format changes are **additive** — a bank not using a new block **parses
unchanged**, proven by a byte-identical fixture, not promised."* The subject of §4.4 is the **format
and the parse**, not the stylesheet. Directive §4a reinforces the scope: *"§4.2 forbids a **second**
parser, scorer, or evidence store. It does not freeze the one parser's grammar."*

**Therefore — LOCKED:**

1. The byte-identity fixture compares the **rendered content region** (the `__BODY__` region of
   `LESSON_TEMPLATE` and the `main` content of any other surface), byte for byte, against Phase 3
   output for a bank using none of TERMS, `[[term]]`, `[!KEY]`, `[!EXAMPLE]`, `[!CHECK:]`, the
   objective line, or a style file.
2. The shared `<style>` block is **explicitly excluded** from that comparison and is named as excluded
   in the fixture, with this section cited, so the exclusion is a recorded decision rather than a
   convenient omission.
3. A **second** fixture asserts the parse is unchanged: the parsed question dicts and the parsed
   lesson structure for the same bank are equal to Phase 3's. That is the clause C3 actually protects.
4. No new block may change the rendering of an absent block. Adding a `[!KEY]` to a lesson must not
   move a paragraph that has no `[!KEY]` near it.

## 13. Interactive lesson figures — the forward-compatible rule — LOCKED

Written per research §1.5's instruction: *"the phase does not need to build this, but its UI-SPEC
should **not** write a prohibition it would then have to unwind in Phase 9. Say 'declarative and
vendored, never author-supplied code,' which is a rule that will still be true in three phases."*

**The rule: a lesson may declare an interactive figure; it may never supply the code that runs one.**

| Legal | Illegal |
|---|---|
| A lesson names a vendored, shared, reviewed scene and its parameters (06.1's declarative SVG protocol; CodeMirror 6 is the precedent for a vendored component) | A `<script>` block in a lesson file |
| A figure inside a section, carrying an equivalent semantic control path (UI-SPEC §8 item 5), a static print form, and a stated behaviour when the daemon is gone | An inline expression evaluator, or arbitrary JS in a fenced block that the renderer executes |

**Ground for the illegal column — C15**, quoted: *"Canvas-only visual assessment, **bank-authored
executable JavaScript**, raw pointer telemetry, or a visual renderer that infers correctness."* Plus
the honest product reason research gives: author-supplied executable content is *"an unbounded review
and security surface, and it stops the lesson being a plain file the learner owns and can hand to
someone else."* This is consistent with ROADMAP 3a's rejection of explorable explanations as a
*style* and with 06.1's existing refusal, and it reopens neither.

**It is not a JavaScript rule.** The enhancement script in §8.3 and the vendored KaTeX and CM6
pipelines are runtime-shipped, reviewed artifacts under C6 and are unaffected.
