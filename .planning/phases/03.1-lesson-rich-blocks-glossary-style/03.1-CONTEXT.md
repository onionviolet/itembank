<domain>
## Phase Boundary

This phase gives a lesson three things it cannot express today: its own vocabulary (`## TERMS` + `[[term]]`), an explicit must-memorize block (`[!KEY]`), and a written style contract enforced by the existing linter (`styles/<id>.md` + a `## Rules` table). It adds one new parse path (`[!CHECK: <id>]`, an anchor with no key and no scoring path), one callout kind (`[!EXAMPLE]`), one optional per-item `Educational Objective` line, and one reserved TERMS meta field (`zh=`).

It does **not** build: the gating loop that consumes `[!CHECK:]` (Phase 6.2), model-driven `restyle` (Phase 11), the bilingual reader (999.2), `## SCENARIO` (Phase 9), or any seeding/authoring loop (Phase 3.2).
</domain>

Every vendored artifact is pinned to a tag, carries a recorded SHA-256, and keeps the license file and the reserved-font-name note already recorded in `.planning/UI-SPEC.md:438-439`. This is required by Directive §4a's supply-chain rule, not optional hygiene. — **Reversibility:** reversible — `UI-SPEC.md:454` already specifies the no-vendor fallback (`--font-paper` → Georgia, `--font-ledger` → `ui-monospace`); backing out is deleting two files and changing two token values, and no surface names a family literally (`UI-SPEC.md:312`).
- **D-02 (ruling 2 — ALREADY SETTLED, not open):** `UI-SPEC.md:324` already defines `text-lesson` at 18px/1.65, scoped to sustained authored lesson prose only. The locked 16px `text-body` is unchanged and still governs every non-lesson surface. Planning treats this as decided; do not re-litigate and do not introduce a sixth type size.
- **D-03 (ruling 6 — ADOPTED AS ASSUMPTION, flagged):** "The Bottom Up" is read as Wienand-style runnable-artifact-first pedagogy. This underwrites the `artifact-first` style only. Falsify it in the **first** planning task that touches `artifact-first`, not after building it. If it falsifies, `artifact-first` loses its ordering rationale and is re-derived from PRIMM alone — no other style is affected.
- **D-04 (ruling 7 — FOLD INTO 09-02):** `lesson_layout: "separate" | "inline"` is added to the closed `subject_profiles` entry contract by **editing `09-02-PLAN.md` before Phase 9 executes**, not by version-bumping a shipped registry. Phase 9 plans exist but are unexecuted (`STATE.md` is at Phase 04), so this is free today and expensive after. — **Reversibility:** one-way once Phase 9 executes — the registry is a closed schema published through `schemas/settings.schema.json` and `itembank config`; adding the field afterward is a registry version bump plus a migration. **Do 09-02 first.**
- **D-05 (ruling 8 — DEFAULT ADOPTED):** `[!KEY]` is **lesson-only**. It is a lint error inside an item rationale. `key.duplicate_id` therefore scopes to lesson files. — **Reversibility:** reversible — widening later is additive (a location the linter currently rejects starts being accepted); narrowing later would not be.
- **D-06 (ruling 9 — DEFAULT ADOPTED, shared with Phase 6.2):** `[!CHECK: <id>]` may reference an item in **its own bank only**. Cross-bank references are a lint error naming the rule. — **Reversibility:** reversible for the same reason as D-05. Phase 6.2 inherits this verbatim; the two phases must not diverge.

### Style registry

- **D-07:** Ship the five styles in the roadmap's order — `expository`, `worked-example`, `checked-prose`, `artifact-first`, `case-narrative` — and ship the Extensibility Rule 6 stub proving a sixth is one file with no parser, lint-code, or renderer change. The four rejected styles (Feynman, cookbook, written Socratic, explorable explanations) are rejected on the reasons already written into `ROADMAP.md` §3.1 criterion 3a; a plan may not revive one without new evidence.
- **D-08 (Directive §3 applied):** `checked-prose` carries `predict_first` as a **flag**, not a second style, and productive failure is that flag rather than a style. Two near-identical styles would be two files with one real difference — the conflict rule says one interface with a setting, and this is that case.
- **D-09:** Style file resolution order is **bank-adjacent `styles/` → user data dir → bundled house**. First match wins by id; a duplicate id across levels is a warning naming both paths, never a silent shadow. Bundled house styles are read-only.
- **D-10:** Selection precedence is fixed by `ROADMAP.md` criterion 3b: **lesson → bank → subject profile → house**. Exactly one inheritance level; `[STYLE-PARENT:]` naming anything but `house` is a lint error. The house `lock` column encodes the five Directive §4 non-negotiables and no style may override a locked row.
- **D-11:** `render_style` (runtime, model-free, permutes existing blocks only) and `restyle` (Phase 11, model-driven, human-gated, writes a new file) are separate commands with separate names. The five mechanically impossible transforms named in criterion 3b are **refused by name**, never approximated.

### Enforcement

- **D-12:** Three cost classes, per criterion 3c. Structural counts over the parsed heading tree and one shared lexical metrics pass run on **every** lint; discourse judgement defers to Phase 11. Budget: whole style pass under 50ms on a 5000-word lesson, asserted by test, not claimed.
- **D-13:** `LINT_CODES` stays a **closed** published catalogue. A style file may enable, disable, re-severity (downward only) and parameterize a check; it may never define one. `error` severity is earned by construction — structural counts or author-controlled literal lists only — and a style may not raise a check to `error` that the catalogue rates lower.
- **D-14:** Every warning ships with a false-positive rate measured against the Phase 3.2 corpus. Above roughly 20% it ships **disabled by default** with the rate recorded beside it. Local `<!-- style-ignore: -->` suppression exists from day one, and suppression counts are themselves a report — the named failure mode is an unsuppressable warning getting its whole category globally disabled.
- **D-15:** A style `error` blocks a **machine-authored write** and never a human's `lint`. A human always gets the diagnosis and keeps the pen.
- **D-16:** A `## Rules` row claiming a lintable severity the linter does not implement is itself a lint error. This is what stops the style contract drifting into aspiration.

### Prompt contract

- **D-17 (criterion 3d):** The authoring model receives **distilled imperatives, capped, placed last in the prompt**, plus exactly one exemplar. It never receives the style file and never receives the `## Voice` prose zone. The cap ships as a **setting with default 7** rather than a constant, because the roadmap records the seven figure as extrapolated from format-compliance research and not measured on pedagogical structure — a setting lets it be measured against the Phase 3.2 corpus without a code change.

### Blocks, evidence, and compatibility

- **D-18:** `[!CHECK: <id>]` is the single new parse path. `[!EXAMPLE]` is a callout **kind** against the existing callout container, not a new block. `runtime.score_response()` is untouched by this phase.
- **D-19:** `term_lookup` and `key_review` are **new event types appended to `KNOWN_EVENT_TYPES` (`evidence.py:43`)**, additively, with `EVENT_SCHEMA_VERSION` handling proven by a fixture. Neither is a `response` and neither carries a score. — **Reversibility:** one-way — the evidence log is append-only, so a shipped event shape cannot be rewritten, only superseded. Fix the field set before the first write.
- **D-20:** A gloss passes through a runtime `glossable()` gate, so a term whose definition would leak a keyed answer renders as plain text with the lookup suppressed. This is Directive §4.1 in miniature: the runtime, not the author and not a model, decides the gloss reaches the learner.
- **D-21:** Hover gloss uses the **Popover API**; the no-JavaScript degradation is a glossary appendix rendered from the same `## TERMS` block, not a second content source. Both paths are built — the appendix is not a fallback stub.
- **D-22:** `[!KEY]` exports to Anki TSV with a `#guid` that round-trips on re-export, and supports `{{cloze}}`. Round-trip is proven by test, not asserted.
- **D-23 (compatibility floor):** A bank and lesson using none of TERMS, `[!KEY]`, `[!EXAMPLE]`, `[!CHECK:]`, the objective line, or a style file renders **byte-identically** to Phase 3 output, proven by a checked-in fixture. Directive §4.4.
- **D-24:** The TERMS grammar reserves one optional ignorable `key=value` meta field (`zh=`). Nothing bilingual is built here; an unknown meta key is ignored, not an error, so 999.2 is a field-read.

### Claude's discretion (for the planner and the executor)

Module factoring, internal names, the exact lexical metrics chosen, and the shape of the style-pass cache are open. Not open: the closed `LINT_CODES` catalogue, the severity ceiling, the selection precedence, the render/restyle split, the byte-identical fixture, and the five non-negotiables.
</decisions>
