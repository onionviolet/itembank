# Phase 03.1 Plan 03: [!KEY] Cards, Anki Export, key_review, and the Private Objective Summary

**The [!KEY] track end-to-end: shared-namespace id minting, the index-card
render with a real Add-to-review form, the multi-directive Anki keys TSV
with a round-tripping #guid, `key_review` events, the drill-print blanking
pass, and the Educational Objective line moved behind the verdict (C7).**

## Accomplishments
- `parse_key_blocks()` reads `> [!KEY]` callouts into `{id, hash, title,
  body, cloze, section_slug}`; `assign_ids()` mints key ids through the
  exact `new_item_id()`/taken-set path items use -- a key-item collision is
  structurally impossible.
- Five key lint codes fire (no_front, missing_id, missing_hash,
  duplicate_id, in_rationale), published in LINT_CODES and the schema enum.
- `itembank export <bank> --format keys` writes `<bank>_keys.tsv` with the
  `#guid column:1`/`#notetype column:2`/`#deck column:3`/`#tags column:6`
  directives; the guid is the minted `[ID:]`, so re-export after a body
  edit is an Anki update, never a duplicate (round-trip proven by test).
- The index card renders with the Ledger footer, `{{cloze}}` shown as
  enclosed text, and a real form when a runtime serves it; static renders
  carry the exact unavailable copy instead of a dead control.
- `POST /key/<id>/review` and `itembank key-review <bank> <id>` share one
  `record_key_review()` path and append `key_review` events (no score).
- `?print=drill` blanks clozes server-side and prints the Answers list last.
- C7 closed: `public_item()` no longer exposes the syllabus `[OBJECTIVE:]`,
  and the new one-sentence `Objective:` line lives only in
  `explain_payload()` (`educational_objective`); study's pre-answer chip
  was removed and the objective now renders behind the verdict.

## Decisions Made
- The authored cloze grammar is any `{{text}}` marker (research), not a
  literal `{{cloze}}` token: `{{text}}` compiles to `{{c1::text}}` with
  sequential numbering, `{{n::text}}` keeps its number, and on screen the
  enclosed text renders.
- The `[!KEY]` card renders the marker's trailing text as a visible title
  line inside the card body, preserving plan 03.1-01's
  callout-body-escaped contract (the KEY kind's body must not vanish).
- C7's "verify no downstream consumer" found `surfaces/study.py` reading
  `public_item()["objective"]` for a pre-answer chip; that chip was removed
  and the objective moved into the revealed explanation.
- The `/key/<id>/review` route resolves the id against the daemon's scanned
  banks' parsed key blocks (never a path join) and records through the one
  writer; the status region is the "Added to review." string.
