## Decisions Made

- **Parent contract (plan-text correction, deviation):** the four non-base
  styles declare `[STYLE-PARENT: house]` (the exactly-one-level machine
  parent, D-10) and document expository as their content parent in prose;
  expository declares no directive. The plan's Task 2 test text asked for
  `[STYLE-PARENT: expository]`, which would have fired
  `style.parent_unknown` on every shipped style and contradicted the plan's
  own must-have, ROADMAP criterion 3b, and the mechanics research. The
  locked contract wins; the test was adapted and the deviation recorded.
- **render_style is CLI-only.** The plan interface sanctioned the CLI-only
  seam ("a POST /render-style route if a route is warranted, else the
  CLI-only seam"); since `render_style` writes an output file (an authoring
  action, not a learner surface) and a new mutating route would expand the
  network surface with no threat-model entry, no route was added and
  `ROUTE_CLI`/`ROUTES` are untouched.
- **house.md documents locks in prose only.** A locked id in a `## Rules`
  row is itself `style.override_locked` by the loader's own lint pass, so
  the house file carries the six ids in the Voice zone and its rule rows
  are the house-wide parameterizations only.
- **`cadence.section` etc. are 03.1-05's enforcement inputs.** render_style
  permutes per `order.before`; density/require/forbid/open.with/cadence
  rows ship in the files but their lint enforcement lands in plan 03.1-05
  (style enforcement cost classes) by design.
