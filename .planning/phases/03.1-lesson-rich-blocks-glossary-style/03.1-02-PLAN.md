<objective>
As a learner, I want a lesson's own vocabulary to explain itself — a hover gloss on first-class terms with a printed glossary appendix behind it — without ever leaking an answer the runtime is holding back.

Purpose: Build the TERMS track end-to-end: the independent parser, the runtime gate, the two render paths (Popover gloss + glossary appendix), and the recorded lookup event. This is the phase's first learner-facing differentiator (D1) and its first evidence-surface.
Output: parse_terms(), glossable(), term_lookup events, the glossary appendix and inline gloss rendering, the /gloss route, and the reader settings.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| bank-authored TERMS/gloss text -> learner HTML | Untrusted author text becomes learner-facing content; escape discipline and the glossable gate both apply |
| lesson glossary -> item answers | A definition must not disclose keyed answer material through any surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-031-04 | Information Disclosure | gloss definition vs keyed answer | high | mitigate | Server-side `glossable()` gate before any gloss is rendered or served (D-20); the no-leak fixture asserts absence in DOM, ARIA, CSS-off text, and accessible names (03.1-UI-SPEC §17 item 1) |
| T-031-05 | Injection | `[[term]]` trigger and glossary markup | high | mitigate | Every term key, alias, and definition passes `lesson_slug()` for ids and `_inline()`/`html.escape()` for text; a hostile marker cannot close attributes |
| T-031-06 | Tampering | /gloss route lookup | medium | mitigate | The slug resolves through `lesson_slug()` and the bank stem through the existing route allowlist; unknown slugs 404 with no event |
| T-031-07 | Repudiation | term_lookup provenance | low | mitigate | The event carries bank, term_slug, source, mode, and ts; the reader path is never presented as complete provenance (§8.5) |
| T-031-SC | Tampering | vendored enhancement script | high | mitigate | The one enhancement snippet is a reviewed, in-repo constant (no fetched script, no CDN), pinned by review per the C6 precedent |
</threat_model>
