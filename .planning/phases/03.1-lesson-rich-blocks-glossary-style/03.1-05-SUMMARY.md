# Plan 03.1-05 Summary — Style lint enforcement (closed catalogue, suppression, prompt compiler)

## What shipped

The enforcement and authoring-prompt halves of the style system, exactly per
the plan's three tasks:

1. **Task 1 — three cost classes + closed-catalogue enforcement.**
   `run_style_pass(lesson, style)` returns `(errors, warnings)` as LintError
   records. Class 1 structural counts run over the parsed heading tree
   (`_style_sections`); class 2 is the one shared lexical metrics pass over
   the fenced/code-span-masked prose; class 3 discourse judgement is declared
   `manual` and skipped by note. The catalogue is closed by construction:
   `STYLE_CHECK_CATALOGUE` names every content code and its severity ceiling,
   and `ceiling()` enforces it row by row. `write_allowed(style, errors)` is
   the D-15 machine-write gate.

2. **Task 2 — suppression, calibration, budget.** `apply_style_ignore()`
   filters `<!-- style-ignore: -->`-suppressed non-locked findings and emits
   `style.ignore_locked` for locked ids before consulting the ignore table;
   `style_suppression_report()` counts per-code suppressions with line
   locations. `warning_ship_state()` implements the 0.20 threshold seam;
   Phase 3.2 populates `STYLE_WARNING_FP_RATES`. The 50ms/5000-word budget is
   an executable fixture.

3. **Task 3 — StylePrompt.** `StylePrompt.prompt_context(style, cap)` emits
   distilled imperatives (capped, `prompt: yes` rows only) then exactly one
   exemplar, last in the output, with no Voice prose. The `style` settings
   group (`imperative_cap` 7, `warn_fp_threshold` 0.20) ships in
   `surfaces/settings.py`, `schemas/settings.schema.json`, and checked-in
   `itembank.json`, validating through the existing config gate.
