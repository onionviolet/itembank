# Phase 03.1 Plan 02: Glossary, Gloss Gate, and term_lookup Summary

**The TERMS track end-to-end: an independent `## TERMS` parser, the
runtime `glossable()` answer-leak gate, append-only `term_lookup` events,
the Popover-API inline gloss with a printed glossary appendix, the `/gloss`
route with its CLI twin, and four registered reader settings.**

## Performance

- **Duration:** ~140 min
- **Started:** 2026-08-10T20:10:00Z (approx)
- **Completed:** 2026-08-10 (approx)
- **Tasks:** 3
- **Files modified:** 15

## Accomplishments
- `parse_terms()` mirrors `parse_lesson()`: same preamble boundary, `None`
  on absence, `zh=` and unknown meta captured as ignored and dropped from
  rendered output (D-24/LESSON-16), refs collected via the one slugifier.
- Five new lint codes (`terms.unknown_ref`, `terms.duplicate_slug`,
  `terms.empty_block`, `key.in_rationale`, `key.duplicate_id`) published in
  `LINT_CODES`, the lint_error schema enum, and the protocol prefix set,
  gated behind the exported `TERMS_UNCHECKED` sentinel.
- `runtime.glossable()` sits beside `public_item()`/`explain_payload()` as
  the runtime's own decision about what reaches the learner (D-20).
- `term_lookup` is a first-class additive event type: no score key, explicit
  `source` provenance, dedupe on replay, schema `$defs` shape.
- The lesson reader renders the glossary appendix (`<section
  id="glossary">`, `<dt id="term-<slug>">`), Popover-API triggers with
  per-term anchor CSS in one style block, a generic held line, reader
  settings, and the vendored §8.3 enhancement hook.
- `GET /gloss/<stem>/<slug>` and `itembank gloss <bank> <term>` share one
  `gloss_lookup()` resolution; the route records `term_lookup` and returns
  a bare 404 for unknown and suppressed slugs alike (no per-term
  disclosure, no event).

## Decisions Made
- `term_lookup.source` is validated to `reader|session` at the builder and
  recorded by the route as `session`; the reader popover path is documented
  best-effort per UI-SPEC §8.5 and is not claimed as complete provenance.
- The `/gloss` route chose the bare-404 branch of the plan's
  "held copy (or bare 404 per §8.4)" pair: a per-term held response would
  itself tell the learner which term is withheld.
- `print_gloss: inline` is one `@media print` block that un-hides each
  term's single panel (emitted after the paragraph of its first marked
  use), so the printed note count equals the distinct-term count.
- The §8.3 enhancement hook ships as a reviewed vendored inline script
  carrying the exact unavailable copy; it is inert on the reader because
  definitions ship with the page. The in-sitting fetch-on-open variant is
  Phase 6.2's fill (the seam is in place, not a stub).
