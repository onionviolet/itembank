# Phase 999.1: Advanced Visual Item Families — Context

**Gathered:** 2026-08-11
**Status:** Ready for execution planning
**Mode:** autonomous, promoted from BACKLOG (2026-08-10 review verdict: re-review

<domain>
## Phase Boundary

This phase extends the Phase 06.1 visual assessment protocol (plot + number
line, protocol integer 1) **additively** into four new declarative visual
families — `hotspot`, `timeline`, `diagram`, and `trace` — each shipping the
same envelope: key-free `interaction_contract`, canonical SCALAR semantic
responses, `runtime.score_response()` as the sole scorer, one
`/api/interact`/CLI commit path, append-only `visual_action` evidence, an
accessible SVG-plus-semantic-HTML renderer, and loud GIFT refusal.

It does **not** add geometry/construction or dense-simulation families, canvas-
only interaction, bank-authored JavaScript, a second parser or scorer, pixel or
screenshot scoring, or a client-side verdict. Geometry/construction and dense
simulation are recorded as named gaps with design sketches in
`999.1-RESEARCH.md` and the HANDOFF, not faked as complete.
</domain>

<decisions>
## Implementation Decisions

### Protocol and scoring
- **D-999.1-01 (LOCKED):** Protocol integer stays **1**; the new families are
  additive members of the same envelope, not a new version. The 06.1-01-PLAN
  mandates extending the interaction envelope additively, and the envelope
  shape (version/type/interaction/renderer_config/response_schema; the
  five-field interact request; the `visual_action` evidence field set) is
  unchanged. `VISUAL_INTERACTIONS`, `VISUAL_KINDS`, and `VISUAL_ACTIONS` grow;
  plot/numberline items remain byte-compatible and their locked tests stay
  green. Bumping the integer would mislabel existing plot items (public_item
  uses one module constant) and break 06.1's locked fixtures for no gain.
- **D-999.1-02 (LOCKED):** New response kinds, exactly:
  `{"kind":"hotspot","region":ID}`,
  `{"kind":"timeline_event","event":ID,"value":SCALAR}`,
  `{"kind":"diagram_connection","from":ID,"to":ID}`,
  `{"kind":"trace_path","points":[{"x":SCALAR,"y":SCALAR},...]}`.
  Identifiers are stable authored strings (bounded length, no script-bearing
  tokens); values stay exact SCALARs canonicalized with `fractions.Fraction`.
  Tolerance applies per-coordinate (timeline value, trace x/y) and is empty
  for exact-id families (hotspot, diagram).
- **D-999.1-03 (LOCKED):** `runtime.score_response()` remains the sole scorer.
  New verdict helpers are named `_hotspot_verdict`, `_timeline_verdict`,
  `_diagram_verdict`, `_trace_verdict` — deliberately never `*_score`, so the
  repository's structural one-scorer scan stays green. Invalid responses
  (unknown ids, malformed shapes, out-of-domain values, forged fields) fail
  closed as False.
- **D-999.1-04 (LOCKED):** The public contract keeps the 06.1 privacy rule:
  only scene/initial state/actions/response grammar/accessibility text. Scene
  members are closed per interaction; accepted states, tolerance, feedback
  anchors, and reveal content never leave the server item.

### Interaction and evidence
- **D-999.1-05 (LOCKED):** New committed-action types:
  `select_hotspot`, `place_timeline_event`, `move_timeline_event`,
  `connect_diagram`, `place_trace_point`, `move_trace_point`. The D-04/D-05
  commit boundary is unchanged: only successful state-changing commits append
  a `visual_action`; pointer-down/move, hover, tentative/cancelled states, and
  unchanged commits append nothing. Final submit stays the ordinary response
  event. `session.do_interact` and POST `/api/interact` need no behavioral
  change — they validate against the grown `VISUAL_ACTIONS` and the same
  canonical-state grammar.
- **D-999.1-06 (LOCKED):** Observations stay runtime-bounded: canonical
  submitted state, a deterministic error/invariant category extended per
  family (`known_region`, `known_event`, `known_nodes`, `distinct_nodes`,
  `point_count`, plus the existing `in_bounds`/`ordered`/`off_grid`/
  `out_of_domain`/`invalid_response`), an opaque authored feedback anchor, and
  only the Phase-6 entitlement hint tier supplied by the caller.

### Renderer and accessibility
- **D-999.1-07 (LOCKED):** The one `asVisual` registry adapter dispatches per
  `interaction` value. Every family keeps inline SVG **plus** an operable
  adjacent semantic HTML control path that serializes byte-identical canonical
  state through one reducer/commit function (D-07 from 06.1). No canvas is
  introduced in this phase; the 06.1 canvas-fallback rule stays the standing
  constraint for any future dense simulation.
- **D-999.1-08 (LOCKED):** The 06.1 accessibility gates are inherited
  unchanged: 320px/200% reflow, visible focus, one polite status
  announcement, reduced motion, 44px targets, keyboard arrows/Enter/Space/
  Escape, pointer cancellation, non-drag alternative, and named SVG geometry.
- **D-999.1-09 (LOCKED):** GIFT refusal is inherited by type: every visual
  item — including the four new families — is refused loudly by item number
  and `gift.type_unsupported` in default and strict modes; no lossy
  approximation.

### Codex's Discretion
Implementation may choose internal factoring (per-family helper modules or
sections in runtime.py/quiz_page.py, per-family lint codes) consistent with
the plans. It may not weaken exact-scalar, public/private, sole-scorer,
committed-evidence, accessibility, or loud-refusal boundaries, and it may not
ship geometry/construction or dense simulation under a different name.
</decisions>

<code_context>
## Existing Code Insights

- `runtime.py` already owns the closed scene/scoring allowlists, the
  `_reject_visual_exec` scan, `canonical_scalar`/`canonical_axis`, the
  canonicalizers, `_visual_verdict`, `visual_observation`, `interaction_result`
  and `_visual_interaction_contract`; the new families extend these, not fork
  them.
- `model.py` parses `[INTERACTION:]`/`[VISUAL:]`/`[SCORING:]` generically (no
  interaction-specific parse branch is needed) and lints through
  `_visual_lint_findings` against the runtime allowlists; the lint's
  `VISUAL_SCENE_MEMBERS` frozenset must become interaction-aware.
- `surfaces/session.py do_interact` and the daemon/CLI twins are already
  generic over `VISUAL_ACTIONS` + the canonical-state grammar; the five-field
  request, dedupe, conflict, and refusal paths carry over unchanged.
- `evidence.visual_action_event`/`visual_actions` are family-neutral; the
  `action_type`/`after_state` values are data.
- `surfaces/quiz_page.py asVisual` is the one renderer registry adapter; it
  currently branches on response `kind`. It needs an `interaction`-level
  dispatch plus per-family scene/controls/serializer.
- `schemas/item.schema.json` and `schemas/visual_interaction.schema.json`
  enumerate interactions/actions/kinds and must grow with the families.
- `model.py` `SPEC` (visual section, lines ~1683-1725) documents the grammar
  authors see; it must name the new families, response kinds, actions, and
  scene members.
</code_context>

<deferred>
## Deferred Ideas (named gaps, not silent drops)

- **Geometry/construction.** Ruler/compass or transform-construction items
  need a *multi-step operation sequence* protocol (drawn-object history,
  undo/redo, step validation), which is a protocol design question beyond a
  single response kind. Sketch in `999.1-RESEARCH.md`; requires its own
  design review before planning.
- **Dense-simulation-style responses.** 06.1 left canvas/dense simulation
  OPEN/UI-BLOCKED: it may ship only with the identical semantic HTML
  state/control path. A deterministic parametric simulation (finite SCALAR
  parameter set, authored deterministic output readout) is sketched in
  `999.1-RESEARCH.md` but not built here.
- **Diagram label/match variants** (assign labels to nodes, node-to-node
  matching lists) and **trace semantics beyond one ordered polyline** remain
  future extensions of the families shipped here.
</deferred>
