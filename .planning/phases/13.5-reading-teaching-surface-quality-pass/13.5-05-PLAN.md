<objective>
Give the glossary term popover a real interaction design, and fix the reason it
has never had one.

DEFECT D-C: `_gloss_anchor_css` emits `position:absolute` and
`position-anchor:--anchor-<slug>` and never emits `position-area` or an
`anchor()` inset. `position-anchor` alone positions nothing, so the UA's
`[popover]` default of `inset:0; margin:auto` wins and the panel opens centred
in the viewport, detached from the term that summoned it. The 2026-08-12 fix
made the panel visible; it did not make it land anywhere. That is why ROADMAP
criterion 3 — a named flagship differentiator in Weibao's own words, "keyterms
with hover over" — has never been designed against.

The mechanism, the DOM shape, the panel sizing, the `aria-details` association,
the no-leak rule and the "hover may never be the only path" rule are INHERITED
and LOCKED from `03.1-UI-SPEC.md` §8.1 and are not re-litigated. This plan adds
the interaction design §8.1 explicitly left open, and fixes the placement bug.

Purpose: the lookup surface a learner touches dozens of times per lesson is the
cheapest interaction in the product and currently the worst.

Output: a panel that lands at its term, flips at the edges, becomes a bottom
sheet on a phone, opens on hover intent without ever stealing focus or a pinned
panel, links onward to its key card and its full entry, and gets the learner
back to where they were reading.
</objective>

  <action>
(1) **Move the placement onto the shared `.gloss` class.** In `LESSON_CSS`, the
`.gloss` rule becomes:

  position:absolute;
  position-anchor:var(--gloss-anchor);
  position-area:block-end span-inline-end;
  margin-block-start:var(--space-2);
  position-try-fallbacks:flip-block, flip-inline, block-start span-inline-start;
  position-try-order:most-height;
  max-width:min(38ch, calc(100vw - var(--space-4)));
  max-height:min(60vh, 24rem);
  overflow:auto;
  overscroll-behavior:contain;

keeping its existing `background`, `padding`, `border`/`box-shadow` treatment.
`position-area` is the missing line: without it `position-anchor` is inert.
`flip-block` lifts the panel above the term near the viewport bottom,
`flip-inline` pulls it back from the inline end near the right edge, the third
fallback covers the corner, and `most-height` prefers whichever side has room
rather than the first that fits. A long definition scrolls inside the panel and
never grows past 60vh — there is no truncation and no ellipsis anywhere in this
project.

(2) **Shrink the per-slug block to custom properties only.** `_gloss_anchor_css`
must now emit, per slug, exactly:

  `button.term[popovertarget="gloss-<slug>"]{anchor-name:--anchor-<slug>}`
  `#gloss-<slug>{--gloss-anchor:--anchor-<slug>}`

and nothing else. Every other declaration it emits today — `position:absolute`,
`position-anchor`, `position-try-fallbacks` — moves into the shared `.gloss`
rule above. **This is the part that must not be missed:** if the per-slug block
keeps emitting `position-anchor` as a property, the id selector outranks the
class, `var(--gloss-anchor)` never applies, and the shared rule's
`position-area` anchors against nothing — which is D-C again with an extra step.
It is also the cheapest thing to emit per term.

(3) **Guard the slug before it reaches a stylesheet.** `_gloss_anchor_css`
interpolates a bank-derived slug into CSS. Refuse to emit a rule for any slug
that does not match `^[a-z0-9-]+$`, and make the trigger renderer fall back to
plain prose for such a term rather than emitting a trigger with no anchor. Add
one fixture asserting a term whose text mints an out-of-charset slug produces no
CSS rule and no trigger.

(4) **The bottom sheet.** Add, after the `.gloss` rule:

  `@media (max-width:767px) and (pointer:coarse){ .gloss{ position:fixed;
    inset:auto 0 0 0; margin:0; max-width:none; max-height:60vh;
    border-radius:var(--r-3) var(--r-3) 0 0; border-inline:0; border-block-end:0;
    padding:var(--space-3) var(--space-3) var(--space-4) } }`

A 38ch panel anchored to a word on a 375px screen is a 340px box with nowhere
to flip to. It is still the same `[popover]` element, so native light-dismiss,
Escape, focus behaviour, DOM order and the no-leak rule are all unchanged. No
animation — it appears.

(5) **The trigger's own treatment.**

  `.term{ text-decoration:underline dotted var(--edge); text-underline-offset:.15em;
          text-decoration-thickness:from-font; padding-block:2px }`

Dotted in `--edge` rather than `currentColor`, so the affordance is legible
without shouting and without a second accent use. `padding-block:2px` enlarges
the pointer target without disturbing `--leading-lesson`; it is deliberately not
`--space-1`, because 4px would begin to affect the inline box, which is the
exact failure the reading spec names by name. It is a declared exception to the
spacing scale, not a stray — record that in the CSS comment beside it. The WCAG
2.2 inline-target exception continues to apply and is compensated by the 44px
glossary-appendix entry.

(6) **Do not touch the print path except to leave it scoped.** `_gloss_print_css`
and `LESSON_CSS`'s `@media print` block stay as they are; the popover-scope
invariant in `tests/stylesheet_roundtrip.py` already fails if a print rule leaks
to screen, which is how that defect was caught the first time.

(7) **Create the phase gates document as a skeleton**, because this is the first
plan in the phase that records a human result into it. Create
`.planning/phases/13.5-reading-teaching-surface-quality-pass/13.5-GATES.md` with a
one-line purpose statement, a `## Human-verified gates` table whose columns are
gate, plan, procedure, result and date, and this plan's rows filled in with the
result field left empty. Plans 14-06 and 14-07 APPEND their rows to this table;

machine-versus-human split and the RTS requirement roll-up. Do not attempt the
full roll-up here — a skeleton with three honest empty result fields is the
deliverable.

**The automated half of this task proves the CSS contract, not the geometry.**

<task type="auto">
  <name>Task 2: Hover intent, and getting back to the text</name>
  <files>surfaces/lesson.py, schemas/settings.schema.json</files>
  <action>
**Hover intent is additive only. The click and keyboard path is complete on its
own and is never modified by this task.**

(1) **The setting.** Add `gloss_hover` to the `reader` object in
`schemas/settings.schema.json`: enum `on | off`, default **`on`**,
`x-itembank-phase: 13.5`, described as applying only under
`(hover:hover) and (pointer:fine)` and as restoring the pure click/focus path
when off. Add it to that object's `required` array and whole-object `default`
alongside the existing reader rows, and thread it into the reader render context
beside `gloss_marks` and `print_gloss`.

(2) **The script**, emitted only when `gloss_hover` is `on`, wrapped so it does
nothing outside `matchMedia("(hover:hover) and (pointer:fine)")`:

  open delay after `pointerenter` on `.term`: **180 ms** — long enough that a
  pointer crossing a sentence never flashes a panel, short enough to feel
  immediate on intent;
  close delay after `pointerleave` of **both** the trigger and the panel:
  **260 ms** — the travel budget from the term to the panel 8px below it;
  re-entering either during the delay cancels the close;
  open transition: **none**. It appears;
  cancel triggers: `scroll`, `pointerdown` anywhere, `keydown`,
  `visibilitychange` — a panel must never arrive after the learner has moved on.

Three rules keep it from becoming a flicker war, and all three are LOCKED:

  a. A hover-opened panel is marked `data-gloss-open="hover"`. A click-opened
     panel is `data-gloss-open="click"` and is **pinned**: hovering a different
     term while a pinned panel is open opens nothing, and the learner must
     click. This is what stops the second of two adjacent terms in one sentence
     from stealing a panel the learner deliberately opened.
  b. **Hover never moves focus.** Only click, Enter and Space do, which is
     native `popovertarget` behaviour and is inherited unchanged.
  c. Terms are `popover` (that is, `popover="auto"`), so opening one natively
     closes any other. Exactly one panel can be open at a time **by platform
     guarantee**. Write no bookkeeping for this; a hand-rolled "close the others"
     loop is code that can only disagree with the platform.

**Evidence:** a hover-open records nothing. `03.1-UI-SPEC.md` §8.5 left the
`term_lookup` field open on this point and the resolution is to record
click-opens only — a hover is weaker intent than a click, under-recording is
reversible, and a polluted append-only field is not. The existing click path's
`term_lookup` write is unchanged; do not add a second write site.

(3) **`Full entry` closes the panel it was clicked from.** Without this the
popover stays in the top layer floating over the appendix. On a click inside
`.gloss-more a`, call `hidePopover()` on the containing panel before the
fragment navigation. With scripting off the panel is dismissed by the next
Escape or outside click — degraded, not broken.

(4) **The arrival is visible.** Add to `LESSON_CSS`:

  `#glossary dt:target, #glossary dt:target + dd{ background:var(--chip) }`
  `#glossary dt:target{ border-inline-start:2px solid var(--accent) }`

Colour is not the only channel: the `:target` entry is also the scroll
destination, which is the primary cue.

(5) **The way back.** The `id="use-<slug>"` anchor on a term's first marked
occurrence and the appendix's `Back to first use` link already exist and are the
unchanged baseline. Add the script-only enhancement: when the appendix was
reached from a specific trigger, that entry's back link swaps its `href` to the
originating occurrence and its label to **`Back to the text`**. Without script
the baseline string and the first-use target are exactly what they are today.

**There is no "back to the section nav" link.** The browser's back button covers
it and a second back-affordance on a reading page is clutter. Recorded here so
it is not invented later.
  </action>

14-UI-SPEC §7.5 settles what criterion 3 actually asks, and it is a rule rather
than a preference:

  the **gloss panel** is a *lookup* — transient, costs nothing, commits to
  nothing. It may contain the term, the definition, the `Full entry` link, and
  when applicable one `Also a key point` link. Nothing else.
  the **`[!KEY]` card** is a *commitment* — "this is on the exam", it exports to
  Anki, and it owns the `Add to review` control it has always owned.
  the **glossary appendix** is the *record* — the print surface, the `Full entry`
  target, and the 44px target path the inline exception owes.

(1) **The gloss panel never carries an `Add to review` control**, and this task
adds none. A transient hover panel is the wrong place for a decision that writes
to a scheduler, and putting one there would make an accidental hover one click
from a commitment.

(2) **`Also a key point`.** Resolve `model.parse_key_blocks` in the same render
pass that builds the gloss map, and build a `{slug: anchor}` lookup. The match
rule, decided here so the executor does not guess: **a `[!KEY]` block whose body
carries a `[[…]]` reference that mints the same slug**. That is a render-time
lookup against already-parsed output — no format change, no new parse, and it is
authored intent rather than a text-similarity heuristic. When a match exists,
`_gloss_panel_html` renders one additional Ledger line linking to that card's
anchor with the copy **`Also a key point`**; when none exists the line is absent
entirely, never an empty or disabled one. If the `[!KEY]` card renderer does not
already emit a stable anchor, give it `id="key-<minted id>"` using the id the
card already carries from plan 03.1-03's minting — do not mint a second id
namespace.

(3) **Fixtures** in `tests/lesson_roundtrip.py`:
  - a lesson whose `[!KEY]` block references a glossed term renders exactly one
    `Also a key point` link, pointing at that card's anchor;
  - a lesson with no such block renders no such line and no empty container;
  - the panel's rendered bytes contain no scheduler or review control;
  - a suppressed term (the `glossable()` silence rule) still produces no panel,
    no trigger, no appendix entry and no anchor rule — the inherited no-leak
    rule is unaffected by everything above;
  - a bank with no `## TERMS` section renders the lesson body byte-identically
    to its pre-plan output, which is the additive-format floor.
  </action>
