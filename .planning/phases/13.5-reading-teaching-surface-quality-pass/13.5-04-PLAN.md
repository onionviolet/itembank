<objective>
Make the sat quiz look like the same product as the reader.

DEFECT D-B is fixed mechanically by plan 14-01 — the shared token layer is now
in the document. This plan spends that: it assigns every string on the quiz page
the voice of whoever authored it, collapses twelve font sizes (five of them
fractional) onto the five project sizes, and raises every response control's
boundary to the 3:1 that WCAG 1.4.11 requires and that a 1.28:1 hairline on a
card has never met.

14-UI-SPEC calls voice repair "the largest single 'feels designed' lever", and
it is right for a blunt reason: half-pixel type sizes are the most legible
symptom of assembled-rather-than-designed, and they are why a learner reads the
quiz and the reader as two products.

Purpose: ROADMAP criterion 2 on the surface a learner spends the most time in,
plus the accessibility gate that is currently failing rather than merely
imperfect.

Output: one type scale, four voices, one palette, and three fixtures that keep
all three true.
</objective>

<task type="auto">
  <name>Task 2: Twelve sizes to five — the per-site disposition</name>
  <files>surfaces/quiz_page.py</files>
  <action>
The deciding rule, LOCKED in 14-UI-SPEC §4.2 and applied here site by site:
**12px is the label size** and may carry only non-interactive labels, small-caps
ledger headers, provenance ids, chips, table column headers and one-line compact
status. **Any string inside an interactive control, and any string a learner
must read in order to recover from a failure, is 16px minimum.**

Stated once as the tie-breaker for every site below: a string that *labels or
identifies* something is 12px; a string that is *read as a sentence* — prose,
an option, a rationale, help copy, recovery copy, a verdict, generated text —
is 16px, as is anything inside a control.

  → **12px**
    `.context-line` (orientation metadata), `.session-details` container,
    `.chip`, `.choices legend`, `.ord`, `.exp h4`, `.case .case-n`,
    `.case .st` (a one-line compact status), `.case .cf h5`,
    `.generated h4` / `.authored-hint h4` / `.rubric h4`,
    `.generated-disclosure`, `.rubric-token`, `.provenance`

  → **16px**
    `body` (`font:16px/1.5 var(--font-chrome)` — the line height moves from
    1.55 to 1.5 to match the shared layer), `.session-details summary`,
    `.session-details a`, `.choice .k`, `.opt .k` (inside a control),
    `.choice .rat`, `.opt .rat`, `.seg button`, `.feedback`, `button.go`,
    `.hint`, `textarea.ans` (also the iOS focus-zoom floor), `.codewrap`
    (and therefore its inheriting `.cm-*` children), `.case pre`, `.refused`,
    `.lti-framing`, `.agent-assist`, `.assist summary`, `.assist-status`

  → **20px**  `h1.stem` inside the `@media (max-width:767px)` block (unchanged),
    and the two inline `17px` sites described below

  → **32px**  `h1.stem` (from 28px), `.score` (from 34px)

  → **weight**  `.score` from `700` to `600`. It is the only off-pair weight
    in the file.

**`.case pre` takes 16px and is not an exception.** 14-UI-SPEC grants exactly
one named exception to the 16px rule — the reader's `.run-stdout`/`.run-stderr`,
an arbitrarily long verbatim transcript whose recovery sentence lives elsewhere
— and says plainly that a second exception would mean the rule is wrong rather
than the site. `.case pre` is not that shape: it holds the authored expected
output beside the learner's actual output, short and compared line by line, and
it IS the content a learner reads to find their bug. Set it at 16px in code
voice and add no exception.

**The four inline styles in the two client scripts** are CSS too, and both
clients carry a copy of each. Replace them with classes defined in the style
block, so a size never hides inside a template literal:

  the model-answer note (`class="blk"` with an inline `color`/`font-size`, in
  both `OFFLINE_JS` and `SERVED_JS`) → a `.blk.note` rule at 16px, `--mut`;
  the auto-marked percentage beside `.score` (an inline-styled `<span>` in both
  clients) → a `.score-sub` rule at **20px**, `--mut`.

**Do not touch the `font-size` attributes on SVG `<text>` elements** in the five
visual-item renderers. Those are SVG presentation attributes inside a scene the
`06.1-UI-SPEC.md` contract owns; they are not CSS declarations, this phase does
not govern them, and Task 3's fixture is written to match declarations only so
it will not flag them. Changing them would alter a scene the visual-interaction
contract specifies.

Leave `.lock-glyph`, `.lock-label`, `.lock-copy` and `.assist-lock` in place for
now — plan 14-07 retires the whole padlock component, CSS and markup together,
and deleting half of it here would leave a broken state between plans.

  <name>Task 3: --edge on the controls, and three fixtures that hold the line</name>
  <files>surfaces/quiz_page.py, tests/stylesheet_roundtrip.py</files>
  <action>
(1) **Apply `--edge`.** `--line` against `--card` measures 1.28:1 in light and
1.26:1 in dark. On this page the response controls are identified by a
`1px solid var(--line)` border on a `--card` fill that sits 1.06:1 from the page
background, so a learner identifies the primary response control by a boundary
at 1.28:1 — WCAG 1.4.11 requires 3:1 for non-text content that identifies a UI
component. Plan 14-01 landed `--edge` at a measured 3.13:1 or better on all
three surfaces in both modes.

Replace `var(--line)` with `var(--edge)` in the border of these, and ONLY these:
`.choice`, `.opt`, `.seg button`, `button.ghost`, `textarea.ans`, `.codewrap`.

Everything else keeps `--line`: `.card`, `.context-line`'s bottom border,
`.feedback`'s top border, `.rowline`'s divider, `.case` (a readout, not a
control), `.case pre`, `.codewrap .cm-gutters`' right rule, `.rubric-row`,
`.generated`, `.done`, `.lti-framing`, and every table rule. A control's
boundary is a control's boundary; a card edge is not.

(2) **`check_no_colour_literal(sheets)`** — for every in-scope surface
stylesheet, fail on any hex colour literal or any `rgb(`/`hsl(` function outside
a `@font-face` block, naming the selector. `surfaces/theme.py` is the one
palette source and is excluded by name with that reason in a comment. This is
what makes "no second palette" testable rather than maintained by eye, and it is
what catches the two `#fff` literals Task 1 removed if they ever return.

(3) **`check_control_boundary_token(sheets)`** — for the six control selectors
above, assert the border declaration resolves through `var(--edge)`. Read the
selector list from a module-level tuple with a comment citing 14-UI-SPEC §3.4,
so adding a seventh control is one line rather than a hunt. Fail naming the
selector and the token it actually uses.

(4) **Extend the type-scale scope.** Append `"surfaces.quiz_page"` and
`"served /quiz/"` to plan 14-02's `TYPE_SCALE_SCOPE` tuple. Confirm the
declaration-only matching genuinely skips the SVG attributes: add one assertion
that the quiz's collected stylesheets contain at least one `<text>`-bearing
template literal and that the fixture still passes, so a future rewrite of the
matcher into something attribute-greedy fails loudly here instead of silently
rewriting a scene.

Wire all three into `main()` and extend its closing `print`.
