<objective>
Give the six-tier authored hint ladder a route to the browser, and a command to
the CLI, without giving either one an opinion about what a tier contains.

This closes DEFECT D-D, the highest-value item in the phase. `runtime.HINT_TIERS`,
`runtime.authored_hint` and `runtime.teaching_transition` have shipped since
Phase 6 and are fully specified and LOCKED in `06-UI-SPEC.md` §5-§6, but
`surfaces/quiz_page.py` contains no occurrence of the string that names the
unlock action, and `surfaces/cli.py` has no subcommand that reaches the fixed
tier reveal either — `itembank hint` is Phase 8's model orchestration, and plan
08-05 deliberately removed the legacy shim from `/api/hint`. The product's
entire teaching differentiator has therefore never been reachable by a learner
in the app or at the terminal.

Purpose: this plan is the backend half of ROADMAP criterion 5. It is the D-09
boundary made concrete — the payload the browser gets is the wire-format
expression of "the runtime, not the model, decides what reaches the learner",
and it is what plan 14-07 renders.

Depends on 14-01 only as the phase's tracer gate: no file, symbol or token from
that plan is consumed here, and the two file sets are disjoint.

Output: one settings pair, one pure payload builder, one session adapter, one
route with its CLI twin and its reserved third-surface name, and the fixtures
that prove nothing leaks.
</objective>

  </read_first>
  <action>
Add ONE pure function to `runtime.py`, beside the Phase 6 block and importing
nothing new:

  `teaching_payload(q, rec, mode, locked_preview="full")`

It takes an item, a teaching record (`new_teaching_record()`'s shape), the
session's feedback mode, and the resolved preview setting. It reads no file,
writes nothing, and touches no session.

**Returned shape**, which is 14-UI-SPEC §9.1's LOCKED payload:

  `available`         — false in any mode whose `FEEDBACK_POLICIES` `wrong`
                        entry is not `hold`. Read that decision from the
                        existing table; do not restate the mode list, or a
                        future mode gets a ladder nobody decided to give it.
  `unavailable_reason`— null when available; otherwise the mode's own inherited
                        sentence: drill, diagnostic and exam each have exactly
                        one in 14-UI-SPEC §9.3, reproduced verbatim.
  `shown`             — one entry per already-shown tier, in index order:
                        `{index, name, label, header, display, available}`.
                        `display` is `authored_hint(...)["display"]` for an
                        available tier and, for an unavailable one, the
                        inherited sentence `This item has no authored {label}.`
                        with the tier's own label. `available` on a SHOWN tier
                        is disclosed information (06-UI-SPEC §5.2 discloses
                        availability at the moment a tier is shown) and is what
                        lets the renderer style it as the unknown state.
  `next_locked`       — `{index, name, header, unlock_copy}` for the single next
                        unshown tier, or null when none remains.
  `further_locked`    — the remaining locked tiers after that one, each
                        `{name, header, unlock_copy}` and **no index**, because
                        their tier number already appears inside their own
                        locked copy and nothing else needs it. Empty when
                        `locked_preview` is `next`.
  `entitled`          — true when a tier is unlocked and not yet shown.
  `exhausted`         — true when the last tier has been shown.
  `unlock_path`       — `"attempt"` when `entitled`, else `"stumped"`.

**`header`** is resolved here, never by a client:
`TIER {n} · {LESSON|OBJECTIVE|TRAP|RATIONALE FOR {letter}|DISCRIMINATOR|REVEAL}`,
where `{letter}` for tier 3 is the first canonical option in the record's
`last_genuine_canonical`. **`unlock_copy`** is a LIST of Ledger lines, not one
string, because the inherited copy table has two separate rows for the next
locked tier and joining them would make a fixture asserting either row depend on
the join: `["Tier {n} unlocks after another attempt.", "Or unlock it now with \"I'm stumped\"."]`
for `next_locked`, and `["Tier {n} unlocks after tier {n-1}."]` for each
`further_locked` entry. Under `locked_preview: next`, append the inherited
`{k} more tiers after this one.` line to `next_locked`'s list instead of
emitting `further_locked`.

**What the payload must never contain**, and what the fixtures assert:
an unshown tier's body or `content`; an unshown tier's availability; a
`highest_tier_unlocked` or `attempt_count` number; anything a client could use
to name a tier in a request. `display` is text the runtime already resolved; a
client that re-derived display text from an id would be a second place deciding
what a learner reads.

Add `teaching_payload` to `itembank.py`'s `__all__` alongside the existing
Phase 6 exports.

Extend `tests/hint_roundtrip.py` with, at minimum: an unshown tier's authored
text is absent from `json.dumps(payload)` at every state from first hold to the
reveal; `further_locked` is empty under `next` and full under `full`; a tier-3
header names the letter the learner actually picked; an unavailable shown tier
carries the inherited sentence and its `available` flag; and each of drill,
diagnostic and exam returns `available: false` with its own reason and an empty
`shown`.

(1) **`surfaces/session.do_teach(session_file, kind=None)`.** With `kind` None

payload with no transition, no evidence write and no session write. With `kind`

ladder is unavailable for the session's mode it returns that payload unchanged
and performs NO transition, then it calls the existing
`do_action(session_file, {"kind": kind})` — the one adapter, which already
appends the hint event with its unlock path and writes the session — and returns
the freshly rebuilt payload alongside `do_action`'s own `accepted`, `action`,
`status`, `evidence` and `next`. It resolves `hint_locked_preview` through

the client never sends it.

  - any top-level field outside `session_id` and `action` is refused 400 by

    the existing `API_ACTION_FORBIDDEN_FIELDS` gate (which refuses `mode`,

    body and the action object before any policy work;

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/agent → `POST /api/teach` | untrusted JSON crosses here and asks for disclosure |
| CLI argv → `do_teach` | a local caller asks for the same disclosure |
| runtime → payload → browser | the tier gate is crossed here, once, in one direction |
| settings file → `hint_locked_preview` | a persisted value widens or narrows what is previewed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-09 | Information Disclosure | `teaching_payload` | critical | mitigate | The payload carries resolved `display` text for SHOWN tiers only; `further_locked` entries carry a header and an unlock sentence and no body, no availability and no index. A fixture serializes the payload at every ladder state and asserts each unshown tier's authored text is absent from the bytes. |
| T-14-10 | Elevation of Privilege | `/api/teach` request body | critical | mitigate | `kind` is an enum of exactly two values; every other body and action field is refused 400 by name before any policy work; the existing `API_ACTION_FORBIDDEN_FIELDS` gate (which names `tier` explicitly) is applied to both objects. A client cannot address a tier at all. |
| T-14-11 | Elevation of Privilege | `hint_locked_preview` | high | mitigate | Resolved server-side from the settings file by `do_teach` and passed into a pure function; it is not a request field, so a client cannot widen its own preview. |
| T-14-12 | Tampering | mode gate | high | mitigate | Availability is derived from the runtime's own `FEEDBACK_POLICIES` table rather than from a restated mode list, and `do_teach` refuses to transition when the payload reports unavailable — so diagnostic and exam sittings cannot be talked into a reveal through this route. |
| T-14-13 | Repudiation | hint evidence | high | mitigate | The transition goes through the existing `session.do_action`, which is the only path that appends a hint event with its `unlock_path`; a read performs no transition, and a fixture asserts a double read appends no second event. No second evidence writer is introduced. |
| T-14-14 | Denial of Service | unbounded reads | low | accept | The route is loopback-only and identifier-addressed; a read is a bounded file load already performed by four sibling routes. |
| T-14-SC | Tampering | npm/pip/cargo installs | high | mitigate | **No package is installed by this plan.** No install command appears in any task. No package-legitimacy checkpoint is owed. |
</threat_model>
