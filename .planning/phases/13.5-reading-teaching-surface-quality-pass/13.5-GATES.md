## Defects and confirmations from the 2026-08-16 agent pass

- **D1 (defect, RTS-04): CLOSED 2026-08-26 by quick plan 260817-q7d.**
  Re-measured 2026-08-26 in a live Chromium engine against the merged tree,
  loopback daemon serving `fixtures/lesson_bank.md`, `/lesson/lesson_bank`
  at a 1280px viewport, geometry read with `getBoundingClientRect` and
  `getComputedStyle`: the prose line box inside `.card` renders **529px** at
  the 18px reading face (`--measure-prose` still `59ch`; `.wrap` computes
  `max-width:611px` = 531 + 32 wrap gutter + 48 card padding; `.card` box
  579px, content 531px, minus the card's 1px border per side leaves 529px of
  prose). 1ch measured 9.000px, confirming the 18px Source Serif 4 reading
  face is what the token resolves against, and a line holds about 58.7 real
  characters. PASS against the 531px contract within the 2px the card border
  takes; the 109px shortfall below is gone. Original defect text follows.
  The real rendered measure was 422px, not the contracted 531px. 13.5-02 retuned `--measure-prose` to 59ch expecting
  59ch at the 18px reading face (531px, 66 real characters). Two mechanisms
  eat it: the `ch` unit resolves where the token is used (`.wrap`, 16px UI
  font), giving 472px; and an inner `.card` layer adds 24px padding per side
  the plan arithmetic never included, leaving 422px of prose, roughly 52
  real characters. Fix candidates: set the reading font on `.wrap` before
  the measure applies, or declare the measure in px as the plan's own 531px,
  and account for the card padding either way. One-file CSS fix in
  `surfaces/presentation.py` or `surfaces/lesson.py`; retune, do not touch
  the scorer path.
- **D2 (defect, 13.5-06 band): CLOSED 2026-08-26 for the total, with one
  named limitation left open.** Re-measured 2026-08-26 against the merged
  tree, same loopback daemon, `/quiz/lesson_bank` (a 3-item sitting): first
  paint reads **"Item 1 of 3"** in both the raw served HTML (`<b id="tot">3</b>`,
  no `__CTX_TOTAL__` leak) and the live DOM before any interaction, and
  `itembank build` writes the same server-rendered total into the offline
  page. The total is fixed. **Still open, deliberately backlogged and not a
  regression of this defect:** the position counter always reads "Item 1"
  under the served baseline, because the client `render()` never runs there;
  only the total was server-rendered by 260817-q7d. Answering item 1 in the
  live browser left the band at "Item 1 of 3". Original defect text follows.
  The quiz context band rendered "Item 1 of 0" on first paint of a 3-item sitting (`#tot` is 0 before any interaction).
  Total should be server-rendered; a counter that self-corrects only after
  the first action still shows a wrong number at first paint.
- **C1 (confirmed safeguard): the runtime `glossable()` suppression gate
  works in a live browser.** Two staged terms whose text overlaps keyed
  content ("Patent airway" in Q1 rationale text, "Jaw-thrust" in the Q3
  model answer) parsed correctly at the model layer but rendered as bare
  text with no trigger, no panel markup, and no glossary entry, exactly as
  the disclosure gate intends.
