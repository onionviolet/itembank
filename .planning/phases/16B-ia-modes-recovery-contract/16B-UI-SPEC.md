# Phase 16B: UI Design Contract

> Visual and interaction contract for frontend phases. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

**Session mode:** autonomous (`--auto`). No `CONTEXT.md` exists for this
phase, matching the recorded precedent for Phases 14A through 16A. Every open
point below was resolved from `16B-RESEARCH.md`, `REQUIREMENTS.md`,
`ROADMAP.md`'s Phase 16B section, `research/phase-16/14-synthesis.md`, and the

**Scope boundary (binding on this document).** Phase 16B is a **logical
contract phase**: information architecture, routes, states, navigation
semantics, mode authority, recovery behavior, and copy. It is explicitly
**not** a visual-token, palette, typography-scale, or component-styling

semantic tokens (`--ok`/`--bad`/`--warn`/`--unknown`/`--pending`) are reused
and assigned to the new IA surfaces this phase introduces.

discipline (`surfaces/daemon.py`, Pattern 2 in `16B-RESEARCH.md`), every row
below is a new entry in those same four parallel structures, never a second
router.

### App level

| Route | Area | Contract |
|---|---|---|

When none exists (including a fresh install before any course is bound), renders today's shipped bank/plan listing unchanged, the literal string `"/"` and its CLI mapping (`daemon`) do not change. |
| `GET /activity` | Activity (durable agent/maintenance jobs) | **Decision (see log): registered in `ROUTES` now**, inserted into the fixed-literal block before `API_ROUTES` per the shipped ordering rule. Recorded here as a reserved App-level area name so a later phase does not have to renegotiate its position. |

### Course level

All course-level routes share the fixed pattern `/course/<course_id>/<area>`,
with `/course/<course_id>` (no area suffix) as Overview. `<course_id>` is an
opaque stable ID (per `ID-01`/`ID-02`), never a title-derived slug or ordinal
position, so a renamed course never breaks a saved or shared link.

| Route | Area | Notes |
|---|---|---|
| `GET /course/<course_id>` | Overview | Current goal, next justified action, blockers, alternate actions (synthesis §9.1). Parent target for every other course-level area's "Back" control. |
| `GET /course/<course_id>/learn` | Learn | Lists lesson/reading entries; `GET /course/<course_id>/learn/<lesson_id>` opens one, `#<anchor>` addresses a heading/term inside it (see Deep Link & Anchor Contract). |
| `GET /course/<course_id>/practice` | Practice | Formative activities and runtime-governed remediation (unchanged runtime authority, see Mode-Layer Precedence Contract). |
| `GET /course/<course_id>/test` | Test | Quiet formal sitting; only permitted controls render (existing DEFERRED/exam-mode contract, unchanged). |
| `GET /course/<course_id>/map` | Course map | Outline projection first; graph/coverage projections are a secondary view reachable from the outline, never the default (per `GRAPH-01`/synthesis §5's "authored outline is the default human projection"). |
| `GET /course/<course_id>/sources` | Sources | Scope, rights, bindings, locators, conflicts. |
| `GET /course/<course_id>/build` | Build and review | Treatments, drafts, diffs, validation, acceptance, upgrades (Loop F). |
| `GET /course/<course_id>/evidence` | Evidence | Honest snapshots and remediation rationale (Loop E), composed from the `GRAPH-03` tuple, never a rollup percent. |
| (none) | Notes | **No dedicated route.** Rendered as contextual anchors/panels inside Learn and Evidence only, per the explicit synthesis §9.1 statement: "contextual within Learn and Evidence first; a cross-course destination is deferred until real use demonstrates the need." A future cross-course Notes route is a backburner item (synthesis §12.2), not this phase's scope. |

### Deep link, anchor, parent/back, and resume contract (APP-02)

1. **Stable opaque identity.** Every route segment that names an object
   (`course_id`, `lesson_id`) is the object's opaque ID, never a title, slug,
   or position. A course or lesson rename never changes its URL.
2. **Anchors address structure, not position.** A `#<anchor>` fragment
   addresses a heading, term, or item by its stable slug (the same
   heading-slug scheme the shipped lesson `--ref` already uses), never by
   ordinal index. Anchors are resolved client-side after the page loads (HTTP
   fragments are never sent to the server), matching the shipped
   RTS-05/RTS-06 precedent.
3. **Parent/back is a fixed two-level chain, not browser history.** Every
   course-level area's "Back" control targets `/course/<course_id>`
   (Overview) with the label "Back to {course name}". Overview's "Back"
   control targets `/` with the label "Back to courses". This is an explicit,
   labeled control rendered in the page, not a reliance on the browser's Back
   button (which remains available and unaffected).
4. **Focus and scroll restoration.** On following a link to a new deep link
   (including an anchor), focus moves to the target's own heading (or, if the
   fragment addresses a term or item with no heading, to that element's
   nearest labeled container) and the viewport scrolls it clear of the sticky
   context line, reusing the shipped RTS-02 guarantee. On using "Back," focus
   and scroll position are restored to what they were before the forward
   navigation, the previously focused control if one existed, else the
   area's primary heading.
5. **Same routes at every width, no width-conditional route.** A route in
   `ROUTES` never gains a second, narrow-screen-only pattern for the same
   object (Pitfall 4, `16B-RESEARCH.md`). Supporting panes (Sources, Evidence,
   Activity, an agent-support panel) become stacked destinations on narrow
   screens by rendering mode, not by URL, the same `(method, pattern)` tuple
   serves both widths, matching the project `UI-SPEC.md` §3 Workspace rules
   already established for the shipped surfaces.
6. **Resume cue is server-computed, never invented client-side.** The
   course-shelf resume cue (APP-01) and each course-level area's "next
   justified action" (FLOW-01) are computed by the route handler from evidence
   and (once Phase 14A lands) the journal, never guessed or cached
   client-side. When the underlying record is unavailable, the cue reads
   "Not started" or "Showing last valid overview," never a stale or invented
   value.

## Core Loop Resume Contract (FLOW-01)

Each of the seven end-to-end loops (verbatim step sequences from
`research/phase-16/14-synthesis.md` §3) is resumable at an exact position with
a next justified action. The table below is this phase's storyboard
contract, the exact resume unit and next-action copy pattern per loop, which
the freeze-gate storyboard fixture exercises by interrupting a synthetic run
of each loop mid-step.

| Loop | Steps (verbatim, synthesis §3) | Resume unit | Next-action copy pattern (Ledger voice) |
|---|---|---|---|
| A: discover, reconcile, bind | declare read roots and rights → scan read-only → identify by stable ID plus fingerprint → preview and classify → surface duplicates/moves/conflicts/unsupported → choose link/import/copy/move/ignore → bind to objectives → validate → checkpoint and index | last completed step, keyed to the discovery run's own ID | "Continue discovery: {N} files not yet reviewed" / "Resolve {N} conflicts before binding" |
| B: design a course | establish target/scope → import or draft graph → separate outline from prerequisites → map sources/artifacts → classify coverage → choose treatment per objective → define paths/completion → review gaps/conflicts → accept a versioned plan | the objective or treatment decision in progress | "Continue course design: {N} objectives still need a treatment" |
| C: learn and construct notes | resume with objective and rationale → orient → read/observe/predict/manipulate/explain/construct → optionally capture notes → inspect citation → perform a check → receive feedback → transfer in changed context → save position/next action | exact lesson position (anchor) plus activity attempt state | "Resume {course name}" (course-shelf CTA) / "Continue reading: {heading}" (in-lesson) |
| D: practice and test | choose practice or enter a fixed test → runtime provides public item → learner responds → runtime records/scores or marks pending → runtime grants the permitted feedback tier → practice may remediate/retry → test preserves formal conditions → report separates settled/pending/unknown/omitted | session cursor (existing shipped session contract, unchanged) | "Resume practice" (an open session exists) / "Start practice" (LOCKED, reused verbatim from project `UI-SPEC.md` §7 Copywriting contract) |
| E: evidence and remediation | replay a named evidence snapshot → show scope/denominator/window/pending/unknown/uncertainty → explain a recommended next action → learner accepts/chooses another/overrides → revisit prerequisite/explanation/example/transfer/retrieval → append new evidence | the evidence snapshot ID last viewed | "Review evidence" (LOCKED, reused verbatim from project `UI-SPEC.md` §6 Day/report wireframe) |
| F: author, review, accept | declare objective/treatment/sources/scope/authority → discover existing work → draft smallest missing artifact → record provenance/fallbacks → parse/lint/render/test → show bounded diff/consequences/undo → accept/reject/revise → publish → mark derivatives stale/rebuild | the draft or diff under review | "Continue draft review: {N} findings to resolve" |
| G: maintain, recover, leave | detect external/source/version change → mark affected bindings/proposals stale → compare base/current/proposal → rebind/migrate/supersede/retain → write atomically with journal → validate → export package/loss report → restore on a clean machine → rebuild disposable state | the pending stale/conflict item, or the export/restore job | "Resolve {N} stale item(s)" / "Continue restore" |

**Rule, binding on every row:** a loop interrupted at any step (crash,
cancellation, close-and-reopen) never loses its position; the next visit to
that loop's owning route recomputes the resume unit from durable state
(evidence, and once 14A lands, the journal), never from client-side memory
alone.

## Mode-Layer Precedence Contract

Reuses the LOCKED seven-layer table already established in project
`UI-SPEC.md` §15.1 and `research/phase-16/14-synthesis.md` §8 verbatim; this
phase's job is to place it as a documented, settings-visible contract (per
`16B-RESEARCH.md` Open Question 3's recommendation), **not** to build the
full enforcement composition, which is Phase 16C's (`STRATEGY-02`).

| Layer (highest authority last) | Controller | Example |
|---|---|---|
| Learner preference | Learner, reversible at any safe transition | reader/guided view, allowed note strategy, "choose another" next action |
| Author/course strategy | Course builder within the registered catalog | authored sequence, required artifact, direct-reading treatment |
| Objective constraint | Objective and blueprint authority | cognitive demand, required construct, permitted evidence |
| Accommodation override | Learner need or assigning authority | equivalent input/output, pace, reduced motion |
| Instructor policy | Assigning authority for a bounded course | required path, deadline, formal completion predicate |
| Runtime authority | Fixed, never user-configurable during a sitting | scoring, keyed disclosure, retries, formal-test pause |
| System safety | Fixed | permission scope, rights/egress checks, no authored-script authority |

**16B's concrete deliverable (not 16C's):**

1. The expanded settings schema (see Settings Expansion Contract) exposes the
   *configurable* layers (learner preference; accommodation, where the
   learner is also the assigning authority) as settings, and renders the
   *fixed* layers (runtime authority, system safety) as read-only text, never
   as a toggle.
2. **Conflict-resolution copy (exact string, reused whenever a lower layer's
   request is overridden):** "{Setting name} is set by {higher layer name}
   for this course and can't be changed here." Example: "Timed test mode is
   set by your instructor's policy and can't be changed here."
3. A settings-schema fixture must prove one conflict (a learner-preference
   value contradicted by instructor policy) resolves toward the higher layer
   with this exact copy, this is the "fixture proving a conflict resolves
   toward the higher layer" `16B-RESEARCH.md` recommends, sharing its shape
   with 16C's own `STRATEGY-02` fixture rather than duplicating enforcement
   logic.
4. Full precedence *resolution* as a runnable function composing every
   layer's live state is explicitly **out of 16B's scope** and belongs to
   Phase 16C, which owns the strategy registry the objective-constraint and
   author-strategy layers actually read from. 16B's freeze record states this
   boundary explicitly, matching the ROADMAP "Prototype-before-freeze
   coupling" note.

## Activity (Durable Jobs) Contract

**Naming warning, load-bearing (Pitfall 3 / Assumption A4,
`16B-RESEARCH.md`):** the IA area named "Activity" here (durable agent and
maintenance jobs) is a **different object** from `REQUIREMENTS.md`'s
`ACTIVITY-01`/`02`/`03` family (purpose-first learner questions/activities).
They share a word, not a schema. Every fixture, route, and test this phase
adds must carry a doc comment distinguishing the two; this UI-SPEC uses
"Activity view" (capitalized, IA sense) versus "activity" (lowercase, learner
question/task sense) to keep them visually distinct on the page.

**Data source (Pattern 3, `16B-RESEARCH.md`):** the Activity view is a
**read model only** over `journal.py`'s planned `entries()`/`replay()`/
`object_state()` surface (Phase 14A). It never writes a journal entry, retries
an operation, or decides whether something applied, every state-changing
action a learner takes from this view (e.g. resolving a needs-input job)
calls into `journal.py`'s own commit/undo functions, never a direct file
write (Pitfall 2).

**States and copy (no invented percent, ever, Pitfall 3):**

| State | Trigger | Copy (Ledger voice) |
|---|---|---|
| Needs your input | a `prepared` journal entry with no resolving `applied`/`refused` entry | "Needs your input" section header; job description names its intent and scope, e.g. "Bind 3 sources to Airway adjuncts, review before continuing." |
| In progress, no denominator | a job with no known total step count | "In progress: no estimate." Never a percent, spinner-implied countdown, or fabricated step count. |
| In progress, known denominator | a job with a real, journal-recorded step count | "Step {n} of {N}: {stage name}." A real denominator only, never derived from guesswork. |
| Completed | resolved `applied` entry | "Completed" (`--ok`) |
| Failed | resolved `refused` entry | "Failed: {reason}" (`--bad`); reason is the journal's own recorded refusal text, never a generic "something went wrong" |
| Cancelled by you | a learner-initiated cancellation | "Cancelled. Partial results are marked below and were not saved as final." |
| Interrupted, recoverable | `journal.object_state()` returns `"interrupted"` | "Interrupted: resume available." with a "Resume" action calling `journal.py`'s own resume path |
| Not yet available (14A unbuilt) | `journal.py` absent from the running install | "Activity isn't available yet in this build. Check back after your next update." (Chrome voice, this is a build-capability statement, not an error) |

**Journal metadata boundary (security-relevant, ASVS V5/Information
Disclosure, `16B-RESEARCH.md` Known Threat Patterns table):** the Activity
view renders journal metadata (state, timestamps, object kind, stated
reason) only. It never serializes a journal entry's `before_image` or raw
content bytes into the page, the same public/private payload split
`runtime.public_item()` already enforces for assessment content.

## Locked-Card Refusal Contract (FLOW-02)

A Socratic or tutoring refusal, including the general case FLOW-02
generalizes from the shipped hint-ladder's RTS-09 locked-tier precedent , 
**always renders as a locked card, never as a chat exchange.** No free-text
input box, no message thread, no "typing…" indicator implies an ongoing
conversation the runtime has not authorized.

**Exact card shape (reused verbatim from the shipped RTS-09 hint-tier
pattern, generalized):**

- Header: `{Step or capability name}, locked`
- Body: exactly one sentence stating the unlock condition, in the form
  `"Unlocks after {condition}."`, for example: `"Unlocks after you submit an
  attempt on this item."` or `"Unlocks after the next authored hint tier."`
- No first person, no encouragement, no progress indicator over the card, no
  dimmed-but-visible preview of the locked content (reuses RTS-09's exact
  no-leak rule).
- No control that could be mistaken for "ask again" or "continue talking" , 
  the only affordance on a locked card is whatever legitimately unlocks it
  (submitting an attempt, waiting for the next tier), never a free-text
  submission.

This card is rendered in-flow, in the same support region the hint ladder
already occupies (project `UI-SPEC.md` §6 wireframe, region `[B]`), so a
learner encountering a Socratic refusal sees the identical visual grammar
they already know from a locked hint tier, not a new interaction pattern.

## Offline Help & Error-Code Routing Contract (APP-03)

**Baseline is always offline, never model-dependent (Pitfall 5,
`16B-RESEARCH.md`):** every error state this phase's IA can produce carries a
stated dotted error/status code (matching the shipped `SETTINGS_CODES`/
`LINT_CODES` convention, e.g. `ia.course_corrupted`, `ia.activity_unavailable`,
`ia.route_not_found`). Each code is a `GET /help/<code>` link reading a
bundled, local lookup table, no network fetch, ever, for the baseline.

| Situation | Copy |
|---|---|
| Help entry exists for the code | Short local explanation plus the next safe action, rendered inline via the `GET /help/<code>` route |
| No help entry exists yet for a code | "No additional help is available for this yet.", never a broken link or a 404 |
| An optional model-backed elaboration layer is available on top | Rendered in a Chrome-voice container explicitly labeled "Generated synthesis," per §7.2's `--pending` rule; the offline baseline entry is always shown first and remains fully readable if the model layer is absent |
| Model layer unavailable | Reuses the LOCKED existing copy verbatim: "Generated help is unavailable. You can keep learning with the lesson and authored hints." (project `UI-SPEC.md` §7 Copywriting contract) |

## Degraded-State Matrix

Every state below preserves the last accepted state and exposes the next
safe action (`RELIABILITY-01`, the ROADMAP Phase 16B goal's own closing
clause). Every banner uses the `--unknown` semantic token (never `--bad`,
since none of these states are a learner error) and renders in Ledger voice,
matching the project's existing `StatusNotice` convention.

| State | Exact copy (verbatim, Ledger voice) | Next safe action offered |
|---|---|---|
| Crash or forced quit | "Restored your last saved position. Nothing was lost since your last saved step." | Continue where the resume cue points; banner is shown once, on the next successful launch only |
| Cancellation (of a discovery scan or Activity job) | "Cancelled. Partial results are marked below and were not saved as final." | Resume the same operation, or discard the partial results explicitly |
| Disk full or interrupted write | "This save could not complete (disk full or interrupted). Your previous version is intact. Free up space and try again." | Retry the save; the prior accepted version remains open and usable meanwhile |
| Offline | "You're offline. Reading, practice, scoring, hints, and evidence keep working. Anything that needs a network connection is marked unavailable below." | Continue using every local capability; no blocking modal |
| Permission denied | "itembank could not access {basename}. Check that the folder is still shared with itembank, then try again.", `{basename}` is the bank-author-written basename only, **never a resolved absolute path** (reuses the shipped `lesson.src_unreadable` precedent verbatim) | Re-grant access, or continue with the rest of the course unaffected |
| Future or unknown schema | "This file was saved by a newer version of itembank. The parts itembank recognizes are shown below; nothing is changed or deleted." | Continue viewing the recognized parts; update itembank to see the rest |
| Agent/model unavailable | Reuses the LOCKED existing copy verbatim: "Generated help is unavailable. You can keep learning with the lesson and authored hints." | Continue the authored loop (scoring, hints, evidence, reports) unaffected, per `FLOW-02`'s fixture |
| Corrupted course (APP-01 fixture) | "This course's full record couldn't be loaded. Showing its last valid overview." | "Open last valid overview" (primary) and "View files" (plain-file access), both stay reachable, never a dead end |
