## Deviations from this plan, with reasons

**1. `itembank evidence` needs a query argument.** The plan's step 2 gave
`python itembank.py evidence <the evidence root>`. The shipped command refuses
with `evidence: give at least one of --objective, --subject, --session or
--bank to query`. The walk passes `--session <session>`, which queries exactly
the evidence the walk just produced and is a stronger assertion than an
unfiltered dump.

**2. The walk selects an `mc` item with `--type mc`.** Without it the selector
served a `dnd` item with no options, so no letter answer existed and the
scoring stage skipped. The plan's own instruction is that a stage that cannot
be exercised is marked `SKIPPED` honestly rather than faked; the better outcome
was to make the stage exercisable, so the walk now lands on a multiple-choice
item and the scorer genuinely runs. The skip path is still implemented and
still reports honestly if it ever fires.

**3. `scenario_no_second_authority` strips string literals before scanning
`surfaces/ia.py` for `score`.** Loop D's verbatim UI-SPEC step text is
`runtime records/scores or marks pending`. That is the contract being
transcribed, not a call being made, and a raw substring scan cannot tell the two
apart. The scan now strips comments, docstrings, and string literals, so it
tests the code and not the data. The ban is otherwise unchanged and still fails
on `import runtime`, `parse_bank`, `mark_event`, or any real `score` reference.

**4. Twelve scenarios, not eleven.** `scenario_steps_are_verbatim` is a twelfth,
added because the acceptance criterion requires the verbatim check and no named
scenario in the plan owned it. The final line reports twelve.

**5. Two suite failures remain, both pre-existing and neither 16B's.**
`tests/retention_roundtrip.py` fails with `3 settled with 1 correct must be
weak, got 'at-risk'`, and `tests/phase_062_audit.py` fails only because it runs
the whole suite and inherits it. Reproduced on a detached `git worktree` at
`HEAD` with no 16B change present, and it passed earlier in this same phase, so
it is date-sensitive rather than code-sensitive. Recorded in
`16B-09-SUMMARY.md` and carried forward here; it is not this phase's to fix.

**6. `python3` for `python`, and the suite run with
`ANKI_CONNECT_URL=http://127.0.0.1:1/`.** Carried forward from
`16B-02-SUMMARY.md`.
