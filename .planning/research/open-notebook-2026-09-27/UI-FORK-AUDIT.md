# Open Notebook UI variants for the itembank course companion

**Checked:** 2026-09-27. **Evidence tier:** pinned component and route source, plus component-test inspection. No live UI, screenshot, packaged app, keyboard trial, screen-reader trial, or learner task was observed. Docker is unavailable on this host and no local Open Notebook API was running at the default port, so a disposable runtime was not practical in this pass. Source code shows intended controls and paths, not whether they work well for a learner.

**Versions:** [Open Notebook upstream `3127f14`](https://github.com/lfnovo/open-notebook/tree/3127f14ea9dbb519f0e4ddc64a0742ca644ba6ef), [eryabyshev desktop fork `f7a7f78`](https://github.com/eryabyshev/open-notebook-app/tree/f7a7f7806d7e7e3b3ca8983c42f3f8ee9ed38b59), and [Construction OS `ff1011a`](https://github.com/Danejw/construction-os/tree/ff1011afb4e99b1435332974993b66c011d63690). The [fork feature report](FORKS.md) owns ancestry, license, dependency, and API findings. The Open Notebook integration research has no original feature row IDs, so `ON-U1` to `ON-U5` are new UI findings, cross-linked to `ON-F` rows. The larger [feature inventory plan](../2026-09-27-source-feature-inventory-absorption-plan.md) will assign `CAP-` IDs later. This report does not add entries to that shared inventory.

## Interaction and accessibility risks from source

Upstream [ChatPanel](https://github.com/lfnovo/open-notebook/blob/3127f14ea9dbb519f0e4ddc64a0742ca644ba6ef/frontend/src/components/sources/ChatPanel.tsx) renders reference links, and [MessageActions](https://github.com/lfnovo/open-notebook/blob/3127f14ea9dbb519f0e4ddc64a0742ca644ba6ef/frontend/src/components/sources/MessageActions.tsx) offers copy feedback and saving an AI response as a note. This is feedback about a research action, not verified correctness. For itembank, a citation click should land on the exact source locator, a save should create a clearly labeled draft note, and neither should imply a scored answer. Those behaviors need a synthetic end-to-end task; the inspected component tests do not cover them.

Upstream [SourceCard](https://github.com/lfnovo/open-notebook/blob/3127f14ea9dbb519f0e4ddc64a0742ca644ba6ef/frontend/src/components/sources/SourceCard.tsx) attaches open to a clickable Card without a visible `tabIndex`, role, or Enter/Space handler in the checked component. [NotesColumn](https://github.com/lfnovo/open-notebook/blob/3127f14ea9dbb519f0e4ddc64a0742ca644ba6ef/frontend/src/app/%28dashboard%29/notebooks/components/NotesColumn.tsx) uses a clickable `div` for opening notes, and its delete menu trigger is hidden with `opacity-0` until hover. [ContextToggle](https://github.com/lfnovo/open-notebook/blob/3127f14ea9dbb519f0e4ddc64a0742ca644ba6ef/frontend/src/components/common/ContextToggle.tsx) renders an icon-only button without a visible accessible name in the checked code. These are **code-level concerns**, not a measured screen-reader result. The desktop fork retains the clickable Card and note `div` patterns in the checked files. Do not copy them into itembank. A keyboard and screen-reader acceptance task should open source and note details, change scope, find the delete action, close a dialog, and restore focus at both 320-pixel and desktop widths.

Upstream's mobile route conditionally mounts only the selected column. Construction OS explicitly keeps hidden Chat mounted while its source or artifact tab is active. That is a plausible continuity improvement for streaming, but only an inference from source. Test switching tabs during a long response and after offline interruption before adopting it. Upstream's [SourceCard retry](https://github.com/lfnovo/open-notebook/blob/3127f14ea9dbb519f0e4ddc64a0742ca644ba6ef/frontend/src/components/sources/SourceCard.tsx) is promising because it exposes recovery on the failed object itself; the actual backend retry and its idempotency remain outside this UI audit.

## Composition and visual styling

The strongest composition pattern is a notebook-level source, note, and conversation workspace with visible context scope. Construction OS adds resizable panels, unread indicators, and an artifact review surface; its broader project model does not map directly to itembank's source-first course. The eryabyshev fork adds a setup wizard and compacts some card headers. These changes alter flow and density. No pinned screenshots or live rendering were inspected, so this report makes **no visual quality ranking** about color, spacing, typography, or polish. A visual trial should compare the same synthetic task at desktop, narrow, zoomed, high-contrast, and reduced-motion settings before any styling adaptation.
