# LearnHouse UI task audit

Date: 2026-09-27. Companion to [the fork feature review](FEATURES.md) and [the original 114-row inventory](../LEARNHOUSE-GAP-INVENTORY-2026-09-27.md). This is a selective interaction audit, not a visual redesign plan.

## Evidence and scope

The original LearnHouse UI is pinned to [`5e28b072`](https://github.com/learnhouse/learnhouse/tree/5e28b0723176b34ba8777b9980db352268aa8234). Forks are pinned to [SYSU-SAM `2c778307`](https://github.com/godarrenw/learnhouse/tree/2c778307db98827b030345e0a98943814b7c6a3a), [St. Joseph's `26682af5`](https://github.com/Shreesh-Sree/learnhouse-stjosephs/tree/26682af57106dabb7ebec77391aeed986d7c8cea), and [Hybreed `75c1783d`](https://github.com/IAmHybreed237/learnhouse/tree/75c1783d7a0b51e4401da0edf477c159765fcb50). Independent [OpenTutor `db15d901`](https://github.com/zijinz456/OpenTutor/tree/db15d901a7c5c5f46941487ca4ebc2cfb20425c2) supplies a block-composition comparison. Itembank's current course shell, workbench, lesson, and quiz source were sampled in this checkout. No learner data was opened.

**Evidence tiers:** `S` means pinned component and route source, which shows intended rendering and event wiring. `P` means a pinned repository screenshot, which shows only one frame and viewport. `T` means a focused automated test exists but was not run here. `R` would mean this review operated a running UI. There is no `R` evidence in this report. The [LearnHouse demo recipe](https://github.com/learnhouse/learnhouse/blob/5e28b0723176b34ba8777b9980db352268aa8234/DEMO_STACK.md) calls for Postgres, Redis, API, collaboration server, and a built web app. A disposable full-stack session was disproportionate to this bounded comparison. Component code and QA screenshots do not prove completed interaction, keyboard use, screen-reader output, zoom, or human accessibility. The fork's recorded browser QA was not reproduced.

## Keyboard, narrow layout, and recovery findings

The most useful fork UI details are mixed with visible limits. SYSU-SAM's quiz choice handlers expose `radiogroup`, `aria-checked`, keyboard events, and focusable options in [component source](https://github.com/godarrenw/learnhouse/blob/2c778307db98827b030345e0a98943814b7c6a3a/apps/web/components/Objects/Editor/Extensions/Quiz/QuizBlockComponent.tsx). Several controls also use `outline-none`; source inspection does not prove a visible replacement focus ring. Its 390-pixel quiz screenshot shows choice text wrapping without horizontal clipping, but only at one content length. The [390-pixel learning-tools screenshot](https://github.com/godarrenw/learnhouse/blob/2c778307db98827b030345e0a98943814b7c6a3a/docs/sysu-sam/QA/learning/08-mobile.png) shows compact tabs and a bottom navigation bar; much of that captured screen is too faint to judge contrast or usable results. Reproduce it before using it as a mobile precedent.

St. Joseph's [course tree](https://github.com/Shreesh-Sree/learnhouse-stjosephs/blob/26682af57106dabb7ebec77391aeed986d7c8cea/apps/web/app/orgs/%5Borgslug%5D/%28withmenu%29/course/%5Bcourseuuid%5D/course.tsx) puts a prerequisite badge on a chapter, but the expandable chapter header is a clickable `div` without a keyboard event or button semantics in the sampled source. The locked activity row still carries a generic sign-in or group tooltip even when the chapter badge says prerequisite. The full locked screen names the prerequisite reason. This is a concrete consistency and keyboard test case, not an accessibility certification for either product.

SYSU-SAM's [lint tab](https://github.com/godarrenw/learnhouse/blob/2c778307db98827b030345e0a98943814b7c6a3a/apps/web/components/SysuTools/tools/learning/LintTab.tsx) handles initial loading and a successful empty result, but the sampled render path does not branch on query error. When data is absent after a failed fetch, it can render the same clean empty state. Itembank should keep `error`, `unavailable`, and `clean` distinct. The fork's publish action has a confirmation and a failure toast, but the [modal wrapper](https://github.com/godarrenw/learnhouse/blob/2c778307db98827b030345e0a98943814b7c6a3a/apps/web/components/SysuTools/shared/ConfirmDanger.tsx) says it closes on either result. The author must be able to recover the exact failed operation without losing context.

## Composition versus styling

**Composition candidates:** the course landing hierarchy, a scoped author readiness list, a preview-to-accept drafting flow, and a return card that names the next real action. These can use Itembank's existing course shell, source bindings, journal, and runtime. OpenTutor's [grid and block wrapper](https://github.com/zijinz456/OpenTutor/blob/db15d901a7c5c5f46941487ca4ebc2cfb20425c2/apps/web/src/components/blocks/block-wrapper.tsx) are a reference for optional derived panels and local failure boundaries, not a reason to replace source documents with blocks.

**Visual styling:** LearnHouse's large thumbnail, floating editor toolbar, rounded cards, fork color coding, and Hybreed's dashboard styling are examples, not established gaps. Compare them against the same Itembank task at desktop and narrow width. A visual treatment earns adoption only if it improves action finding, reading continuity, feedback comprehension, or recovery without weakening text contrast or focus. No screenshot here proves that outcome.
