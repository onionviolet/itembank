# L2: source research and notebook continuity

Date: 2026-09-28. Status: bounded research and implementation routing, not acceptance or installed-app verification. This lane reads the September 8, 18, and 27 source records and samples current Itembank symbols. It does not rerun donors, refresh their heads, import code, or change source and note authority. The [absorption plan](../2026-09-27-source-feature-inventory-absorption-plan.md#d3-five-independent-lanes) defines the shared fixture. The [feature inventory](../../FEATURE-INVENTORY.md) supplies the existing CAP IDs. Evidence classes below are **S** for pinned source inspection in the cited audit, **D** for primary documentation, **H** for a dated hands-on observation, and **I** for an inference or proposed route. None means a successful installed Itembank path.

## Decision for this lane

Preserve Itembank's source objects, locator sidecars, bindings, learner notes, and journal. First test the existing Open Notebook companion and the native reader on one duplicate-passage fixture. Use Open Notebook as a separate, learner-owned research workspace if a pinned local service passes the task. Add a small read-only REST bridge and explicit reviewed note transfer only after identity, auth, rights, and API-shape checks. Benchmark Docling against an actual native extraction loss before adding an extractor. No inspected donor offers a reason to replace the course source owner or fork its entire application.

Current source sample: `source_adapters.py` has extraction paths for Markdown, text, PDF, DOCX, PPTX, web, transcript, OCR, EPUB, and ASR, and `build_sidecar`, `import_source`, `recheck_origin`, and `preview_source` symbols. `course.py` has source-fingerprint validation, rights checks, and `bind_source`. `notes.py` has note-document read/write and separate promotion review. `surfaces/open_notebook.py` currently accepts `healthy` and `ok` for loopback health and opens the external UI root. The September 27 **ON-F1** audit found that the then-inspected companion accepted only `ok`. The sampled current source has since changed, so this is a **source-level repaired candidate**, not a verified service or installed-flow fix. These modules were sampled by symbol and small windows, not read whole. The integration report's broader no-import and no-live-service limits still apply until tested.

## Shared acceptance packet and next dependency

Use one synthetic course with two duplicate passages, a table or equation, one private note, a corrected source revision, an unsupported claim, and a deliberately failed extraction. Capture raw source and accepted fingerprints before each operation. The packet passes only if the second occurrence reopens exactly, excluded material remains excluded, a retained note reopens its source after restart, failed extraction and provider loss preserve readable originals and drafts, and link/copy rights and undo are explicit. Report source, packaged, installed, and human-tested states separately. A healthy API response proves only connectivity.

The source owner should order the work as follows: verify the current companion against a pinned disposable Open Notebook instance, run native exact-anchor and note-return tasks, then compare extraction on a measured failure. A read-only notebook client depends on the first gate. A transfer operation depends on verified API identity, actual response shape, rights, and the course journal. Accessibility needs a later human keyboard and screen-reader pass for source selection, citation return, note preview, and recovery; the pinned UI audit identified code-level concerns but did not run that pass.
