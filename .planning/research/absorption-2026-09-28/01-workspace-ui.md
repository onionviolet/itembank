## Task and existing owner

A learner should enter a course, see one real next action, open a source or lesson, detour to notes or practice, and return to the same objective and reading position. `surfaces/course_workbench.py` supplies the course-area projection, `surfaces/lesson.py` supplies reading, and the shelf/session routes in `surfaces/daemon.py` supply resume. `tests/course_resume_roundtrip.py` covers new, active, complete, ambiguous and unavailable sitting states. `tests/course_workbench_roundtrip.py` checks an objective return link and saved sitting route. These are deterministic source and served-flow checks, not an installed UI trial.

## Decision and cost

First test the existing course and resume path with one synthetic source, long lesson, saved sitting, pending prose item, draft note and unavailable artifact. Add only a failing seam: a scoped source cue, a small preview, or panel-level recovery. A new block registry and persisted layouts would create state, migration and accessibility cost without a demonstrated learner gain. Keep those as registered possibilities under the inventory rather than making them default UI.

The donor repos above are implementation references only. No code or assets are imported, so no donor dependency or attribution is added. Remote egress, canonical course state and assessment authority stay under current Itembank owners. Installation, touch, screen-reader and learner preference remain unverified. L2 owns source research and L3 owns authoring readiness; this report does not decide those flows.
