## Task and current owner

An author should keep an adequate source as direct reading, draft only a missing lesson, correct one block, inspect source citations and a bounded diff, accept the new revision, then reopen and restore it. The course graph and treatment choice belong to `surfaces/course_ops.py` and `blueprint.py`. `surfaces/agent_operation.py` has `start`, `accept`, `reject`, and `undo`; `authoring.py` validates source scope and builds a proposal with `make_diff`. `journal.py` owns fingerprinted atomic writes and undo. `surfaces/lesson.py` renders the accepted Markdown. `course_package.py` and the course package operations own export, verification, losses, and restore. `tests/agent_operation_roundtrip.py` checks a bounded lesson proposal, one journaled accept, double-accept rejection, and undo. `tests/course_package_roundtrip.py` checks package behavior. These are source and test observations; a joined author task in the installed UI has not been shown here.

## Editor and publishing comparison

The [2026-08-09 editor brief](../2026-08-09-lesson-display-editor.md) compared CodeMirror 6, TipTap, Milkdown, a textarea overlay, and external editors. Its recommendation was source-first editing with inline diagnostics and Itembank's own renderer for preview. That recommendation is historical design evidence, not proof of a shipped editor or a current dependency/license check. The [phase-16 editor survey](../phase-16/16-editor-reader-landscape.md) adds a useful version pattern from Ellipsus and GitBook: keep a draft separate, compare it, then create an accepted revision. Obsidian demonstrates plain Markdown with different source and reading views. The same survey cautions that a rich block model or session-as-version storage would compete with Itembank's accepted files and journal. These are product and documentation observations, not copied code.

[Pressbooks](../phase-16/05-learning-program-landscape.md) and [EPUB/MyST](../phase-16/06-feature-style-atlas.md) show portable reading and semantic publication options. They do not settle an editable source format for this task. LearnHouse, Open edX and eXeLearning publish into multi-user or platform contexts with separate access and operations. **CAP-21** stays backburner until a named destination, audience, source rights, account owner, and recovery path exist. A local package and a public publication are separate operations.

## First native slice and cost

Start with **CAP-03 joined to CAP-02 and CAP-23**: one direct reading, one source-grounded lesson draft, one paragraph edit, learner-rendered preview, citation and bounded diff, explicit accept, restart, and undo. Run it first against current source and focused tests. Only implement the smallest failing route or UI element observed in that task. A block editor, slide canvas, background workbench, and new document model would add parsing, selection, accessibility, migration, and recovery work before this first task proves a need for them.

No donor runtime, asset, account service, or dependency is needed for the first slice. Recheck exact source pins and file licenses before any later code adaptation. LearnHouse and eXeLearning are AGPL in the cited surveys; their behavior is a reference here. OpenMAIC and fork licenses need an exact-file check before copying. Every cited source must have read, quote, transform, remote-process, package, export and share rights evaluated for the proposed operation. Keep raw source and accepted lesson files local; hosted generation requires declared egress. The expected fingerprint, atomic write, journal entry, cancellation state, source staleness, and offline restore are acceptance gates, not follow-up polish.
