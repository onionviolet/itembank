## Measured uncertainty: native objective-history scale

Question: does the existing evidence index justify replacement before expanding
the connected course loop? `probe.py benchmark` exercised actual
`evidence.objective_history` and its linear fallback on 1,000, 10,000 and 50,000
synthetic responses across 50 objectives. Scores were supplied synthetic facts,
including pending nulls; no assessment content was scored or disclosed.

| Events | Matched rows | Cold query/rebuild ms | Warm median ms (7 reads) | Linear median ms (3 reads) | Append ms | Retraction ms | Forced-index-directory fallback ms |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1,000 | 20 | 18.951 | 0.357 | 7.508 | 1.650 | 1.289 | 25.386 |
| 10,000 | 200 | 161.597 | 1.121 | 84.071 | 3.897 | 2.343 | 246.947 |
| 50,000 | 1,000 | 861.056 | 5.294 | 394.025 | 9.128 | 7.744 | 1,236.010 |

Observed: indexed and scan results agreed, including same-timestamp order and
pending scores; append added one matching response; retraction removed it;
corrupt index bytes rebuilt transparently; making the index path a directory
forced a warned fallback with the same result. Query operations left log bytes
unchanged. The 50,000-event log occupied 22,471,555 bytes; corrupt-index recovery
took 906.449 ms and its next warm read took 4.296 ms.

Inference: retain the native index and prioritize joined task correctness.
Cold and degraded work deserve visible availability and measurement at the
actual course route. Repeated full-log materialization or parsing on a page
could still dominate, but this probe did not measure it. Before caching a new
view, measure native Overview/Map/Evidence response latency, long-course startup,
source search and restart with identical synthetic inputs. Reuse one immutable
evidence snapshot per operation and invalidate derived state by accepted
revision; do not freeze permissions in a cache.

Limits: one macOS machine, Python 3.14.7, SQLite 3.53.4, sequential local reads,
one cold sample per condition, no HTTP/concurrent writers/power-loss/profiled
memory or learning-effect claim. Two initial probe runs used an integer
`item_ref`, outside the real string reference contract; the mismatch was in the
synthetic generator. It was corrected before the successful benchmark. The
final receipt records the exact `evidence.py` hash; concurrent diagnostics work
was already present, so this is a source snapshot rather than a HEAD-only run.
