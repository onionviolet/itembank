# Product craft references for a distinctive itembank desktop UI

Research date and source access date: 2026-09-25. Status: primary-source research and design proposals, not an accepted visual contract. This report is limited to product design craft. The companion research lanes cover community criticism and learning interactions.

## Scope and evidence standard

The September 18 [UI reference pass](../../../prototypes/ui-renewal-20260918/research/references.md) already recommended a course-centered shell, stable question states, meaningful visual explanations, a clear next action, and parity checks. This pass asks what makes that shell feel deliberately made for learning instead of like a template. The [source-to-course contract](../../SOURCE-TO-COURSE.md) names the course as the user-facing unit and requires sources, lessons, notes, practice, tests, review, and recovery to form one desktop experience. The [September 18 vision entry](../../USER-VISION.md#2026-09-18-coherent-app-renewal-inspired-by-stronger-learning-interfaces) asks for a coherent app renewal without letting the old UI constrain it.

The table records what the product makers or platform owner publish. It does not report a new hands-on trial of any competitor. The application and tradeoff columns are our inferences. Page publication dates are marked unknown when the page did not provide one.

## Synthesis: where the product should have its own voice

The shared lesson is deliberate allocation of attention. Linear spends less attention on chrome as the work grows. Things gives movement a clear destination. Nova lets context appear without displacing the document. Procreate pairs expression with a visible current value and precision controls. Apple ties typography and motion to legibility. Those are craft principles, not a request to copy a screen.

One candidate direction is a **learning workshop**: a light or warm-neutral main reading surface with a stable course map, a source gutter, and carefully colored diagrams or examples. Course identity can come from subject-specific marks, specimen illustrations, and useful visual structures. A biology unit might need an annotated system diagram; a proof unit might need premises, transformations, and a counterexample panel. Both use the same navigation and type rules. This is intentionally different from a monochrome productivity app while still supporting dark and high-contrast appearances. It is a prototype direction, not a decision to make every course colorful.

Avoid a uniform card grid for unlike content. A source excerpt should read like a source with locator and rights context. A worked example should expose steps and assumptions. A question needs response, submission, feedback, and review states. A course map needs structure and status. Generic cards may still be useful containers when their size and behavior fit the task.

Likewise, surface depth should describe meaning. A raised panel can signal a temporary note or active tool; a quiet divider can separate a citation from authored explanation. Shadows and gradients without a role add noise. Distinctiveness comes from a recognizable study rhythm and precise relationships, not from decorative texture alone.

## Five applications and evidence gates

| Priority | Proposed application | Tradeoff and limit | Evidence gate before acceptance |
| --- | --- | --- | --- |
| C1 | Put the actual next learning task at the top of the desk and course shelf. Show course, objective, last place, and what the action opens. Move slogan-like hero copy and decorative art out of the task path. | A first-use empty shelf still needs orientation and a way to add or discover a course. Do not imply a recommendation when evidence is missing. | At desktop and 390 px, a returning learner can identify and open the correct next reading or practice in one obvious action. Empty and unknown states name their cause. |
| C2 | Use one type scale and spacing rhythm across shelf, source, lesson, practice, and review. Give reading text ample width and line spacing. Reserve large display type for genuine section entry. | Uniform typography can flatten subject identity. Allow a restrained second voice in course covers or subject illustrations, with body readability unchanged. | Compare the same synthetic journey at 100%, 200% zoom, narrow window, light, dark, and high contrast. No clipped key text, hierarchy reversal, or hidden action. Human review remains required. |
| C3 | Give each content type a fitting composition inside a shared shell. Use a source gutter for provenance, step layouts for examples, a stable response region for questions, and spatial diagrams only when relations matter. | More templates cost design and maintenance effort. Add a composition only when it improves a named learner task and has a useful plain-file form. | Four representative fixtures, source reading, worked example, nonstandard question, and review, must retain orientation and state. A learner can tell authored explanation from source quotation and runtime feedback. |
| C4 | Use color and modest depth as semantic tools. Prototype both a warm, expressive learning workshop and a quieter neutral treatment. Keep theme choice separate from content and scoring state. | Subject color can collide with status colors or reduce contrast. No status may depend on hue alone. | Show both directions on the same tasks with contrast, color-blind, high-contrast, and reduced-motion checks. Keep the direction that improves scan and comprehension in a user walkthrough, not the one that wins a static screenshot. |
| C5 | Define the complete interactive state set before visual polish: empty, loading, active, selected, submitting, feedback, pending review, saved, stale, conflict, offline, and recovery where applicable. Put source and notes panels under learner control. | State coverage expands the prototype matrix. It prevents attractive default screens from concealing broken work. | Run a synthetic source-to-lesson-to-question-to-review-to-resume path in the installed app. Check keyboard focus, screen-reader names, touch alternatives, saved position, failed submission retention, and truthful runtime state. |

## What would change this recommendation

These are design hypotheses. A learner's same-task comparison may show that a denser map is better than a calm shelf, or that the expressive workshop distracts during formal testing. If so, preserve the underlying contracts and change the composition. A visual prototype alone cannot establish learning benefit, installed-app parity, accessibility, or human acceptance. The prototype should use synthetic material and record the exact task and state being judged. No competitor assets or UI code are needed.
