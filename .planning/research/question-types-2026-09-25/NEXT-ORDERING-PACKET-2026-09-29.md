CONTRACT PROPOSAL: An additive `[ORDERING: {...}]` declaration on build items,
version 1, contains an ordered list of block IDs, required IDs and dependency
edges `[before, after]`. `STEP) block_id | text` defines each block exactly once.
A submitted response is an array of selected block IDs. All required blocks
must occur once; optional unselected distractors remain in the source area;
selecting a declared distractor is incorrect. No duplicate IDs or foreign IDs
are valid input. Every dependency endpoint must name a required block. Reject
cycles, self-edges, duplicate edges, empty/unknown required IDs, missing text,
and more than 64 blocks or 256 edges. Two orders satisfying all dependencies
are equally correct. No dependency means no relative-order constraint.

This contract is a proposal to validate through a reversible synthetic slice
before making it durable. Do not silently reinterpret existing STEP text.
Indentation, executable assembled code, grouped constraints and partial credit
remain registered follow-ups with explicit grammar and scoring prerequisites.
Structural Parsons checks do not establish execution isolation. Promote
indentation only after declaring allowable levels and their exact validity
constraints; executable checking remains a separate runtime strategy.
