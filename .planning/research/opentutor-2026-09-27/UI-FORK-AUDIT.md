## Evidence and limits

**V** means a bundled screenshot was viewed at the pinned repository revision. It establishes composition, visible copy and spacing for one captured state. It cannot prove clicking, viewport reflow, saved state or accessibility. **C** means UI source was read at the pinned revision. It establishes an implemented path, not that the path works in a browser. **T** means a test assertion was read, not rerun. **R** would mean a running interaction was exercised; there is no R evidence in this audit. The original checkout has no installed web dependencies or API virtual environment, and `docker` is unavailable, so a disposable full stack was impractical here. The independent repositories were inspected from pinned source and bundled images. This audit did not inspect a screen reader, touch device, high contrast mode, reduced motion mode or the installed itembank UI.

## Composition and visual direction

**Composition decision.** Reuse itembank's existing course shelf, objective map, lesson reader, runtime, notes and proposal records. Prototype a small optional course-home composition with a prominent continue/source action and two real previews. The original block registry and preview-to-route pattern are useful, while its full dashboard can place many empty cards before a learner reaches a reading. The independent reader's persistent outline and restrained reading column suit an active lesson. The unmerged review chip is a small, clear feedback addition. A separate author workbench can borrow the independent teacher page's source inputs beside an editable draft, with itembank's review and compare-and-swap save replacing auto-save.

**Styling decision.** The original dark cards and muted green accents are a style reference (**U19**), not a capability. The independent reader's warm article layout is another style reference. Test both on the same source, long heading, math, missing-content and narrow-screen fixtures against the current itembank visual system before changing tokens. No viewed screenshot proves contrast, readable zoom, motion behavior or preference from learners.

**Next verification gate.** Build one disposable course with a source, lesson, pending short answer, saved review and intentionally unavailable artifact. Run the acceptance tasks above in the installed itembank UI and a runnable pinned reference if its dependencies become available. Record keyboard and screen-reader observations separately from screenshot judgments. There was no live UI execution in this audit.
