# OpenTutor fork and independent variant audit

Date checked: 2026-09-27. Status: source audit, no code import or product acceptance.
Owner: OpenTutor gap inventory follow-up. Baseline: [GAP-INVENTORY.md](GAP-INVENTORY.md) and the [source-linked absorption plan](../2026-09-27-source-feature-inventory-absorption-plan.md).

## Search scope and result

The original repository was inspected at [zijinz456/OpenTutor `db15d901`](https://github.com/zijinz456/OpenTutor/tree/db15d901a7c5c5f46941487ca4ebc2cfb20425c2). The GitHub [fork API](https://api.github.com/repos/zijinz456/OpenTutor/forks?per_page=100&sort=stargazers) returned 22 public forks. Their **default branches** were compared with the current upstream main using GitHub's compare API. Twenty-one were behind with no unique commits. [JesseQin123/OpenTutor `e5c7a72`](https://github.com/JesseQin123/OpenTutor/commit/e5c7a72ce51b171b8059eb95ad6ff610f4224fc9) had two unique commits that only added six README lines. Neither stars nor a recent fork date identified a better feature implementation. The census covers listed public default branches at this time. It does not cover private or deleted forks, every nondefault branch, or a running app.

Open and recently closed [upstream pull requests](https://github.com/zijinz456/OpenTutor/pulls) were then used to find nondefault fork branches. Selected code and tests were inspected at pinned PR head commits. No fork test suite or live app was run here. A PR author's test checklist is a claim until independently rerun. A closed PR with `merged_at: null` is not upstream behavior. The local upstream source was checked for each claimed overlap.

Independent repositories with a similar name are **separate products**, not forks of Zijin Zhang's OpenTutor. GitHub repository search and the authors' own source were used to screen them. The most relevant inspected ones are [shayan-shojaei/open-tutor `48a011a`](https://github.com/shayan-shojaei/open-tutor/tree/48a011a1269f7f092ce40b1a5a16849e91491321), [LEARNableLabs/opentutor `76dd0c7`](https://github.com/LEARNableLabs/opentutor/tree/76dd0c725e1eaaddbf26741e0c1db45275a2872a), and [itsnone-liu/OpenTutor `ca75336`](https://github.com/itsnone-liu/OpenTutor/tree/ca75336d5065f8ac2ba77d271ae7757d5205b644). The last retains OpenTutor's README and MIT notice but GitHub does not mark it as a fork. Treat it as a source derivative without assuming shared Git ancestry. [Open TutorAI-CE `ffeb896`](https://github.com/arshads1206/OpenTutor/tree/ffeb896ab63381e9008f06a47e1fc53645c358c4) was screened by README, tree, tests and license; its account and enterprise administration stack is outside this bounded learner-workspace audit. `tutornew/OpenTutor` was screened by README and metadata only because it is classroom teacher orchestration, has no repository license detected by GitHub, and does not implement this OpenTutor codebase. No ranking below treats those two as tested variants.

## Decision for the shared inventory

There is **no public default-branch fork to import** from the checked OpenTutor fork set. The strongest near-term improvement is the unmerged #89 failure-versus-empty behavior, followed by the unmerged #69 review outcome and recall-input presentation. These are small UI and read-model changes that should be implemented through itembank's existing course, evidence, and runtime owners. The independent variants contribute a source-first author packet, a text-selection prototype, and a bounded agent-critique idea. Each needs the gate above before promotion. This report changes no original inventory row, contract, implementation, or accepted learner data.

Next search, if a specific slice is selected: inspect that PR's current state again, run its smallest synthetic path, inspect its tests and license at the then-current pinned revision, and compare with the installed itembank UI. Public GitHub metadata and read-only source inspection cannot establish human accessibility, latency, educational benefit, or clean offline restore.
