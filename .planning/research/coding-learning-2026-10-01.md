## Original objective and treatment

Objective: interpret inclusive/exclusive integer boundaries, implement the
matching predicate, explain a failing equality case and transfer the rule to
two-boundary event windows. Prerequisites: functions, lists, loops, conditionals
and integer returns. A short original explanation is useful because the missing
piece is assembling existing primitives into a coherent path, not replacing
the language reference. [Python control flow](https://docs.python.org/3/tutorial/controlflow.html#if-statements)
grounds the semantics; all prompts, inputs, code and explanations are original.

The native unit is prediction, count-over implementation, count-at-most repair,
then an unworked count-active transfer. The existing paired selection contract
keeps the four authored items together and in order in a genuine practice
sitting. This is not a new immutable activity graph. A local project brief
connects the predicate to a file-driven command-line tool without claiming
automatic grading of that project.

Passing examples or finishing the unit does not establish mastery. The
automated benchmark proves that the runtime accepts an independently supplied
transfer implementation, rejects specified misconceptions and records original
attempts; a person must demonstrate unaided transfer and review learning/visual
quality before those claims can be accepted.

### Implemented bounded seam and authority

**Observed defect:** canonical check evidence retained submitted source and an
outcome vector but discarded actual output and error observations. They cannot
be faithfully recreated from the vector. Recovering them by executing on GET
would create a new run and potentially different results.

**Change:** newly recorded check response events optionally carry
`check_feedback`: exact whole-bank SHA-256, tested-item fingerprint and the
existing runtime `interaction_result` envelope from that single bounded run.
It is stored by the existing append-only evidence writer, before the session
write, alongside the existing canonical answer/score. No second state store,
parser, scorer, execution adapter or required event/session field is added.
The optional v2 snapshot is a source implementation extension; old events remain
readable and receive no invented observations. The bank is checked before and
after execution; concurrent changes omit the snapshot. A replay keeps the
original retained event, not a replacement observation run.

`runtime.saved_check_feedback` owns release. The session adapter selects the
latest live current-item response under the existing owner lock, matches the
rendered session/cursor/item, and supplies current revisions. Runtime excludes
other sessions, modes, banks, items, completed sittings, successful/advanced
items, stale revisions, missing legacy snapshots and unreleased staged events.
The evidence fold excludes retractions. Exact bank binding also covers language,
harness and match configuration that the narrower item fingerprint excludes.
No historical attempt is transferred to a changed item.

Native GET derives its observations from this release only when the immediate
receipt has no observations. A hint, reload or process restart neither reruns
source nor appends a response. The UI labels it "Saved run. Current edits have
not been checked." and provides an escaped, keyboard-operable native details
block containing the submitted code. Editing a draft cannot silently make the
old result a verdict on the edit. Formal active feedback remains withheld.
The persisted evidence remains private local data; GET adds no remote egress.

Restart verification found another concrete defect: `session.schema.json`'s
response enum omitted the shipped `check` type. A saved code response therefore
failed the native restart gate even though the JSON/API path could read it.
The enum now names that existing type; no new item semantics are introduced.

Maintenance owner is the existing runtime/session/native quiz route. Storage
cost is bounded case output per genuine retained attempt; it follows existing
evidence export/retention rather than an independent cache lifecycle. Corrupt,
legacy, stale or unavailable snapshots fail closed with the ordinary current
item still usable. Undo reverses these named source diffs; snapshots in later
learner evidence would remain readable optional fields, not require migration.
No real learner evidence was modified in this source pass.
