# OpenMAIC fork census

Research window: 2026-09-27 Eastern / 2026-09-28 UTC. Upstream baseline: [`f2875426`](https://github.com/THU-MAIC/OpenMAIC/tree/f2875426ae5712d26f0a76e54e9de763e86027a6). This is a source audit, not a live trial or a code import.

## Method and meaning

I paged [`GET /repos/THU-MAIC/OpenMAIC/forks`](https://docs.github.com/en/rest/repos/forks#list-forks) with `per_page=100&sort=newest`, de-duplicated repository names, and requested each returned repository's default branch tip and immediate parent through GitHub GraphQL. I compared each tip with the 2,309 commit objects in a full, blob-filtered clone of upstream at the baseline SHA. A tip present in that history is an unchanged or upstream-only default branch at this snapshot. For tips absent from upstream history, I queried [`GET /repos/THU-MAIC/OpenMAIC/compare/main...OWNER:BRANCH`](https://docs.github.com/en/rest/commits/commits#compare-two-commits), recording `ahead_by`, `behind_by`, commit subjects, and changed paths.

`ahead_by` is a commit-graph count relative to the common ancestor. It does not measure distinct current capabilities. A fork can be ahead only because it merged upstream, changed branding, added CI, or kept a feature that upstream later implemented independently. The tables below distinguish substantive source paths from those cases. Source paths prove implementation exists in the fork tree; they do not prove a working learner flow.

Coverage is limited to public repositories returned by GitHub's fork endpoint and their default branches during this window. Feature branches, deleted or private forks, independent copies outside the fork network, and runtime behavior are outside this census. The list changed while paginating, so reported repository counts are snapshot counts rather than a timeless total.
