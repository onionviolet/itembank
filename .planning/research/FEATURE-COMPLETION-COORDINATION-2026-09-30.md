## Delivered native merge-copy seam

`course_package.restore_merged_copy` now copies an explicitly authorized complete
populated root into an owner-only private stage, replays an ordinary package
through existing journal/evidence authorities and publishes the validated union
at a fresh destination with no-replace publication. `merge_source_fingerprint`
provides its required expected revision. Original private files, unrelated
accepted objects, empty directories, permission bits and history are preserved.
Known identity/path/evidence conflicts remain refusals. Reading transport keeps
its dedicated fresh-root restore and is refused by this new union API.

This is a real union operation, but it does not replace or automatically enroll
the original course. Reopen the new root deliberately, with both identities
visible. Copying a root copies its private files, so the caller must authorize
that exact scope, including locally owned unregistered files. Every registered
source-root object requires existing read/export grants; unknown or denied
grants refuse before payload capture. Copying never creates rights. This is an
offline recovery API, not a silently extended
course-enrollment endpoint. Its source-tree cap is 10000 entries and one GiB,
with existing per-file limits; links, special files and unsafe paths refuse.

The source revision is checked against expectation and rechecked after replay.
This detects observed source races; it is not an external writer lease or an
atomic snapshot guarantee against noncooperating changes. No in-place directory
swap is attempted. R's old-descriptor probe proves why a stable generation gate
must precede every canonical writer before in-place replacement can be safe.
Whole-root in-place merge therefore remains open, with the exact writer inventory,
stable external lock, supported exchange and durable recovery intent named in
[R's report](POPULATED-RESTORE-2026-09-30.md).

Synthetic `merged_copy_restore_roundtrip` passes eleven tests: union and private
file preservation, independent accepted object/history, stale expectation,
path/acceptance conflict, observed staging edit, cancel, disk/publication failure,
raced destination, links/FIFO refusal, modes, fresh-process offline retry and
hard process exits before/after publication. Hard exit can retain an owner-only
stage. No automatic abandoned-stage deletion or power-loss guarantee is claimed.
Original root remains untouched; before-publication failure publishes no union;
after publication the complete union reopens and exact restore is a no-op.
