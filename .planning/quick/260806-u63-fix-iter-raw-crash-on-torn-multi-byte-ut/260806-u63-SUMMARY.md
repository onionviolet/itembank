## Files Created/Modified

## Decisions Made
- The functional fix is exactly the one keyword the plan specified (`errors="replace"`) — no restructuring, no raw-bytes read, matching the two sibling readers already on this posture.
- Padding content crosses the subprocess boundary as an ASCII key (`PAD_CHARS` lookup inside the child), never the raw multi-byte character, to avoid Windows console code-page hazards.
- `probe_unlocked`/`probe_locked` were deliberately left on ASCII padding — their `PAD_SHORT`/`PAD_LONG` constants are calibrated in bytes against NTFS sector boundaries, and multi-byte padding would silently triple those line sizes.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed a pre-existing subprocess-startup race in `probe_kill()`**
- **Found during:** Task 3, while confirming the full suite passes reliably after switching the kill probe to CJK padding.
- **Issue:** `probe_kill()` sleeps a fixed 0.2s after spawning the writer subprocess, then unconditionally does `with open(path, "rb") as fh:`. On this machine, Python interpreter startup for the child occasionally exceeds 0.2s, so the writer's own `os.open(..., O_CREAT)` had not yet run when the parent terminated it and tried to read — raising `FileNotFoundError` and crashing the whole suite. Reproduced identically with the original ASCII `"x"` pad key (2 failures in 5 runs) and with the new `"cjk"` key (comparable failure rate) — confirmed this is a startup-timing race unrelated to the multi-byte padding change, not a regression introduced by Task 3.
- **Fix:** Guarded the raw read with `os.path.exists(path)`, treating a not-yet-created file as 0 complete lines — the same "missing log is an empty log, never an error" posture `iter_raw` itself takes for a missing evidence log.
- **Files modified:** `tests/durability_roundtrip.py` (within the already-in-scope file).
- **Verification:** Ran `tests/durability_roundtrip.py` 5 times consecutively after the fix — all 5 passed (0 failures), versus consistent failures beforehand under the same system load.
- **Committed in:** `4c2ba4b` (Task 3 commit).
