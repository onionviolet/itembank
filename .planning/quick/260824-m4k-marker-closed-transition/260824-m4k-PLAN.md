<objective>
Implement the marker-closed transition: the half of the Phase 6 feedback policy
that is specified, depended upon, and implemented nowhere. Today a bank
containing one short item cannot be completed on any surface, browser or CLI,
because a pending prose answer parks the cursor and nothing ever unparks it.
Found by the 13.9 walking-skeleton sitting on 2026-08-24, whose shuffle put the
short item first, so a ten-item sitting ended after one response.
</objective>

<context>
The park is deliberate and asserted. `hint_roundtrip` pins both halves by name:
`a pending short response must not advance the cursor`, and `exam must not move
the cursor before an accepted mark`. The second names the missing transition:
`before` implies an `after` that does not exist.

Three artifacts show the gap rather than argue it:

1. `runtime.py` `teaching_transition`, the `score is None` branch, returns
   `defer_feedback` with the session's cursor untouched. Re-submitting returns
   the same. Measured 2026-08-24 on a fixture: cursor stayed at 1 across three
   submissions.
2. `itembank mark --session S --item Q --verdict pass` records the mark as an
   evidence event and never touches a session file. Measured: cursor unchanged
   after an accepted mark, and the next submit still deferred.
3. `tests/lti_roundtrip.py:1478` reaches a completed session with a pending
   short item by hand-writing `data["cursor"] = len(data["items"])` and
   `data["status"] = "complete"`, under the comment "the marker-closed state:
   the runtime's own completion arithmetic applied to the real session file".
   The runtime never applies it. `tests/agent_roundtrip.py:85` simply `break`s
   out of its sitting loop when it meets a short item.

The consequence beyond 13.9: `finish()` renders an "N short items pending"
summary line and `do_report` reports `pending_manual`, both of which describe a
finished sitting that no learner can currently reach.
</context>

<task type="auto">
  <name>Task 1: The runtime transition, on supplied facts</name>
  <files>runtime.py, surfaces/session.py</files>
  <action>
Give `teaching_transition` the settled-mark facts it needs WITHOUT teaching the
runtime to read the evidence log: it is a pure function over
`(session, q, action)` and must stay one. Add an optional keyword carrying the
set of item keys whose marks are accepted in this session. `surfaces/session.py`
`do_action` already opens the evidence log; it computes that set and passes it.

In the `score is None` branch: if the current item's key is in the settled set,
advance the cursor with `_advance_cursor` and return the advancing action.
Otherwise return `defer_feedback` with the cursor untouched, exactly as today.
The default when no facts are supplied is today's behaviour, so every existing
caller is unchanged.

Do the same for the two policy `defer_feedback` sites (diagnostic and exam), so
`exam must not move the cursor before an accepted mark` gains its `after`.

The mark stays evidence and the runtime stays the settler: nothing here scores
anything, and no second store or scorer is introduced.
  </action>
  <verify>
`python3 tests/hint_roundtrip.py`, `python3 tests/evidence_roundtrip.py`,
`python3 tests/agent_roundtrip.py`, `python3 tests/scoring_roundtrip.py` exit 0
with their park assertions UNCHANGED. A fixture walk shows a short item parked
before a mark and advancing after one.
  </verify>
