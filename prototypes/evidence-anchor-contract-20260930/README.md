# Fixed evidence-anchor readiness prototype

This is a tested proposal, not accepted production syntax. It reuses the
existing fixed-span multi experiment in `../audit-question-families/families.py`
and strengthens its source binding and recovery. All content is fictional.

Run from the repository root:

```sh
python3 tests/evidence_anchor_contract_roundtrip.py
python3 prototypes/evidence-anchor-contract-20260930/anchor_contract.py --mode practice --port 8768
```

Open the printed loopback URL. Use Space on a native checkbox, Save draft,
reload, then Submit selection. `--mode exam` and `--mode diagnostic` use those
actual runtime policies. Every launch creates a fresh temporary course and
ordinary sitting; Ctrl-C closes the server and removes its temporary workspace.
No installed app or real course is opened. The server is a single-process
tracer, not a production concurrency or authorization boundary.

The plain fixture at `fixtures/bank.md` includes the passage, exact ranges,
anchor IDs, questions and ordinary multi options. The native view uses labeled
checkboxes, a fieldset and legend, visible focus, controls at least 44px high,
and no script or motion. Diagnostics are optional disclosure. Human screen
reader, physical touch and learning acceptance remain open.

`declaration.example.json` is the complete proposed v1 shape. Its repeated
digit object IDs are illustrative placeholders, not accepted objects. The
tracer creates real source/binding IDs through existing owners before testing.
The proposed per-item spelling is `[EVIDENCE-ANCHORS: <one-line JSON>]`, on an
ordinary multi item. This prototype does not teach `model.py` that spelling.

The named readiness report is
`../../.planning/research/question-types-2026-09-25/EVIDENCE-ANCHOR-READINESS-2026-09-30.md`.
It contains exact decisions, production insertion points, validation and
recovery gates. Nothing here scores outside the runtime or accepts a new
evidence authority. Free annotation and first-error grading stay separate.
